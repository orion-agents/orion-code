# Migrating Orion Code from v0.3.3 to v0.3.4

v0.3.4 is a compatible stabilization release. Existing projects, Sessions, Goals, settings and terminal preferences require no data migration.

## Web API callers

`PATCH /api/v1/settings` now requires the active Context guard in addition to Settings CAS:

```json
{
  "requestId": "<uuid>",
  "workspaceId": "<bootstrap.workspaceId>",
  "expectedContextRevision": "<bootstrap.contextRevision>",
  "expectedRevision": "<settings.revision>",
  "operations": [{ "op": "set", "key": "appearance.theme", "value": "dark" }]
}
```

A stale page receives `409 context_revision_conflict`. The client must refresh bootstrap/settings and ask the user to retry; it must never replay the mutation automatically into a different Workspace.

File tree responses may add `targetKind: file|directory` for readable symbolic links. Callers should preserve `kind=symlink` for display/security and use `targetKind` only to choose file preview versus directory expansion.

Review responses add `totalChangedFiles`. `changedFiles.length` is the visible bounded page and must not be presented as the repository total when `truncated=true`.

## Runtime behavior

- Blank Session rename requests now return 400 instead of persisting an empty title.
- A busy `reject-busy` slash command no longer clears the active turn state.
- Tool receipts with one-sided or mismatched durable evidence fail closed in UI projections.
- Terminal reconnect sends all replay frames before live tail and exit; unpaired UTF-16 input is normalized at the transport boundary.

## Security behavior

Internal symbolic-link aliases do not bypass sensitive-file policy. Git diff blocks sensitive current paths and rename sources. Structured X-prefixed credentials, URL userinfo and captured command output pass through the shared redaction boundary.

No configuration key is renamed and no manual file rewrite is required.
