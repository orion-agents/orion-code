# Orion Code v0.1.8 → v0.1.9 migration and rollback

Status: release-candidate guidance. Update release receipts before treating v0.1.9 as published.

## What changes

- TaskContract V3 is an additive contract stored inside the existing HarnessState V2 sidecar.
  Legacy string criteria remain readable and normalize deterministically to stable criterion IDs.
- Compact Checkpoint V1 remains readable. v0.1.9 writes Checkpoint V2 with source and replacement
  hashes, semantic candidate receipts, target-headroom validation, and Harness/Goal bindings.
- The canonical session transcript remains append-only. Compact replaces only the model-visible
  projection, so an invalid or stale checkpoint can fall back to the transcript without replaying
  external side effects.
- Legacy Goal continuation counters remain readable as telemetry, but no longer terminate a
  progressing Goal after five continuations. Explicit resource budgets, no-progress, provider,
  permission, abort, and evidence gates remain active.
- Deprecated subagent turn fields remain accepted for one compatibility window and translate to
  request/tool budgets.

## Before upgrading

1. Stop active Orion CLI processes so session sidecars are quiescent.
2. Record the installed version with `orion --version`.
3. Make a recoverable backup of `~/.orion-code` using a copy or snapshot tool appropriate for the
   machine. Keep file permissions intact and do not commit the directory.
4. Run `orion doctor` on v0.1.8 and resolve storage/native dependency errors first.

Install the immutable candidate only after its npm receipt exists:

```bash
npm install -g @orion-agents/orion-code@0.1.9
orion --version
orion doctor
```

## First resume on v0.1.9

- Resume a non-critical session first and inspect `/context explain`.
- A valid V1 checkpoint is accepted. The next successful compact writes V2.
- A stale, corrupt, source-mismatched, Harness-mismatched, or Goal-mismatched V2 checkpoint is not
  installed. Orion keeps the canonical transcript and reports an actionable diagnostic.
- Do not delete `.candidate`, `.previous`, `.lock`, or `.recovery` files while an Orion process is
  running. Use the explicit storage repair flow after confirming no process owns them.

## Rollback

The executable can be rolled back without deleting session data:

```bash
npm install -g @orion-agents/orion-code@0.1.8
orion --version
```

v0.1.8 does not understand V2 Compact sidecars. It can still read the canonical transcript, but it
may ignore the latest model projection and V3-only criterion metadata. For the cleanest rollback,
stop Orion, restore the pre-upgrade `~/.orion-code` backup, then resume. Never copy only the compact
pointer without its session meta, transcript, Harness, and Goal sidecars.

If rollback was caused by a data mismatch, preserve the v0.1.9 backup and diagnostic output for
audit; do not repeatedly compact or resume the affected session until the mismatch is understood.
