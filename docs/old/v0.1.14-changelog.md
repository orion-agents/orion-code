# OpenHorse v0.1.14 Roadmap - 多模型提供商 & 知识系统 & 钩子框架

> **版本定位**: 打破单一模型依赖、引入知识检索能力、建立事件驱动钩子框架
> **基础版本**: v0.1.13 (自愈系统 & 插件生态 & 会话管理深化)
> **创建日期**: 2026-05-23
> **目标日期**: 2026-Q4

---

## Context

### v0.1.12-v0.1.13 已完成/规划
- ✅ CLI Commands 系统基础 (v0.1.12)
- 🔄 自愈系统 Auto-Compact / Auto-Fix / Hook Chains (v0.1.13 P0)
- 🔄 插件生态生命周期管理 (v0.1.13 P1)
- 🔄 权限智能分类器 (v0.1.13 P1)
- 🔄 会话存储增强 (v0.1.13 P2)

### v0.1.14 战略方向
v0.1.14 聚焦于 OpenHorse **差异化竞争力** 的三个核心支柱：

1. **多模型提供商 (Multi-Provider)** — 打破单一模型锁定，支持 Qwen/GPT/Claude/Gemini 等
2. **知识系统 (Knowledge System)** — 本地知识检索 + 语义搜索增强
3. **钩子框架 (Hook Framework)** — 轻量事件驱动，比 OpenClaude 的 Hook Chains 更灵活

- 钩子有独立的错误处理
- 钩子可按技能/插件注册

#### 2. 与 Hook Chains 的关系

```
Hook Framework (v0.1.14)
  ├── 事件注册和分发 (基础层)
  ├── 钩子类型定义 (扩展层)
  └── 钩子执行引擎 (运行时)
        ↓
Hook Chains (v0.1.13 P0)
  ├── 自愈规则 (应用层)
  ├── 修复动作 (应用层)
  └── 安全限制 (防护层)
```

**关键认知**: Hook Framework 是基础设施，Hook Chains 是上面的一个应用。v0.1.14 应先建基础设施，v0.1.13 的 Hook Chains 依赖于此。

## P0 (必须) — 多模型提供商

### 1. Provider 抽象层

**目标**: 实现统一的模型提供商接口，支持多模型切换

**OpenClaude 参考**: `src/utils/model/`, `src/utils/api.ts`

**技术方案**:
```typescript
// src/providers/provider.ts
interface Provider {
  id: string;                      // 'openai' | 'anthropic' | 'qwen' | ...
  name: string;                    // 显示名称
  baseUrl: string;                 // API 基础 URL
  models: ModelCatalog;            // 支持的模型列表
  adapter: RequestAdapter;         // 请求/响应适配器
  costCalculator?: CostCalculator; // 费用计算
}

interface ModelCatalog {
  list(): ModelInfo[];
  get(modelId: string): ModelInfo | null;
  search(query: string): ModelInfo[];
}

interface ModelInfo {
  id: string;
  name: string;
  contextWindow: number;           // 最大上下文长度
  maxOutputTokens: number;         // 最大输出长度
  supportsVision: boolean;         // 是否支持图像输入
  supportsReasoning: boolean;      // 是否支持推理
  pricing: {
    inputPerMTokens: number;       // 输入价格 ($/M tokens)
    outputPerMTokens: number;      // 输出价格 ($/M tokens)
  };
}

interface RequestAdapter {
  // 统一请求格式 → 提供商特定格式
  formatRequest(request: UnifiedRequest): ProviderRequest;
  // 提供商特定格式 → 统一响应格式
  parseResponse(response: ProviderResponse): UnifiedResponse;
  // 流式响应适配
  parseStream(stream: ReadableStream): AsyncGenerator<UnifiedStreamChunk>;
}
```

**验收标准**:
- [ ] 至少支持 3 个提供商 (OpenAI, Anthropic, Qwen)
- [ ] 模型切换无需重启
- [ ] 请求/响应格式正确适配
- [ ] 流式响应正常工作

### 6. 钩子框架 (Hook Framework)

**目标**: 实现轻量事件驱动钩子框架

**OpenClaude 参考**: `src/utils/hooks/AsyncHookRegistry.ts`

**技术方案**:
```typescript
// src/hooks/hook-framework.ts

// 事件类型
type HookEvent =
  | 'before_prompt'
  | 'after_prompt'
  | 'before_tool_use'
  | 'after_tool_use'
  | 'tool_use_failed'
  | 'session_start'
  | 'session_end'
  | 'session_resume'
  | 'skill_registered'
  | 'agent_spawn'
  | 'agent_complete'
  | 'file_changed';

// 钩子定义
interface Hook {
  id: string;
  event: HookEvent;
  priority: number;               // 执行优先级 (小数字优先)
  handler: (context: HookContext) => Promise<HookResult>;
  enabled: boolean;
  source: 'builtin' | 'plugin' | 'skill' | 'user';
}

// 钩子注册表
interface HookRegistry {
  register(hook: Hook): void;
  unregister(hookId: string): void;
  listHooks(event?: HookEvent): Hook[];
  
  // 触发钩子 (顺序执行)
  trigger(event: HookEvent, context: HookContext): Promise<HookResult[]>;
  
  // 触发钩子 (并行执行)
  triggerParallel(event: HookEvent, context: HookContext): Promise<HookResult[]>;
  
  // 拦截模式 (钩子可修改上下文)
  triggerIntercept(event: HookEvent, context: HookContext): Promise<HookContext>;
}

// 钩子上下文 (按事件类型不同)
interface HookContext {
  event: HookEvent;
  timestamp: number;
  sessionId: string;
  // 事件特定数据
  data: Record<string, unknown>;
}

interface HookResult {
  hookId: string;
  success: boolean;
  error?: string;
  modified?: boolean;             // 是否修改了上下文
}
```

**验收标准**:
- [ ] 钩子注册和注销正常
- [ ] 事件触发和分发正确
- [ ] 钩子可修改上下文 (拦截模式)
- [ ] 钩子错误不影响主流程
- [ ] 支持 builtin/plugin/skill 来源

## OpenClaude vs OpenHorse 对比分析 (v0.1.14 视角)

### 可引入的关键设计

| OpenClaude 设计 | OpenHorse 引入方式 | 优先级 | 差异化 |
|----------------|-------------------|--------|--------|
| **Provider Registry** | 统一提供商抽象 | P0 | 更轻, 按需加载 |
| **Model Router** | 智能模型选择 | P0 | 支持自定义路由策略 |
| **Cost Tracking** | 会话费用追踪 | P0 | 简化, 无 UI 依赖 |
| **Orama Knowledge** | 混合搜索增强 | P1 | 已有向量基础, 加全文 |
| **Web Search Adapters** | 多搜索后端 | P1 | 可加国内源 (百度/搜狗) |
| **Async Hook Registry** | 事件驱动钩子 | P1 | 比 Hook Chains 更通用 |
| **Agent Swarm** | 动态协调 | P2 | 更轻量的 Worker |
| **MCP Lifecycle** | 完整管理 | P2 | 按需加载 |
| **Conversation Export** | MD + JSON | P2 | 简单实现 |

### OpenHorse 差异化竞争优势

| 方向 | OpenClaude | OpenHorse v0.1.14 优势 |
|------|-----------|----------------------|
| **多模型** | 15+ 但配置复杂 | 精简配置, 开箱即用 |
| **知识系统** | Orama (较重) | 轻量混合搜索 |
| **钩子系统** | 复杂 Hook Chains | 简单事件驱动, 易理解 |
| **部署** | React + Ink + Bun | Node.js + 零 UI 依赖 |
| **国内模型** | 间接支持 | 原生支持 (Qwen/GLM/Kimi) |
| **学习曲线** | 高 (大量概念) | 低 (渐进复杂度) |

**核心竞争力**:
1. **多模型优先** — 内置多提供商支持, 不被单一模型锁定
2. **轻量知识** — 在现有向量搜索上扩展, 不引入重型依赖
3. **事件驱动** — 钩子框架作为基础设施, 支撑未来所有扩展
4. **国产化** — 原生支持国内主流模型和搜索源
5. **零 UI 依赖** — 纯 Node.js, 部署极简

## 风险控制

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| Provider API 不兼容 | 高 | 适配器模式 + 单元测试覆盖 |
| 模型切换丢失上下文 | 中 | 统一消息格式 + 迁移逻辑 |
| 钩子性能开销 | 中 | 钩子执行超时 + 并行优化 |
| 混合搜索准确度 | 中 | 可调权重 + A/B 测试 |
| 成本追踪不准 | 低 | 定期校准 + 手动覆盖 |
