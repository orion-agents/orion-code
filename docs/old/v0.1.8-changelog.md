## P0 (必须) — 自动化核心

### 1. Session Memory 服务

**目标**: 自动维护会话笔记 markdown 文件

**OpenClaude 参考**: `src/services/SessionMemory/` (4 文件)

**技术方案**:
```typescript
// src/services/session-memory/sessionMemory.ts
interface SessionMemoryService {
  // 配置
  config: SessionMemoryConfig;
  
  // 自动更新
  runBackgroundUpdate(): Promise<void>;
  
  // 阈值触发
  hasMetUpdateThreshold(): boolean;
  hasMetInitializationThreshold(): boolean;
  
  // Forked Agent 执行
  extractMemories(): Promise<void>;
}

interface SessionMemoryConfig {
  updateInterval: number;      // 更新间隔 (默认 5 次工具调用)
  maxTokens: number;           // 最大 tokens
  templatePath: string;        // 模板路径
}
```

**实现要点**:
```
src/services/session-memory/
├── sessionMemory.ts          # 主服务
├── prompts.ts                # 提取提示模板
├── sessionMemoryUtils.ts     # 工具函数
└── config.ts                 # 配置管理
```

**会话笔记内容**:
- 当前任务摘要
- 关键决策记录
- 待解决问题列表
- 重要代码片段引用

**验收标准**:
- [ ] `SESSION_MEMORY.md` 自动生成
- [ ] 每 5 次工具调用自动更新
- [ ] Forked Agent 后台执行
- [ ] 笔记内容准确记录会话关键信息

### 2. AutoFix 服务

**目标**: 代码修改后自动运行 lint + test，检测并修复错误

**OpenClaude 参考**: `src/services/autoFix/` (6 文件)

**技术方案**:
```typescript
// src/services/auto-fix/autoFixRunner.ts
interface AutoFixRunner {
  // 执行检查
  runLintCheck(options: AutoFixCheckOptions): Promise<AutoFixResult>;
  runTestCheck(options: AutoFixCheckOptions): Promise<AutoFixResult>;
  
  // 自动修复
  attemptAutoFix(result: AutoFixResult): Promise<FixResult>;
  
  // 配置
  config: AutoFixConfig;
}

interface AutoFixConfig {
  lintCommand: string;        // 默认 'npm run lint'
  testCommand: string;        // 默认 'npm test'
  timeout: number;            // 超时时间 (默认 60s)
  autoFixEnabled: boolean;    // 是否自动修复
}
```

**实现要点**:
```
src/services/auto-fix/
├── autoFixRunner.ts          # 主运行器
├── autoFixHook.ts            # Post-sampling hook
├── autoFixConfig.ts          # 配置管理
└── prompts.ts                # 修复提示
```

**工作流程**:
1. 代码编辑完成后触发 hook
2. 运行 lint 检查
3. 运行 test 检查
4. 检测到错误 → 尝试自动修复
5. 修复失败 → 提示用户

**验收标准**:
- [ ] 代码修改后自动运行 lint
- [ ] 代码修改后自动运行 test
- [ ] 检测到 lint 错误尝试自动修复
- [ ] 检测到 test 错误尝试自动修复
- [ ] 超时处理正常

### 3. Smart Model Routing

**目标**: 智能路由简单请求到便宜模型，复杂请求到强模型

**OpenClaude 参考**: `src/services/api/smartModelRouting.ts`

**技术方案**:
```typescript
// src/services/smart-routing.ts
interface SmartRoutingService {
  // 路由决策
  route(input: RoutingInput): RoutingDecision;
  
  // 配置
  config: SmartRoutingConfig;
}

interface RoutingInput {
  userText: string;           // 用户输入
  recentToolUses?: number;    // 最近工具调用数
  turnNumber?: number;        // 会话轮次
}

interface RoutingDecision {
  model: string;              // 选择的模型
  complexity: 'simple' | 'strong';
  reason: string;             // 决策原因
}
```

**路由规则**:
- **简单** (< 160 chars, < 28 words, 无强关键词):
  - "ok", "thanks", "continue", "good"
  → 路由到 Haiku/Mini
- **复杂** (> 160 chars 或含强关键词):
  - "plan", "design", "implement", "debug"
  → 路由到 Sonnet/Opus

**验收标准**:
- [ ] "ok" 路由到简单模型
- [ ] "plan the refactor" 路由到强模型
- [ ] 配置可自定义阈值
- [ ] 路由决策显示原因

## 差异化竞争优势

OpenHorse vs OpenClaude:

| 方向 | OpenClaude | OpenHorse v0.1.8 优势 |
|------|-----------|----------------------|
| Session Memory | 复杂 Fork 机制 | 简化后台更新 |
| AutoFix | 6 文件复杂实现 | 简化 Runner + Hook |
| Smart Routing | 完整路由系统 | 简化规则路由 |
| Diagnostic | IDE 集成复杂 | LSP 基础追踪 |
| Speculation | 完整预测系统 | 简化预测场景 |

**核心竞争力**:
1. **简化服务层** — 核心功能，无过度复杂
2. **智能成本优化** — Smart Routing 节省 API 成本
3. **自动化效率** — AutoFix + Session Memory 自动化
4. **诊断追踪** — 新错误检测，提升代码质量
