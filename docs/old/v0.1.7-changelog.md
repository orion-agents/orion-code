## P0 (必须) — 生产级核心

### 1. 会话压缩服务 (compact)

**目标**: 长对话性能优化，支持超过 100 条消息的会话

**OpenClaude 参考**: `src/services/compact/` (15 文件)

**技术方案**:
```typescript
// src/services/compact/
interface CompactService {
  // 压缩策略
  microCompact(messages: Message[]): CompactResult;      // 快速压缩
  sessionMemoryCompact(messages: Message[]): CompactResult; // 记忆压缩
  autoCompact(messages: Message[], threshold: number): CompactResult; // 自动触发
  
  // 压缩边界
  createCompactBoundary(summary: string): SystemCompactBoundaryMessage;
  
  // 配置
  maxOutputTokens: number;  // 压缩后最大 tokens
  autoTriggerThreshold: number; // 自动触发阈值 (默认 50 条)
}
```

**实现要点**:
```
src/services/compact/
├── compact.ts              # 主压缩服务
├── micro-compact.ts        # 快速压缩算法
├── session-memory-compact.ts # 记忆保存压缩
├── auto-compact.ts         # 自动触发逻辑
├── boundary.ts             # 压缩边界处理
├── summary-generator.ts    # 摘要生成
└── config.ts               # 压缩配置
```

**压缩策略**:
1. **microCompact**: 保留最近 10 条消息 + 关键工具调用
2. **sessionMemoryCompact**: 提取关键记忆保存到 memory 系统
3. **autoCompact**: 消息数超过阈值自动触发

**验收标准**:
- [ ] `microCompact` 压缩延迟 < 500ms
- [ ] `autoCompact` 自动触发阈值可配置
- [ ] 压缩边界消息正确生成
- [ ] 压缩后会话可正常继续

### 2. Coordinator 模式

**目标**: 多 Agent 协调器，实现真正的 Agent Swarm

**OpenClaude 参考**: `src/coordinator/` + `isCoordinatorMode()`

**技术方案**:
```typescript
// src/agents/coordinator.ts
interface Coordinator {
  // 协调器状态
  agents: Map<AgentId, AgentState>;
  taskQueue: Task[];
  taskAssignments: Map<TaskId, AgentId>;
  
  // 协调方法
  assignTask(task: Task): AgentId;
  broadcast(message: CoordinatorMessage): void;
  collectResults(): TaskResult[];
  
  // 模式切换
  enableCoordinatorMode(): void;
  disableCoordinatorMode(): void;
}
```

**协调模式特性**:
- 主 Agent 作为协调者，不直接执行任务
- 子 Agent 执行分配任务，结果汇报主 Agent
- 支持动态 Agent 注册/注销
- 任务优先级队列管理

**验收标准**:
- [ ] `/coordinator` 进入协调模式
- [ ] 主 Agent 可分配任务给子 Agent
- [ ] 子 Agent 结果汇总到主 Agent
- [ ] 协调模式与 Fork 模式互斥
