## Part 1: DashScope/Bailian API 工具调用修复

### 问题背景

GLM-5 模型（百炼/DashScope API）调用工具时全部失败，显示：

```
Turn 1...
  ▸ list_files  ✗ 0ms
    Error: list_files requires a path parameter
```

### 根因分析

通过 `OPENHORSE_DEBUG_TOOLS=true` 调试发现，DashScope API 返回的 streaming chunk 格式与 OpenAI 不同：

```json
// DashScope 在同一个 chunk 中返回完整的 tool_call
{
  "delta": {
    "tool_calls": [{
      "index": 0,
      "id": "tool-c70c4b1aecd841b2...",
      "type": "function",
      "function": {
        "name": "list_files",
        "arguments": "{\"path\": \".\"}"  // 参数已完整返回！
      }
    }]
  }
}
```

**原代码问题**：使用 `if-else` 结构，当 `tc?.id` 存在时跳过了 `arguments` 处理：

```typescript
// 错误的实现
if (tc?.id) {
  toolCallsMap.set(idx, {
    id: tc.id,
    function: { name: tc.function?.name ?? '', arguments: '' },  // 空字符串！
  });
} else if (tc?.function?.arguments) {  // 这个分支永远不会执行
  entry.function.arguments += tc.function.arguments;
}
```

### 修复方案

改为同时处理 `id` 和 `arguments`：

```typescript
// 正确的实现
const tc = delta?.tool_calls?.[0];
if (tc) {
  const idx = tc.index ?? 0;
  if (tc.id) {
    toolCallsMap.set(idx, {
      id: tc.id,
      type: 'function',
      function: {
        name: tc.function?.name ?? '',
        arguments: tc.function?.arguments ?? ''  // 直接获取 arguments
      },
    });
  } else if (tc.function?.arguments) {
    // 处理后续的 arguments chunk（流式追加）
    const entry = toolCallsMap.get(idx);
    if (entry) {
      entry.function.arguments += tc.function.arguments;
    }
  }
}
```

## Part 2: OpenClaude 轮数控制调研

### 背景

OpenHorse 当前使用固定 `maxTurns = 20` 限制 agent 循环轮数。调研 OpenClaude 的实现方式，为改进提供参考。

### OpenClaude 核心发现

**OpenClaude 没有固定轮数限制！** 默认 `maxTurns ?? Infinity`，依赖多维度安全机制。

#### 源码位置

| 文件 | 关键代码 |
|------|---------|
| `src/query.ts:1451` | `turnCount < (maxTurns ?? Infinity)` |
| `src/query.ts:1923-1929` | max_turns_reached 信号 |
| `src/QueryEngine.ts:144` | `maxTurns?: number` 可配置参数 |

#### Turn 计数逻辑

```typescript
// query.ts
let state: State = {
  turnCount: 1,  // 初始值
  ...

// 每轮工具执行后递增
```

### 停止条件优先级

```
1. 用户中断 (abort signal)
2. 预算超限 (maxBudgetUsd)
3. Task Budget 耗尽
4. Token Budget diminishing returns
5. Tool Failure Loop Guard 触发
6. Stop Hook 阻止
7. Continuation Nudge 达上限
8. Max Output Tokens 恢复失败
9. Reactive Compact 失败
10. Max Turns 达上限（可选）
11. 任务完成（无 tool_calls）
```

#### Step 4: 集成到 Query Loop

**文件**：`src/framework/query.ts`

```typescript
import { createFailureGuard, recordFailure, recordSuccess } from '../core/tool-failure-guard';
import { shouldNudge, createNudgeMessage } from '../core/continuation-nudge';

export async function* query(params: QueryParams) {
  const failureGuard = createFailureGuard(params.failureGuardConfig ?? DEFAULT_FAILURE_CONFIG);
  const nudgeState = { count: 0, lastNudgeTime: 0 };
  
  while (true) {
    // ... LLM 调用
    
    // Tool 结果处理
    for (const toolResult of toolResults) {
      if (!toolResult.success) {
        const failure = recordFailure(failureGuard, toolResult.name, toolResult.error, toolResult.path);
        if (failure.tripped) {
          yield { type: 'failure_guard_tripped', reason: failure.reason };
          return;
        }
      } else {
        recordSuccess(failureGuard);
      }
    }
    
    // 检查是否需要 nudge
    if (!hasToolCalls && shouldNudge(nudgeState, assistantContent, false, nudgeConfig)) {
      nudgeState.count++;
      messages.push({
        role: 'user',
        content: createNudgeMessage(),
      });
      continue;
    }
    
    // 无工具调用且无 nudge -> 完成
    if (!hasToolCalls) {
      yield { type: 'complete', content };
      return;
    }
  }
}
```
