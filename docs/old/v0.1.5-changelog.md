# v0.1.5 Roadmap: CLI 交互体验增强

> **版本目标**：打造比 OpenClaude 更好用的 CLI Coding Agent
> **核心原则**：保留 readline + chalk，递进式增强，专注 CLI UX

---

## 背景

经过对 OpenClaude 能力的完整调研（见 `docs/old/openclaude-capabilities-reference.md`），发现其 CLI 交互有以下亮点：

1. **Ink 渲染栈**：React reconciler + frame-buffer 双缓冲，流畅的组件化渲染
2. **键盘事件系统**：支持组合键绑定（如 `ctrl+x ctrl+b`）
3. **Footer Suggestions Panel**：类型化图标 + 焦点导航的命令面板
4. **流式 Markdown**：混合渲染策略，代码块/表格等逐步显示
5. **权限对话框 UX**：审批模式、信任对话框等交互模式

OpenHorse 当前使用 readline + chalk 的简单架构，目标是在**保持轻量**的前提下，实现类似或更好的交互体验。

---

## Part 1: Slash 命令自动补全面板 (P0)

**问题**：当前 `/help` 后需手动输入命令，无自动补全，无预览。

**目标**：实现类似 OpenClaude Footer Suggestions Panel 的命令选择面板。

**设计**：
```
用户输入: /
┌─────────────────────────────────────────────────────────┐
│ /help     显示帮助信息                          [命令]  │
│ /clear    清除对话历史                          [命令]  │
│ /config   配置管理                              [命令]  │
│ /mcp      MCP 服务器管理                        [命令]  │
│ /model    切换模型                              [命令]  │
│ /resume   恢复上次会话                          [命令]  │
│ /exit     退出程序                              [命令]  │
└─────────────────────────────────────────────────────────┘
↑↓ 导航  Enter 选择  Esc 取消
```

**实现**：
1. **触发条件**：输入 `/` 后自动显示面板
2. **过滤逻辑**：继续输入时实时过滤匹配命令
3. **导航方式**：`↑` `↓` 选择，`Enter` 确认，`Esc` 关闭
4. **类型图标**：命令类型 `[命令]` `[工具]` `[技能]`
5. **描述显示**：右侧显示命令简短描述

**文件**：
- `src/ui/command-panel.ts` (NEW)：命令面板组件
- `src/ui/autocomplete.ts` (NEW)：自动补全逻辑
- `src/cli.ts`：集成 readline 事件监听

**工作量**：1.5d

## Part 2: 多行输入支持 (P0)

**问题**：当前 `Enter` 直接发送消息，无法输入多行代码块或长文本。

**目标**：支持 `Shift+Enter` 换行，`Enter` 发送。

**设计**：
```
用户: 这是一个代码示例：
      ```typescript
      function hello() {    ← Shift+Enter 换行
        console.log('hi');
      }
      ```                    ← Enter 发送
```

**实现**：
1. **按键检测**：`readline` 监听 `keypress` 事件，区分 `Enter` vs `Shift+Enter`
2. **视觉指示**：多行模式下显示行号或 `...` 续行符
3. **历史记录**：多行输入作为单条消息存入历史
4. **取消操作**：`Ctrl+C` 在多行模式下取消当前输入

**文件**：
- `src/ui/multiline-input.ts` (NEW)：多行输入处理
- `src/cli.ts`：集成按键事件

**工作量**：1d

## Part 3: 输入历史导航 (P0)

**问题**：无法查看或搜索历史输入，重复输入效率低。

**目标**：实现 `↑` `↓` 历史导航 + `Ctrl+R` 反向搜索。

**设计**：
```
用户: 帮我写一个
     [历史记录模式]
     > 帮我写一个单元测试
       帮我写一个 API 接口
       帮我写一个工具函数
     ↑↓ 导航  Enter 选择  Ctrl+R 搜索
```

**实现**：
1. **历史存储**：`~/.openhorse/history.json`，最多保存 1000 条
2. **简单导航**：空输入时 `↑` 进入历史模式
3. **反向搜索**：`Ctrl+R` 后输入关键词实时过滤
4. **去重逻辑**：相似输入只保留最新一条
5. **会话关联**：历史记录可选关联 session ID

**文件**：
- `src/ui/input-history.ts` (NEW)：历史管理
- `src/services/history-storage.ts` (NEW)：历史持久化
- `src/cli.ts`：集成历史导航

**工作量**：1d

## Part 4: @-提及文件路径补全 (P1)

**问题**：手动输入文件路径容易出错，无自动补全。

**目标**：输入 `@` 后自动补全文件路径。

**设计**：
```
用户: 帮我分析 @src/to
     ┌─────────────────────────────────────────────────────┐
     │ src/tools/                                         │
     │ src/tools/index.ts                                 │
     │ src/tools/todo.ts                                  │
     │ src/tools/mcp.ts                                   │
     │ src/tools/web.ts                                   │
     └─────────────────────────────────────────────────────┘
     Tab 补全  ↑↓ 导航  Enter 选择
```

**实现**：
1. **触发条件**：输入 `@` 后开始文件匹配
2. **匹配逻辑**：glob 模式，支持相对路径和绝对路径
3. **忽略文件**：读取 `.gitignore` 排除 `node_modules` 等
4. **补全方式**：`Tab` 补全当前选择，`Enter` 确认
5. **多选支持**：`Space` 选中多个文件，一次性插入

**文件**：
- `src/ui/file-completion.ts` (NEW)：文件补全组件
- `src/services/file-glob.ts` (NEW)：文件匹配逻辑
- `src/cli.ts`：集成补全事件

**工作量**：1.5d

## Part 5: 状态栏增强 (P1)

**问题**：当前状态栏信息有限，无法直观了解 token 使用量和上下文占用。

**目标**：实时显示 token 数、成本、上下文使用百分比。

**设计**：
```
┌─────────────────────────────────────────────────────────┐
│ OpenHorse v0.1.5 | glm-5 | 🔮 12,345 tokens | 📊 45% ctx │
│ 💰 $0.0023 this session                                 │
└─────────────────────────────────────────────────────────┘
```

**实现**：
1. **Token 显示**：每次对话后更新累计 token
2. **上下文百分比**：当前消息数 / 最大上下文窗口
3. **成本追踪**：根据模型定价计算实时成本
4. **模型指示**：当前使用的模型名称
5. **连接状态**：MCP 服务器连接状态指示

**文件**：
- `src/ui/status-bar.ts` (NEW)：状态栏组件
- `src/cli.ts`：集成状态更新

**工作量**：0.5d

## Part 6: 流式 Markdown 渲染优化 (P1)

**问题**：当前流式输出直接打印，代码块可能断裂，表格渲染不完整。

**目标**：优化流式 Markdown 渲染，确保代码块、表格等完整显示。

**设计**：
1. **缓冲策略**：检测到代码块开始时缓冲到结束
2. **表格检测**：检测表格语法，整表渲染
3. **语法高亮**：代码块使用 chalk 高亮
4. **进度指示**：长输出时显示加载动画

**文件**：
- `src/ui/stream-markdown.ts` (NEW)：流式 Markdown 渲染器
- `src/ui/syntax-highlight.ts` (NEW)：语法高亮

**工作量**：1d

## Part 7: 工具预览与 Diff 显示 (P2)

**问题**：工具执行结果直接打印，难以阅读；文件修改无 diff 预览。

**目标**：优化工具执行结果显示，增加 diff 预览。

**设计**：
```
┌─ 工具执行 ─────────────────────────────────────────────┐
│ 📖 Read: src/cli.ts                                    │
│ ✅ 成功 (234ms)                                        │
│ ─────────────────────────────────────────────────────  │
│ 1│ import { createInterface } from 'readline';        │
│ 2│ import chalk from 'chalk';                          │
│ ...                                                    │
└─────────────────────────────────────────────────────────┘

┌─ 文件修改 ─────────────────────────────────────────────┐
│ ✏️ Edit: src/config.ts                                │
│ ─────────────────────────────────────────────────────  │
│ - const MAX_TOKENS = 4096;                            │
│ + const MAX_TOKENS = 8192;                            │
└─────────────────────────────────────────────────────────┘
```

**实现**：
1. **工具卡片**：每个工具调用显示为卡片形式
2. **结果截断**：超过 20 行自动折叠，可展开
3. **Diff 高亮**：`Edit` 工具显示 `+` `-` 行
4. **执行时间**：显示工具耗时

**文件**：
- `src/ui/tool-preview.ts` (NEW)：工具预览组件
- `src/ui/diff-display.ts` (NEW)：Diff 显示组件

**工作量**：1d

## 验收标准

1. **命令面板**：输入 `/` 显示命令列表，`↑↓` 导航，`Enter` 选择
2. **多行输入**：`Shift+Enter` 换行，`Enter` 发送
3. **历史导航**：`↑` 查看历史，`Ctrl+R` 搜索历史
4. **文件补全**：`@src/` 显示匹配文件列表
5. **状态栏**：显示 token 数、成本、上下文百分比
6. **渲染质量**：代码块完整无断裂，表格对齐

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| readline 事件监听限制 | 按键检测可能不完整 | 使用 `readline.createInterface` 的 `terminal: true` |
| 终端兼容性 | 不同终端行为不一致 | 添加终端类型检测，降级处理 |
| 性能影响 | 大量文件匹配可能卡顿 | 使用 debouncing + 异步 glob |
| 历史文件过大 | 加载历史慢 | 限制 1000 条，惰性加载 |
