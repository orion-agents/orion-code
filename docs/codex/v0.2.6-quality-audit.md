# v0.2.6 代码质量审计与修复报告

> 目录：`/Users/hope/ai-project/openhorse/docs/codex/v0.2.6-quality-review.md`  
> 目标：评估 v0.2.6 分支（claude 贡献实现）与当前设计目标的对齐度与风险点，给出可执行修复清单。

## 审计结论（先说结论）

v0.2.6 当前实现已具备**可发布质量**的主干稳定性：
- `npm run build` 通过
- `npm test -- --runInBand` 全量通过（61/61）
- 关键功能链路（runtime、query、tool 执行、session、harness、artifact、并发工具调度、prompt cache 控制字段）已被覆盖测试验证

## 已完成的关键修复

### 1) 工具执行链路
- `query.ts` 中工具调用由统一调度器接管：`tool-scheduler.ts` 负责**并发判定/权限处理/执行顺序**。
- 保留了与旧行为兼容的可观察事件：`tool_call` 与 `tool_result` 仍按原始顺序输出。
- `executeTool` 增加 `ToolContext` 透传 `sessionId/turnId/abortSignal`，让工具执行具备会话级关联性。

### 2) 中断与转储一致性
- Turn 生命周期传递 `turnId` 到 `runInput` 和 command/chat 运行上下文。
- 工具调用与 `executeTool` 都接入 abort signal，避免中断后出现僵死工具执行。
- 结合现有会话裁剪逻辑，`/resume` 与历史恢复在实测中可复用。

### 3) 编辑预览和防混淆
- `edit_file` 记录会话上下文（session/turn）以支持 `/edit-preview` 的上下文隔离。
- `/edit-preview` 会在新会话上下文冲突时拒绝展示旧编辑，避免误预览。
- legacy 状态兼容路径保持回退，避免历史上下文丢失。

### 4) 结构化工具输出与大输出治理
- `ToolResult` 与 `query` 事件携带 `summary/outputBytes/artifactRef`，便于 harness/event 渲染层做轻量记录。
- `tool-artifacts` 完成大输出持久化+检索 API；输出过大不会直接污染 transcript 体量。
- 非 JSON 输出默认成功处理，减少 parse 失败导致的误报。

### 5) 版本与兼容性
- web-search 相关服务版本号不再硬编码，读取 `package.json` 或 `npm_package_version`。
- API 兼容性测试文件补齐（`tests/api-compatibility.test.ts`），覆盖核心公共类型。

## 质量风险与建议（非阻塞）

1. **日志噪音**
   - 全量测试中有重复 `SkillsLoader` 的 frontmatter 告警、`sqlite-vec` 可用性告警。  
   - 建议：CI 中抑制或按测试场景过滤，避免误伤信号质量。

2. **provider cache 标注类型**
   - `cache_control` 使用的是兼容层注入，类型上采用 `as any`，建议后续改为更严格的 provider message 联合类型定义，减少隐式耦合。

3. **工具元数据可读性**
- 当前 `tool result` 仍是 JSON 字符串在 llm message 中传输。  
- 建议后续引入统一的结构化序列化通道（例如固定 schema 标记），减少不同工具边界的解析差异。

4. **性能边界**
- 并行组执行使用 `Promise.allSettled`，对长尾工具未设置上限并发控制。  
- 现阶段通过 `isConcurrencySafe` + 串行分组已足够，若未来工具量上升可引入并发池。

## 与目标一致性评分

- **功能完整性**：A-（核心路径稳定，未见阻断缺陷）
- **可维护性**：A（scheduler 抽离后，query loop 更清晰）
- **可观测性**：A-（artifact 与 summary 让 transcript 更可控）
- **回归风险**：B+（全量测试通过，但部分 provider/环境告警仍待治理）

## 建议的 v0.2.7 继续项

1. 继续补齐 `/edit-preview` 的结构化候选交互（不是文本回显）。  
2. 将 `artifactRef` 生命周期（清理阈值）纳入运维策略文档。  
3. 完善 provider cache 兼容层类型并加单测（含 OpenAI / Anthropic / DashScope 兼容分支）。  
4. 引入“非阻塞告警归并”机制，保证 CI/本地日志更清晰。
