# v0.2.21 TUI 能力收敛技术方案

## 文档状态

- 目标版本：`v0.2.21`
- 当前基线：`v0.2.20` 开发分支上的 TUI、Ink 和 subagent runtime 接口
- 文档属性：本地开发指导，不进入 Git；仓库已通过 `.gitignore` 忽略整个 `docs/`
- 分支策略：等待 `v0.2.20` 完成、合并并发布后，再从最终 `main` 创建 `v0.2.21`
- 版本策略：开发期间保持上一发布版本号，进入 release gate 后才更新 `package.json` 为 `0.2.21`

当前工作区存在正在开发的 v0.2.20 subagent 代码。执行本计划的 coding agent 不得在当前脏工作树直接开始
v0.2.21 实现，也不得覆盖、回退或重新设计 v0.2.20 的 subagent runtime。

## 当前能力评估

OpenHorse 当前有三条交互路径：

- `terminal`：稳定默认，scrollback-first，日常发布质量基线。
- `ink`：React/Ink beta，界面丰富，支持 Markdown、多行 prompt、输入历史和组件化 overlay，但存在 React 17、
  Ink 3、Yoga、native cursor 和 resize 清屏维护成本。
- `tui`：renderer-owned alternate-screen beta，拥有显式 frame、terminal writer、input parser、state、layout 和
  runner，resize、CJK、paste、permission、resume、tool ordering、live revision 和受控退出已有自动化覆盖。

当前 TUI 主要差距：

1. `TuiCell` 只有 `char` 和 `width`，不能表达颜色、粗体、dim、代码块、diff 等样式。
2. transcript 只做纯文本换行，无法显示 heading、list、quote、inline code、code fence、diff 和 table。
3. prompt 高度固定为 3 行，长输入被截断，没有多行 viewport、Alt+Enter、Ctrl+J 和输入历史。
4. 每次 state action 都立即 render；layout 每次从完整 transcript 重新生成全部 visual lines，长会话成本为 O(n)。
5. alternate screen 隔离了 shell 原生 scrollback、选择和复制；内部 PageUp/PageDown 仍无法提供用户熟悉的终端历史体验。
6. TUI status 使用 renderer-local 字符串拼接，没有完整复用 `StatusSnapshot`，ctx、MCP、permission、loop 和
   subagent 状态不完整。
7. `RuntimeSubtaskEvent` 已进入 runtime protocol，但 TUI 和 Ink event sink 都尚未消费。
8. TUI 异常路径的 terminal restore 仍以 best effort 为主，强制信号、renderer exception 和 primary-screen
   live region 清理需加强。
9. Ink 中已经实现的 grapheme、input-buffer 和 prompt-layout 仍位于 `src/ink-ui/runtime/`，不能直接成为 TUI
   长期依赖。

当前聚焦基线：Ink、TUI、runtime parity 和 controller 共 10 suites、236 tests 通过。v0.2.21 必须在此基础上
增量开发，不能用功能升级换取已有输入、permission、session 或 terminal restore 回归。

## 版本目标

v0.2.21 的主题是 **TUI 能力收敛和主力候选准备**。

目标不是简单给 TUI 加颜色，而是让 TUI 在保留确定性 frame model 的前提下，达到或超过 Ink 的关键日常能力，
成为后续唯一高级终端 renderer 的候选实现。

版本必须交付：

- rich Markdown transcript：heading、paragraph、list、quote、inline code、code fence、diff、table、link。
- 带样式、宽字符安全、可 diff 的 frame/cell/writer。
- 多行 prompt viewport、Alt+Enter/Ctrl+J、输入历史、行内 Home/End、CJK/emoji/grapheme 光标。
- 增量 transcript layout cache 和 render coalescing，长流式输出不做全量重排风暴。
- primary-screen Inline TUI：已完成内容进入 shell 原生 scrollback，底部 live region 只重绘活动内容。
- 完整 status snapshot、tool timeline 和 subagent lifecycle timeline。
- terminal、Ink、TUI 对 runtime event 的语义 parity 不回退。
- abnormal exit、SIGTERM/SIGHUP、renderer exception 和 child process 往返后的 terminal restore。
- 真实终端矩阵与可复现 PTY 证据。

## 产品决策

### v0.2.21 内的 renderer 策略

- `terminal` 继续保持稳定默认，不在版本开始时切换默认 renderer。
- `tui` 是唯一继续获得新交互能力的高级 renderer。
- `ink` 进入 feature freeze：只修阻塞回归、安全问题和 runtime parity，不再新增产品能力。
- 只有当本文全部 P0 和 release acceptance 通过后，才允许把 TUI 标记为 `recommended beta`。
- v0.2.21 不删除 Ink；至少保留一个版本的 deprecation 窗口。
- React、Ink、Yoga 和 native cursor 依赖的删除安排在后续版本，不能与 TUI 收敛混在一个高风险提交中。

### Primary-screen Inline TUI

- v0.2.21 的 TUI 默认不进入 alternate screen，P0 只交付 primary-screen inline surface，不同时维护两套全屏模式。
- finalized transcript 是 append-only terminal output，只提交一次并由 shell/terminal 保存、滚动、选择、复制和重排。
- TUI 只拥有底部有界 live region：streaming assistant、running tool/subagent、overlay、status 和 prompt。
- live entry finalized 时先清理 live region，再把最终 rich rows 提交一次，最后重建 live region。
- TUI 不注册内部 transcript 导航；scrollback 使用终端实际绑定的 Shift+PageUp、鼠标滚轮、选择和复制。
- 外部 pager 降为 P1 export/viewer 能力，不作为 v0.2.21 scrollback 的必要条件。
- 如果后续确需 alternate-screen dashboard，必须作为独立 renderer mode 评估，不能污染 inline surface 的提交语义。

### 为什么不直接复制 Ink

Ink 的 `Markdown.tsx`、`PromptInput.tsx` 和 React state 不能直接导入 TUI：

- JSX 和 Yoga layout 不是 renderer-independent model。
- Ink native cursor 的坐标语义与 TUI frame cursor 不同。
- 直接复用会让 TUI 反向依赖准备淘汰的 renderer。
- TUI 需要可测试的 visual rows、cell style 和 cursor，而不是 React element tree。

正确路径是把可复用算法提升到 `src/runtime/` 或新的 shared view-model 模块，再由 Ink 和 TUI 分别适配。

## 非目标

- 不把 agent loop、subagent supervisor、permission policy、session、memory、skills 或 MCP 逻辑搬进 TUI。
- 不在 v0.2.21 删除稳定 `terminal` renderer。
- 不在实现中途切换 TUI 为默认。
- 不引入 Rust、ratatui、native addon 或新的全屏 UI 框架。
- 不重写 `AgentRuntimeController`。
- 不在 TUI 解析 assistant prose 来推断 tool/subagent 状态；只消费结构化 runtime event。
- 不实现鼠标文本选择、复杂 pane resize、任意窗口 docking 或远程 UI。
- 不实现 renderer-owned transcript scroll offset、follow-tail、新消息计数或鼠标滚动接管。
- P1 pager/export 若实现，不得执行 shell 字符串；必须使用结构化 `spawn` 和受控 argv。
- 不为了 rich text 允许模型输出中的 ANSI escape 直接进入 frame。

## 目标架构

```text
AgentRuntimeController
  -> AgentRuntimeEvent / UiEventSink
     -> TuiUiReducer
        -> shared View Models
           - TranscriptRichTextModel
           - ComposerBuffer / ComposerViewport
           - StatusSnapshot
           - ToolActivity / RuntimeSubtaskEvent
        -> TranscriptCommitQueue + LiveRegionState
        -> TuiLayoutCache
        -> TuiFrame<TuiCell + TuiStyle>       # live region only
        -> InlineTerminalSurface
           - commit(rows): append-only stdout
           - renderLive(frame): bounded bottom redraw
           - suspend/restore/unmount
        -> primary screen / native shell scrollback
```

关键原则：

- runtime event 是事实来源。
- shared view model 负责内容结构和状态规范化。
- TUI reducer 负责 renderer-local interaction state 和 transcript commit 边界。
- layout 负责待提交内容和 live region 的宽高预算与 visual rows。
- frame 只负责 live region 的 cell/style/cursor，不重新绘制已提交历史。
- surface 负责 append-only commit、底部最小 diff 和 stdout/stderr 复用。
- launch 负责 TTY 生命周期、signals、child process suspend/restore 和 shutdown。

## 1. Shared Composer Core

把以下 Ink 算法迁移为 renderer-independent 模块：

```text
src/runtime/composer/
  grapheme.ts
  buffer.ts
  layout.ts
  history.ts
```

目标 API：

```ts
interface ComposerBuffer {
  value: string;
  cursor: number;
  preferredColumn?: number;
}

type ComposerAction =
  | { type: 'insert'; text: string }
  | { type: 'backspace' }
  | { type: 'delete' }
  | { type: 'move'; direction: 'left' | 'right' | 'line-start' | 'line-end' | 'up' | 'down' }
  | { type: 'set'; value: string; cursor?: number }
  | { type: 'clear' };

interface ComposerViewport {
  lines: ComposerVisualLine[];
  hiddenRowsAbove: number;
  hiddenRowsBelow: number;
  cursorRow: number;
  cursorColumn: number;
}
```

语义要求：

- cursor 必须始终位于 grapheme boundary。
- Left/Right 按 grapheme 移动，不能拆分 emoji、组合字符或 CJK surrogate pair。
- Home/End 移动到当前 logical line 首尾，不是整个 buffer 首尾。
- Ctrl+A/Ctrl+E 与 Home/End 语义一致。
- Alt+Enter 和 Ctrl+J 插入 `\n`，Enter 提交。
- Up/Down 在多行输入中按 visual row 移动并保留 preferred column。
- 只有在单行、无 overlay、cursor 位于边界时，Up/Down 才进入 history navigation。
- bracketed paste 保留换行，但不得自动 submit。
- permission overlay 活跃时忽略普通文本、paste 和 composer editing key。

迁移方式：

- 先把 Ink 现有实现移动到 shared 模块并保留兼容 re-export。
- 先让 Ink 测试继续通过，再切 TUI 使用 shared composer。
- 不允许复制两份算法后分别演进。

## 2. Styled Frame Model

扩展 `TuiCell`：

```ts
interface TuiStyle {
  foreground?: TuiColor;
  background?: TuiColor;
  bold?: boolean;
  dim?: boolean;
  italic?: boolean;
  underline?: boolean;
  inverse?: boolean;
}

interface TuiCell {
  char: string;
  width: 0 | 1 | 2;
  style: TuiStyle;
}
```

实现要求：

- `writeFrameText` 接受可选 style，不接受原始 ANSI。
- 宽度仍由 grapheme + `string-width` 计算；style 不参与 visual width。
- 双宽字符的 continuation cell 必须继承 style，但不能重复输出字符。
- frame diff 同时比较 char、width 和 normalized style。
- writer 按连续 style span 输出 ANSI，并在每个 changed row 结束时 reset。
- `NO_COLOR`、非 TTY 或 color disabled 时只输出字符，不改变 frame 布局。
- assistant/model/tool 文本中的 `\x1b`、C0/C1 控制字符必须 sanitize，允许的换行和 tab 在进入 layout 前规范化。
- 任何异常或中断后都必须输出 style reset、autowrap restore 和 cursor restore。

颜色语义保持克制：

- heading：bold/cyan。
- inline code/code fence：neutral foreground + dim border/background when supported。
- added diff：green；removed diff：red；hunk/header：cyan/dim。
- warning/error：yellow/red。
- tool/subtask running：yellow；success：green；failed：red；cancelled：dim。
- 普通 assistant 文本保持 terminal default foreground。

## 3. Rich Transcript View Model

新增 renderer-independent parser：

```text
src/runtime/rich-text/
  types.ts
  markdown-parser.ts
  sanitizer.ts
  layout.ts
```

使用现有 `marked` 依赖，但不复用 React component。输出结构化 block：

```ts
type RichTextBlock =
  | { type: 'paragraph'; spans: RichTextSpan[] }
  | { type: 'heading'; level: number; spans: RichTextSpan[] }
  | { type: 'list'; ordered: boolean; items: RichTextBlock[][] }
  | { type: 'quote'; blocks: RichTextBlock[] }
  | { type: 'code'; language?: string; lines: string[] }
  | { type: 'diff'; lines: DiffLine[] }
  | { type: 'table'; headers: RichTextSpan[][]; rows: RichTextSpan[][][] }
  | { type: 'rule' };
```

支持范围：

- heading 1-6。
- paragraph、hard break、soft break。
- unordered/ordered list，最多 4 层缩进，超过后 flatten。
- blockquote。
- inline bold、italic、code、link；link 显示 label，并在空间允许时显示 URL。
- fenced code；`diff`/`patch` 使用专门 DiffLine。
- GFM table；窄宽度下按 key/value row fallback，不能产生负列宽或重叠。
- HTML 不直接渲染，转义或显示安全纯文本。
- 超深 nesting、超大 table、超长单词必须有确定性降级。

布局要求：

- transcript prefix 和 rich content 分开预算宽度。
- 普通段落按 visual width wrap。
- code 保留缩进；超长行按 visual width soft-wrap，并用 continuation marker 表示。
- diff 保留 `+`、`-`、`@@` 前缀。
- table 先测量 min/preferred width，再按可用宽度压缩；低于阈值时 fallback。
- 所有输出行必须满足 `stringWidth(line) <= frame.width`。
- 解析失败不得崩溃，回退为安全 plain text block。

缓存：

- finalized transcript 按 `entry.id + content hash` 缓存 parsed blocks。
- 待提交 entry 和 session restore 按 `entry.id + content hash + width + theme` 缓存 visual layout。
- live assistant entry 只重排当前 entry，不重排全部历史。
- resize 只使 live/未来提交的 visual layout cache 失效；已经进入 shell scrollback 的历史不重写。

## 4. Inline Terminal Surface 与 Shell-native Scrollback

新增 terminal surface 抽象，把 durable transcript 和 ephemeral live region 分离：

```ts
interface TuiTerminalSurface {
  mount(): Promise<void>;
  getSize(): { width: number; height: number; safeContentWidth: number };
  commit(batch: RenderedTranscriptCommitBatch): Promise<void>;
  renderLive(frame: TuiFrame): Promise<TuiTerminalRenderResult>;
  resize(width: number, height: number): Promise<void>;
  suspend(): Promise<void>;
  restore(): Promise<void>;
  flush(): Promise<void>;
  unmount(): Promise<void>;
}

interface TuiTranscriptCommitState {
  generation: number;
  committableTranscriptCount: number;
  queuedTranscriptCount: number;
  committedTranscriptCount: number;
}

interface InlineSurfaceState {
  mounted: boolean;
  suspended: boolean;
  width: number;
  height: number;
  liveRegionCapacity: number;
  cursorRow: number;
  cursorColumn: number;
}
```

提交协议：

- mount/restore/unmount 不得发送 `\x1b[?1049h` 或 `\x1b[?1049l`，始终留在 primary screen。
- finalized entry 必须按稳定 entry id 只提交一次；commit 以显式换行结束，不能依赖终端 pending-wrap。
- streaming delta、spinner、elapsed time、permission overlay、status 和 prompt 只能进入 live region，不能泄漏为重复 scrollback。
- entry finalized 时执行 `clear live -> commit final rows -> render next live`，三步由 surface 串行化，不能与 scheduler paint 交错。
- live region 使用相对 cursor movement 和 erase-in-line，只允许覆盖自己记录的行数；不能使用绝对屏幕坐标重画历史。
- writer 必须规避最后一列 pending-wrap，可使用 width-1 安全预算或显式换行，并由 PTY screen model 验证。
- 所有 TUI-owned terminal output 都经过 surface；审计 mounted 期间的 background stdout/stderr，日志不能插入 live
  region 中间破坏 cursor ownership。
- resize 只重排 live region 和未来提交内容。已经提交的历史交给 terminal reflow，renderer 不回写、不去重排。
- session resume/replace 可以在启动时一次性提交恢复历史，但必须建立 display boundary，避免同一 entry 在后续 event 中再次输出。
- PageUp/PageDown、Ctrl+Home/Ctrl+End 不绑定内部 transcript action；scrollback 导航使用终端实际支持的快捷键和鼠标。
- selection、copy 和 scrollback 容量由 terminal 配置决定；TUI 不开启 mouse reporting，不实现内部选择模型。
- suspend 用于显式 child process：surface 清理 live region/cursor，launch 恢复 cooked mode；restore 后只重建 live region，
  不重复提交历史。
- unmount 清除 ephemeral live region，输出必要的最终换行并恢复 terminal 状态，但绝不擦除 committed scrollback。

v0.2.21 不实现自动剪贴板写入和 OSC52，避免未明确触发的数据外发。可选 pager/export 留到 P1；原生选择和
复制直接在 shell scrollback 中完成。

## 5. 动态 Layout Budget

替换固定 `PROMPT_TOP_ROWS = 3`：

```ts
interface TuiLayoutBudget {
  liveTranscriptRows: number;
  timelineRows: number;
  overlayRows: number;
  statusRows: 1;
  promptRows: number;
}
```

规则：

- prompt 最少 3 行，最多 `min(8, floor(height * 0.35))`。
- permission/edit/session overlay 优先于 live transcript，但不能覆盖 prompt/status。
- running tool/subtask timeline 默认最多 3 行；完成后折叠，由 runtime 已产生的对应 transcript entry 进入 scrollback。
- 极小尺寸 24x8 时优先保留 prompt、permission 和一行 status，live transcript 可为 0。
- 所有 section 使用稳定 row range；内容变化不能让 cursor 跳到其他 section。
- overlay 和动态 prompt 同时存在时必须重新预算，不允许负高度。

## 6. Tool 与 Subagent Timeline

TUI 不从 transcript 文本反向解析状态。扩展 state：

```ts
interface TuiActivityState {
  tools: ToolActivity[];
  subtasks: RuntimeSubtaskEvent[];
}
```

要求：

- `UiEventSink.subtaskEvent` 必须 dispatch 到 reducer。
- subtask 按 `batchId/taskId` 更新，而不是无限 append 重复状态。
- running 显示 role、短 objective、elapsed time。
- completed/failed/cancelled/timed_out 显示 summary 和 duration。
- 同一 batch 最多展示 3 个 active child；已完成项由 runtime 对应 transcript/trace 保留，renderer 只从 active area 折叠。
- tool sequence、batch index、artifact hint、duration、error layer 保持现有 structured data。
- activity area 只显示事实状态，不显示 token delta stream。
- Ctrl+C 取消 root turn时，child 状态必须依次转为 cancelled，不能永久停在 running。
- TUI、Ink、terminal 的 runtime event sequence parity 继续由共享 fixture 断言。

## 7. Structured Status Snapshot

移除 TUI `launch.ts` 中 renderer-local `statusSnapshot()` 字符串拼接，使用 shared
`createStatusSnapshot()` 和结构化状态：

```ts
interface TuiStatusState {
  phase: 'ready' | 'running' | 'error' | 'interrupted';
  snapshot: StatusSnapshot;
  message?: string;
  activeTools: number;
  activeSubtasks: number;
  committedTranscriptEntries: number;
}
```

宽度降级：

- >= 100 columns：phase、model、session、tokens、cost、ctx、MCP、permission、subtasks。
- 60-99 columns：phase、model、session、ctx、subtasks。
- 40-59 columns：phase、model、ctx。
- < 40 columns：phase + 最重要 warning。

状态数据只能来自 runtime/store/view-model，layout 不直接调用 provider、MCP manager 或 session storage。

## 8. Render Scheduler 与性能

当前 `dispatch -> render()` 同步一一对应。改为：

- reducer 同步更新 state。
- `TuiRenderScheduler` 在同一 event-loop tick 合并重复 render 请求。
- streaming 高频事件最多 30 FPS；permission、input、cursor 和 resize 走 immediate render。
- transcript commit queue 不受 FPS 丢帧策略影响，finalized entry 必须按事件顺序提交一次。
- resize 清空 live visual layout cache 和 previous live frame，并立即重绘一次 live region。
- transcript cache 只重排变化 entry；已 committed entry 不参加后续 render。
- terminal writer 只写 live region changed rows，styled span 不能导致历史区域重绘。

建议可测性能基线：

- 已提交 500 transcript entries 后，append 一个 live chunk 只重排当前 entry，不扫描或重写 500 条历史。
- 连续 100 个 stream delta 产生的 terminal paint 次数不超过 scheduler 上限。
- 无状态变化时 render output 为空。
- 单行 cursor move 不能输出 committed transcript。
- resize 后第一个 live frame 完整，第二个相同 state frame output 为空，scrollback 中没有重复 entry。

CI 不使用绝对毫秒作为唯一门禁；优先断言工作量、重排 entry 数、paint 次数和 changed rows 上界。

## 9. Terminal 生命周期

`launchTuiUI()` 改为单一 lifecycle owner：

- 所有 listener 注册后进入 `try/finally`。
- cleanup 使用 once guard，允许 Ctrl+C、SIGINT、SIGTERM、SIGHUP、runtime shutdown、child process 和 renderer error
  竞争调用。
- cleanup 顺序固定：cancel active turn -> flush finalized commit queue -> stop render scheduler -> remove listeners ->
  pause input -> clear ephemeral live region -> reset style -> disable bracketed paste -> enable autowrap -> show cursor ->
  restore raw mode -> final newline -> runtime shutdown。
- renderer error 先执行 emergency restore，再向 stderr 输出一条明确的 renderer-layer error。
- 不吞掉原始 exit code 或 signal 语义。
- child process suspend 和最终 shutdown 使用不同状态，child 返回不能触发 runtime shutdown 或重复提交 transcript。
- cleanup 不能发送 alternate-screen exit、清屏或向上擦除 committed scrollback。

## GLM 5.1 开发执行手册

本节是实现指令，不是可选建议。GLM 5.1 开发时必须按这里的边界、顺序和门禁执行；遇到代码与本文不一致时，
先用测试证明差异，再对计划做最小修正，不能自行改成全新 renderer 架构。

### 开始编码前必须读取

按以下顺序读取，不要一开始扫描整个仓库：

1. `src/tui-ui/state.ts`：理解 finalized prefix、generation 和当前 overlay state。

### Reducer、Effect 与 Paint 管线

现有 reducer 保持纯函数，但 runner 增加 reducer 后置 effect。不要让 reducer 返回 Promise，也不要在 event sink 中直接写 terminal。

```ts
type TuiEffect =
  | { type: 'commitTranscript'; batch: TranscriptCommitBatch }
  | { type: 'renderLive'; priority: 'immediate' | 'stream' }
  | { type: 'reportInvariant'; message: string };

interface TuiEffectPlan {
  state: TuiUiState;
  effects: TuiEffect[];
}

function dispatch(action: TuiUiAction): void {
  const previous = state;
  const reduced = tuiUiReducer(previous, action);
  const plan = planTuiEffects(previous, reduced, action);
  state = plan.state; // 已同步预留 queued transcript boundary

  for (const effect of plan.effects) {
    if (effect.type === 'commitTranscript') {
      surfaceQueue.enqueue(() => commitAndAcknowledge(effect.batch));
    } else if (effect.type === 'renderLive') {
      scheduler.request(effect.priority);
    } else {
      reportInvariant(effect.message);
    }
  }
}
```

顺序要求：

1. action 必须先同步进入 reducer，input/permission state 立即可见。
2. finalized commit effect 必须在该 action 的 live paint 之前进入同一个 surface queue。
3. scheduler 可以合并 `renderLive`，不能合并、覆盖或丢弃 `commitTranscript`。
4. commit batch 是 action 时刻的 immutable snapshot；后续 update 不能改变已排队内容。
5. commit effect 入队前必须同步推进 queued boundary，防止下一个 action 重复规划同一 batch。
6. surface write 失败时不能 dispatch committed acknowledgement，必须进入 renderer error cleanup。
7. `markTranscriptCommitted` action 只更新 boundary，不再次生成 commit effect。

不要在第一步同时实现 scheduler。切片 4 先允许每次完整重绘“有界 live region”；切片 6 再引入 row diff 和 FPS
coalescing。这样能把 scrollback 正确性和性能优化分开验证。

`UiEventSink` 和 `runner.dispatch()` 保持同步 API，不能让 runtime 等待 terminal paint。runner 新增 `flush(): Promise<void>`
只供 lifecycle、tests 和 child suspend 使用；原来同步读取 terminal bytes 的测试改为 dispatch 后 `await runner.flush()`。
logical state/frame 可以同步更新，真实 stream write 和 committed acknowledgement 在 serialized queue 完成。

### Transcript Commit 状态机

建议状态：

```ts
interface TuiTranscriptRecord extends TranscriptEntry {
  finalized: boolean;
  revision: number;
}

interface TuiTranscriptState {
  entries: TuiTranscriptRecord[];
  generation: number;
  committableTranscriptCount: number;
  queuedTranscriptCount: number;
  committedTranscriptCount: number;
}

interface TranscriptCommitEntry {
  displayKey: string;       // `${generation}:${entry.id}`
  entry: TranscriptEntry;  // immutable snapshot
}

interface TranscriptCommitBatch {
  generation: number;
  fromIndex: number;
  toIndexExclusive: number;
  reason: 'append' | 'finalize' | 'restore' | 'replace' | 'clear-divider';
  entries: TranscriptCommitEntry[];
}

interface RenderedTranscriptCommitBatch extends Omit<TranscriptCommitBatch, 'entries'> {
  entries: Array<TranscriptCommitEntry & { rows: StyledRow[] }>;
}
```

四个边界的含义：

- `entries.length`：renderer 当前知道的全部 transcript records。
- `committableTranscriptCount`：从索引 0 开始连续 finalized 的前缀，后面若有未 finalized live entry 则停止。
- `queuedTranscriptCount`：已经预留并进入 serialized surface queue 的前缀，防止连续 action 重复 enqueue。
- `committedTranscriptCount`：该 generation 已经成功写入 shell scrollback 的前缀，必须满足
  `0 <= committed <= queued <= committable <= entries.length`。

action 规则：

| Action | Reducer 行为 | Surface effect |
|---|---|---|
| append finalized | append record，推进 committable prefix | commit 新增可提交前缀 |
| append live | append `finalized=false` | 只 render live |
| update uncommitted | revision +1，更新内容 | render live |
| finalize uncommitted | finalized=true，推进连续前缀 | 按 transcript 顺序 commit 整个新增前缀 |
| remove uncommitted | 删除并重算前缀 | clear/repaint live |
| update/remove committed | 不重写 terminal history | production 保持历史不变并报告 invariant；测试必须失败 |
| replaceTranscript | generation +1；committable=entries.length，queued/committed=0 | 可选 divider 后一次提交恢复内容 |
| clearTranscript | generation +1，清空 logical state | 只提交 `Transcript cleared` divider，不清 shell history |
| reserve queued | 同步推进 queued count | effect 进入 surface queue 前完成 |
| mark committed | 单调推进 committed count | 无二次 effect |

关键行为：

- 后加入的 tool/status 即使先 finalized，也必须等待前面的 live assistant finalized，避免 shell 历史乱序。
- `displayKey` 包含 generation，session replace 后复用相同 entry id 不会被误判为重复。
- committed entry 不可变是 UI protocol invariant。不要尝试用 cursor-up 修改已经提交的文本。
- production 中遇到 late update/remove 不能崩溃 agent loop；记录 renderer-layer diagnostic，并保持已显示历史不变。
- initial session restore 可以不输出 divider；运行中切换 session 必须先提交一行明确 divider，再提交 restored entries。
- 旧 generation 的 commit acknowledgement 在 replace 后到达时必须忽略；surface queue 本身仍保证旧 batch 先于新 divider 输出。
- UI state 不是 session durability source；session storage/runtime event 仍是事实来源。

effect 规划伪代码：

```ts
function collectCommitBatch(previous: TuiUiState, next: TuiUiState): TranscriptCommitBatch | null {
  if (next.transcriptGeneration !== previous.transcriptGeneration) {
    return buildGenerationBatch(next);
  }

  const from = previous.queuedTranscriptCount;
  const to = next.committableTranscriptCount;
  if (to <= from) return null;

  return buildCommitBatch(next, from, to);
}
```

`buildCommitBatch()` 只捕获 immutable entry snapshot，不提前固定 visual rows。surface queue 执行该 operation 时，runner 使用
当时的 `surface.safeContentWidth` 生成 `RenderedTranscriptCommitBatch`，再交给 surface。这样 resize 与 commit 无论谁先进入
queue，都使用一致宽度；rich-text parser/layout 仍在 renderer 层，surface 不理解 Markdown。

关键事件时序必须按以下语义实现：

```text
assistant stream
  transcript_append(live A)     -> A 只在 live region
  transcript_update(A, rev 2)   -> 覆盖 live A，不 commit rev 1
  transcript_update(A, rev 3)   -> 覆盖 live A，不 commit rev 2
  transcript_finalize(A)        -> 清 live，commit rev 3 一次，重建 prompt/status
```

```text
tool + permission
  transcript_append(live T)     -> active tool/live row
  tool_started(T)               -> keyed timeline 更新
  permission_requested          -> overlay 进入 live region
  permission denied             -> overlay 关闭
  transcript_finalize(T, skip)  -> commit skipped tool entry 一次
  tool_finished(skipped)        -> timeline 同 key 进入 terminal state 后折叠
```

```text
session replace
  replaceTranscript(entries)    -> generation + 1，旧 shell history 保留
  surface commit divider        -> 明确显示 session boundary
  surface commit restored rows  -> 新 generation 每条一次
  later repaint/resize          -> committed boundary 阻止二次 commit
```

```text
subtask lifecycle
  subtask_event(queued/running)  -> keyed active timeline 更新
  runtime transcript_append     -> runtime 决定的 durable summary 正常 commit
  subtask_event(completed)       -> 同 key terminal state，不能另造 transcript
```

### InlineTerminalSurface 详细设计

surface 内部只使用以下控制序列：

```text
CR       \r                   回到当前行第 0 列
EL2      \x1b[2K             清当前行
CUU(n)   \x1b[<n>A           相对上移
CUD(n)   \x1b[<n>B           相对下移
CUF(n)   \x1b[<n>C           相对右移到 live cursor
SGR0     \x1b[0m             reset style
DECTCEM  \x1b[?25l / ?25h   hide/show cursor
DECAWM   \x1b[?7l / ?7h     paint batch 内临时关闭/恢复 autowrap
```

禁止发送：

- `\x1b[?1049h`、`\x1b[?1049l`。
- `CSI row;column H` 或 `f` 形式的绝对屏幕行定位。
- `CSI 2J` 全屏清除。
- save/restore cursor 作为核心定位机制；不同 terminal 和 resize 下行为不一致。
- mouse reporting、OSC52、OSC8 或模型内容中的任意 escape。

surface 状态不变量：

```ts
interface InlineSurfaceState {
  phase: 'idle' | 'mounted' | 'suspended' | 'unmounted' | 'failed';
  width: number;
  height: number;
  liveRegionCapacity: number;
  cursorRow: number;       // 相对 live region top
  cursorColumn: number;
  previousFrame: TuiFrame | null;
  writePending: boolean;
}
```

- mounted 时真实 terminal cursor 必须位于 live region 内，且逻辑坐标与 state 一致。
- `liveRegionCapacity` 在一次 mount 生命周期内只增不减；frame 变矮时清空多余行但不删除 terminal 行。
- capacity 最大为 `max(1, terminalHeight - 1)`，不能把 live region 扩展到 scrollback 中的 committed rows。
- 所有 frame row 使用 `safeContentWidth = max(1, columns - 1)`，v0.2.21 不写满最后一列。
- 每次写 styled row 后输出 SGR0；模型文本永远不能改变后续 prompt 样式。

写入队列：

- runner 只创建一个 `SerializedSurfaceExecutor`；surface operation 必须严格 FIFO，`commit`、`renderLive`、`resize`、
  `suspend`、`unmount` 不得并发写同一个 stream。
- `output.write()` 返回 false 时等待 `drain` 后再执行下一 operation；`flush()` 同时等待队列为空和 pending drain。
- stream `error` 或同步 write exception 将 phase 置为 failed，并通知 launch 进入一次性 cleanup。
- 测试 output 要能模拟 backpressure、drain 和 write failure，验证 batch 不乱序、不重复 acknowledgement。

`mount()`：

1. 校验 phase 为 idle，记录 width/height。
2. 输出 bracketed paste enable 和 cursor hide；不进入 alternate screen，不清屏。
3. capacity 保持 0；首次 `renderLive()` 再预留需要的行。

`ensureCapacity(requiredRows)`：

1. clamp 到 `[1, height - 1]`。
2. 从当前 cursor 相对移动到 live region 最后一行。
3. 每增加一行输出显式 newline，形成 hard line boundary。
4. 相对移动回 live top，更新 capacity；不能使用 insert/delete line。

`renderLive(frame)` 的切片 4 correctness-first 算法：

1. `ensureCapacity(frame.height)`。
2. 从 tracked cursor 移到 live top。
3. 对 capacity 每行执行 `CR + EL2`，清完后回到 top。
4. 逐行写 frame styled row；行间使用相对 down + CR，不依赖 pending wrap。
5. 空白 trailing capacity 继续保持已清空。
6. 相对移动到 `frame.cursor`，恢复 cursor visibility 和 autowrap。
7. 保存 clone frame 和 cursor 坐标。

切片 6 再把第 3-5 步替换为 changed-row diff。diff 仍使用 tracked relative row movement，不能重新引入 `moveTo(row,
column)` 的 absolute `H`。

`commit(batch)` 必须是一个不可打断的 surface operation：

```text
move tracked cursor to live top
clear all live capacity rows
move to live top
write each committed styled row + SGR0 + explicit newline
reset capacity/cursor anchor at current line
render latest live frame
acknowledge committed boundary
```

注意：commit 前后的 live frame 可能已经变化。surface queue 中不要保存过期 frame；commit 完成后调用 runner 提供的
`getLatestLiveFrame()`，重建最新状态。这样 finalize 与高频 stream 交错时不会恢复旧 prompt。

`resize(width, height)`：

- committed history 完全交给 terminal reflow，surface 只处理 previous live rows。
- 扩宽时按新宽度使 live layout cache 失效并重绘。
- 缩窄时旧 live row 可能发生 physical wrap。根据每个旧 row 的 visual width 和新 `safeContentWidth` 计算
  `max(1, ceil(rowWidth / safeContentWidth))`，得到清理所需 physical row 数和旧 cursor 的新相对位置。
- 清理估算后的 live physical rows，再将 capacity 置 0，用新 frame 重建。
- resize recovery 仍不得使用 `CSI 2J` 或重新打印 committed transcript。
- PTY test 必须覆盖 120 -> 40 -> 80、CJK 双宽、emoji、满宽 border 和 cursor 位于 prompt 中间。

`suspend()`：

1. drain surface queue，停止 scheduler。
2. surface 清空 ephemeral live rows，输出 SGR0，show cursor，disable bracketed paste。
3. launch 暂停 input/listener 并恢复 cooked mode；surface phase 变为 suspended。
4. 不调用 runtime shutdown，不提交重复 transcript；child process 使用结构化 command/argv 和 inherited stdio。

`restore()`：

1. child 退出后由 launch 恢复 raw mode、input 和 resize listener。
2. surface 恢复 bracketed paste，将 previous frame/capacity 置空，phase 变 mounted。
3. 只重建最新 live frame；不重新 commit generation history。

`unmount()`：

1. 只执行一次；先 flush finalized commit queue。
2. surface 清空 live rows，SGR0、show cursor、enable autowrap、disable bracketed paste。
3. launch 随后恢复 cooked mode；输出一个必要的 final newline，让 shell prompt 从干净行开始。
4. 不发送 exit alternate screen，不擦除 committed rows。

输出隔离：

- 不要全局 monkeypatch `process.stdout.write` 或 `console.*` 作为长期方案。
- TUI 自身输出必须只经过 surface 注入的 `output.write`。
- command/runtime 中现有 `console.*` 应继续由 chat-controller 的结构化 capture 转成 transcript event；新增旁路输出必须改为
  logger/event injection。
- MCP/LSP/background warning 若可能在 TUI mounted 期间直接写 stderr，必须审计并通过 renderer-aware logger 或 event sink 路由；
  不能让日志插入 live region 中间。
- 如果 PTY 证明必须修改 `src/tools/*` 才能阻止 background 直写，将其报告为独立 prerequisite/范围例外；未经确认不能把
  tool/MCP 重构混入 Inline surface 切片。

### Shared Composer 实现指导

迁移顺序：

1. 原样复制算法到 `src/runtime/composer/`，先保持行为和测试不变。
2. 将 Ink 文件改成 compatibility re-export，确认 Ink tests 全绿。
3. TUI runner 删除本地 `graphemeBoundaries()`、insert/delete helper，改用 shared reducer。
4. 最后增加 multiline/history 行为；不要迁移和功能扩展同时进行。

建议核心 state：

```ts
interface ComposerState {
  buffer: { value: string; cursor: number };
  preferredVisualColumn: number | null;
  history: {
    entries: string[];
    index: number | null;
    draft: string;
  };
}

type ComposerAction =
  | { type: 'insert'; text: string }
  | { type: 'backspace' | 'delete' }
  | { type: 'moveHorizontal'; direction: 'left' | 'right' }
  | { type: 'moveVertical'; direction: 'up' | 'down'; width: number }
  | { type: 'moveLineBoundary'; direction: 'home' | 'end' }
  | { type: 'history'; direction: 'previous' | 'next' }
  | { type: 'set'; value: string; cursor?: number }
  | { type: 'clear' };
```

输入协议：

| Bytes/key | 语义 |
|---|---|
| `\r` | submit |
| `\n` / Ctrl+J | insert newline，不 submit |
| `ESC + CR` 或 `ESC + LF` | Alt+Enter，insert newline |
| bracketed paste payload | 原样插入规范化后的 `\n`，永不自动 submit |
| Left/Right | grapheme boundary 移动 |
| Home/End | 当前 logical line 首/尾 |
| Up/Down | prompt 内存在上一/下一 visual row 时垂直移动，否则访问 history |
| Ctrl+U | 清空 composer |
| Ctrl+W | grapheme-safe 删除前一个 word |

当前 parser 将 CR/LF 都映射为 enter，必须先拆分为 `enter`、`ctrl+j`、`alt+enter`。Alt+Enter sequence 可能被拆成
多个 chunk，继续使用 pending escape state，测试单 chunk 和逐字节 feed。

history 规则：

- 只在非空 submit 后写入，连续相同输入去重，内存上限 100。
- 第一次 history previous 前保存当前 draft；返回 history 尾部时恢复 draft。
- 编辑历史项后不修改原 entries，只修改当前 buffer。
- multiline prompt 中 Up/Down 优先移动 visual row；只有到达最上/最下 visual row 才切 history。
- v0.2.21 不持久化 history 到磁盘，不修改 session schema。

prompt viewport：

- 复用 `getPromptInputViewport()` 算法，但迁移后输入是 grapheme-safe buffer。
- max rows 由 layout budget 提供，不能在 component 内读取 terminal height。
- cursor column 使用 `string-width` 计算 cursor 前 grapheme，不使用 UTF-16 index 作为视觉列。
- IME 依赖真实 terminal cursor，frame cursor 必须停在当前输入 grapheme 位置，不能只绘制假 cursor glyph。
- prompt 为空、末尾 newline、连续空行、CJK、emoji ZWJ、combining mark 都要有 fixture。

### Styled Frame 与 ANSI Writer 实现指导

类型建议：

```ts
type TuiColor =
  | { kind: 'named'; value: 'black' | 'red' | 'green' | 'yellow' | 'blue' | 'magenta' | 'cyan' | 'white' }
  | { kind: 'indexed'; value: number }
  | { kind: 'rgb'; r: number; g: number; b: number };

interface TuiStyle {
  foreground?: TuiColor;
  background?: TuiColor;
  bold?: boolean;
  dim?: boolean;
  italic?: boolean;
  underline?: boolean;
  inverse?: boolean;
}

interface StyledSpan {
  text: string;
  style: TuiStyle;
}

type StyledRow = StyledSpan[];
```

实现步骤：

1. 给 `TuiCell` 增加 normalized style；empty cell 使用共享不可变 default style 或新对象，禁止后续 mutation。
2. `writeFrameText(frame, row, column, text, style?)` 先 sanitize，再按 grapheme 写 cell。
3. 双宽 grapheme continuation cell 保存相同 normalized style，但 `renderFrameRows()` 不输出 continuation char。
4. `diffTuiFrames()` 比较 char、width、style key 和 cursor；不要先转 plain string 后比较。
5. 新增 `renderStyledFrameRow()`，将连续相同 style cells 合并为 span，减少 SGR 切换。
6. row 结束强制 SGR0；`NO_COLOR`/non-TTY 只关闭颜色，不删除 bold 之外的结构文本。
7. 切片 2 保留现有 absolute writer API 兼容测试；切片 4 才由 Inline surface 接管 row addressing。

style normalization：

- `false`、空 color、越界 indexed/rgb value 归一化为 undefined 或 clamp 后 canonical value。
- style equality 使用字段比较或稳定 key，禁止每次 `JSON.stringify` 整个 cell array。
- theme 只返回 semantic token：`assistantText`、`heading`、`code`、`diffAdded`、`diffRemoved`、`warning`、`error`、
  `activityRunning`、`activitySuccess`、`activityFailed`、`muted`。
- layout 不写具体 ANSI code；ANSI 只在 terminal row encoder 出现。

sanitizer：

- 删除 ESC、DEL 和除 `\n`、`\t` 外的 C0/C1 control；tab 在 layout 前展开为固定空格。
- 不允许模型文本注入 SGR、OSC、CSI、title、clipboard 或 hyperlink sequence。
- link 默认显示 `label (url)` 或 label；v0.2.21 不发送 OSC8。
- 对非法 surrogate、zero-width-only grapheme 和负宽度做确定性 fallback。

### Rich Text Parser 与 Layout 实现指导

解析流水线：

```text
raw model text
  -> sanitizeTerminalText
  -> marked.lexer(text, { gfm: true })
  -> normalizeMarkedTokens
  -> RichTextBlock[]
  -> layoutRichText(blocks, width, theme)
  -> StyledRow[]
```

不要调用 `marked.parse()` 生成 HTML，也不要把 `Markdown.tsx` 中的 React element 作为中间结构。
不要复制 Ink 中 `Token & Record<string, any>` 的宽泛类型；使用 `marked` token union、局部 type guard 和 exhaustive fallback。

token 映射：

- `heading` -> heading block，level clamp 1-6。
- `paragraph`/`text` -> inline span list，保留 soft/hard break 语义。
- `list` -> ordered/unordered items，最多 4 层；更深 flatten 并保留文本。
- `blockquote` -> quote blocks，layout 添加安全文本前缀。
- `code` -> code block；language 为 `diff`/`patch` 时转换 DiffLine。
- `table` -> headers/rows；先测量 min/preferred width，再决定 table 或 key/value fallback。
- `html` -> decode entity 后显示安全 plain text，绝不解释 tag。
- 未识别 token -> `token.raw` 的 sanitized plain text fallback，不能静默丢内容。

资源上限使用命名常量并测试：

```ts
const MAX_RICH_TEXT_INPUT_BYTES = 1_000_000;
const MAX_RICH_TEXT_BLOCKS = 2_000;
const MAX_MARKDOWN_NESTING = 4;
const MAX_TABLE_COLUMNS = 20;
const MAX_TABLE_ROWS = 200;
```

超限时显示明确 truncation/fallback marker，不得 OOM、递归溢出或阻塞 event loop。完整大输出仍由 artifact/session 保存，
renderer 只负责可用预览。

layout 规则：

- 每个输出 row 的 visual width 必须 `<= safeContentWidth`。
- 普通 paragraph 按 grapheme wrap；优先在空白断行，超长 word 再 hard-wrap。
- code/diff 保留前缀和缩进；continuation row 使用固定 marker，marker 也计入宽度。
- table 先保留 header，再分配列宽；总 min width 超限立即 key/value fallback，不做负列宽计算。
- 空 block、尾随 newline 和连续空 paragraph 归一化，避免无界空行。
- committed entry 的 prefix 与正文分别计算宽度，continuation row 对齐正文起点。

缓存分两层：

```ts
parseCacheKey  = `${entry.id}:${contentHash}`
layoutCacheKey = `${entry.id}:${contentHash}:${width}:${themeId}`
```

- finalized content parse/layout 后可缓存；live content 每 revision 只替换当前 entry cache。
- 使用有界 LRU 或按 transcript generation 清理，不能让每个 stream delta 永久留下 cache entry。
- resize 只清 layout cache，不清 parse cache。
- hash 使用轻量稳定实现；不要引入 crypto 热路径或新依赖。
- parser exception 返回 plain text block，并通过 renderer diagnostic 记录一次，不得终止 agent turn。

### Live Layout、Status 与 Activity 实现指导

`renderTuiLiveFrame()` 只接收 renderer state 和明确 options：

```ts
interface TuiLiveLayoutInput {
  width: number;
  height: number;
  liveEntries: TuiTranscriptRecord[];
  tools: ToolActivity[];
  subtasks: RuntimeSubtaskEvent[];
  overlay: TuiOverlayState;
  status: TuiStatusState;
  composer: ComposerState;
}
```

不要把 committed transcript 传入 live layout。这样 type boundary 会直接阻止 O(n) 历史重排。

布局顺序从底向上预算：

1. prompt：最少 3 行，最大 `min(8, floor(height * 0.35))`。
2. status：固定 1 行。
3. permission overlay：若存在，优先占用剩余区域。
4. 其他 overlay：最多 10 行，可滚动选项但不能覆盖 prompt/status。
5. active tool/subtask timeline：最多 3 行。
6. live transcript：使用剩余行；不足时只显示尾部 visual rows。

所有 budget 用纯函数一次算完；任何 section row count 必须非负，总和不能超过 `height - 1`。24x8 下允许 live transcript
为 0，但 permission、status 和至少一行 prompt 必须可操作。

StatusSnapshot 接入：

- 删除 `launch.ts` 本地字符串 `statusSnapshot()`，使用 shared `createStatusSnapshot()`。
- 如 release target 需要 MCP 数量，先向 shared `StatusSnapshot` 增加可选
  `mcp?: { connected: number; total: number }`，再给所有 renderer parity fixture 补字段；不要只给 TUI 私有字符串。
- `createTuiUiEventSink()` 增加 `statusSnapshotProvider` 注入。`setStatus`、`setProcessing`、`sessionRestored`、
  `loopStatsUpdated` 事件边界刷新 snapshot 并 dispatch；layout 内不能调用 provider。
- elapsed time 每秒最多刷新一次，只在 active tool/subtask 存在时启动 injectable timer。

Tool activity reducer：

```ts
interface TuiActivityState {
  toolById: Record<string, ToolActivity>;
  toolOrder: string[];
  subtaskById: Record<string, RuntimeSubtaskEvent>;
  subtaskOrder: string[];
}
```

- tool key 是 `callId`；subtask key 是 `${batchId}:${taskId}`。
- started/queued/running 更新同一 key，terminal state 覆盖 running state，不 append duplicate row。
- order 只在 key 首次出现时追加；最多保留最近 100 个 terminal records，active records 不能被裁掉。
- timeline 只显示 active 或刚完成的短状态；runtime 已经产生的 transcript entry 是 durable history，renderer 不得再生成一份。
- tool/subtask terminal state 对应 transcript entry committed 后，从 active timeline 折叠；不能把 trace 当 transcript 重新输出。
- root Ctrl+C 后收到 cancelled/timed_out 必须更新 existing key，不能留下 running。

### Render Scheduler 实现指导

接口建议：

```ts
interface TuiRenderSchedulerDeps {
  now: () => number;
  queueMicrotask: (callback: () => void) => void;
  setTimeout: (callback: () => void, delay: number) => NodeJS.Timeout;
  clearTimeout: (timer: NodeJS.Timeout) => void;
  paint: () => void;
}

interface TuiRenderScheduler {
  request(priority: 'stream' | 'immediate'): void;
  flush(): void;
  stop(): void;
}
```

- immediate：input、permission、cursor、overlay、resize；同 tick 最多 paint 一次。
- stream：按 30 FPS 上限计算下一次 paint；多个 delta 只保留最新 state。
- commit 不经过 scheduler，由 surface queue 保序；commit 后主动请求一次 immediate live paint。
- executor 中最多保留一个 pending paint token；token 执行时调用 `getLatestLiveFrame()`，不能把请求时的旧 frame 排队。
- commit token 不可合并；paint token 可以跨多个 state revision 合并，但不能越过已经先入队的 commit token。
- timer 必须可注入并在 stop 时清理；Jest 使用 fake timer，不使用固定 sleep。
- paint 抛错转交 launch renderer error handler，scheduler 自身不吞异常。
- 无 state/frame 变化时 writer output 必须为空。

性能计数器只在 test/debug 注入：`parsedEntries`、`laidOutEntries`、`paintCount`、`changedRows`、`committedEntries`。
production 默认不输出 debug dump。

### Launch 生命周期状态机

建议显式 state：

```ts
type TuiLifecyclePhase =
  | 'starting'
  | 'running'
  | 'suspending'
  | 'suspended'
  | 'stopping'
  | 'stopped'
  | 'failed';

interface TuiLifecycleState {
  phase: TuiLifecyclePhase;
  cleanupPromise: Promise<void> | null;
  signal: NodeJS.Signals | null;
}
```

启动顺序：

1. 校验 input/output TTY。
2. 创建 surface、scheduler、runner、controller，但此时不订阅 input。
3. `surface.mount()`。
4. 注册 data/resize/SIGINT/SIGTERM/SIGHUP listener。
5. enable raw mode，resume input。
6. 提交 banner/status，首次 render live。

停止顺序：

1. once guard 将 phase 改为 stopping，保存同一个 cleanup promise。
2. stop active turn，等待 presenter finalize/cancel event。
3. flush transcript commit queue 和 scheduler。
4. remove listeners、pause input。
5. `surface.unmount()`。
6. restore raw mode。
7. `runtime.shutdown()`；保留原 exit code/signal 语义。
8. phase 改 stopped，resolve launch promise。

错误处理：

- reducer/layout/surface/scheduler exception 都进入同一个 `failRenderer(error)`。
- 先 best-effort emergency restore，再向 stderr 输出一条 sanitized renderer-layer error。
- emergency restore 必须独立于 partially constructed runner/controller，使用 optional guards。
- SIGTERM/SIGHUP 不走“双 Ctrl+C”产品语义，直接 cancel + cleanup。
- 重复 signal、Ctrl+C、runtime exit、renderer error 竞争时只执行一次 shutdown。
- cleanup error 不能掩盖原始 renderer/runtime error；聚合或附加 cause 后报告。

## Coding Agent 执行规范

### 开始前

1. 确认 `v0.2.20` 已发布，工作区干净。
2. `git fetch origin`，从最新 `origin/main` 创建 `v0.2.21`。
3. 读取本计划以及目标文档，但不要尝试 stage/push `docs/`。
4. 运行切片 0 基线命令并记录真实结果。
5. 检查 `git status`，保留任何用户已有改动。

### 开发原则

- 一次只执行一个切片。
- 每个切片先写失败测试，再实现，再跑聚焦测试。
- shared 算法从 Ink 迁移时先保持 Ink 测试绿色，不能先删旧代码。
- 不把 presentation concern 放进 runtime controller。
- 不从 ANSI 字符串计算宽度；layout 输入必须是结构化 span/cell。
- 不用 snapshot 替代关键语义断言；同时断言 cursor、width、row ownership 和 state。
- 不为通过 PTY 测试加入固定 sleep；使用确定性 marker、screen model 和 bounded wait。
- 不在未完成真实 IME 验证时宣称默认 UI ready。
- 不修改 package version，直到 release slice。
- 不 push、PR 或 npm publish，除非用户明确要求。

### 每个切片的交付格式

coding agent 完成切片后必须报告：

```text
Slice:
Changed files:
Behavior added:
Focused tests:
Build status:
PTY/manual status:
Known gaps:
Next dependency:
```

### Review 要点

独立 review 必须优先检查：

- CJK/grapheme cursor 是否拆字符。
- model content 是否能注入 ANSI/control sequence。
- style diff 是否遗漏 reset。
- transcript cache 是否因 live update/resume/resize 返回陈旧内容。
- finalized entry 是否重复 commit，streaming partial 是否泄漏进 scrollback。
- live region 是否越界覆盖历史，last-column pending-wrap 是否导致 cursor 漂移。
- resize/child suspend 是否留下 raw mode、listener、残余 live rows 或重复 history。
- subtask/tool event 是否重复、乱序或永远 running。
- renderer 是否复制 runtime semantics。
- 大 transcript 是否出现 O(n) per delta。
- terminal/Ink compatibility 是否被无意破坏。

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| Styled cell 扩大 frame 成本 | normalized style、span output、changed-row diff、性能 fixture |
| Markdown parser 造成 stream 抖动 | AST/layout 双层缓存、只重排 live entry、render coalescing |
| 多行 cursor 与 CJK 失配 | shared grapheme core、visual row fixture、真实 IME 测试 |
| inline live region 覆盖 shell history | 明确 row ownership、相对 cursor、commit/live 串行协议、PTY screen model |
| stream partial 重复进入 scrollback | stable entry id、commit boundary、finalized-once integration tests |
| last-column wrap 导致 cursor 漂移 | width-1 安全预算或显式换行、窄终端/CJK PTY matrix |
| background stdout/stderr 插入 live region | TUI output 单一 surface、审计直写路径、必要时注入 logger/event sink |
| subtask event 冲击布局 | active area 上限 3、terminal state 折叠、低高度降级 |
| TUI 与 Ink 同时改导致范围失控 | Ink 只做 shared composer compatibility，不新增 UI 能力 |
| 过早切默认 | terminal 继续默认，TUI 先达到 recommended beta gate |
| coding agent 大重写 | 1 个基线切片 + 8 个开发切片、明确所有权、每切片独立 review |

## Definition of Done

v0.2.21 完成时，TUI 必须能承担真实 coding-agent 长会话：用户可以阅读结构清晰的 Markdown/diff/code，编辑多行
prompt，通过 shell 原生 scrollback 可靠查看、选择和复制历史，观察 tool/subagent 状态，并在 resize、中断、child
process 和异常退出后得到完整 terminal 恢复。finalized 内容只提交一次，底部 live region 不覆盖历史或泄漏 streaming
partial。实现必须保持 renderer-independent runtime 边界，长流式输出不产生全量重排风暴，且 terminal、Ink
compatibility 和完整发布门禁全部通过。

只有达到以上条件，TUI 才能被标记为 `recommended beta`；是否在后续版本设为默认，需要独立发布决策。
