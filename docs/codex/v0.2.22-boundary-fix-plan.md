## 三、P0 问题清单（必须修复）

### 3.1 [P0] `services/llm.ts:637` — JSON.parse 无 try-catch，Agent 循环崩溃

```typescript
// 问题代码
const result = await toolExecutor(tc.function.name, JSON.parse(tc.function.arguments));
//                                              ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
// 无 try-catch，无效 JSON 直接抛 SyntaxError
```

- **影响范围**: `chatWithTools` 路径，所有非流式 Agent 调用
- **后果**: LLM 返回畸形 JSON arguments 时整个 Agent 循环崩溃，用户会话中断
- **修复方案**: 包裹 try-catch，失败时回退为 `{}`
- **涉及文件**: `src/services/llm.ts`

---

### 3.2 [P0] `core/checkpoint.ts:158-164` — JSON.parse 后直接迭代未校验字段

```typescript
const meta = JSON.parse(content);  // 合法 JSON 但可能缺少 files 字段
for (const file of meta.files) {    // meta.files 为 undefined → TypeError
```

- **影响范围**: 检查点恢复功能
- **后果**: 检查点元数据缺 `files` 字段时 TypeError 崩溃，无法回滚
- **修复方案**: 添加 `Array.isArray(meta.files)` 校验
- **涉及文件**: `src/core/checkpoint.ts`

---

### 3.3 [P0] `services/session-storage.ts:837` — 单行损坏导致全部历史丢失

```typescript
const entries = lines.map(line => JSON.parse(line) as HistoryEntry);  // 一行坏 → 全部丢
```

- **影响范围**: 会话历史读取
- **后果**: JSONL 文件任意一行损坏（如写入中断），所有历史记录被 catch 块返回空数组
- **修复方案**: 改为逐行 try-catch，跳过损坏行保留可用记录
- **涉及文件**: `src/services/session-storage.ts`

---

### 3.4 [P0] `harness/safety.ts:117,131` — 用户配置正则无转义，ReDoS 风险

```typescript
const blockedMatch = this.policy.blocked.find(pattern =>
  new RegExp(pattern, 'i').test(action),  // pattern 来自用户配置，可能为恶意正则
);
```

- **影响范围**: 安全检查器，影响所有工具执行
- **后果**: 恶意构造的正则（如 `(a+)+$`）导致 ReDoS；无效正则导致安全检查崩溃（检查被跳过）
- **修复方案**: 构造函数中预编译所有正则，无效正则回退默认；引入 ReDoS 检测
- **涉及文件**: `src/harness/safety.ts`

---

### 3.5 [P0] `services/auto-fix/autoFixHook.ts:103` — glob 转 RegExp 未转义特殊字符

```typescript
const regex = new RegExp(pattern.replace(/\*/g, '.*'));  // 未转义 . + ? ( [ 等
```

- **影响范围**: auto-fix 文件匹配
- **后果**: 无效 glob pattern 导致 SyntaxError 崩溃；恶意 pattern 导致 ReDoS
- **修复方案**: 先转义所有正则特殊字符，再替换 glob 通配符
- **涉及文件**: `src/services/auto-fix/autoFixHook.ts`

### 3.6 [P0] `agents/worker-pool.ts:229-235` — executeTask 递归调用未 await

```typescript
this.executeTask(workerId, nextTask, forkOptions);  // 未 await，Promise 被丢弃
```

- **影响范围**: 多 Agent 协作，子任务队列执行
- **后果**: 未处理的 Promise 拒绝可能导致进程崩溃；failed worker 被错误复用导致任务静默丢失
- **修复方案**: 添加 `.catch()` 错误处理；不复用 failed worker
- **涉及文件**: `src/agents/worker-pool.ts`

### 3.7 [P0] `runtime/agent-runtime-controller.ts:100,192` — stopping 标志永不重置

```typescript
private stopping = false;
async stopActiveTurn() { this.stopping = true; /* ... */ }
// 没有任何地方重置 stopping = false
// 后续 runTurn 的 while 条件永为 false → 用户输入被静默吞掉
```

- **影响范围**: Agent 运行时控制器，影响所有 UI 渲染器
- **后果**: 调用 `stopActiveTurn()` 后，该 controller 实例的所有后续 turn 都不执行
- **修复方案**: 在 `stopActiveTurn` 完成后或 `runTurn` 的 finally 中重置 `this.stopping = false`
- **涉及文件**: `src/runtime/agent-runtime-controller.ts`

### 3.10 [P0] 模型定义三源不一致

`services/model-catalog.ts`、`services/model-context.ts`、`core/cost-tracker.ts` 各自维护模型列表，覆盖范围和字段互不匹配。

- **示例**: `glm-4` 在 model-context 有但 catalog 无；`gemini-1.5-pro` 仅 cost-tracker 有
- **Provider 命名不一致**: catalog 用 `'Bailian (Zhipu)'`，model-context 用 `'glm'`
- **影响范围**: 模型诊断、上下文窗口计算、成本追踪
- **修复方案**: 建立单一模型注册表 (single source of truth)，三个文件从它派生
- **涉及文件**: `src/services/model-catalog.ts`, `src/services/model-context.ts`, `src/core/cost-tracker.ts`

### 3.11 [P0] `sdk/query.ts:15-33` — SDK query() 是 mock 实现

```typescript
export async function query(options: SDKQueryOptions): Promise<SDKQueryResponse> {
  // Simple mock implementation for SDK entry points
  const response: SDKQueryResponse = {
    content: `Processed ${options.messages.length} messages`,  // 硬编码
    usage: { inputTokens: options.messages.reduce(...), outputTokens: 0 },
```

- **影响范围**: 公开 SDK API
- **后果**: 任何通过 `import { query } from 'openhorse'` 的外部代码得到 mock 响应，不调用 LLM
- **修复方案**: 实现 `query()` 调用 `framework/query.ts`，消费事件并聚合为 `SDKQueryResponse`
- **涉及文件**: `src/sdk/query.ts`, `src/sdk/types.ts`

### 3.12 [P0] Legacy `init.ts` 与实际运行时双轨架构

`init.ts` 构造的 `Brain`/`Harness`/`MemorySystem`/agents 在实际 CLI 聊天循环中不被使用。`chat-controller.ts` 使用的是 `framework/store.ts`、`harness/context-harness.ts`、`services/llm.ts`、`runtime/subagents/` 等完全不同的对象。

- **影响范围**: 全局架构
- **后果**: 两套并行架构共存，维护成本翻倍；外部使用者通过 `index.ts` import 得到 legacy 路径
- **修复方案**: 评估 legacy 代码是否仍被外部依赖；标记 deprecated；`OpenHorseRuntime` 接口应反映实际运行时
- **涉及文件**: `src/init.ts`, `src/core/state.ts`, `src/core/brain.ts`, `src/agents/`, `src/harness/harness.ts`

---

### 3.13 [P0] `core/state.ts` GlobalState 完全死代码

`GlobalState` 接口及其所有函数（`initGlobalState`/`getGlobalState`/`ensureGlobalState`/`resetGlobalState`/`STATE_MANAGER`）全项目无任何 import 使用。

- **影响范围**: 无运行时影响，但增加维护负担
- **后果**: 字段定义暗示了与实际不符的状态模型，误导新开发者
- **修复方案**: 直接删除 `src/core/state.ts`
- **涉及文件**: `src/core/state.ts`

---

### 3.14 [P0] `sdk/types.ts` 与内部类型严重不兼容

| 概念 | SDK 类型 | 内部类型 | 不一致 |
|------|---------|---------|--------|
| 消息角色 | `role: 'user'\|'assistant'\|'system'` | 含 `'tool'` | SDK 缺 tool 角色 |
| 工具结果 | `output?: string` | `output: string` (必选) | 可选性不一致 |
| 用量命名 | `inputTokens/outputTokens` | `promptTokens/completionTokens` | 字段名完全不同 |

- **影响范围**: 公开 SDK API
- **后果**: SDK 消费者无法完整表达内部消息流，字段名不同导致统计读取失败
- **修复方案**: SDK 类型改为 re-export 内部类型，或定义显式映射层
- **涉及文件**: `src/sdk/types.ts`, `src/services/llm.ts`, `src/framework/tool.ts`
