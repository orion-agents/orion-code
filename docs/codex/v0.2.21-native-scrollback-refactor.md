## 一、已完成工作（/resume 修复）

用户报告 `/resume` 后三个症状：整页空白、历史需上滚、新输出在顶部滚动不能填充空白页。

### 1.1 根因与修复

| 根因 | 文件 | 修复 |
|------|------|------|
| `replaceTranscript` 把全部恢复 history 标 `finalized` → 全量 commit → live region 空 → 空白页 | `src/tui-ui/state.ts` | 加 `RESUME_LIVE_TAIL=50`：较旧前缀标 finalized（可 commit），最近 50 条保留 LIVE（显示在 live region） |
| `restoreSession` 用 `console.log` 裸写 stdout → 绕过 surface 游标追踪 → `this.cursorRow` 失步 → frame 几何错乱 | `src/commands/index.ts` | 横幅改走 `ctx.writeLine?.(line)`（TUI 模式走 surface，非 TUI 保留彩色 console.log）；先 `setSession` 再写 |
| `commit()` 大量提交后 `cursorRow` 未锚定底部 → 后续 live-frame 从错误行 re-anchor | `src/tui-ui/inline-surface.ts` | `this.cursorRow = Math.min(this.height-1, this.cursorRow + committedLines)` |

### 1.2 回归防护

- `inline-surface.ts` 加 `whenIdle()` 测试缝（FIFO 队列末尾 enqueue no-op 并 await）。

## 二、尚未解决的核心问题：原生 Scrollback 不生效

### 2.1 用户期望

Inline surface 的设计承诺（也是去除 alternate-screen 的核心动机）：**已提交的历史进入终端原生 scrollback，用户可以像普通 shell 一样上滚查看完整对话历史**。

### 2.2 实际行为

上滚终端看到的是之前 shell 的内容，**不是**对话历史。对话历史只显示在 live region（底部整屏），从不进入 scrollback。

### 2.3 根因分析

`src/tui-ui/inline-surface.ts` 的 `commit()` 协议（194–233 行）：

1. **`clearLiveRegion()`** 把光标移到 live region 顶部（row 0），清屏；
2. **写已 finalize 的历史行**在 live region 内（从 row 0 向下写 `\n`）；
3. **`getLatestLiveFrame()`** 返回新 live frame → `renderLiveInternal()` **又做一次 `clearLiveRegion`**（回到 row 0，EL2 清 23 行），然后重绘整屏 live frame。

结果：步骤 2 写的历史行在步骤 3 被清屏+覆盖，**从未滚入原生 scrollback**。

原生 scrollback 只有在输出**超过可见高度、终端自动滚屏**时才会累积。但 live region 占了整屏（`runner.ts:199` 传 `height - 1`），且原地重绘（清屏+重写），所以：

- 第一次 `mount` 时 `ensureCapacity` 写 23 个 `\n` 触发 1 次滚屏 → 仅 1 行空行进 scrollback；
- **之后每一次 commit = 0 行进 scrollback**（capacity 早已满，不再滚屏）。

> 上轮我说的"较旧历史进 scrollback、上滚可查看"——**机制上是错的**：那些历史被写进 live region 后立刻被 live frame 覆盖清空，根本没进 scrollback。

### 2.4 根因总结

**live region = 整屏 + 原地重绘 = commit 的历史被覆盖而非滚动 → 原生 scrollback 从不累积。**

## 三、重构方案：底部 Band + 原生 Scrollback

### 3.1 设计思路

把 live region 从"整屏"改成**底部 band**（约 75% 屏高）。已提交的历史写在 band **上方**（历史区），随填满自然上滚进终端原生 scrollback；底部 band（状态栏 + prompt + 最近 tail）原地重绘。

| 区域 | 行数（24 行终端） | 内容 |
|------|-------------------|------|
| 历史区（上方） | ~6 行 (25%) | 最近已提交的对话行；填满后上滚进 scrollback |
| Live band（下方） | ~18 行 (75%) | LIVE transcript tail + overlay + status + prompt |

用户交互：
- **正常查看**：底部 band 显示最近流式输出 + prompt，上方 6 行显示刚提交的历史。
- **上滚终端**：完整对话历史在原生 scrollback 里，与普通 shell 体验一致。
- **`/resume` 后**：最近 50 条 LIVE 显示在 band，较旧 10 条 finalize → commit 写在上方 → 可见 + 可上滚。

### 3.2 具体改动

#### `src/tui-ui/inline-surface.ts`（核心改动）

| 方法 | 当前行为 | 目标行为 |
|------|---------|---------|
| `clearLiveRegion()` | cursorUp(cursorRow) 到 row 0，EL2 清 **整屏** | cursorUp(cursorRow) 到 band 顶（row `height - bandRows`），EL2 只清 **band** 行 |
| `commit()` | clearLiveRegion→写历史在 row 0→renderLiveInternal 覆盖 | **不 clearLiveRegion**；cursor 到 screen row 0（历史区顶）→ 写已提交行（自然上滚进 scrollback）→ cursor 回 band 顶→clearLiveRegion(band)→renderLiveInternal(band) |
| `renderLiveInternal()` | ensureCapacity(height-1), 整屏重绘 | ensureCapacity(bandRows), **只在 band 内重绘**；历史区不动 |
| `ensureCapacity()` | capacity 增到 height-1 | capacity 增到 **bandRows** |
| 新增概念 | — | `liveBandRows`: live region 高度（约 75% 屏高）。`historyAreaRows = height - liveBandRows`。`cursorRow` 相对于 band 顶部（row `height - liveBandRows`）。 |
| `whenIdle()` | 已有 | 保持不变 |

关键：`commit()` 新协议

```
1. cursor 到 screen row 0（历史区顶）：cursorUp(cursorRow + historyAreaOffset)
2. 写已提交行 + \n：每行自然向下写，超出屏幕 → 终端自动上滚进 scrollback
3. cursor 回 band 顶：cursorDown 到 row (height - liveBandRows)
4. clearLiveRegion(band)：只清 band 行
5. renderLiveInternal(liveFrame)：band 内重绘
```

步骤 1–2 让历史自然滚入 scrollback（与普通 shell 输出一致）；步骤 3–5 重绘底部 band，不动历史区。

#### `src/tui-ui/runner.ts`

- `getLiveFrame()` 传 `height: liveBandRows`（而非 `height - 1`）。
- 新增 `getLiveBandRows()` 方法或常量，可配置（默认约 75%）。
- `tryCommit` 无需改动（仍走 `surface.commit(batch, getLatestLiveFrame)`）。

#### `src/tui-ui/layout.ts`

- `renderTuiLiveFrame(state, {width, height: bandRows})` —— frame 高度 = bandRows。
- promptTop = bandRows - 3, statusRow = bandRows - 4, liveTranscriptRows = bandRows - 4。
- 历史区不参与 layout（终端自然排版）。

#### `src/tui-ui/state.ts`

- 不变。`RESUME_LIVE_TAIL=50` 保持。commit 的历史条目通过 surface 写到历史区。

#### `src/commands/index.ts`

- `restoreSession` 横幅走 `ctx.writeLine?.(line)` — 不变。横幅现在也会出现在历史区（写在上方），自然上滚进 scrollback。

### 3.3 Band 高度计算

```typescript
const LIVE_BAND_RATIO = 0.75; // 可配置
const MIN_BAND_ROWS = 8;      // band 至少 8 行（prompt 3 + status 1 + transcript 4）
const MAX_BAND_ROWS = height - 1; // band 上限（历史区至少 1 行才有效果）

liveBandRows = Math.max(MIN_BAND_ROWS, Math.min(MAX_BAND_ROWS, Math.round(height * LIVE_BAND_RATIO)));
historyAreaRows = height - liveBandRows;
```

24 行终端：band = round(24×0.75) = 18, history = 6。
8 行终端：band = max(8, round(8×0.75)) = 8, history = 0 → 等同当前行为（无 history 区，但也 8 行足够用）。

### 3.4 测试更新

| 测试 | 改动 |
|------|------|
| `tests/tui-ui-resume.test.ts` | 更新 frame height 断言为 bandRows；端到端测试验证 commit 的历史出现在 MemoryOutput 原始流中（且不在 band 内） |
| `tests/tui-inline-surface.test.ts` | 更新 capacity/清屏 断言为 bandRows；新增 commit→scrollback 用例（验证已提交行在 raw output 且 band 内不含已提交行） |
| `tests/tui-ui-pty-smoke.py` | 新增：resume 后**上滚**验证（如果 TerminalModel 能模拟 scrollback 读取）；或保留现有断言 + 新增 raw stream 包含已提交历史行 |
| `tests/tui-ui-runner.test.ts` | getLastFrame/getVisibleRows 断言适配 bandRows |
| `tests/tui-ui-layout.test.ts` | frame height 断言适配 bandRows |

### 3.5 风险与边界

- **resize**：`surface.resize()` 需重新计算 bandRows 并重绘。历史区内容随终端 resize 自然 reflow（终端自身处理）。
- **suspend/restore**：`suspend` 清 band + 显示 cursor；`restore` 重绘 band。历史区在 suspend 期间保留（终端 scrollback 不清除）。
- **大量 commit 单次超屏**：如一次 commit 60 行（resume 的 10 条 finalized × 多行），历史区只有 6 行可见，但超出部分已滚入 scrollback——终端自然处理，无需特殊逻辑。
- **historyAreaRows = 0**（极小终端 8 行）：退化为当前行为（band = 整屏，无 history 区），不会出错。
