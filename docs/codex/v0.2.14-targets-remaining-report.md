# v0.2.14 Targets Remaining Work

## Summary

This document consolidates the unfinished work from the current target documents:

- `docs/targets/first-class-coding-agent-vision.md`
- `docs/targets/agent-loop-final-form.md`
- `docs/targets/ui-runtime-boundary.md`
- `docs/targets/ui-ultimate-experience.md`

Current direction is clear: keep `terminal` as the stable product UI, keep
`ink` and `tui` as beta renderers, and continue moving agent behavior into a
renderer-independent runtime protocol. The remaining work is not a UI rewrite.
It is a staged stabilization plan for a first-class coding-agent.

## Current Position

Already substantially started:

- Runtime boundary exists through `AgentRuntimeController`,
  `AgentRuntimeInput`, `AgentRuntimeEvent`, and renderer adapters.
- Terminal UI is the stable default path and keeps shell scrollback.
- Live revision, Ctrl+C interrupt/double-exit, session picker, permission
  request, and resume have shared runtime paths.
- Terminal UI has focused coverage for CJK input, paste, resize, session picker,
  shortcut help, error layering, tool summaries, and runtime parity.
- Agent loop foundations exist: loop budget, fast path, provider retry/fallback
  diagnostics, trace metadata, tool output compression, and `/loop-stats`.

Still incomplete:

- The target-level completion gate, verification state, replay trace, prompt
  assembly observability, compact/resume reconcile, and renderer parity are not
  yet complete enough to claim the target.

## P0: Release-Blocking Remaining Work

### 1. Terminal UI Long-Session Reliability

Required outcome:

- Long output must remain searchable in terminal scrollback.
- Prompt must remain stable during streaming, resize, live revision, and tool
  output.
- Local help, picker, shortcut output, and status refresh must not pollute
  durable session history.

Evidence needed:

- PTY smoke covering long output while typing, resize during active input,
  multi-line paste, `/resume`, permission prompts, Ctrl+C, and tool ordering.
- Manual long-session run with scrollback inspection and resume inspection.

Remaining tasks:

- Add explicit PTY assertions for tool timeline order.
- Add PTY or integration coverage for long assistant output plus active input.
- Add manual validation notes for real macOS Terminal with Chinese IME.

### 2. Runtime Completion Gate

Required outcome:

- Changed-file turns cannot claim completion unless verification is run or
  explicitly skipped with reason.
- The turn records what files changed, what checks were expected, what checks
  ran, what failed, and whether success may be claimed.

Evidence needed:

- Tests for `finishReason=completion_gate`.
- Trace events for `verification_profile`, `verification_result`, and
  `verification_summary`.
- Final answer tests or fixtures proving unverified changed-file work is not
  reported as fully done.

Remaining tasks:

- Make verification state first-class in runtime/session.
- Add repo-aware verification profiles.
- Link tool results into verification events.

### 3. Compact / Resume Continuity

Required outcome:

- After compact and resume, a generic `继续` must preserve the correct
  `rootObjective`, `activeInstruction`, constraints, and next action.
- Resume must reconcile transcript, harness sidecar, project path, model,
  skills, MCP config, and artifacts.

Evidence needed:

- Compact/resume fixture with 20+ turns.
- Test proving `继续` assembles prompt with restored objective.
- Diagnostics when reconcile is uncertain.

Remaining tasks:

- Persist model-visible compact history in session.
- Add reconcile diagnostics and tests.
- Strengthen `/harness explain` around restored context.

## P1: Core Coding-Agent Quality Work

### 4. Prompt Assembly Observability

Required outcome:

- Every model-backed turn records prompt assembly stats without storing full
  prompt, secrets, transcript, or full tool output.
- Users can inspect what evidence was included or omitted.

Evidence needed:

- Redacted `prompt_assembly` trace event.
- `/harness explain` includes included/omitted evidence counts, sections, token
  estimate, budget pressure, and reason summary.

Remaining tasks:

- Promote evidence index and prompt stats into runtime trace.
- Add redaction tests for prompt stats and trace metadata.

### 5. Tool Scheduler And Read-Only Batching

Required outcome:

- Independent read-only exploration is grouped or clearly hinted before it
  becomes many model/tool cycles.
- Tool events remain ordered by original call id and user-visible chronology.
- Full output is retained through artifacts while model-visible output remains
  compact.

Evidence needed:

- Tests for parallel read-only execution with ordered results.
- PTY/tool timeline fixture proving ordered display.
- Artifact tests for long output and long command args.

Remaining tasks:

- Add scheduler-level grouped read-only execution where safe.
- Expand `/trace` and `/artifacts` around compacted long args.

### 6. Safety, Permissions, And Checkpoints

Required outcome:

- Dirty worktree state is recorded before edits.
- Risky multi-file edits create checkpoints or rollback guidance.
- Permission decisions are redacted and auditable.
- Secret-like values never appear in traces, summaries, or prompt stats.

Evidence needed:

- Dirty-worktree fixture.
- Secret-redaction fixture across trace, prompt stats, summaries, and artifact
  indexes.
- Permission-denial fixture proving no mutation and clear finish reason.

Remaining tasks:

- Add checkpoint policy for risky edits.
- Persist permission decision latency/scope/reason with redaction.
- Expand command safety classifications.

## P2: Renderer Parity And Future UI Work

### 7. Renderer Parity

Required outcome:

- `terminal`, `ink`, `tui`, future `print`, and future remote renderers consume
  the same runtime protocol for exposed features.
- Renderer differences are presentation-only.

Evidence needed:

- Parity tests for chat input, slash commands, live revision, permission
  decisions, session picker, tool ordering, session restored, and errors.
- Known beta UI gaps documented for Ink/TUI.

Remaining tasks:

- Keep terminal as release path.
- Add parity cases when adding new runtime events.
- Do not move agent logic into Ink/TUI to fix visual bugs.

### 8. Print Mode And Remote UI

Required outcome:

- Print mode becomes deterministic for CI/scripts.
- Remote UI eventually connects through the same event protocol and never
  copies agent runtime logic.

Evidence needed:

- Non-interactive tests for permission-required failure.
- JSON output fixtures for deterministic commands.
- Remote protocol design before implementation.

Remaining tasks:

- Keep print/remote out of current interactive completion scope.
- Reuse runtime permission and picker events when implemented.

## P3: Platform And Ecosystem Work

### 9. Skills, MCP, Hooks, Plugins

Required outcome:

- Skills, MCP, hooks, and plugins register through runtime capabilities and do
  not require query-core rewrites.

Evidence needed:

- Skill discovery/loading tests for repo/user/system scopes.
- MCP stdio/http/auth/tool-policy tests.
- Hook lifecycle tests.

Remaining tasks:

- Add hook protocol after runtime trace stabilizes.
- Keep skills metadata compact and load instructions on demand.
- Add plugin packaging only after skills/MCP/hook APIs stabilize.

### 10. Multi-Agent Runtime

Required outcome:

- Subagents are supervisor-managed runtime capabilities, not UI features.
- Planner/coder/reviewer/researcher agents work through bounded task packets,
  artifacts, budgets, permissions, and merge protocol.

Evidence needed:

- Isolated subagent session/workspace tests.
- Supervisor merge and review fixtures.
- Aggregate budget accounting.

Remaining tasks:

- Do not pull this into v0.2.x stabilization unless single-agent loop,
  verification, trace, and harness continuity are solid.
