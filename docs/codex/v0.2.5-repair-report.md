# v0.2.5 Repair Report

## Summary

v0.2.5 focuses on repairing issues found during the v0.2.4 review. The work keeps the project aligned with the OpenHorse target: reliable session recovery, safe code editing, runtime-owned tool behavior, compact/resume continuity, and stable public APIs.

## Fixed Issues

### Session Index and Resume Stability

v0.2.4 stored `<sessionId>.index.json` files beside session metadata. Session listing still parsed every non-harness `.json` file as metadata, so index sidecars could enter `/resume` candidates and crash prefix lookup.

Changes:

- Added strict session meta validation before normalization.
- Excluded `.messages.json`, `.harness.json`, and `.index.json` from session metadata scans.
- Updated batch message writes to maintain the session index.
- Deleted session index sidecars when a session is removed.

### Safer `edit_file`

The v0.2.4 fuzzy edit path automatically wrote changes when exact `old_string` matching failed. That made code edits less predictable.

Changes:

- Restored exact-match default behavior: missing `old_string` fails safely.
- Added explicit `fuzzy_match: true` opt-in.
- Reworked fuzzy matching to avoid consuming unrelated blank lines.
- Rejected ambiguous fuzzy matches even when `replace_all` is set.

### Tool Result Summaries

v0.2.4 added `getSummary` to tools, but runtime events and session rendering did not consume it.

Changes:

- `executeTool()` now returns `summary` and `outputBytes` in structured tool results.
- `query()` propagates summary metadata in `tool_result` events.
- Terminal and runtime transcript rendering prefer tool summaries when available.
- PTY smoke tests now assert the new summary output.

### LLM Compact Summary Wiring

`generateLLMSummary()` existed but was not used by auto or manual compact paths.

Changes:

- `AutoCompactConfig` now accepts an optional LLM service.
- Auto compact passes LLM through to `compactMessages()`.
- `/compact` passes the current command context LLM.
- Heuristic summaries remain the fallback when LLM is unavailable or fails.

### Public API Compatibility

v0.2.4 removed the public `HarnessEngine` export in a patch version.

Changes:

- Restored `src/harness/harness.ts` as a compatibility API.
- Re-exported `HarnessEngine` and related types from `src/index.ts`.
- Kept CLI runtime on the newer `ContextHarness` path.

## Tests Added or Updated

- Session storage tests for index sidecar filtering and batch index updates.
- Tool tests for explicit fuzzy matching, ambiguous fuzzy rejection, and tool summary metadata.
- Query tests for propagating `summary` and `outputBytes`.
- Compact tests for LLM summary usage in direct and auto compact paths.
- MCP and PTY tests updated for structured tool summaries.

## Alignment With Project Targets

These changes improve the core coding-agent foundation rather than only the UI:

- Session recovery is more reliable and project-scoped.
- Editing defaults are safer and more deterministic.
- Tool summaries now flow through runtime events instead of staying as unused tool-local code.
- Compact/resume behavior can use higher-quality summaries while preserving fallback behavior.
- Patch-level API compatibility is preserved for npm users.

## Follow-Up Recommendations

- Store tool outputs as structured records with both full output and summary, then let harness evidence consume the summary directly.
- Add a dedicated `edit_file --preview` or candidate-return mode for fuzzy edits.
- Extend session index search into the session picker UI.
- Add API compatibility tests for public exports before publishing patch releases.
