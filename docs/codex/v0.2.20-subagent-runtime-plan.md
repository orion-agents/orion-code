### Usage

配置（`~/.openhorse/openhorse.json`，均可选，缺省即默认）：

```json
{
  "subagents": {
    "mode": "auto",
    "maxParallel": 3,
    "maxTasksPerTurn": 3,
    "maxTurnsPerTask": 6,
    "roles": ["research", "review", "test-investigate"]
  }
}
```

环境变量：`OPENHORSE_SUBAGENTS=off|explicit|auto`、`OPENHORSE_SUBAGENT_MAX_PARALLEL=1..3`。

- `off`：不向模型暴露 `subtask` capability。
- `explicit`：仅当 root objective 含明确委派意图（"并行/分别/research/review/调研/审查" 等）时允许。
- `auto`（默认）：模型可在符合策略时主动调用。

根 Agent 调用 `subtask` 后，Supervisor 在统一预算/权限/trace 内启动 1-3 个只读 child，结构化结果（summary/findings/files/commands/verification/risks/usage）作为 tool result 返回。child 无法 edit/write/exec/memory/subtask。

### 已知限制（P1+）

- child 不可执行命令，只在结果 `commands` 中建议（`executed=false`）。
- provider gate 共享 cooldown 仅在 child 主动报告 429 时生效；query() 内部重试的细粒度 retry-after 协调待 P1。
- ui-view-model 结构化 subtask timeline entry 为 P1（当前最小可见性经 transcript 摘要 + runtime event 满足）。
- 进程重启后续跑未完成 subtask 不支持；只持久化已落盘 trace 和结果摘要。
- 单 child 重试、动态并发降级、`/subagents` 诊断命令为 P1。

## 当前状态

当前分支为 `v0.2.20`，从已发布的 `v0.2.19` 创建。`package.json` 在开发启动阶段仍保持
`0.2.19`，只在进入发布流程后更新为 `0.2.20`。

OpenHorse 当前已经具备单 Agent 内的批量探索能力：

- 主模型可以在一次响应中产生多个 tool call。
- `src/framework/tool-scheduler.ts` 会并发执行声明为 `isConcurrencySafe` 的工具，默认并发上限为 6。
- `batch_read` 可以在一次 tool call 中执行最多 8 个只读探索步骤，减少模型往返次数。
- `ContextHarness`、loop budget、permission、session、trace、artifact 和 completion gate 已接入主 agent loop。

但以上仍然是一个 Agent、一个上下文和一个根任务。当前不会为 research、review、测试调查或多目录探索
自动创建独立 Agent。

仓库中已有 `src/agents/fork.ts`、`worker-pool.ts`、`coordinator.ts` 和 `router.ts` 原型，但不应直接作为
v0.2.20 的实现基础：

- 未接入 `AgentChatController` 或主 `query()` loop。
- `fork.ts` 通过 `require('../cli').llm` 获取全局 LLM，但 CLI 没有导出该实例，且导入 CLI 会执行 `main()`。
- 没有继承当前 harness、permission、trace、session、artifact 和 aggregate budget 语义。
- `background` 只控制 stdout，不具备任务句柄、取消、超时、状态查询或恢复能力。
- Coordinator、WorkerPool 和 fork 没有自动化测试，也没有从 npm 公共入口导出。

因此 v0.2.20 应实现 runtime-owned subagent，而不是继续给旧原型补接线。

## 版本目标

v0.2.20 的主题是 **只读 Subagent Runtime Beta**：当根 Agent 识别到多个可独立探索的工作包时，可以主动
调用 `subtask` runtime capability，由 Supervisor 在统一预算和权限边界内启动独立 subagent，并只把结构化
结论返回根 Agent。

版本必须交付：

- 根 Agent 能在 `auto` 模式下主动请求 1 至 3 个独立 subtask。
- 支持 `research`、`review`、`test-investigate` 三种内置角色。
- subagent 使用独立消息上下文、受限工具集和独立 loop budget。
- 多个通过审批的只读 subtask 可以并行运行。
- 根 Agent 保持 root objective、最终编辑权、最终验证权和最终答复权。
- subtask 的启动、进度、结果、失败、取消和资源消耗可追踪。
- terminal、Ink 和 TUI 只消费统一 runtime event，不实现 renderer-local 调度逻辑。

## 非目标

- v0.2.20 不允许 subagent 编辑、写文件、提交、推送、发布或修改配置。
- 不实现多个 worktree、分支合并或并发 coding worker。
- 不允许 subagent 再创建 subagent，最大深度固定为 1。
- 不复制完整父 transcript，也不把完整子 transcript注入根上下文。
- 不引入远程 worker、跨机器任务、定时任务或持久后台 daemon。
- 不让 UI 决定是否拆分任务，也不在 renderer 内维护 subagent 生命周期。
- 不承诺进程退出后继续运行未完成 subtask；v0.2.20 只持久化已发生的 trace 和最终结果。

## 核心设计决策

### 1. 模型发起，Supervisor 审批

“自动启动”定义为：根 Agent 根据 system prompt 和当前任务主动调用 `subtask`，无需用户逐次确认；但工具调用
不是直接 spawn，必须先经过确定性的 `SubagentPolicy` 审批。

不使用隐藏的关键词分类器直接抢占主 loop，原因是任务是否可独立拆分通常依赖当前上下文。模型负责提出工作包，
runtime 负责执行不可绕过的角色、预算、权限、深度和并发检查。

### 2. `subtask` 是 runtime capability，不是全局静态工具

`subtask` 需要当前 LLM、session、harness、permission mode、budget ledger、event sink 和 abort signal，不能加入
无状态的全局 `TOOLS` 后再从 CLI 反向获取依赖。

由 `AgentChatController` 在每个根 turn 创建并注入：

```text
AgentChatController
  -> SubagentSupervisor
     -> createSubtaskTool(supervisor)
     -> SubagentRunner
        -> query(child params)
```

child 的工具列表必须移除 `subtask`，从结构上禁止递归委派。

### 3. 第一版只读，共享 cwd，不共享可变会话状态

subagent 可以读取同一 canonical project cwd，但只能使用角色 allowlist 中的只读工具。所有写工具、git mutation、
发布工具、memory mutation 和需要交互授权的工具均不提供给 child。

child 不直接写父 `Store`、父 transcript 或父 harness state。Supervisor 只在 child 完成后把结构化结果作为一个
tool result交回根 loop，并把生命周期事件写入父 session trace。

### 4. 预算先预留，结束后结算

Supervisor 在启动前为每个工作包预留模型请求、tool call、model-visible bytes 和时间预算。预留失败的工作包不启动。
结束后按真实用量结算，所有 child 用量计入根用户 turn 的 aggregate budget 和 `/cost` 统计。

该约束必须在 runtime 层实现，不能只依赖 prompt 中的“节约调用”要求。

### 5. 返回结构化结论，不返回完整 transcript

subagent 最终结果必须解析并规范化为固定 schema。根 Agent只看到摘要、证据和资源消耗，避免多个 child 的完整
对话快速污染主上下文。

### 6. Child 不共享可变 LLMService 实例

当前 `LLMService` 持有 `lastRequestDiagnostics`、`consecutive529Errors`、`usingFallback` 和可变 model 状态。多个并发
child 共用同一实例会互相覆盖 diagnostics，并可能让一个 child 的 fallback 改变其他 child 的 model。

`SubagentLlmFactory` 必须根据根 runtime 的已解析配置为每个 child 创建独立 client。所有 child 仍经过同一个
`SubagentProviderGate`，由它限制并发请求并共享 provider cooldown/retry-after 状态。根 Agent在等待 `subtask`
tool result期间不会发起新的模型请求；后续如支持父子同时 streaming，再把根请求也接入统一 provider gate。

## Runtime 协议

### Subtask 请求

一次 `subtask` tool call 可以提交 1 至 3 个工作包，避免依赖不同 provider 是否稳定地产生并行 function calls：

```ts
type SubagentRole = 'research' | 'review' | 'test-investigate';

interface SubtaskPacket {
  id?: string;
  role: SubagentRole;
  objective: string;
  reason: string;
  scope?: {
    paths?: string[];
    symbols?: string[];
  };
  contextHints?: string[];
  expectedOutput?: string;
}

interface SubtaskRequest {
  tasks: SubtaskPacket[];
  execution: 'parallel' | 'serial';
}
```

`id` 由 runtime 最终生成，不能信任模型提供的值。`scope.paths` 必须 canonicalize，并拒绝逃逸 project root 的路径。

### Subtask 结果

```ts
interface SubtaskResult {
  id: string;
  role: SubagentRole;
  status: 'completed' | 'failed' | 'cancelled' | 'timed_out' | 'rejected';
  summary: string;
  findings: Array<{
    severity?: 'critical' | 'high' | 'medium' | 'low' | 'info';
    title: string;
    evidence: string;
    file?: string;
    line?: number;
  }>;
  files: string[];
  commands: Array<{ command: string; purpose: string; executed: false }>;
  verification: string[];
  risks: string[];
  usage: {
    modelRequests: number;
    toolCalls: number;
    promptTokens: number;
    completionTokens: number;
    durationMs: number;
  };
}

interface SubtaskBatchResult {
  batchId: string;
  results: SubtaskResult[];
  aggregateUsage: SubtaskResult['usage'];
}
```

结果顺序必须与请求顺序一致，即使并行任务以不同顺序结束。

## 自动触发策略

`SubagentPolicy` 允许调用的必要条件：

- 当前调用来自根 Agent，`depth === 0`。
- `mode` 不是 `off`；`explicit` 模式还要求当前 root objective 含明确委派意图。
- role 已启用，任务数、并发数和预算没有超限。
- 每个 objective 边界明确，能够独立产生有用结论。
- child 工具 allowlist 不包含写操作或 `subtask`。
- 当前没有等待用户处理的 permission request。
- 父 abort signal 尚未触发。
- provider gate 没有处于不可恢复的 cooldown，且能为 batch 预留请求槽位。

适合自动委派的场景：

- 同时调查两个以上独立模块或候选根因。
- 对现有 diff 做独立 review，同时由另一个 child 检查测试缺口。
- 分别进行仓库事实检索和外部官方文档检索。
- 测试失败可以按 suite、平台或根因方向独立调查。

必须拒绝或留在根 Agent 的场景：

- 简单问答、单文件读取、一次 grep 可以解决的问题。
- 后一个步骤依赖前一个步骤结论，无法并行。
- 任务主要工作是编辑、提交、push、PR 或 npm 发布。
- 子任务描述只有“处理一下”“继续看看”等不可验证目标。
- 剩余 aggregate budget 不足，或 provider 正在 rate limit/backoff。
- 同一 scope 已有 running child，且新任务没有不同的验证目标。

Policy 的每次 allow/reject 都写入 trace，记录 reason 和当时预算快照。

## 内置角色与工具边界

| 角色 | 用途 | 默认工具 | 禁止项 |
|------|------|----------|--------|
| `research` | 仓库事实、官方文档、API 调研 | read/list/glob/grep、LSP 只读、git status/diff/log、web search/fetch | edit/write、exec、memory mutation、subtask |
| `review` | diff、风险、回归和测试缺口审查 | research 工具、artifact read | 修复代码、执行 shell、提交、改变 review scope |
| `test-investigate` | 分析失败日志、测试代码和配置 | research 工具、artifact read | 直接执行测试、安装依赖、更新 snapshot、写 fixture、发布 |

v0.2.20 的 child 不获得 `exec_command`。根 Agent负责运行测试或构建，并把失败输出保存为 artifact 后交给
`test-investigate` 分析。child 可以在结果的 `commands` 字段中建议根 Agent下一步执行什么，但 `executed` 固定为
`false`。受操作系统约束的只读 test sandbox 延后到 P1，避免在当前 sandbox wrapper 尚未接入时给出虚假的只读保证。

## 上下文组装

child 不复制完整父 messages。`SubagentContextBuilder` 组装：

1. 角色 system prompt 和严格 JSON 输出 schema。
2. root objective 的只读摘要，不包含无关闲聊。
3. 当前 task packet、canonical cwd、scope 和 expected output。
4. project instructions、已激活 skills 的只读指引。
5. 父 harness 的 context capsule、已知证据和相关 artifact 引用。
6. 必要的 workspace snapshot、git status 和 current model/provider 信息。

默认不继承：

- 父完整 transcript。
- 父 pending tool calls。
- 父 permission callback。
- 父可写 memory/store 引用。
- 父 renderer 或 UI 状态。

## 生命周期与取消

状态机：

```text
requested -> rejected
requested -> queued -> running -> completed
                              -> failed
                              -> timed_out
                              -> cancelled
```

- 根 turn 的 AbortController 派生 child AbortController。
- 用户第一次 Ctrl+C 中断根 turn 时，Supervisor 必须取消全部 queued/running child 并等待清理完成。
- 单 child 超时只终止该 child；batch 其余任务继续，除非 execution 为 `serial` 且后续依赖已失败。
- Supervisor 在根 turn 结束时不得遗留 timer、promise、child process 或 pending permission。
- v0.2.20 不做进程重启后的续跑；resume 只能恢复已落盘结果和“上次运行被中断”的事实。

## Session、Trace 与 Artifact

复用项目级 session storage，不创建第二套全局数据库：

- 生命周期写入父 session trace：`subtask_requested`、`subtask_started`、`subtask_completed`、
  `subtask_failed`、`subtask_cancelled`、`subtask_rejected`。
- 最终 `SubtaskResult` 写为 session sidecar artifact，trace 只保存摘要和 artifact ID。
- P0 复用 `storeArtifact(projectPath, 'subtask_<role>', json, bytes)`；同时扩展 artifact metadata 或 trace 字段，
  使 `/artifacts` 可以区分普通 tool output 和 subtask result。
- child 完整内部消息默认不持久化；debug 模式可写受大小限制、自动脱敏的诊断 artifact。
- `/trace` 和 `/artifacts` 可以查看 subtask 结果，不新增独立隐藏存储格式。
- session resume 将已完成结果恢复为 transcript 摘要，不把 child 重新标记为 running。

## Runtime Event 与 UI

在 `AgentRuntimeEvent` 增加 renderer-independent 事件：

```ts
type RuntimeSubtaskState =
  | 'queued'
  | 'running'
  | 'completed'
  | 'failed'
  | 'cancelled'
  | 'timed_out'
  | 'rejected';

interface RuntimeSubtaskEvent {
  batchId: string;
  taskId: string;
  role: SubagentRole;
  state: RuntimeSubtaskState;
  objective: string;
  summary?: string;
  durationMs?: number;
}
```

v0.2.20 UI 只要求最小可见性：

- terminal 显示启动、完成、失败和取消摘要。
- Ink/TUI 在现有 tool timeline 中显示同样的 role、state 和 summary。
- UI 不展示 child token stream，不提供 renderer-local task queue。
- 三种 renderer 必须通过同一组 runtime parity fixture。

## 代码结构

新增模块：

```text
src/runtime/subagents/
  types.ts                 # packet/result/event/config 类型
  presets.ts               # role prompt 和工具 allowlist
  policy.ts                # 自动触发审批、scope、permission 规则
  budget.ts                # reserve/reconcile aggregate ledger
  provider-gate.ts         # child 请求并发、cooldown 和 retry-after 协调
  context-builder.ts       # 独立 child 上下文组装
  runner.ts                # 单个 child query loop
  supervisor.ts            # 队列、并发、取消、聚合、trace
  tool.ts                  # runtime-bound subtask tool factory
```

主要接入点：

- `src/runtime/chat-controller.ts`: 创建 Supervisor，向根 turn 注入 tool，归集 aggregate usage。
- `src/runtime/agent-runtime-protocol.ts`: 增加 subtask runtime event。
- `src/runtime/ui-events.ts`: 增加统一 view event 和 trace 类型。
- `src/framework/query.ts`: 暴露可结算的 child loop stats，不内置 subagent 策略。
- `src/services/llm.ts`: 提供安全的 child client factory 输入或每请求 diagnostics，禁止共享可变请求状态。
- `src/services/config.ts`: 解析和验证 `subagents` 配置。

### 发布阻塞项（必须在 v0.2.20 修复）

#### R1. 修复 config -> subagent barrel -> tools -> web -> config 循环依赖

**问题**：`src/services/config.ts` 从 `../runtime/subagents` barrel 导入配置常量和 clamp；该 barrel 又导出
`runtime-integration.ts`，后者导入 `src/tools/index.ts`。当 `src/tools/web.ts` 先加载 config 时形成环，
`WEB_TOOLS` 尚未初始化就被展开，导致全量测试失败。该问题具有导入顺序依赖，聚焦测试无法稳定发现。

**技术路径**：

- [ ] `config.ts` 直接从 `runtime/subagents/types.ts` 导入 `DEFAULT_SUBAGENT_CONFIG`、
  `SUBAGENT_LIMITS` 和 `SubagentConfig`，从 `policy.ts` 导入 `clampSubagentConfig`。
- [ ] 约束 leaf config/type 模块不得导入 production、runtime-integration 或 tools barrel。
- [ ] 增加独立 import-order regression test，分别先导入 `tools/web`、`services/config` 和
  `runtime/subagents`，确保三种顺序均可初始化。
- [ ] 全量 `npm test -- --runInBand` 必须恢复为 0 failed。

#### R2. 在 child 工具执行边界强制只读和 MCP 权限

**问题**：`READ_ONLY_INVESTIGATION_TOOLS` 包含通用 `mcp_call`，它可以调用任意 MCP action；child executor
直接调用 `executeTool()`，不会执行工具的 `checkPermissions`。因此 child 可以绕过 root permission，调用写入、
删除、发消息或其他外部副作用工具，违反本版本最核心的只读承诺。

**技术路径**：

- [ ] v0.2.20 默认从 child allowlist 移除通用 `mcp_call`。
- [ ] 如必须保留 MCP 读取能力，只向 child 暴露解析后的 first-class MCP tool，并要求可信元数据
  `readOnlyHint === true`；未知或缺失 annotation 一律拒绝。
- [ ] child executor 在执行前再次验证 tool identity、`isReadOnly()`、permission policy 和 MCP annotation，
  不能只依赖工具名称 allowlist，也不能依赖 prompt 禁止语句。
- [ ] 使用 fake MCP server 暴露 read-only 与 mutating 两个 action，验证 child 只能调用前者，后者不会执行。

#### R3. 在 executor 层落实 project root 与 packet scope 隔离

**问题**：policy 只 canonicalize `packet.scope.paths`，canonical scope 随后仅写入 child prompt；
`read_file`、`list_files`、`glob`、`grep` 和 `batch_read` 的实际参数没有按 root/scope 校验。child 仍可读取
绝对路径、`../`、同仓库 scope 外文件或 symlink 指向的仓库外文件。`history_search` 还会默认搜索最近 5 个
session，可能泄露其他项目的工具参数和结果。

**技术路径**：

- [ ] 新增 `ChildToolExecutorGuard`，在每次执行前提取 path-bearing 参数，基于 realpath 做 containment 检查。
- [ ] 第一层边界固定为 canonical project root；packet 指定非空 scope 时再施加第二层 scope 边界。
- [ ] 对不存在路径校验最近存在父目录的 realpath，防止通过未来创建路径或 symlink parent 绕过。
- [ ] `batch_read` 必须递归校验每个 nested operation；glob/grep 的 cwd/base/path 参数使用同一 guard。
- [ ] v0.2.20 从 child allowlist 移除 `history_search`，或改为只允许注入的 current session/current project，
  禁止 child 自选 sessionId 和跨项目 recent-session 搜索。
- [ ] 表驱动测试覆盖绝对路径、`..`、scope 外同仓库路径、symlink escape、glob/grep base、
  `batch_read` nested args 和跨项目 history。

#### R4. 修复 Provider Gate 的排队、cooldown 和取消语义

**问题**：policy 要求整个 batch 立即占满 provider 空闲槽，导致 `maxParallel=2` 的 3-task parallel batch 和
`maxParallel=1` 的 serial batch被直接拒绝，而不是排队。`enterCooldown()` 没有到期唤醒 timer，waiter 只在
`release()` 时 drain；冷却期间最后一次 release 后，等待任务可能永久挂起。`acquire()` 也不接收 AbortSignal，
Ctrl+C 无法移除 queued waiter。

**技术路径**：

- [ ] policy 只判断 provider 是否处于不可恢复状态；正常并发不足交给 FIFO semaphore 排队。
- [ ] parallel batch 允许任务数大于 `maxParallel`，峰值并发受 gate 限制；serial 只需逐个 acquire。
- [ ] gate 维护单一 cooldown wake timer，延长 cooldown 时重排 timer，到期主动 drain。
- [ ] `acquire(signal)` 支持 abort，原子移除 waiter 并拒绝 promise，不得泄漏 active slot 或 listener。
- [ ] 测试必须断言所有任务实际完成，不能只断言 `peak <= maxParallel`；补充 peak 恰为 2、serial/1、
  cooldown 自然到期、cooldown 延长和 queued abort 场景。

#### R5. 收紧 parent abort、timeout 与 child shutdown

**问题**：parent abort 没有作为独立 outcome 参与 race；如果 query 在 signal abort 后正常 resolve，结果仍可能被
标记为 completed。timeout 返回后未等待 query 清理，Supervisor 已释放 provider slot，而旧 child promise 仍可继续
模型请求或工具调用，造成并发超限、晚到副作用和 open handle。

**技术路径**：

- [ ] runner 将 parent abort、timeout、query completion/error 建模为互斥 terminal outcome。
- [ ] 任一 abort 后即使 query 随后 resolve，也必须保持 cancelled/timed_out，不允许翻转为 completed。
- [ ] provider slot 只能在 child query 已确认停止后释放；为不合作 executor 增加有界 shutdown grace period，
  超出后记录明确 diagnostic，但不静默当作已清理。
- [ ] 关闭 timeout、abort listener、cooldown timer 和 waiter listener，增加 `--detectOpenHandles` 回归。
- [ ] 测试覆盖 resolve-on-abort、reject-on-abort、忽略 abort 的延迟 query、取消后无晚到 tool/model call。

#### R6. 把任务数、permission、预算和成本变成 turn 级不可绕过状态

**问题**：每次 `runSubtaskBatch()` 都把 `tasksStartedThisTurn` 重置为 0，并把 `hasPendingPermission` 固定为
false；同一 root turn 多次调用 `subtask` 可超过 `maxTasksPerTurn`，也无法反映真实 pending permission。
预算目前只预留后结算，不在 child loop 中强制；`reconcile()` 的超限结果被忽略，并把真实 model/tool/duration
usage 截断到上限，导致超支被隐藏。失败、取消、超时前已经发生的 usage 还会被记为 0。
此外 child ledger 与 root `query()` 的 loop budget 相互独立，child 只在 root query 结束后被加到展示统计，
无法阻止 `root requests + child requests` 突破根 turn 上限。`/cost` 命令读取 `CostTracker`，而当前 child 仅更新
store token usage，没有写入 CostTracker，因此文首“child 已计入 /cost”的声明不成立。

**技术路径**：

- [ ] 将 started/reserved task counter 放入 `SubagentTurnBundle`/Supervisor 实例，审批和增量更新原子化。
- [ ] 从 root runtime 注入实时 permission state，不允许硬编码 `false`。
- [ ] 把 per-task 与 aggregate request/tool allowance 传到 query loop，在每次模型请求和工具调用前原子扣减；
  超限时停止 child 并返回可诊断终态。
- [ ] root query 与所有 child 共享同一个 turn ledger；child 预留后 root 的后续请求也必须受剩余额度约束。
- [ ] ledger 保存 observed usage 原值；enforced allowance、violation 和 observed usage 分开建模，禁止用 clamp
  修改 `/cost` 和 telemetry 事实。
- [ ] query error/cancel/timeout 需要携带 partial stats，所有终态都结算 model/tool/token/duration usage。
- [ ] 每次 child LLM response 按真实 model、taskId、token 和 request 写入共享 CostTracker，不能只取最终
  completion usage；`/cost`、store token usage 和 batch aggregate 必须来自同一份 observed facts。
- [ ] 测试覆盖同 turn 两次 `subtask`、pending permission、3 个 child 合计超 turn limit、单 child 超 model/tool
  cap、root+child 总上限，以及失败/取消/超时前已消费 usage 的精确核算。

#### R7. 统一所有终态的 finalize、持久化与审计

**问题**：queued serial task 被取消、整批 rejected 等路径没有统一调用 `onSubtaskResult`；event/artifact callback
抛错还会使标称“Never throws”的 batch 直接 reject 并留下未结算 reservation。policy allow/reject 也没有完整记录
reason 与 budget snapshot，rejected event 的可见摘要不足。completed 先写 lifecycle trace，artifact 成功后又写第二条
同类型 trace；失败、取消、超时结果不存 artifact。更严重的是 child 完成后如果 root synthesis 被 Ctrl+C/provider
error 中断，session messages 尚未落盘；resume 只从 session messages 恢复，不读取 subtask trace/artifact，已完成结论
会从恢复后的 UI 和根模型上下文中消失。

**技术路径**：

- [ ] 建立单一 `finalizeTask()`：terminal event、budget reconcile/release、result callback 和 trace 在此完成，
  每个 packet 恰好执行一次。
- [ ] event/trace/artifact sink 异常必须隔离为 diagnostic，不能改变 child 业务终态或破坏 sibling 聚合。
- [ ] allow/reject trace 记录 reason、task count、running count、remaining budget 和 provider/cooldown snapshot。
- [ ] 每个 terminal state 只保留一条带 summary、duration、usage、artifactId 的权威 trace，`/trace` 与
  `/artifacts` 可以双向发现，不重复写 `subtask_completed`。
- [ ] root 中断前 durable flush 已完成 child result/artifact reference；resume 恢复 completed 摘要和 interrupted
  root 状态，不伪造 running，也不重新执行已完成 child。
- [ ] 测试覆盖 rejected、queued-cancelled、callback throws、artifact failure、每任务 exactly-once finalize，
  以及“child completed -> root synthesis 中断 -> restart/resume”。

#### R8. 让真实 Terminal、Ink、TUI sink 消费统一 subtask event

**问题**：`agent-runtime-protocol.ts` 已能转发 synthetic `subtask_event`，但 Terminal、Ink、TUI 的真实
`UiEventSink` 没有实现 `subtaskEvent` consumer；当前用户可见性来自 `chat-controller.ts` 额外 append 的普通 system
transcript。现有 parity test 使用人工 sink，只证明 adapter case 存在，不能证明真实 renderer parity。

**技术路径**：

- [ ] 在共享 view-model 层把 queued/running/completed/failed/cancelled/timed_out/rejected 映射为稳定 timeline entry。
- [ ] Terminal、Ink、TUI sink 只消费共享 view-model event，不各自实现调度或状态机。

#### R9. 为默认 auto 模式增加确定性的根任务适用性门禁

**问题**：默认 `auto` 会在所有非 skill-scope turn 暴露 `subtask`；“简单任务不委派”目前只写在 prompt，policy
只检查 child packet 是否 bounded。若 root model 对简单问答主动构造 packet，runtime 仍会批准，无法满足零额外请求

- [ ] 在 turn 开始时计算可审计的 delegation eligibility，至少要求两个独立调查方向，或明确的 review + test
  investigation 组合；结果作为 policy context，不能只靠 child 自述 reason。
- [ ] eligibility 判定保持保守、可解释并写 trace；不确定时留在 root，用户显式委派可走 explicit-intent 分支。

  child query 次数为 0；正向 E2E 仍需证明多 scope 场景可启动。
