### ⚠️ No behavioral regressions -- 1 potential issue

**[F1] `readOnlyToolCalls` includes child tool calls, may inflate metrics**

`chat-controller.ts` foldSubagentUsage:
```ts
readOnlyToolCalls: (stats.readOnlyToolCalls ?? 0) + usage.toolCalls,
```
Child tool calls are all read-only, so including them in `readOnlyToolCalls` is semantically correct. But `toolCalls` is also added to `stats.toolCalls`, meaning the root agent's total tool call count includes child calls. If `/cost` or loop-budget checks are based on `toolCalls` for throttling, child calls will accelerate root budget consumption. **This is by design** (children share root budget), but need to confirm loop-budget guard accounts for this.

**Severity: Low** -- Current loop-budget check runs inside `runChat`, subagent usage is only folded after turn completion, so no mid-turn false triggers.

## 4. Architecture Assessment

**Subagent runtime design quality: High**

1. **Clear layering**: types -> policy -> budget -> presets -> provider-gate -> runner -> supervisor -> tool -> production -> runtime-integration, single dependency direction, each layer has clear responsibility.
2. **Defense in depth**: Scope escape triple check (`..` / absolute / symlink), tool allowlist + deny-set + assert, depth limit, budget clamp.
3. **Testability**: All external dependencies (LLM, query loop, clock) injectable, production binding separated from logic.
4. **Unified event protocol**: `RuntimeSubtaskEvent` is renderer-agnostic, terminal/Ink/TUI consume same events.
5. **Gradual integration**: `mode: 'off'` default disable, skill scope active hides subtask tool, no breaking existing flows.

**Code style**: Consistent with project conventions (JSDoc comment density, naming, Chinese comments preserved).
