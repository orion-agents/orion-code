# v0.2.22 TUI 友好渲染与视觉分层技术方案

## 文档状态

- 目标版本：`v0.2.22`
- 当前基线：`v0.2.21-fix1` 工作树中的 primary-screen Inline TUI
- 目标 renderer：`tui`
- 实施状态：代码与自动化验收已完成；真实 macOS Terminal 截图和选择/复制待人工确认
- 文档属性：本地开发指导，不进入 commit、push 或 PR
- 约束：不得回退 shell 原生 scrollback，不修改 agent runtime、session、permission 或 tool 执行语义

## 背景与问题

当前 TUI 已具备 styled cell、ANSI writer、Markdown AST、rich-text layout、ANSI sanitizer、typed tool activity、
transcript cache 和 InlineTerminalSurface，但最终用户仍看到接近纯文本的界面：

1. Assistant Markdown 标记没有转换为终端视觉结构，标题、粗体、列表、表格和代码块仍显示原始符号。
2. 工具调用与 Assistant 正文使用同一套默认样式，运行、成功、失败和元信息缺少视觉层级。
3. 用户输入只有 `› ` 前缀，没有背景带，长会话中难以快速识别提问边界。
4. live transcript 和 committed scrollback 使用两套纯文本 layout，后续即使只修一处，也会产生样式或换行不一致。

问题不在底层 terminal encoder，而在 transcript 进入 frame 前仍被降级为 `string[]`：

- `src/tui-ui/layout.ts` 的 `formatTranscriptEntry()` 只拼 prefix、split newline 和 wrap。
- `src/tui-ui/runner.ts` 的 `layoutTranscriptEntry()` 再次实现相同的纯文本排版。
- `src/runtime/rich-text/markdown-parser.ts` 和 `layout.ts` 已完成，但没有接入 TUI。
- `src/runtime/rich-text/ansi-parser.ts` 已完成，但工具 transcript 没有消费其 StyledSpan 输出。
- `src/tui-core/style.ts` 已支持 foreground、background、bold、dim、italic 和 underline，但 role theme 未进入 transcript。

## 版本目标

v0.2.22 必须交付：

- Assistant Markdown 的结构化终端渲染。
- 用户消息的多行、宽字符安全背景带。
- 工具运行、成功、失败、跳过和输出元信息的视觉分层。
- live frame 与 committed shell scrollback 使用同一份 StyledRow layout。
- `NO_COLOR` 下仍保留可辨识的 prefix、缩进和文本层级。
- resize、CJK、emoji、流式更新、恢复会话和 native scrollback 不回归。

## 非目标

- 不实现 alternate screen 或 renderer-owned scrollback。
- 不实现 Markdown HTML、图片预览或终端超链接自动打开。
- 不重写 Markdown parser，不引入新的 Markdown 依赖。
- 不把工具状态从正文字符串反向解析出来；状态必须来自 `toolActivity`。
- 不让模型或工具原始 ANSI 直接进入 frame。
- 不在本版本增加 pane、card、mouse navigation 或 transcript collapse。
- 不改 `terminal` renderer 的产品行为。

## 产品视觉规范

### 用户消息

- marker 使用 `› `，采用 accent foreground 和 bold。
- 消息正文按 literal text 渲染，不解析 Markdown，避免用户输入被改写。
- 每个 visual row 使用完整背景带，背景填充到当前 transcript 内容宽度。
- 多行 continuation 与正文左边界对齐，不重复 marker。
- 背景必须按 terminal cell width 填充，CJK、emoji 和组合字符不能造成少一列或越界。
- `NO_COLOR` 时移除背景，但保留 marker、bold 和 continuation indent。

建议默认 dark theme：

- user marker：cyan / bold。
- user text：white。
- user background：低对比度 neutral dark，不使用高饱和蓝色或紫色。

### Assistant Markdown

- paragraph：终端默认前景色，无背景。
- heading：cyan、bold；所有 heading level 保持终端正文尺寸，只用颜色和粗体区分。
- strong/emphasis：bold / italic。
- inline code：浅色 foreground + neutral dark background。
- fenced code：独立 neutral background，保留缩进和换行；可显示 dim language label。
- list：保留 ordered/unordered marker，continuation 对齐正文。
- quote：使用 muted `> ` 或竖线语义，不使用卡片。
- table：宽度足够时使用列布局；窄宽度自动降级为 key/value。
- diff：added green、removed red、hunk cyan、context muted。
- link：显示 label，使用 cyan + underline；不自动访问 URL。
- rule：使用 dim horizontal rule，不占用额外 frame 区域。

### 工具消息

工具消息优先读取 `TranscriptEntry.toolActivity`：

- running：yellow marker/name。
- success：green marker，工具名使用 accent，duration 和 output bytes 使用 muted。
- error：red marker/error，工具名保持可读。
- skipped：dim marker 和正文。
- command：`$` marker 使用 cyan，命令正文使用 neutral foreground。
- artifact hint、output size 和 duration：dim。
- 工具 stdout/stderr 若包含 ANSI，只允许通过 `parseAnsiToStyledSpans()` 保留安全 SGR 样式。
- cursor movement、erase、OSC、alternate screen 等控制序列必须被丢弃。

失败的工具 transcript 可能使用 `role: error`，但 `title === 'tool'` 或存在 `toolActivity` 时仍应走 tool presenter，
不能退化成普通 runtime error 样式。

### 其他角色

- `system`：dim neutral。
- `command`：cyan prefix，正文 neutral。
- `status`：dim neutral；warning 状态为 yellow。
- `error`：red marker 和正文，必要时显示 error layer。
- `assistant`：默认正文色，避免大面积着色影响阅读。

## 目标架构

```text
AgentRuntimeController / UiEventSink
  -> TuiUiReducer
     -> TuiTranscriptRecord { role, content, toolActivity, revision, finalized }
        -> layoutTranscriptEntry(record, context)
           -> userPresenter()       -> StyledRow[]
           -> assistantPresenter()  -> parseRichText() -> layoutRichText()
           -> toolPresenter()       -> typed activity + ANSI-safe spans
           -> errorPresenter()      -> StyledRow[]
           -> systemPresenter()     -> StyledRow[]
        -> TranscriptLayoutCache
           -> live path: writeStyledRowsToFrame()
           -> commit path: InlineTerminalSurface.commit()
              -> primary screen / shell native scrollback
```

关键约束：

- `layoutTranscriptEntry()` 是 transcript visual rows 的唯一事实来源。
- live 和 commit 只能选择不同的 rows 范围，不能各自实现 role formatting。
- runtime 继续只提供结构化事件和 transcript 数据，不依赖 TUI theme。
- layout 输出不能包含原始 ANSI；ANSI 只能由 terminal encoder 生成。
- finalized entry 只提交一次，样式增强不能改变 append-only 语义。

## 详细技术设计

### 1. 新增共享 Transcript Layout

新增：

```text
src/tui-ui/transcript-layout.ts
```

建议接口：

```typescript
export interface TranscriptLayoutContext {
  width: number;
  revision: number;
  finalized: boolean;
  theme: TuiTheme;
}

export function layoutTranscriptEntry(
  entry: TranscriptEntry,
  context: TranscriptLayoutContext,
): StyledRow[];
```

内部只按 role/title/toolActivity 分派 presenter，不读取全局 state，不写 stdout，不产生 ANSI。

需要同时提供：

```typescript
export function writeStyledRowToFrame(
  frame: TuiFrame,
  row: number,
  spans: StyledRow,
): void;
```

该函数按 span 顺序调用 `writeFrameText()`，使用 cell width 推进 column，禁止按 JavaScript string length 推进。

### 2. 保留 Renderer-local Revision

当前 `TuiTranscriptRecord` 已包含 `revision`，但 selectors 会在进入 runner layout 前 strip 掉该字段，runner cache 只能使用
`entry.content.length` 作为近似 identity。这不能可靠识别相同长度的内容替换，也不包含 role、toolActivity 或 theme 变化。

调整 `src/tui-ui/state.ts`：

- 增加 `staticTuiTranscriptRecords()`。
- 增加 `liveTuiTranscriptRecords()`。
- 增加 `pendingCommitRecords()`。
- 仅在导出 runtime/session contract 时调用 `stripRecord()`。

cache key 必须包含：

```text
entry.id + revision + width + themeId
```

generation 变化、resize 或 theme 变化时整体失效。

### 3. Assistant Markdown 接入

Assistant presenter：

```typescript
const document = parseRichText(entry.content);
return layoutRichText(document, {
  width: contentWidth,
  theme: resolveRichTextTheme(theme),
  indent: assistantIndent,
});
```

约束：

- 继续复用 `marked.lexer()`，不得调用 HTML renderer。
- 继续执行现有 sanitizer 和资源上限。
- streaming assistant 每次 revision 允许重新解析，但受现有 render scheduler 合并，不能绕过 30 FPS 限制。
- streaming 内容只存在于 live region；finalize 后使用最终 revision 重新 layout，再提交一次 scrollback。
- 不完整 Markdown 必须 deterministic degrade，不得抛异常或清屏。

需要补齐 rich-text layout：

- `RichTextStyleToken` 增加 `inlineCode` 和 `link`。
- inline code 不再只映射为 dim，应使用独立背景样式。
- code block 每行补齐背景到 content width，避免只有文字部分着色。
- code language label 必须是可选 visual metadata，不写回 transcript content。

### 4. 用户消息背景带

用户 presenter 按 literal lines 进行 grapheme/cell wrap，然后：

1. 第一行写入 styled `› ` marker。
2. continuation 写入相同宽度的空 indent。
3. 内容 span 使用 user text style。
4. 行尾补充 padding span，使总 visual width 等于 transcript width。
5. marker、content 和 padding 都包含 user background。

禁止使用 `padEnd()` 处理 CJK；必须使用 `string-width` 或现有 grapheme/cell helper 计算剩余宽度。

### 5. 工具 Presenter

工具 presenter 判断顺序：

```text
entry.toolActivity exists OR entry.title === "tool"
  -> tool presenter
else entry.role === "error"
  -> normal error presenter
```

tool header 从 `toolActivity` 生成，禁止从 content 推断 success/error：

```text
✓ read_file  src/index.ts  12ms
  output 2.0 KB  artifact tool-1
```

如果现有 content 已包含 header，第一阶段允许把 content 作为 body 进行 role styling；第二阶段应扩充
`StructuredToolActivity`，使 command、outputBytes、artifactRef、summary 等字段直接进入 TUI，逐步消除重复 header。

工具 ANSI 路径：

```text
raw body
  -> parseAnsiToStyledSpans()
  -> split/wrap styled spans by cell width
  -> merge semantic base style only when span has no explicit safe SGR style
```

### 6. Theme 设计

新增：

```text
src/tui-ui/theme.ts
```

扩展 `TuiTheme` semantic tokens：

```text
userMarker
userMessage
assistantText
heading
inlineCode
code
link
toolRunning
toolSuccess
toolError
toolSkipped
toolName
toolMetadata
systemText
commandText
warning
error
muted
```

layout 只索取 semantic token，不包含具体色值。默认先交付 dark theme；`NO_COLOR` 继续由 encoder 层统一抑制颜色和背景。
light theme 可以作为 P1，但 token contract 必须在 P0 定型，避免再次改 presenter。

### 7. Live 与 Commit 路径统一

修改 `src/tui-ui/layout.ts`：

- 删除 `formatTranscriptEntry()` 和纯字符串 role prefix 实现。
- measure、full frame、live frame 全部使用共享 `layoutTranscriptEntry()`。
- frame 写入逐 span 保留 style。

修改 `src/tui-ui/runner.ts`：

- 删除私有纯文本 `layoutTranscriptEntry()`。
- commit batch 直接使用共享 StyledRow 输出。
- 使用 record revision 访问 TranscriptLayoutCache。
- live 与 commit 传入相同 width 和 themeId。

修改 `src/tui-ui/inline-surface.ts`：

- 保持现有 commit protocol 和 append-only 顺序。
- 每行结束继续发送 `SGR_RESET`，防止用户背景或工具颜色泄漏到下一行和 shell prompt。
- 不修改 autowrap、cursor ownership 和 live region release 语义。

## 风险与控制

### Markdown streaming 重排

风险：未闭合 code fence 或 table 在 streaming 中导致 visual rows 变化。

控制：只重绘 live region；finalize 后重新 layout 并只 commit 最终版本。不得把 streaming 中间版本写入 scrollback。

### 背景色泄漏

风险：用户背景延续到下一条消息或 shell prompt。

控制：每个 committed row 结尾强制 `SGR_RESET`；surface unmount/restore 再执行全局 reset。

### Rich layout 性能

风险：每个 token chunk 都重复 parse 大段 Markdown。

控制：scheduler coalescing、revision cache、finalized cache 和输入资源上限；禁止在 frame diff 阶段重新 parse。

### live/commit 不一致

风险：两个路径使用不同 width、prefix 或 theme。

控制：共享 `layoutTranscriptEntry()`；增加 live/commit StyledRow 深度相等测试。

### 工具 ANSI 污染

风险：外部命令借 ANSI 控制 cursor、erase 或 alternate screen。

控制：只接受 ANSI parser 明确支持的 SGR，其他 escape sequence 全部丢弃。

## 2026-07-18 Terminal 窗口切换输入框残影修复

### 现场问题

真实 macOS Terminal 157x50 截图显示：窗口切换或尺寸变化后，当前 prompt frame 正常，但其下方累积多条
不同宽度的旧 `└───┘` 底边。该问题说明 logical live row 跟踪与终端 resize 后的 physical row 已经失配，
原“按 `cursorRow + liveRegionCapacity` 清理”的实现不能满足 resize recovery。

### 根因

1. `SIGWINCH` 到 100ms debounce 结束之间，scheduler 仍可能按旧 width 输出 live frame。
2. terminal 已按新列宽回流旧 frame 时，一个 logical row 可能占多个 physical rows；旧算法少清理了底部行。
3. commit 在 debounce 窗口内仍可能按旧 width layout，且关闭 autowrap 后写入会截断 durable history。
4. rapid resize 与 output backpressure 交错时，较早 resize 可能错误清除较新的 pending 状态。
5. frame 默认空白 cell 被完整输出，放大了横向回流的 physical row 数。

### 技术修复

- `launch.ts` 收到 resize 事件后立即调用 `runner.beginResize(newWidth)`，debounce 只延迟最终 layout/repaint。
- `runner.ts` 在 pending 期间暂停 live paint 和新 commit；最终 resize 完成后按最终 width 重新 layout 并提交。
- `inline-surface.ts` 为 resize 增加 generation；只有最新 generation 可以完成 repaint、清除 pending 并唤醒
  等待中的 commit。
- resize 清理根据 previous frame 每行在新 width 下的 physical row height 计算 cursor offset 和清理范围，
  不再假设一行 frame 等于一行 terminal。
- live frame 生产宽度固定为 `terminalWidth - 1`；默认样式行尾空格不写入 terminal，避免制造无意义的
  full-width reflow 候选。带背景的用户行和 prompt 边框仍保留完整样式宽度。
- committed transcript 使用 shell 原生 autowrap；已进入队列的旧宽度 batch 在突然缩窄时仍保留完整内容。
- PTY session fixture 与当前 hashed project key 规则保持一致，避免 `/resume` 验证误用当前会话。

### 新增回归矩阵

- 40x14 -> 20x14：旧 full-width live frame 回流后不残留旧底边，history 保留。
- 低历史区 40x14 -> 20x14：先消耗 viewport 尾部空白，不把 status/prompt 推入 native scrollback。
- resize pending：拒绝旧 width live paint。
- backpressure + 连续 30 -> 20 resize：旧 generation 不得覆盖最终 frame 或清除新 pending。
- resize 窗口内 finalize：commit 必须延迟并按最终 width layout。
- resize 前已排队 commit：autowrap 后完整内容不得被截断。

### Primary-screen 极端 resize 边界

以下情况不能宣称由 v0.2.22 完全解决：最大高度、多行、非空 live region 在 terminal 处理 resize 的瞬间，从宽窗口
一次缩到最小 24x8。terminal 可能在应用收到 `SIGWINCH` 之前把顶部 live physical rows 推入 native scrollback；
进入 scrollback 后，`CUU/CUD/EL2` 无法访问，除非使用被本计划禁止的 scrollback clear、全屏重绘或 alternate screen。

v0.2.22 的控制措施是：生产宽度保留最后一列、停止 debounce 窗口旧 frame、裁掉默认行尾空格、按 physical rows
清理、限制 live 内容为 tail、并用真实 Terminal 验收日常窗口切换。若真实终端仍能在 active streaming 场景复现
scrollback 污染，后续版本必须改为“append-only transcript + 单行/小高度 composer”，不再维护可增长的多行 primary-screen
live transcript；不得用 `CSI 2J/3J` 掩盖问题。
