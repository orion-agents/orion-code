# v0.2.18 Transcript 与工具详情收束计划

## 背景

`package.json` 当前版本为 `0.2.17`。v0.2.17 已把 Ink beta 的基础组件、resize、bracketed paste、runtime parity 和 PTY smoke 推到可持续验证状态；`docs/exp/runs/v0.2.17-real-usage-test-2026-07-10.md` 记录的自动化与 PTY 基线为绿。

基于 `docs/targets` 的最终目标，v0.2.18 不应继续做泛化 UI 美化，也不应把 Ink 设为默认 UI。更合适的下一个版本目标是进入 `ui-ultimate-experience.md` 的第二阶段：结构化 transcript、工具详情、artifact/trace 入口和 resume 可审计性。这个方向同时补齐 `agent-loop-final-form.md` 对工具顺序、权限、artifact、verification 可审计的要求。

## 调研结论

- `src/runtime/ui-view-model.ts` 已有 `TranscriptBlock`、`ToolActivity`、`PromptState`、`PickerState`、`StatusSnapshot` 等基础结构，v0.2.18 不需要从零设计 View Model。
- `/trace`、`/last-tool`、`/artifacts` 已在 `src/commands/index.ts` 落地，并有 `tests/status-command.test.ts` 覆盖，下一步应做可发现性、按序号/调用 id 追溯和跨 renderer 展示一致性。
- `RuntimeToolStartedEvent` / `RuntimeToolFinishedEvent` 目前包含 `callId`、batch 信息和 artifact 引用，但没有稳定的用户可见序号；Ink 的 `ToolActivity` 组件仍通过解析 transcript 文本推断状态，结构化协议没有完整贯通。
- `docs/targets/ui-runtime-boundary.md` 明确要求 renderer 不能反推 agent 语义；因此 v0.2.18 的 P0 应把工具活动和 transcript detail 从字符串约定推进到 runtime-owned 数据模型。
- v0.2.17 的剩余 beta 风险主要是 native cursor 与中文 IME 的真实终端表现。它适合作为 P1 验证和保守 fallback，不应拖住 P0 的结构化收束。

## 版本主题

v0.2.18 = **结构化 transcript / 工具详情 / resume 诊断收束版**。

目标是让 terminal 稳定 UI、Ink beta、TUI beta 在已暴露能力上消费同一套 runtime 语义：工具调用顺序一致、长参数和长输出可追溯、resume/compact 标记清楚、错误层级和权限结果不会被 renderer 文本解析破坏。

## P0 开发范围

### 1. 工具活动协议结构化

要做：

- 在 runtime 工具事件里增加稳定的 `sequence` 或 `order` 字段，覆盖 `tool_started`、`tool_finished`、trace `tool_call`、trace `tool_result`。
- 让 `ToolActivity` 直接承载 `sequence`、`callId`、`argsSummary`、`argsArtifactId`、`artifactRef`、`outputBytes`、`durationMs`、`error`、`skipped`。
- `createToolEventPresenter` 负责生成同一套结构化工具活动；terminal、Ink、TUI 只渲染结构，不再各自猜测顺序。
- 保留当前 transcript 文本作为兼容输出，但 renderer 侧不能依赖解析文本才能得到状态。

验收：

- batched tool、skipped tool、failed tool、artifact tool 都显示稳定 `#N`。
- `/trace latest`、`/last-tool`、transcript 工具行中的 call order 一致。
- 增加 runtime parity 测试，证明 terminal/ink adapters 收到的 structured tool event 一致。

### 2. TranscriptBlock 与错误/恢复元数据补齐

要做：

- 扩展 `TranscriptBlock` 映射，保留 `kind`、`role`、`title`、`errorLayer`、`sourceTurnId`、`toolCallId`、`restored` 等 renderer 需要但不应自行推断的信息。
- resume 标记、restored messages、system/status/error 不伪装成 assistant 回复。
- aborted assistant partial 继续保持不可作为 completed assistant message 持久化。
- Ink `Transcript` 优先消费 `TranscriptBlock` / structured activity，逐步移除对 tool transcript 文本格式的硬解析依赖。

验收：

- `/resume` 后 terminal 和 Ink 都能展示恢复标记、恢复条数、session summary。
- error block 都带 layer：renderer/runtime/provider/tool/session/memory/MCP/skills。
- overlay、picker、help、paste marker 不进入 durable transcript。

### 3. 工具详情与 artifact 可发现性

要做：

- 扩展 `/last-tool`：支持 `latest`、`#N`、`callId` 或短前缀定位，不只限最后一次工具调用。
- 增加最近工具列表视图，显示序号、工具名、状态、耗时、artifact、turn id。
- `/last-tool --full` 与 `/artifacts show <id> --full` 继续统一走 redaction，不能泄漏 bearer token、API key、authorization header。
- transcript 中当命令、参数或输出被截断时，统一提示 `/last-tool #N`、`/trace latest`、`/artifacts show ... --full`。

验收：

- 失败工具、无 matching call 的 result-only trace、长 args artifact、长 output artifact 都可被定位。
- `tests/status-command.test.ts` 覆盖 latest、按序号、按 callId、redaction、ambiguous ref。

### 4. Resume / Compact 诊断一致性

要做：

- 将 `createSessionRestoredView` 的输出接入 terminal、Ink、TUI 已暴露的 resume 路径。
- resume 时显示 session id、project、model、restored count、message count、summary；如果 project/model/config 与当前上下文不一致，显示风险而不是静默恢复。
- compact/resume 后输入“继续”仍锚定 root objective 和 active instruction；已有 harness/compact 测试要纳入 v0.2.18 必跑门禁。

验收：

- session picker 选择、直接 `/resume <id>`、最近 session 恢复在可见 transcript 和 runtime session state 上一致。
- 增加或更新 `tests/session-commands.test.ts`、`tests/runtime-ui-parity.test.ts`、`tests/ink-ui.test.ts` 覆盖 restored view。

### 5. 发布前真实使用记录

要做：

- 新增 `docs/exp/runs/v0.2.18-real-usage-test-YYYY-MM-DD.md`。
- 记录 terminal 默认 UI 与 Ink beta UI 的真实终端验证，不只记录 mock/PTY。
- 至少覆盖中文输入、长工具输出、失败命令、权限 allow/deny、`/trace`、`/last-tool #N`、`/artifacts show`、`/resume`。

验收：

- 自动化基线全绿。
- 有一份真实终端记录，明确说明失败项、已知 beta gap 或 release blocker。

## P1 开发范围

- Native cursor / 中文 IME：在 macOS Terminal 和 iTerm2 抽样验证候选词位置；如果偏移明显，给 Ink 增加保守 cursor fallback 或 beta known gap，而不是修改 runtime。
- TUI beta parity：仅覆盖 TUI 已暴露能力的 command input、permission decision、session picker、tool ordering；不把 TUI 作为默认 UI。
- `/status` 与 `/doctor` 诊断打磨：展示 renderer stable/beta、capability labels、artifact/checkpoint 存储状态、当前 session trace 可用性。

## P2 / 暂缓

- Print mode JSON、remote UI、subagent runtime、插件生态不进入 v0.2.18 主线。
- 不做 Rust/native TUI rewrite。
- 不重写 agent loop、tool schema、harness prompt 组装。
- 不为了 Ink 展示问题修改 terminal 默认行为或 runtime 语义。

## 建议实施顺序

1. 先补测试：用 failing tests 锁住 tool sequence、structured activity、`/last-tool #N`、resume restored view。
2. 扩展 runtime event 类型和 `createToolEventPresenter`。
3. 更新 `ui-view-model.ts` 的 `ToolActivity` / `TranscriptBlock` 映射。
4. 更新 terminal、Ink、TUI adapters，只消费结构化数据或统一 view model helper。
5. 扩展 `/last-tool` 与 artifact/trace 交叉引用。
6. 跑自动化基线，补 v0.2.18 真实使用记录。

### 必须补的 P0 优化项

1. **补齐所有测试事件的 `sequence` 字段**
   - 对所有手写 `RuntimeToolStartedEvent` / `RuntimeToolFinishedEvent` fixtures 增加稳定 `sequence`。
   - 起始事件和完成事件必须使用同一序号。
   - 同一测试内多工具调用应使用 `1, 2, 3...`，不要重复。

2. **抽一个测试 helper，避免后续漏字段**
   - 建议新增局部 helper 或共享 helper：
     - `makeToolStartedEvent(overrides)`
     - `makeToolFinishedEvent(overrides)`
   - helper 默认填入 `sequence: 1`，测试需要多工具顺序时显式覆盖。
   - 覆盖 `agent-runtime-controller`、print、TUI state、TUI runner 这些跨 renderer 测试。

3. **把 print/TUI 纳入 v0.2.18 sequence parity**
   - 当前切片测试覆盖了 terminal/Ink，但全量 suite 暴露 print/TUI fixtures 未同步。
   - 增加或调整断言，明确 print/TUI beta/non-interactive renderer 也能接收 `sequence`，即使它们不展示完整工具详情。

4. **重新跑全量发布门禁**

