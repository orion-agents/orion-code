# v0.2.12 Runtime Reliability Plan

## Summary

v0.2.12 should be a reliability iteration on top of the v0.2.11 stable
terminal baseline. The goal is to make OpenHorse behave predictably in real
coding sessions when providers return confusing errors, tools produce long
outputs, skills are loaded from multiple locations, and the user depends on
terminal scrollback as the primary interface.

This release should not introduce a new UI architecture. `terminal` remains the
stable product UI; Ink/TUI remain beta renderers. The version focus is runtime
quality: model/provider diagnostics, request efficiency, tool observability,
skills loading hygiene, and release-grade regression coverage.

## Current Execution Scope

This pass completes the highest-risk runtime reliability fixes: provider error
diagnostics, provider config redaction, terminal tool-event observability, and
skills duplicate diagnostics. Agent-loop counters and resume-time consistency
checks remain planned follow-up items unless explicitly pulled into this branch
before release.

## Product Goals

- Detect model/provider misconfiguration before a user wastes a turn on a
  generic `404 status code` or provider-specific opaque error.
- Reduce avoidable LLM calls and prompt noise while preserving the existing
  agent loop semantics.
- Make terminal tool output auditable: full command is available, ordered tool
  events remain readable, and long output does not collapse useful context.
- Make skills loading deterministic, quiet, and diagnosable across builtin,
  user, configured, and project scopes.
- Keep session, harness, tools, MCP, skills, and permissions runtime-owned, in
  line with `docs/targets/ui-runtime-boundary.md`.

## Workstreams

### 1. Provider Configuration & Health Diagnostics

- Add a provider/model validation path used by `openhorse doctor` and startup
  diagnostics.
- Normalize provider errors into clear classes:
  - `model_not_found`
  - `invalid_endpoint`
  - `auth_failed`
  - `quota_or_credit_exhausted`
  - `rate_limit`
  - `provider_busy`
  - `unknown_provider_error`
- Surface actionable messages for common failures, especially 404 model errors,
  Xunfei `NotEnoughCvError`, provider busy responses, and missing API keys.
- Record model metadata from `model-context.ts` as advisory data only; never let
  stale metadata hide a live provider error.
- Add tests proving provider errors do not crash the CLI and do not trigger
  useless retry loops for non-retryable failures.

### 2. Agent Loop Efficiency & Prompt Noise Control

- Introduce a small request-efficiency layer around the existing loop:
  - batch safe read-only tool calls when the model already requested multiple
    independent reads/searches;
  - keep write/edit/git/publish commands sequential and explicit;
  - avoid injecting duplicate tool-failure text into the next user-facing prompt;
  - cap model-facing command/output summaries while keeping full details
    available in UI/session artifacts.
- Add runtime counters for one turn:
  - LLM requests;
  - tool calls;
  - retry count;
  - fallback model use;
  - compact trigger reason.
- Expose these counters in a lightweight diagnostic command or existing status
  output without leaking secrets or full transcripts.

### 3. Terminal Tool Output & Scrollback UX

- Improve terminal utilization for wide screens:
  - use the available terminal width for assistant text, tool summaries, and
    markdown tables;
  - avoid over-narrow content blocks unless the content is inherently short;
  - keep prompt compact but readable.
- Tool display rules:
  - always preserve tool event order;
  - show full command text in scrollback, wrapping instead of truncating;
  - show output byte/line counts and a clear path to the saved artifact when
    output is summarized;
  - keep error blocks visually distinct and actionable.
- Add regression tests for command wrapping, long tool output summaries, and
  chronological rendering.

### 4. Skills Loading Reliability

- Treat skills as a first-class runtime capability:
  - builtin skills;
  - `~/.openhorse/skills`;
  - configured `skills.paths`;
  - project `.openhorse/skills`.
- Add duplicate-name diagnostics that explain which scope wins.
- Add validation warnings for malformed frontmatter that identify the file and
  reason without printing noisy raw paths into normal startup output.
- Ensure Markdown-link locators and directory-vs-file confusion never surface as
  tool read errors.
- Keep `SKILL.md` content lazy-loaded unless the skill is selected or triggered.

### 5. Session/Harness Continuity Checks

- Add a resume-time consistency check:
  - session transcript exists;
  - harness sidecar exists or can be rebuilt;
  - model/provider info is advisory and not trusted as current config;
  - compacted sessions preserve root objective and next action.
- Extend `/harness explain` or status diagnostics to show whether the current
  turn is continuing, verifying, replacing, or configuring the task.
- Keep short feedback such as `继续`, `不对`, and `再检查` from overwriting the
  root objective.

## Public Interfaces

- `openhorse doctor` should include provider, skills, storage, and runtime
  readiness checks.
- Config keeps the existing shape, with no breaking migration:
  - `provider`
  - `model`
  - `fallbackModel`
  - `skills.paths`
  - permission and MCP settings as-is.
- Optional new diagnostics may be added as slash commands only if they reuse the
  runtime event protocol and do not fork UI behavior.

## Out of Scope

- Making Ink or TUI the default renderer.
- Rewriting the agent loop into a local planner.
- Parallelizing unsafe write/edit/git/publish operations.
- Session JSON schema migration.
- Remote UI, daemon mode, or print-mode expansion.
- New provider integrations unrelated to reliability of existing config paths.

## Team Execution

- Main agent: owns scope control, integration, final validation, and release
  readiness.
- Plan agent: reviews this plan against `docs/targets/` and flags drift from
  terminal-first runtime reliability.
- Coding agent: implements scoped runtime, provider, skills, terminal, and test
  changes.
- Review agent: checks provider error handling, tool ordering, prompt-noise
  regressions, session compatibility, and test coverage.

## Test Plan

- Provider diagnostics:
  - 404 model error classification;
  - invalid endpoint;
  - missing API key;
  - quota/credit no-retry;
  - rate-limit retry/fallback.
- Agent loop:
  - safe read-only batching preserves tool result order;
  - unsafe commands remain sequential;
  - failed tool result does not create duplicate user prompt noise;
  - runtime counters are accurate.
- Terminal UI:
  - full command wrapping;
  - long output summary plus artifact pointer;
  - wide terminal markdown/table rendering;
  - ordered tool events in scrollback.
- Skills:
  - builtin/user/configured/project load order;
  - duplicate-name diagnostics;
  - malformed frontmatter warning format;
  - Markdown link locator normalization.
- Session/harness:
  - resume with missing sidecar rebuilds safely;
  - compacted session preserves root objective;
  - short feedback does not replace task contract.
- Release gate:
  - `npm run build`
  - `npm test -- --runInBand`

## Acceptance Criteria

- A wrong model or endpoint produces a clear diagnostic before or during the
  first turn, not a raw opaque error.
- Frequent provider throttling does not cause tight retry loops or immediate
  CLI exit.
- Terminal output uses practical screen width and preserves full command text.
- Tool summaries reduce model-facing noise while keeping human-auditable detail.
- Skills load by default from configured paths without startup warning noise.
- Resume/compact continues the correct user objective after long sessions.
- All changes are covered by focused tests plus the full build/test gate.
