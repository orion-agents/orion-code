# v0.2.9 Runtime/UI Boundary Report

## Summary

v0.2.9 aligns OpenHorse with the target in `docs/targets/`: the stable
`terminal` renderer is the primary product UI, `ink` and `tui` are explicit beta
renderers, and print/remote UI remain future renderer targets. The existing
print path is treated as an early experimental non-interactive protocol check,
not as a completed automation or remote UI surface. The key direction is "one
agent brain, many UI shells": runtime semantics must stay below the UI layer,
while renderers only adapt local input, layout, cursor, overlay, and transcript
presentation.

## Completed Changes

- Normalized renderer selection around `terminal`, `tui`, and `ink`.
  `legacy` and `v2` remain accepted CLI aliases but are not persisted renderer
  values.
- Moved shared runtime context naming to `OpenHorseUiRuntime`; the old
  `OpenHorseInkRuntime` name remains only as a deprecated compatibility alias.
- Added runtime-level UI protocol events for ordered tool lifecycle updates:
  `tool_started` and `tool_finished`.
- Added `UiRendererCapabilities` and `resolveUiRendererCapabilities()` so slash
  commands consume renderer capabilities instead of branching on concrete
  renderer names. Missing renderer metadata resolves to the stable `terminal`
  capability profile; compatibility-only `legacy` / `v2` values also resolve to
  terminal-like interactive capabilities; explicit `print` remains
  non-interactive.
- Added `AgentChatControllerOptions.uiCapabilities` so renderer adapters can
  explicitly declare presentation capabilities before commands execute.
- Added top-level `AgentRuntimeControllerOptions.uiCapabilities` so renderer
  adapters declare presentation capabilities at the runtime boundary, without
  reaching into chat-controller internals. `chatOptions.uiCapabilities` remains
  compatible and can still override when needed.
- Updated terminal, Ink beta, TUI beta, and print launcher paths to pass their
  capability profile explicitly when constructing `AgentRuntimeController`.
  Controller defaults now reuse the shared `resolveUiRendererCapabilities()`
  helper instead of carrying a second hard-coded interactive profile.
- Removed the command-layer fallback to `ctx.config.ui.renderer` when resolving
  command UI behavior. Slash command business logic now consumes
  `CommandContext.uiCapabilities` only, with the shared resolver providing the
  stable terminal default when no adapter profile is supplied.
- Removed the chat-controller fallback to `runtime.config.ui.renderer` when
  constructing `CommandContext`. Renderer names are now centralized in
  `resolveUiRendererCapabilities()` and launcher-provided capability profiles;
  command/chat execution no longer branches on concrete renderer names.
- Added runtime controller tests proving `/resume` follows adapter capability
  declarations: structured picker when supported, textual fallback when not.
- Reused runtime event request types for structured command output:
  `SessionPickerRequest` and `EditPreviewRequest`.
- Moved shared terminal UI helpers out of `ui-v2` into `src/ui/shared/`.
  Terminal command/file completion now depends on shared helpers, while `ui-v2`
  re-exports compatibility APIs.
- Added a shared `formatBytes()` helper and removed duplicate local
  implementations from UI/storage paths.
- Updated the early experimental print path JSON output to retain structured
  tool events without polluting assistant content.
- Tightened the early experimental print path permission handling around the shared
  `ToolPermissionRequest` type and added coverage that non-interactive
  permission requests become deterministic, auditable errors.
- Explicitly routes the early experimental print path through non-interactive
  `UiRendererCapabilities`, so slash commands use deterministic text fallbacks
  instead of assuming picker/dialog support.
- Added protocol-level renderer parity tests. The same runtime inputs now run
  through both the legacy `UiEventSink` adapter path and the structured
  `AgentRuntimeEventSink` path, proving identical live revision, permission
  decision, and session picker selection semantics.
- Exported the stable terminal renderer sink for focused adapter testing and
  added smoke coverage for session picker selection, append-only tool output
  ordering, and scrollback-preserving clear behavior.
- Added TUI beta runner smoke coverage proving visible tool transcript output
  and structured runtime tool events preserve the same chronological order.
- Verified existing Ink beta PTY smoke coverage for CJK input, streaming edits,
  tool ordering, slash palette behavior, and native cursor anchoring. Ink also
  has unit coverage for tool activity parsing, stream/tool transcript ordering,
  resumed tool rows, and cursor/prompt layout helpers.
- Verified existing print smoke coverage for text, JSON, piped stdin, and
  deterministic non-interactive permission denial. This is evidence for the
  shared runtime protocol, not a claim that print/remote UI is product-complete.
- Added print regression coverage that `/resume` in JSON print mode uses the
  non-interactive fallback text and does not request a live session picker.
- Increased slow CLI/PTY smoke-test timeouts to tolerate `ts-node` cold starts
  during full serial release gates. This stabilizes terminal, Ink beta, TUI
  beta, print, doctor, diff, and commit-plan smoke checks without changing
  runtime behavior.
- Verified that production source paths no longer import `src/ui-v2`; the
  remaining `ui-v2` files act as compatibility exports/tests over shared
  terminal helpers.
- Restored the lint toolchain by adding the missing TypeScript ESLint
  dependencies and correcting the ESLint recommended config name. `npm run lint`
  now exits successfully; existing type/unused/prefer-const debt remains as
  warnings for a later cleanup.
- Made `docs/targets/` trackable so target documents are part of the repository
  state instead of ignored local notes.

## Remaining Work

- Ink beta still displays tool activity through transcript rows and
  `createToolEventPresenter`; it does not yet retain a separate
  `runtimeToolEvents` state like TUI. That is acceptable for beta in v0.2.9, but
  should be considered if Ink becomes a serious product renderer again.
- Lint now runs, but the existing codebase has a warning backlog
  (`any`, unused symbols, `prefer-const`, and a few ban-type/ts-comment cases).
  Keep these as follow-up cleanup rather than blocking the runtime/UI boundary
  release.
- Production dependency audit has no high-severity findings at the configured
  gate. The remaining `uuid` moderate advisory needs a deliberate dependency
  upgrade plan because the automatic fix is breaking.
- Add more golden-frame tests for exact Ink/TUI visual rendering over time. PTY,
  cursor, CJK input, resize, prompt wrapping, tool ordering, and transcript
  behavior are covered, but not every visual permutation has a golden snapshot.
- Remove the `ui-v2` compatibility package in a later breaking cleanup after
  downstream imports have had time to migrate to `src/ui/shared`.
- Expand print/remote UI support only in later iterations and only through the
  runtime event protocol, not through renderer-local copies of
  command/session/permission semantics.

## Release Notes Draft

v0.2.9 focuses on runtime/UI boundary cleanup. It keeps terminal as the stable
default UI, treats Ink/TUI as beta renderers, treats print as an early
experimental non-interactive path for future automation work, centralizes
renderer capability metadata, and makes tool, picker, permission, and runtime
context structures less renderer-specific. This should reduce UI regressions
from changing agent semantics and make future renderer experiments safer.
