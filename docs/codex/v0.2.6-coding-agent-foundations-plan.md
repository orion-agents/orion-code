## 工作内容

### P0: Tool Result 结构化

**目标**: 工具结果不再只是 raw string，而是结构化记录，包含完整输出和摘要，harness evidence 直接使用摘要。

**文件**: `src/framework/tool.ts`, `src/framework/query.ts`, `src/tools/index.ts`, `src/harness/evidence.ts`

**变更**:
1. `ToolResult` 扩展为:
   ```typescript
   interface ToolResult {
     success: boolean;
     output: string;           // 完整输出（用于 UI 展示）
     error?: string;
     summary?: string;         // 紧凑摘要（用于 harness evidence）
     outputBytes: number;      // 输出字节数
     metadata?: Record<string, unknown>;
   }
   ```
2. `query()` 中 `tool_result` event 携带 `summary` 和 `outputBytes`
3. `harness.recordToolResult()` 使用 `summary` 存入 evidence，而非完整 output
4. 渲染层优先使用 `summary`，fallback 到 `output` 截断

**验收**: `/harness explain` 中 evidence tokens 显著减少，harness 不再被大输出撑爆

### P0: Aborted-Turn 清理

**目标**: 用户中断后，不完整的 assistant 输出不应作为完成消息保留在 session 中。

**文件**: `src/runtime/agent-runtime-controller.ts`, `src/runtime/chat-controller.ts`, `src/services/session-storage.ts`

**当前问题**: `chat-controller.ts` 在 abort 时弹出了最后一条 history message，但 session JSONL 中可能已追加了不完整的 assistant 内容。

**变更**:
1. `AgentRuntimeController.runTurn()` 在 abort 时标记 turn 为 aborted
2. `chat-controller.ts` 在 abort 路径调用 `removeLastIncompleteAssistantMessage(sessionId)`
3. `session-storage.ts` 新增 `truncateSessionToLastComplete(sessionId)`:
   - 读取 JSONL，找到最后一个完整的 assistant→tool 对
   - 截断之后的不完整内容
   - 更新 messageCount

**验收**: 中断后立即 resume，不看到不完整的 assistant 输出

---

### P0: Prompt Cache 友好化

**目标**: 将 system prompt 分为稳定前缀和动态后缀，利用 provider prompt caching 节省 30-50% input tokens。

**文件**: `src/framework/prompt.ts`, `src/harness/assembler.ts`, `src/runtime/chat-controller.ts`

**变更**:
1. `buildSystemPrompt()` 返回 `{ stable: string, dynamic: string }`:
   - **Stable prefix**: intro + capabilities + tool descriptions + project instructions + skills (变化频率低)
   - **Dynamic suffix**: harness state + capsule + evidence + recent turn summaries (每轮变化)
2. `assembleMessages()` 将 stable 和 dynamic 分开放入 system message
3. 对于支持 prompt caching 的 provider (OpenAI, Anthropic)，stable prefix 在连续 turn 间复用缓存
4. `query.ts` 传递 model 信息给 assembler，支持 per-model 缓存策略

**验收**: 连续 5 轮对话后，system message 的 stable 部分保持不变

---

### P1: Tool 并行执行

**目标**: 当 LLM 返回多个 `tool_calls` 时，并发安全的工具可并行执行。

**文件**: `src/framework/query.ts`

**变更**:
1. 在 tool_call 循环中分组:
   - `isConcurrencySafe === true` 的工具: 收集后 `Promise.allSettled()` 并行
   - `isConcurrencySafe === false` 的工具: 逐个串行
2. 保持 `tool_call` / `tool_result` event 的原始顺序（按 tool_call id 排序后 emit）
3. 并行工具组失败时，其余工具继续执行
4. `AbortSignal` 传播到所有并行任务

**验收**: `read_file` + `glob` + `grep` 同时调用时，总耗时 ≈ max(单个耗时)

---

### P1: Edit File Preview Mode

**目标**: `edit_file` 支持 `--preview` 模式，先展示候选匹配再执行，不直接写入。

**文件**: `src/tools/index.ts`, `src/commands/index.ts`

**变更**:
1. `edit_file` 参数新增 `preview?: boolean`
2. `preview=true` 时:
   - 精确匹配: 显示匹配位置（行号 + 上下文）
   - 模糊匹配: 显示所有候选匹配
   - 不执行写入
3. 新增 `/edit-preview` 命令: 对上次 edit_file 调用执行 preview

**验收**: `edit_file preview=true` 返回候选列表，不修改文件

---

### P1: Session 索引 → Picker UI

**目标**: `/sessions` 命令支持按文件路径、工具名搜索。

**文件**: `src/commands/index.ts`, `src/services/session-index.ts`

**变更**:
1. `/sessions` 接受可选搜索参数: `/sessions <query>`
2. 如果有搜索参数，使用 `searchSessions()` 过滤
3. 显示 session 索引摘要: 涉及的文件数、工具调用数、主题数
4. `/sessions --recent` 显示最近 10 个（当前行为）

**验收**: `/sessions auth` 显示涉及 auth 相关文件的 sessions
