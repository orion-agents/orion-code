# UI Renderer Stability Notes for v0.2.3

## Current Decision

Current direction: the stable scrollback terminal renderer is the product
default. It is available as `openhorse` and `openhorse --ui terminal` because it
preserves committed Chinese input, Backspace, shell scrollback, visible history,
and live input restoration while assistant output streams.
The renderer-owned TUI remains available as `openhorse --ui tui` so OpenHorse
can continue moving toward the Claude Code/Codex model: one input parser, one
frame model, one terminal writer, ordered transcript events, and a declared
native cursor.

OpenHorse still must keep terminal history recoverable and anchor IME candidate
windows to the prompt. The TUI owns transcript scrollback internally with
PageUp/PageDown, while the next renderer slice should add Codex-style
main-screen history insertion for finalized transcript rows before TUI can be
considered as the default again.

The Ink UI remains available through `--ui ink` as an experimental renderer. It uses a bounded live frame plus a native cursor bridge that tracks the frame baseline and parked caret position explicitly, restores Ink's baseline before every frame write, and parks the real terminal cursor at the prompt synchronously at the end of the same frame write.

This is still below the final OpenClaude/Codex bar. The Ink cursor bridge must
remain isolated and experimental; product work should continue on the
renderer-owned TUI.

## What Went Wrong

The previous implementation mixed three incompatible behaviors:

- Official Ink main-screen rendering assumes it owns the cursor position between frames.
- A previous stdout proxy parked the native cursor inside the prompt but did not reliably restore Ink's baseline before the next frame.
- Dynamic overlays could exceed the terminal viewport and trigger Ink full-screen reset sequences.

This caused repeated prompt borders in scrollback, occasional cursor drift to the footer/status area, and `2J/3J/H` clear-screen output when command overlays became too tall.

## Reference Lessons

- OpenClaude keeps cursor positioning inside its renderer. It tracks a `displayCursor`, moves back to the renderer baseline before diff output, then parks at the declared input cursor.
- Codex's Rust TUI separates terminal state, history insertion, resize reflow, bottom panes, and input rendering. It does not patch stdout from outside the renderer.
- Both designs treat raw terminal input as a first-class adapter. OpenHorse must not blindly map Ink's `key.delete` to forward-delete because macOS terminals commonly send `DEL` for Backspace.
- Tool and assistant output must share one ordered transcript stream. A separate "live tools at the bottom" lane breaks chronology whenever the model streams more text while a tool is still running.

OpenHorse should follow the same boundary: the renderer owns cursor and screen invariants; app components only declare state.

## v0.2.3 Stabilization

Non-interactive coding-agent surface:

- Added `-p` / `--print` as a Claude Code/Codex-style non-interactive execution path.
- Added `openhorse doctor` and `/doctor` as a shared diagnostic surface for config, LLM, tools, MCP, skills, project rules, sessions, harness, and context size.
- Added `openhorse diff` and `/diff` as a deterministic Git workspace summary for staged, unstaged, untracked, and diff-stat state.
- Added `openhorse commit` and `/commit` as a read-only commit plan and suggested-message surface. It never creates a commit by default.
- Print mode accepts prompt arguments or piped stdin and runs the same `InkChatController -> query -> tools/session/harness` path as the interactive UI.
- Text print mode writes assistant/system output to stdout and status/tool progress to stderr, keeping stdout useful for scripts.
- JSON print mode emits `{ content, entries, statuses, errors, sessionId, model }`.
- Print mode waits for MCP startup before running the prompt, so one-shot invocations see the same runtime tool set as interactive sessions.
- Print mode deliberately does not render banners, prompt frames, or interactive pickers.

Default scrollback terminal UI:

- `openhorse` starts the stable scrollback terminal UI by default;
  `openhorse --ui terminal` is the explicit form, `openhorse --ui tui` starts
  the renderer-owned TUI, and `openhorse --ui ink` starts the experimental Ink
  UI.
- The default terminal renderer does not clear the screen, enter alternate
  screen, or draw persistent prompt frames into shell scrollback. It uses a
  small raw editor so OpenHorse can restore in-progress input while assistant
  output streams.

Explicit renderer-owned TUI:

- The TUI owns raw stdin parsing, frame layout, row diffs, cursor placement,
  prompt editing, live revision, session picker overlay, command/file/shortcut
  overlays, and transcript scrollback state.
- The TUI owns raw stdin parsing, frame layout, row diffs, cursor placement,
  prompt editing, live revision, session picker overlay, and transcript
  scrollback state.
- PageUp/PageDown scroll through retained transcript rows. New transcript output
  snaps the viewport back to the bottom.
Native terminal UI:

- `openhorse` and `openhorse --ui terminal` start the stable terminal renderer.
- The stable renderer does not clear the screen, does not enter alternate screen, and does not draw a bottom overlay. It preserves normal terminal scrollback while a lightweight raw editor owns the current prompt buffer.
- The stable renderer reuses the same `InkChatController` execution path, so chat, slash commands, session restore, harness, tools, skills, and MCP continue through one agent runtime.
- Repository guidance is loaded as first-class prompt context:
  - OpenHorse scans from project root to the current directory for `AGENTS.md`, `CLAUDE.md`, `.openhorse/instructions.md`, `.cursorrules`, and `.cursor/rules/*.md|*.mdc`.
  - Root-level guidance appears first; deeper directory guidance appears later and is treated as more specific.
  - Instruction files are bounded per file and by total prompt budget, then injected as an independent dynamic prompt section, not mixed into user memory.
- `/resume` in the stable renderer uses the complete session picker data. After the picker prints, users can type an index, id, or name to restore that session.
- The stable renderer handles terminal editing bytes such as `DEL`, `Backspace`, `Ctrl+U`, `Ctrl+W`, arrows, history navigation, and CSI escape sequences before input reaches the command/chat parser.
- The stable renderer uses prompt-level completion for core coding-agent entry points:
  - `/` command names complete from the visible slash command registry.
  - `@` file mentions complete from project files through the existing gitignore-aware file matcher.
- The stable renderer uses the same event-driven raw editor during idle and
  running turns. While a turn is running, ordinary input is treated as a live
  revision: OpenHorse aborts the active turn, discards the partial assistant
  persistence through the shared controller path, and restarts with the latest
  user instruction.
- Running slash commands do not execute concurrently with an active turn; the
  UI asks the user to interrupt first.
- `@` file mentions are semantic, not just UI text:
  - Mentioned project files are read and injected into the current turn's dynamic system prompt.
  - Mentioned directories are summarized with bounded entry lists.
  - Missing, binary, unreadable, and project-external paths are represented as explicit notes instead of being silently ignored or loaded unsafely.
  - File content is bounded per file and by total prompt budget, so large references cannot swamp the harness context.
- Stable multiline input is supported without full-screen rendering:
  - `/paste` enters multiline mode.
  - `/end` submits the collected block.
  - `/cancel` cancels it.
  - A trailing `\` continues the next line and submits when a non-continuation line is entered.
- External editor input is supported with `/edit`:
  - `$VISUAL` is preferred, then `$EDITOR`, then `vi`.
  - `/edit initial text` seeds the temporary prompt file with initial content.
  - Empty saved content cancels the turn.
  - The editor inherits stdio and OpenHorse restores its prompt after the
    external editor exits.

Experimental Ink renderer:

- Replaced the fragile cursor parking runtime with `native-cursor`, which always un-parks before frame writes and parks after frame writes.
- Changed cursor parking from delayed `setTimeout(0)` restore to frame-tail restore. When a stdout chunk contains the prompt frame, the cursor is restored immediately; other chunks coalesce through a microtask so partial Ink writes do not park the cursor at a half-rendered baseline.
- Removed interval-based cursor reassertion. Repeated out-of-band cursor writes are a symptom of not owning the renderer; the bridge now only writes when frame output, prompt layout, or raw input requires it.
- Added `NativeCursor`, which declares the prompt cursor row/column from the prompt layout.
- Fixed `NativeCursor` lifecycle so typing no longer disables/unparks the cursor during every value update; the bridge is disabled only when the component unmounts.
- Corrected prompt cursor row math so a single-line prompt parks on the input text row after Ink renders the bottom border. In a real PTY this means moving up two rows from Ink's post-render cursor, which keeps macOS IME candidate windows attached to the prompt instead of the border/next line.
- Kept visual cursor rendering as a testable fallback, while the live prompt uses the native cursor for IME anchoring.
- Made command/file/session pickers fixed-width and single-line truncated.
- Capped picker rows from terminal height, prompt height, live transcript budget, and status budget.
- Added resize state so width/height changes force React layout recalculation.
- Changed multiline paste handling to route through the input reducer, preventing control characters from becoming visible text.
- Routed batched `Ctrl+U` chunks through the input reducer so terminal/input-method batches like `Ctrl+U` plus text clear and then insert instead of swallowing the trailing text.
- Made prompt editing grapheme-aware with `Intl.Segmenter` fallback logic so Backspace/Delete and wrapping do not split emoji sequences or combining marks.
- Stopped `/clear` from clearing terminal scrollback through `3J`.
- Counted repeated `Ctrl+C` bytes inside one stdin chunk so fast double-press exits reliably.
- Added a raw-input adapter so `DEL` behaves as Backspace while `ESC[3~` remains forward-delete.
- Enabled stdin raw mode before Ink mounts so terminal local echo cannot leak CJK input outside the prompt frame.
- Replaced split `archived/live` transcript state with a committed-prefix model so running tools keep their chronological position between assistant segments.
- Changed assistant streaming from buffered append-on-close to live append/update/finalize entries, with unfinished partial output removed on interrupt.
- Added structured `ToolActivity` rendering so running/completed/error tool rows are parsed, truncated by visual width, and shown as stable timeline entries.
- Added `scripts/ink-ui-pty-smoke.py` plus a Jest wrapper to exercise the Ink UI inside a real pseudo terminal.
- Resize handling now reads the latest stdout dimensions during render, preventing a stale React size snapshot from being reused after `SIGWINCH`.
- Shutdown now disables native cursor parking and renders an empty dynamic frame before exiting, so the live prompt is erased instead of being left behind and interleaved with the next shell prompt or next `openhorse` launch.
- Native cursor parking now uses a prompt-box ref and Ink/Yoga computed layout to derive the cursor row and column from the rendered tree. This is a step toward OpenClaude-style cursor declarations: the input component declares its caret position, and the terminal cursor bridge parks there after Ink writes the frame. The older prompt-bottom row calculation remains only as a non-TTY/fallback path.
- Native cursor parking no longer relies on terminal save/restore cursor sequences (`ESC7`/`ESC8`). The bridge maintains two positions in code: the frame baseline that Ink expects before the next diff and the prompt caret where IME composition should appear. Before a frame write, it moves from the parked caret back to the baseline; after parsing the frame output, it moves from the new baseline to the declared prompt caret. This mirrors the OpenClaude renderer-owned `displayCursor` model more closely while OpenHorse still uses official Ink.
- Native cursor state is now owned by an explicit `NativeCursorController` instance created by the Ink launcher and passed through `App -> ReplScreen -> NativeCursor`. This removes the previous module-level global cursor state from the UI path and makes renderer instances isolated in tests and future embedded surfaces.
- Cursor tracking now advances by grapheme cluster, not code point. Combining marks and ZWJ emoji such as `👨‍👩‍👧‍👦` are measured as one visible unit, so the frame baseline does not drift after rich Unicode output or prompt text.
- The cursor bridge now observes the rendered prompt frame in stdout and records the real terminal row of the latest prompt top border. Cursor parking targets `promptTop + 1 + cursorLineIndex`, so old-frame cleanup below the prompt no longer pulls IME candidates to the footer or shell area.
- Cursor tracking now clamps row movement to the terminal viewport and treats full-width line endings as pending-wrap style movement instead of immediately advancing to the next row. This matches real PTY behavior closely enough to survive large overlay clear sequences such as closing `/` command palette.
- The PTY smoke test now starts a local OpenAI-compatible SSE server and drives a real chat turn through `LLMService.chatStream -> query -> Ink UI`. During the mock assistant stream it types Chinese text into the prompt and verifies that the prompt remains editable and anchored while output is still arriving.
- The same PTY smoke also drives a tool-call turn: the mock model streams assistant text, requests `list_files`, OpenHorse executes the real runtime tool, and the UI is checked for chronological display of assistant intro, running tool row, successful tool row, and final answer.
- The PTY smoke restarts OpenHorse with the same config directory, runs `/resume --last`, and verifies the transcript is rebuilt with prior chat text, assistant text, completed tool activity, and final answer visible after restore.
- Resume transcript reconstruction now pairs stored assistant `tool_calls` with matching tool result messages so completed tools render as activity rows such as `✓ list_files .` instead of a requested row plus raw `Tool result ...` JSON.

## Next Renderer Work

To reach Claude Code/Codex quality, implement a renderer-owned cursor system and retire the bridge:

1. Add a small OpenHorse render abstraction around Ink output events.
2. Track frame baseline, live prompt bounds, and declared cursor position inside that renderer.
3. Add vt100 snapshot tests for scrollback, resize, overlay mount/unmount, and input cursor movement.
4. Move native IME candidate anchoring from the bridge into renderer-owned cursor declarations.
5. Keep transcript/history rendering independent from overlays and live prompt state.

## Next Coding-Agent Work

The stable terminal renderer is the current product UI. Ink and TUI remain
explicit beta experiments, while print mode and remote UI are future renderer
targets that must keep using the same runtime contract. The next implementation
slices should follow the reference products' boundaries:

1. Harden the stable terminal path first: scrollback, IME, resize, multiline
   input, live revision, and ordered tool output must be reliable for daily use.
2. Keep Ink and TUI experiments behind explicit `--ui ink` / `--ui tui`
   selection. They can validate screen buffers, diff rendering, cursor
   declarations, and prompt bounds, but they must not change agent semantics.
3. Keep the agent runtime UI-agnostic: `query`, tools, MCP, skills, session, and
   harness should emit structured events consumed by terminal, Ink beta, TUI
   beta, print future, and remote future renderers.
4. Treat print mode as an early non-interactive protocol check, not a stable
   automation product yet. Later `openhorse exec` / print work should provide
   deterministic JSON, explicit permission failures, and CI/script docs through
   the shared runtime protocol.
5. Continue the command audit for coding-agent parity: `/doctor`, `/diff`,
   `/commit`, `/resume`, `/compact`, `/harness explain`, `/mcp`, `/skills`,
   `/permissions`, and `/model` should keep explicit interactive and
   non-interactive behavior defined.
6. Make live revision a runtime contract rather than a UI trick: input during a
   running turn should abort, discard partial assistant persistence, and restart
   with the latest user instruction across every renderer that supports it.

## Manual IME Verification Boundary

PTY tests are necessary but not sufficient for Chinese input. They prove raw bytes, redraw order, prompt layout, and cursor escape sequences. They cannot display or measure macOS IME candidate windows. For Terminal.app/iTerm verification, OpenHorse must be checked manually with:

- pinyin composition before commit, with the candidate window near the prompt text.
- Backspace during composition and after commit.
- Streaming assistant output while composing Chinese in the prompt.
- Window resize while the prompt contains full-width Chinese text.

Any future cursor implementation must preserve the invariant that native cursor parking is appended to the same render frame, not deferred by timers.
