# v0.2.13 Agent Loop Frequency Optimization

## Goal

v0.2.13 reduces unnecessary base-model requests during complex coding tasks without rewriting the existing runtime, query, tool, harness, or session architecture. The release focuses on stable guardrails: loop budgets, read-only fragmentation diagnostics, conservative local fast paths, and operator-visible metrics.

Target outcomes:

- Medium tasks should use fewer avoidable LLM turns by nudging batched read-only exploration.
- Release-level tasks should stop before runaway request/tool loops hit provider API limits.
- Explicit mechanical commands should not require a model round trip.
- Diagnostics should make request volume, tool volume, compression, and fast-path usage visible.

## Adaptive Loop Budget

The base per-user-turn `LoopBudget` is:

- `maxLlmRequestsPerUserTurn = 24`
- `maxToolCallsPerUserTurn = 120`
- `maxReadOnlyFragmentation = 3`
- `maxModelVisibleToolBytes = 64KB`

This is a guardrail against runaway loops, not a one-size product limit. It
must not block legitimate large coding tasks at 24 requests.
`AgentChatController` raises the runtime budget for explicit complex coding
tasks and release tasks:

- complex implementation/refactor/debug/review tasks: up to 48 LLM requests,
  180 tool calls, and 96KB model-visible tool bytes;
- release/push/PR/publish tasks: up to 64 LLM requests, 240 tool calls, and
  128KB model-visible tool bytes.

Continuation inputs such as `继续` are evaluated together with the restored
harness root objective, active instruction, contract objective, and next action.
This prevents compact/resume or short follow-up prompts from silently falling
back to the conservative 24-request default while the active task is still a
large multi-step coding task.

`query()` also has a runtime promotion fallback. If a turn started with the
default profile but actually becomes a multi-turn tool-heavy loop, the budget is
promoted once to the complex profile instead of stopping exactly at 24. Explicit
config overrides are never auto-promoted; if a user sets 24 in config, that cap
is respected.

Users can override the guardrail through `openhorse.json`:

```json
{
  "agentLoop": {
    "budget": {
      "maxLlmRequestsPerUserTurn": 96,
      "maxToolCallsPerUserTurn": 360
    }
  }
}
```

Environment overrides are also supported:

```bash
OPENHORSE_MAX_LLM_REQUESTS_PER_TURN=96
OPENHORSE_MAX_TOOL_CALLS_PER_TURN=360
OPENHORSE_MAX_READ_ONLY_FRAGMENTATION=4
OPENHORSE_MAX_MODEL_VISIBLE_TOOL_BYTES=131072
```

When a hard budget is exceeded, `query()` completes with
`finishReason = "budget_exceeded"`. The response states that session state was
preserved, tells the user they can reply `继续` to continue the same objective,
points to `/loop-stats`, and mentions `agentLoop.budget` for intentionally long
work. This hard stop applies to LLM request caps and tool-call caps. If a model
response would exceed the tool-call cap, OpenHorse stops before emitting
unresolved assistant tool calls or executing any requested tool. Model-visible
tool bytes are handled as a context budget: full output remains available to the
UI/session artifacts, while the next model request receives compressed or omitted
tool-result text after the cap is reached. This is a safety valve, not a task
planner.

The same continuation strategy is also emitted as structured metadata:
`continuationActions = ["reply_continue", "narrow_instruction",
"inspect_loop_stats", "raise_budget"]` plus a redacted `continuationHint`.
Runtime renderers and `/trace` must consume these fields instead of parsing the
assistant text. Loop stats are published after workspace and verification
post-processing, so a changed-file turn that becomes `completion_gate` does not
briefly report `completed` to renderers.
Complete trace events also persist the active loop budget source and caps, so
`/trace <turn>` can explain whether a turn used the default, complex, release,
or config-overridden profile and which LLM/tool/model-visible limits applied
when the loop stopped.

Provider or transport failures are part of the same loop accounting model.
When `LLMService.chatStream()` throws after a request starts, the runtime records
`finishReason = "failed"`, counts the failed provider attempt as an LLM request,
publishes `loop_stats_updated`, and persists `provider_retry` plus failed
`complete` trace metadata when diagnostics are available. This keeps Xunfei/
DashScope quota, busy, and fallback failures inspectable through `/status`,
`/loop-stats`, and `/trace` instead of collapsing them into an opaque CLI error.

If a failed model-backed turn modified files before the failure, OpenHorse emits
a recovery status notice, records the notice on the failed trace event, and
points to the saved pre-edit checkpoint. `/checkpoint` lists checkpoints and
`/checkpoint restore <turn-id|prefix>` previews the restore target; actual
restore requires `--yes` to avoid accidental overwrites. Restore validates that
checkpoint metadata stays inside the project and deletes files that did not
exist when the checkpoint was created, so failed new-file writes can be rolled
back instead of only overwritten.

## Read-Only Fragmentation Diagnosis

OpenHorse tracks consecutive turns where the model calls exactly one read-only local tool from:

- `git_status`
- `list_files`
- `glob`
- `grep`
- `read_file`

After the threshold is reached, the next model context receives a short hint to use `batch_read` for independent local exploration. OpenHorse does not rewrite provider tool calls because doing so would risk breaking provider tool protocol semantics.

## Local Fast Path

`AgentChatController.runInput()` now routes only explicit mechanical inputs directly to tools:

- `git status`
- `读取 <path>` / `read <path>`
- `搜索 <pattern>` / `grep <pattern>`
- `运行测试: <command>` / `run test: <command>`

Fast path execution:

- calls the existing `executeTool()` entry point with normal cwd/config/session context;
- records the user input and a compact assistant summary in session history;
- displays the local tool result in the transcript;
- stores large fast-path output in artifacts and keeps only a small preview in assistant history;
- stores loop stats with `localFastPathUsed = true` and `llmRequests = 0`.

Ambiguous coding, refactoring, debugging, release, and planning tasks still go through the LLM.

## Diagnostics

`/status` shows a compact last-loop summary. `/loop-stats` shows full diagnostics:

- finish reason;
- continuation actions and hint for budget exits;
- LLM requests and turns;
- tool call distribution;
- model-visible vs total tool bytes;
- actual budget caps and budget source (`default`, `complex`, `release`, or
  `config over <profile>`);
- provider retry count, accumulated retry delay, last retry type/status, and
  fallback model path without raw provider error text;
- verification profile, required status, passed/failed/missing check counts,
  and whether the turn is allowed to claim verified completion;
- summarized bytes saved from model context;
- compact trigger;
- budget reason;
- read-only fragmentation streak and `batch_read` hint count;
- local fast-path usage.

`/trace <turn>` reads the session trace sidecar and shows model/tool/workspace/
verification events for one turn. Permission decisions produced by the scheduler
are recorded with approved/denied status, source (`user`, config, tool policy, or
harness drift guard), behavior, reason summary, and decision latency. Trace data
is redacted before persistence.
Provider retry/fallback pressure is recorded as structured `provider_retry` and
`provider_fallback` trace events with counts, delay, type/status, and model path,
without persisting raw provider error text.

Prompt assembly is also recorded as a per-turn trace event before the model
request. The event stores only safe metadata: model id, estimated/budget tokens,
section names, included/omitted evidence ids, evidence kinds, scores, token
counts, and aggregate counts. It must not persist full prompt text, full
transcript, tool output bodies, or secret-bearing evidence contents.

Long tool arguments, especially shell commands, are represented in trace with a
short redacted summary plus an `argsArtifactId` when the exact argument text is
too large for inline display. `/trace` renders that reference as
`/artifacts show <id> --full`. The artifact stores redacted full arguments, so
users can inspect the exact command shape without bloating the trace sidecar or
leaking obvious secrets through trace metadata.

Artifact ids are generated from sanitized tool names only. They must not include
path separators, `..` segments, or obvious secret-like fragments, so `/trace` and
`/artifacts` indexes remain safe metadata even when a tool name is malformed.

Denied permission decisions stop the current user turn with
`finishReason = "blocked"` after recording the denied tool result. OpenHorse does
not spend another model request asking the model to react to a tool that the
runtime already knows was not allowed to execute.

Renderer-independent protocol additions:

- `loop_stats_updated`: emitted whenever runtime loop stats are updated.
- `trace_event_recorded`: emitted after a trace event is persisted and redacted.
- `harness_diagnostics_updated`: emitted after a successful turn updates the
  harness, carrying objective, active instruction, epoch, counts, and prompt
  assembly summary without full transcript or evidence contents.
- `session_restored`: emitted after `/resume` restores a session, carrying only
  session metadata, restored message count, and compact summary so renderers and
  future remote clients do not parse resume prose.

These are additive runtime events. Terminal, Ink, TUI, print, and future remote
renderers should consume them through adapters rather than reimplementing loop
or trace behavior.

## Verification Gate

Changed-file turns now record:

- pre/post workspace snapshots;
- workspace delta with separate new files, all changed files, pre-existing dirty
  files modified again during the turn, and files resolved by the turn;
- repo-aware verification profile;
- verification command results;
- verification summary with passed, failed, missing checks and
  `claimAllowed`.

If required verification is incomplete, the turn is marked with
`finishReason = "completion_gate"` and a verification gate notice is persisted
into assistant context so the next model step cannot treat the task as verified.

## Compact / Resume Continuity

Manual compact now persists the compacted model-visible history back into the
active session. The original JSONL transcript remains append-only, but the
session meta records a display/model-visible boundary so `/resume` restores the
compact context plus the recent tail instead of replaying all old raw messages.

The compacted context includes the structured `[OpenHorse Context State v2]`
block from the harness. After resume, a generic continuation such as `继续`
should keep the restored `rootObjective` and `activeInstruction` in the assembled
prompt rather than treating the short continuation as a new task.

## Risk Boundaries

- No UI renderer changes.
- No session JSONL schema change.
- No subagent runtime or task decomposition rewrite.
- No automatic tool-call rewriting.
- No destructive migration or storage change.

## Validation

Focused validation:

```bash
npm test -- --runInBand tests/query.test.ts tests/agent-runtime-controller.test.ts tests/status-command.test.ts tests/doctor.test.ts
npm test -- --runInBand tests/runtime-ui-parity.test.ts tests/verification-profile.test.ts tests/workspace-state.test.ts tests/tool-artifacts.test.ts
npm run build
npm test -- --runInBand
```

Manual validation:

- Run `npm run start`.
- Enter `git status`; verify no LLM call is required and `/loop-stats` reports `Fast path yes`.
- Use `/trace latest` after a tool-using turn; verify ordered trace events and no secrets in summaries.
- Run a long `run test: ...` command; verify `/trace latest` includes an
  expandable `args=/artifacts show ... --full` reference for the full command.
- Trigger an ask-required tool in tests; verify `/trace` records the permission decision before the tool result.
- Deny an ask-required tool; verify no file mutation occurs, no second model request is made, and the turn finishes as `blocked`.
- Run `/compact`, `/resume <session-id>`, then enter `继续`; verify the next
  model request includes the restored root objective and active instruction.
- Complete a normal tool-using chat turn; verify renderer protocol sinks receive harness diagnostics.
- Use `/artifacts` after large output; verify full output is retrievable without entering model context.
- Ask a normal coding question; verify it still enters the LLM loop.
- Force repeated single `read_file` style tool use in a mock/focused test; verify read-only fragmentation stats and `batch_read` hint count.
- Force a model response with more tool calls than `maxToolCallsPerUserTurn`;
  verify no tool is executed, no unresolved assistant tool-call message is
  persisted, and the final trace records `finishReason=budget_exceeded` with
  continuation actions.
