## 一、总体结论

`v0.2.21-问题分析.md` 诊断的**核心断路（runner 未切换到新管线）已经修复**。当前代码里 `TuiRunner` 已经持有 `InlineTerminalSurface`、走 `renderTuiLiveFrame` + commit 协议、`TranscriptLayoutCache` 已接入、`TuiRenderScheduler` 已在生产路径启用、`unhandledRejection` 监听与 cleanup 顺序都已就位。切片 3–6 的"可插拔但未插入"状态已被解除。

**但并未全部完成。** 剩余缺口集中在三处：
1. **P0-2 Composer 接入不完整** —— 多行换行与 History 已可用，但 `reduceInputBuffer` 共享缓冲未接、多行 prompt 内 Up/Down 仍跳 History、视觉多行被压平为单行 `⏎`。
2. **P1-3 Timeline 区域与动态预算完全缺失** —— `subtaskTimeline` / `runtimeToolEvents` 数据已到位但 layout 从不渲染，状态栏只有 `working/ready`。
3. **P1-1 / P1-6 数据质量与渲染性能** —— 工具 activity 仍按数组 append（未 callId keyed）、live band 每帧全量重绘（无 changed-row diff）。

另外，用户最初反馈的 **"没有原生 shell 滚动效果"** 问题**已通过底部 band 重构解决**（见 §二）。

## 二、用户原始诉求：原生 shell 滚动（/resume 后看历史）

**状态：已修复 ✅**

`inline-surface.ts` 现在实现了底部 band 设计：
- `LIVE_BAND_RATIO = 0.75`（line 94），`computeBandRows()`（line 127）将 live 区固定为屏幕底部约 75%，上方 25% 为 history area（`historyAreaRows`，line 141）。
- `commit()`（line 233–271）协议：将光标移到屏幕底部，用 `CR` + 内容 + `SGR_RESET` + 硬 `\n` 逐行写出（line 244–257）。因为光标停在最后一行，每个 `\n` 都把该行卷进终端原生 scrollback，history 在 band 上方自然累积、可上翻查看，且**绝不被 live band 覆盖**。
- `/resume` 后：`state.ts` 的 `replaceTranscript`（line 170–188，`RESUME_LIVE_TAIL = 50`）把最近 50 条保留为 LIVE，更早的标记 finalized；`runner.ts` 的 `tryCommit`（line 222–264）把它们一次性 commit 进 scrollback。

结论：上翻查看历史、以及 commit 只提交一次的行为现在都成立。这条最初的痛点已闭环。

## 七、v0.2.22 修复优先级建议（基于本次评估）

### 阶段 1（阻塞 F2/F4，需先做的体验项）

1. **P0-2 收尾 — 多行编辑器语义**
   - 接入 `src/runtime/composer/buffer.ts` 的 `reduceInputBuffer` 替换本地 helper（或保留本地 helper 但补齐语义）。
   - `up`/`down` 在**多行 prompt 内**改为行内光标移动（按 `\n` 切分），仅在首行/末行或单行长 prompt 时回退到 History。
   - `home`/`end` 改为相对当前行首/尾。
   - layout `renderPrompt` 支持多行回显（按 `\n` 拆行，在 prompt box 内多行展示），而非压成 `⏎` 单行。
   - 范围：`runner.ts`、`layout.ts`、`input-parser.ts`。

2. **P1-3 — Timeline 区域 + 动态预算**
   - 在 `renderTuiLiveFrame` 中新增 timeline 区域（复用 `subtaskTimeline` 与 `runtimeToolEvents`）。
   - 引入 `TuiLayoutBudget`，按 height 动态分配 transcript / timeline / status / prompt 行数（替代固定 `PROMPT_TOP_ROWS = 3`）。
   - 范围：`layout.ts`、`state.ts`（已就绪）、`runner.ts`（高度传入）。

### 阶段 2（数据质量 + 性能）

3. **P1-1 — tool activity callId keyed**：`appendRuntimeToolEvent` 改为按 `callId` 去重（started/finished 合并为一条带状态的 activity），保留最近 N 条。
4. **P1-6 — changed-row diff**：`renderLiveInternal` 用 `previousFrame` 做行级 diff，仅对变化行发 `EL2`+重绘；不变行跳过。这是 P3/P4 性能验收的前提。
5. **P1-7 文案瑕疵**：`layout.ts:271` 改为 "scroll terminal (↑/↓) to review history"。

### 阶段 3（收口 / 发布）

6. **P2-1** 500-entry / 100-delta 性能 fixture（依赖 P1-6）。
7. **P2-2** Ink 测试收口为 compat/parity。
8. **P2-3 / P2-4** 迁移文档清理 + background stdout/stderr 审计。
9. **P2-6** 提交工作区改动、打 tag、发布 `0.2.22`，对齐 npm tarball 与 git commit。
