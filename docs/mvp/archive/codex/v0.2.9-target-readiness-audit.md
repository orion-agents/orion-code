# v0.2.9 Target Readiness Audit

## Scope

This audit checks v0.2.9 against the current target documents in
`docs/targets/`. It does not claim the long-term "first-class coding-agent"
north star is complete. The v0.2.9 release scope is the runtime/UI boundary:
terminal is the stable product UI, Ink/TUI are beta renderers, and print/remote
remain future renderer targets. The existing print path is audited only as an
early experimental non-interactive protocol path, not as a completed automation
or remote UI product surface.

## Remaining Non-Blocking Work

- Ink beta still primarily consumes tool activity through transcript rows. It
  has unit and PTY coverage for tool ordering, but it does not yet retain a
  separate structured `runtimeToolEvents` state like TUI.
- More golden-frame tests would improve confidence for Ink/TUI resize and exact
  frame rendering. Existing tests cover cursor, CJK input, prompt wrapping,
  PTY smoke, and TUI resize, but not every visual permutation.
- `ui-v2` compatibility exports remain intentionally present. Production source
  paths no longer import them; removal can wait for a later breaking cleanup
  after callers migrate to `src/ui/shared`.
- Print and remote UI are future targets. v0.2.9 keeps the current print path as
  an early deterministic non-interactive protocol check, but does not claim a
  complete automation, daemon, or remote renderer surface.
- Lint warnings remain as technical debt. They are intentionally warning-level
  for v0.2.9 and should be reduced in a dedicated cleanup pass.
- The remaining production audit advisory is a moderate `uuid` issue whose
  automatic fix requires a breaking `uuid@14` upgrade. Treat that as dependency
  maintenance rather than part of this runtime/UI boundary iteration.

## Release Readiness

v0.2.9 is ready as a runtime/UI boundary iteration if the release goal is:

- make terminal the stable default product UI,
- keep Ink/TUI as explicit beta experiments,
- prevent UI renderer choice from changing agent runtime semantics,
- preserve runtime-owned turn, permission, picker, session, and tool-event
  behavior,
- provide automated evidence for protocol parity, terminal behavior, TUI beta
  behavior, print non-interactive behavior, lint executability, production
  high-severity audit health, and full test/build health.

It is not a completion point for the broader north-star goals around Harness v3,
full remote UI, hooks/plugins/subagents, or organization/team workflows.
