# v0.2.6 Optimization Plan

## Summary

v0.2.6 的核心目标是补齐 OpenHorse 作为专业 coding-agent 的基础能力：稳定 harness prompt 组装、可靠 session 恢复、安全 edit preview、结构化 tool result、并行只读工具执行，以及可验证的 API 兼容性。

当前分支已经完成一轮修复：`npm run build` 与完整 `npm test -- --runInBand` 通过。后续优化重点不是继续扩大功能面，而是把这些能力打磨成可长期维护、可发布、可回归验证的稳定基础。

## Current State

已完成能力：

- Harness 动态上下文不再污染 user/assistant transcript，改为插入稳定 system prefix 后的动态 system context。
- Runtime 使用 `buildSystemPrompt()` 的 static/dynamic 结构，为 provider prompt caching 留出正确接口。
- Abort 后会截断 session JSONL 尾部不完整 turn，并重建 session index。
- `query()` 支持 `isConcurrencySafe=true` 的工具并行执行，同时保持 `tool_result` 输出顺序稳定。
- `edit_file preview=true` 支持精确/模糊多候选预览且不写文件。
- `/edit-preview` 可复看上一次 `edit_file` 的候选匹配。
- `/sessions <query>` 可搜索完整 session 列表，并支持跨 project index。

剩余风险：

- Provider 级 prompt cache 仍只是结构准备，尚未针对 OpenAI / Anthropic / DashScope 做请求层策略。
- Tool 并行调度逻辑集中在 `query.ts`，后续应抽出 scheduler，降低主循环复杂度。
- Session 截断策略目前按“最后完整 assistant answer”判断，复杂 tool-call 中断场景需要更多 fixtures。
- `/edit-preview` 是命令行输出，Ink/TUI picker 化仍未完成。

## P0: Release Hardening

### Prompt Cache Request Strategy

目标：让 static system prefix 真正进入 provider cache 路径，而不仅是 message 结构分离。

实施：

- 在 LLM provider 层识别支持 prompt caching 的模型。
- 为 OpenAI/Anthropic 兼容层预留 cache-control 或 equivalent metadata 注入点。
- DashScope/Qwen 不支持时保持普通 message，不影响正确性。
- 增加测试：连续 5 轮 turn 的 stable prefix 内容不变，dynamic context 可变。

验收：

- 不改变现有 prompt 语义。
- 不支持 cache 的 provider 行为完全兼容。
- `/harness explain` 能展示 stable/dynamic token 估算。

### Session Abort Fixtures

目标：确保 interrupt/live revision 后 resume 不带回脏历史。

实施：

- 增加 fixtures：仅 user、assistant tool_calls 后中断、tool result 后中断、final answer 后中断。
- 验证 transcript、session meta `messageCount`、session index 三者一致。

验收：

- 所有 aborted incomplete tail 被截断。
- 完整 final answer 后不会误删。

## P1: Tool Runtime Professionalization

### Extract Tool Scheduler

目标：把 tool 分组、权限判断、并行执行、顺序 emit 从 `query.ts` 抽出。

建议路径：

- 新增 `src/framework/tool-scheduler.ts`。
- 输入：tool calls、tool registry、permission context、abort signal。
- 输出：按原始 order 排列的 execution result。
- `query.ts` 只负责 LLM loop 和事件转换。

验收：

- read-only 并行工具仍并发。
- write/destructive/interactive-confirm 工具仍串行。
- abort signal 传播到所有 running tool。

### Structured Tool Artifacts

目标：让 tool result 同时保留 full output、summary、metadata，harness 只消费 summary/evidence。

实施：

- 统一 `ToolResult.outputBytes` 为必填运行时字段。
- 为大输出存储 artifact reference，而不是把完整输出塞入 harness。
- UI 默认显示 summary，可展开 full output。

验收：

- 大输出不会撑爆 harness evidence。
- session replay 可恢复 tool summary 和必要 full output。

## P1: UX Integration

### Edit Preview Picker

目标：把 `/edit-preview` 从纯文本升级为结构化候选展示。

实施：

- preview result 返回 `metadata.candidates`。
- Ink/TUI 层可展示候选列表、行号、上下文、是否 replace_all。
- 后续支持用户选择候选再执行 edit。

验收：

- 多候选 fuzzy match 不写文件。
- 用户可清楚看到候选位置与替换内容。

### Session Search Picker

目标：让 `/sessions <query>` 和 `/resume` picker 使用同一套搜索结果。

实施：

- 将 search result 暴露成 command result payload，而不是只 `console.log`。
- Ink/TUI renderer 展示滚动列表、size、files/tools/topics。
- 支持 `/resume <query>` 直接进入 filtered picker。

验收：

- 超过 10 个 session 可滚动选择。
- search 不受最近 N 条限制。

## P2: Maintenance and Release Quality

### API Contract Tests

目标：防止 patch/minor 版本破坏 SDK 用户。

实施：

- 增加 compile-time type assertion 文件。
- 覆盖 `ContextHarness`、`HarnessEngine`、`query()` event union、`OpenHorseTool`、session APIs。

### Performance Benchmarks

目标：量化优化收益。

指标：

- 多 tool-call turn latency。
- prompt stable/dynamic token size。
- session resume latency。
- compact 后 context size。

## Test Plan

必跑：

```bash
npm run build
npm test -- --runInBand
```

重点回归：

- `tests/harness.test.ts`
- `tests/query.test.ts`
- `tests/session-storage.test.ts`
- `tests/tools.test.ts`
- `tests/api-compatibility.test.ts`

手动验证：

- 运行中输入修正后 interrupt，再 `/resume`，确认不显示半截 assistant。
- 让模型同时调用 `read_file`、`glob`、`grep`，确认总耗时接近最长单个工具。
- 对多匹配文件运行 `edit_file preview=true`，确认只展示候选不写入。
- `/sessions auth` 能搜索完整 project sessions，并展示 index 摘要。

## Release Criteria

v0.2.6 可发布条件：

- Build 和全量测试通过。
- Abort/resume、parallel tools、edit preview、session search 均有自动测试。
- 不引入 UI 层对 agent runtime 的反向依赖。
- 文档记录已知限制和后续 v0.2.7 优化方向。
