# Tool Artifact Lifecycle — 运维策略

> **版本**: v0.2.7  
> **模块**: `src/core/tool-artifacts.ts`

## 概述

当工具输出超过 10KB（`ARTIFACT_THRESHOLD`）时，系统自动将完整内容写入磁盘文件，并在上下文中保留截断后的摘要。每条记录包含 `artifactRef: { id, outputBytes }`，指向磁盘上的实际文件。

## 存储路径

```
~/.openhorse/projects/<hash>/_artifacts/<toolName>-<timestamp>-<random>.txt
```

文件权限 `0o600`（仅当前用户可读），目录权限 `0o700`。

## 清理策略

### 自动清理

`cleanupArtifacts(projectPath)` 删除 **超过 24 小时** 的 artifact 文件。基于 `mtime` 判断。

### 建议的清理时机

| 场景 | 触发方式 | 说明 |
|------|---------|------|
| session 结束 | `/exit` | 可在 session 生命周期结束时调用 `cleanupArtifacts` |
| session 恢复 | `/resume` | 恢复前调用 `cleanupArtifacts`，清理上一轮遗留的过期文件 |
| 定时任务 | crontab / 手动 | `find ~/.openhorse -name "*.txt" -path "*/_artifacts/*" -mtime +1 -delete` |
| 磁盘空间不足 | 手动 | `du -sh ~/.openhorse/**/_artifacts/` 检查后清理 |

### 磁盘占用估算

- 单次 artifact 最大无上限（工具输出全部保存）
- 典型场景：`grep` 大文件匹配、`exec_command` 长输出、`read_file` 大文件
- 默认 24h TTL 下，日常使用约 0–50MB/session
- 极端场景（批量 grep 整个代码库）可能单次产生 100MB+

### 当前清理调用点

```
cleanupArtifacts() — 目前仅在单元测试中调用
```

**v0.2.7 后续建议**：在 session 启动/退出流程中自动调用 `cleanupArtifacts(projectPath)`。

## API 参考

```typescript
// 常量
export const ARTIFACT_THRESHOLD = 10_240;  // 10KB

// 存储大型输出为 artifact
export function storeArtifact(
  projectPath: string | undefined,
  toolName: string,
  output: string,
  outputBytes: number,
): ToolArtifact | null

// 读取已存储的 artifact
export function retrieveArtifact(artifactPath: string): string | null

// 截断大输出（用于上下文显示）
export function truncateForContext(output: string, maxBytes?: number): string

// 清理过期 artifacts（24h TTL）
export function cleanupArtifacts(projectPath: string): void
```

## ToolResult.artifactRef 结构

```typescript
interface ToolResult {
  success: boolean;
  output: string;
  artifactRef?: {
    id: string;         // "read_file-1718880000000-abc123"
    outputBytes: number; // 完整输出的字节数
  };
  summary?: string;
  outputBytes?: number;
}
```

`artifactRef` 仅在大输出时存在。小输出时 `artifactRef` 为 `undefined`，`output` 包含完整内容。
