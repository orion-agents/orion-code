# TUI 原生 Scrollback 修复计划（底部 Band 方案）

> 目标：让已提交的对话历史真正进入终端原生 scrollback，用户上滚可见，与普通 shell 体验一致。
> 对照：`docs/workBuddy/v0.2.21-native-scrollback-refactor.md`

## 一、问题根因（来自分析文档 2.3）

当前 `InlineTerminalSurface.commit()` 协议：
1. `clearLiveRegion()` 清**整屏**（live region = height-1 = 整屏）；
2. 在 live region 内（从 row 0）写已提交行 + `\n`；
3. `renderLiveInternal()` **又做一次 `clearLiveRegion`**（清整屏）并重绘整屏 live frame。

结果：步骤 2 写的历史行在步骤 3 被清屏 + 覆盖，**从未滚入原生 scrollback**。native scrollback 只在输出超过可见高度、终端自动滚屏时才累积；而 live region 占满整屏且原地重绘，每次 commit = 0 行进 scrollback。

## 二、修复方案：底部 Band + 提交行从屏幕底部写入

### 2.1 设计

- **Live band**（底部约 75% 屏高）：状态栏 + prompt + LIVE transcript tail。**原地重绘**（清 band → 重绘 band）。
- **历史区**（band 上方）：已提交行从这里滚入原生 scrollback。

### 2.2 提交协议（核心修正）

分析文档 3.2 的 commit 协议（从 screen row 0 写、cursorDown 回 band 顶）在“一次提交行数 > historyAreaRows”时会越过 band 顶、且 cursorDown 在滚动后方向反转，是**错的**。

**正确协议**：已提交行从**屏幕底部**写入，每个 `\n` 立即把该行滚入 scrollback（与普通 shell 输出一致）：

```
commit(batch, getLatestLiveFrame):
  1. 光标移到屏幕底部（band 底 = height-1）：cursorDown(bandRows-1 - cursorRow)
  2. 逐行写 \r + style + text + SGR0 + \n
     每个 \n 把该行滚入 scrollback；光标钉在 height-1（band 底）
  3. 光标回 band 顶：cursorUp(bandRows-1)   -> cursorRow = 0
  4. liveRegionCapacity 保持 bandRows；previousFrame = null
  5. renderLiveInternal(liveFrame)：清 band 行 → 重绘 band → 定位 cursor
```

这样**每一行已提交历史都进 scrollback**，无论单次提交多少行。band 被覆盖后由步骤 5 重绘。

### 2.3 Band 高度

```ts
const LIVE_BAND_RATIO = 0.75;
const MIN_BAND_ROWS = 8;
liveBandRows = clamp(MIN_BAND_ROWS, height-1, round(height*0.75));
historyAreaRows = height - liveBandRows;
```
24 行：band=18，历史=6。8 行：band=8，历史=0（退化为整屏 band，不出错）。

## 三、具体改动

### 3.1 `src/tui-ui/inline-surface.ts`（核心）

新增字段：
- `liveBandRows: number`（band 高度，mount/resize 时计算）
- `getLiveBandRows(): number`（供 runner 读取）

新增 helper：
- `private computeBandRows(): number` —— 按 2.3 计算
- `get historyAreaRows(): number` —— `height - liveBandRows`

`mount(w,h)`：计算 `liveBandRows`；`liveRegionCapacity=0`；`cursorRow=0`。仍只发 `ENABLE_BRACKETED_PASTE + HIDE_CURSOR`（不发 1049）。

`ensureCapacity(requiredRows)`：目标改为 `min(requiredRows, liveBandRows)`。**首次**（capacity=0）写 `height-1` 个 `\n` 把光标推到屏幕底部（滚动 shell 历史进 scrollback，0 空行新增），置 `liveRegionCapacity=liveBandRows`，`cursorRow=liveBandRows-1`（band 底）。之后 no-op。

`renderLiveInternal(frame)`：
- `requiredRows = min(frame.height, liveBandRows)`
- `ensureCapacity`（首次锚定后 no-op）
- `cursorUp(cursorRow)` → band 顶（cursorRow=0）
- 清 **bandRows** 行（CR+EL2，cursorDown 串接），`cursorUp(bandRows-1)` 回顶
- 写 frame 行（最多 bandRows 行）
- 定位 cursor（相对 band 内），`cursorRow` 跟踪
- SHOW/HIDE cursor、ENABLE_AUTOWRAP

`clearLiveRegion()`：清 **bandRows** 行（不是 height-1）。

`commit()`：按 2.2 协议重写（从底部写、滚入 scrollback、回 band 顶、renderLiveInternal）。**删掉** 旧的 `clearLiveRegion()` 开头与旧的 `cursorRow = min(height-1, cursorRow+committedLines)` 跟踪（新协议光标钉底，无需此式）。

`resize(w,h)`：重算 `liveBandRows`；`liveRegionCapacity=0`；`cursorRow=0`；`previousFrame=null`；`renderLiveInternal(liveFrame)`（首次 ensureCapacity 重新锚定 band 到新底部）。

`suspend()`：清 band、显 cursor、禁 bracketed paste、ENABLE_AUTOWRAP。`restore()`：重绘 band。`unmount()`：清 band、恢复终端、末尾 `\n`。均只动 band（historyArea 在 scrollback 不清）。

### 3.2 `src/tui-ui/runner.ts`

- `getLiveFrame()` 传 `height: this.surface ? surface.getLiveBandRows() : this.height - 1`。
  - 有 surface：用 `liveBandRows`（band 高）。
  - 无 surface（测试）：保持 `height-1`（完整 frame，向后兼容 `renderFullFrame` 路径）。
- `resize()`：已调 `surface.resize`，无需改。

### 3.3 `src/tui-ui/layout.ts`

- `renderTuiLiveFrame(state, {width, height: bandRows})`：promptTop=bandRows-3、statusRow=bandRows-4、liveTranscriptRows=bandRows-4。**不变函数签名**，只由调用方传 bandRows。
- `renderTuiUiFrame`（legacy 全帧，无 surface 测试用）：不变。

### 3.4 `src/tui-ui/state.ts`

- 不变。`RESUME_LIVE_TAIL=50` 保持。

### 3.5 `src/commands/index.ts`

- 不变。resume banner 走 `ctx.writeLine`（→ system entry → finalized → commit → 滚入 scrollback）。

## 七、风险

- **mount 首次锚定**：`height-1` 个 `\n` 假设从近顶部开始。若 shell 光标已在底部，会滚动空行。与当前代码行为一致（当前也写 height-1 个 `\n`），不引入回归。
- **band=height（极小终端）**：historyArea=0，退化为整屏 band，commit 仍从底部写滚入 scrollback，不出错。
- **resume 大量 finalized（10 条）**：10 行从底部滚入 scrollback，band 重绘 tail，符合预期。

## 八、实现中额外发现并修复的问题

实施 band 方案时，PTY 冒烟测试在“长输出 + resize + permission”序列下出现 flaky 失败（“got 0 top border(s) / 2 bottom border(s)”），根因是两个独立缺陷：

### 8.1 autowrap pending-wrap 损坏 prompt 边框（已修复）

`renderLiveInternal` 画 band 行时**未禁用 autowrap**。满宽行（如 `┌` + 98×`─` + `┐` 正好 100 列）写满最后一列后，终端进入 pending-wrap 状态，下一个 `CR`/重绘会让 `┐` 错位/被覆盖，导致 `prompt_frame_rows` 检测不到 top border。

修复：`renderLiveInternal` 开头 `DISABLE_AUTOWRAP`，结尾 `ENABLE_AUTOWRAP`（与 `TuiTerminalWriter.renderTerminalFrame` 的 `bracketAutoWrap` 一致）。保持 prompt 边框满宽，不缩短。

### 8.2 resize reflow 残影（已修复）

resize 后终端对 scrollback/可见行做 reflow，band 上方历史区可能残留旧 prompt 边框（ghost）。`ensureCapacity` 只清 band 行，不清历史区。

修复：新增 `clearVisibleScreen()`（相对寻址逐行 EL2，**非** 2J、**非** 绝对 H），在 `ensureCapacity` 重新锚定 band 时先清整屏可见行再锚定底部。EL2 原地擦除不滚入 scrollback，已 committed 的历史不受影响。

### 8.3 CJK prompt 编辑测试（已修复）

`tui-ui-launch.test.ts` 的 `keeps CJK prompt editing visible` 在 surface diff-rendering + scheduler coalescing 下失败：输入和退格在同一 tick 被合并成一次渲染，pre-backspace 状态未进 stream。

修复：在击键之间 `await tick()` 让前一状态渲染 flush。这是 surface 接入（fix1）带来的既有测试与时序问题，非 band 方案引入。
