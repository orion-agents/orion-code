## Renderer 生效范围

v0.2.23 采用 **Terminal-first 双轨交付**：

- `openhorse --ui terminal`：稳定默认和 P0 主力路径。继续 append-only 完整输出，同时交付输入草稿保护、串行输出与
  backpressure、长会话内存有界、超长输入保护、`Ctrl+L` 无损重绘、session sidecar 修复和 compact/resume 真实验收。
- `openhorse --ui tui`：增强轨道。启用 adaptive collapse、`Ctrl+O` Transcript Inspector、结构化聚合工具展示和交互展开。
- `openhorse --ui ink`：保持现有展示行为，只做新增 optional 类型字段的兼容。
- print / JSON 输出：保持完整、稳定、机器可消费，不应用交互展示策略。

共享 runtime 可以增加 call id、sequence、artifact/detail reference、compact metadata 等 renderer-neutral 元数据，但不得
在共享层决定某个 renderer 是否折叠。Terminal UI 默认完整输出；折叠 policy 只由 TUI adapter 应用。

## 结论先行

v0.2.23 不能只优化 TUI。Terminal UI 是主力入口，必须先完成可靠性收口；TUI 工具输出折叠则必须尊重 v0.2.22
已确定的 native scrollback 架构边界：

1. **Terminal UI 保持完整、append-only 输出。** 不引入历史原地折叠、alternate-screen Inspector 或鼠标接管。
2. **Terminal UI 必须建立明确的输入/输出所有权。** permission prompt 不能清空用户正在输入的 draft；assistant、tool、
   status 输出必须经过同一串行队列并处理 stdout backpressure。
3. **Terminal UI 的 renderer state 必须有界。** 已经写入 native scrollback 的 finalized entry 不应继续以完整正文常驻内存；
   input history 和 subtask timeline 也必须设置上限。
4. **超长输入必须可控退化。** 以 UTF-8 bytes 计量，达到软阈值提示 `/edit`，达到硬阈值拒绝继续增长但不崩溃、不丢失
   已接收内容。
5. **`Ctrl+L` 是无损恢复，不是清屏。** Terminal 和 TUI 都只能重画自己拥有的当前输入/live region，不得清空或 replay
   native scrollback。

6. **TUI 折叠可直接实现。** 工具结束时只把摘要和有限预览提交到 shell scrollback，完整结果继续保存在
   runtime、session trace 和 artifact 中。
7. **已经写入 native scrollback 的历史行不能可靠原地展开。** 普通终端没有跨终端统一的 API，可以安全定位、删除并重写
   任意历史行。使用相对光标移动强行修改会破坏 resize reflow、复制、搜索和当前输入框。
8. **TUI 使用混合模式。** 默认主界面保持 primary screen 和 shell 原生滚动；用户按 `Ctrl+O` 时，显式进入一个临时、
   renderer-owned 的 Transcript Inspector，在 Inspector 内选择工具、展开详情、搜索和滚动，退出后恢复主界面。
9. **折叠只改变展示，不改变事实数据。** 给模型的 tool result、trace、artifact、session transcript、费用统计和工具成功状态
   都不能因 UI 折叠而被截断或改写。
10. **v0.2.23 不追求在主界面点击旧 scrollback 行。** 鼠标点击展开依赖 mouse capture 和 renderer-owned viewport，
   会损害原生文本选择。P0 采用键盘交互；鼠标仅作为 Inspector 内的 P1 能力评估。

因此，本方案的产品定义不是“把 shell 历史变成可折叠 DOM”，而是：

> Terminal UI 提供可靠、完整、原生 shell 风格的主力体验；TUI 提供更高信息密度和显式详情交互；两者共享事实数据，
> 不共享会破坏各自交互模型的展示 policy。

## 问题证据

用户截图中的 `batch_read` 已成功完成 4 个步骤，输出约 3.9 KB。当前 TUI 先展示工具摘要，随后把完整 JSON envelope
作为普通正文提交，其中重复包含：

- 顶层 `success`、`output`、`summary`；
- 每个 step 的 `args`、`success`、`summary` 和完整 `output`；
- 已经在工具 header 中出现过的工具名、步骤数量和输出大小。

这会产生四类问题：

1. 单次工具调用占据数十到数百行，Assistant 正文被挤出当前视口。
2. JSON 转义符和 envelope 字段面向机器而不是用户，扫描成本高。
3. 相同摘要和命令被重复展示，信息密度低。
4. 输出一旦提交到 native scrollback，当前架构没有历史行选择和原地重绘能力。

根因位于展示链路，而不是工具执行链路：

```text
QueryEvent.tool_result
  -> createToolEventPresenter()
  -> StructuredToolActivity.body + legacy TranscriptEntry.content
  -> layoutToolEntry()
  -> pendingCommitRecords()
  -> InlineTerminalSurface.commit()
  -> shell native scrollback
```

当前 `layoutToolEntry()` 在存在 `activity.body` 时会完整排版 body；`tryCommit()` 对 finalized entry 只提交一次。这保证了
native scrollback 的稳定性，也意味着折叠策略必须在 commit 之前完成。

Terminal UI 代码审计同时发现以下主力路径缺口：

- `RawTerminalEditor.ask()` 在权限确认开始时直接把 `value` 和 `cursor` 清空，没有保存用户在流式输出期间输入的 draft。
- `TerminalWriter.write()` 返回 `void`，`RawTerminalEditor.writeExternal()` 直接写 stdout，没有串行 queue、`drain` backpressure
  或 writer shutdown/flush contract。
- `TerminalEventSink.entries`、`printedContent`、`subtaskTimeline` 和 `RawTerminalEditor.history` 没有容量上限；finalize 后仍保留
  已经写入 native scrollback 的完整正文。
- inline input 硬上限为 1,000,000 JavaScript characters，不按 UTF-8 bytes；大 paste 会同时进入 editor value、history、
  session message 等多个位置，仍有内存和延迟风险。
- shared input parser 尚未识别 `Ctrl+L`/`Ctrl+R`；Terminal UI 缺少用户可触发的 prompt-only 恢复和历史增量搜索。
- session scanner 会把合法的 legacy `*.runtime.json` sidecar 当成 session meta 并输出 `missing valid id`，影响 `/sessions`
  和 `/resume` 的主力体验。

这些问题不要求改变 Terminal UI 的 append-only 产品模型；应通过 ownership、queue、bounded state 和 sidecar 分类修复。

## Claude Code 交互参考

调研时间：2026-07-20。只把 Claude Code 作为产品交互参考，不复制其内部实现。

- Claude Code 官方交互文档将 `Ctrl+O` 定义为 Transcript Viewer，用于查看详细工具执行；MCP 调用默认可以压缩成一行。
  参考：[Interactive mode](https://code.claude.com/docs/en/interactive-mode)。
- 官方 Fullscreen 文档说明，全屏模式使用 alternate screen 和 renderer-owned conversation；在该模式下可以点击折叠的工具结果
  展开或再次折叠。参考：[Fullscreen rendering](https://code.claude.com/docs/en/fullscreen)。
- 同一文档明确区分了 renderer-owned history 和 native scrollback，并提供把完整展开内容写回 terminal scrollback 的显式操作。
- 官方 keybinding 文档将 `Ctrl+O` 映射为 `app:toggleTranscript`。参考：
  [Customize keyboard shortcuts](https://code.claude.com/docs/en/keybindings)。

由此可以得出一个可验证的架构判断：

- 动态展开历史块需要应用持有可重排的 transcript viewport。
- shell native scrollback 是 append-only 输出，不适合任意历史块原地切换。
- OpenHorse 可以保留默认 native scrollback，同时在用户显式进入详情模式时临时拥有一个独立 viewport。

## 版本目标

v0.2.23 必须交付：

- Terminal UI permission、interrupt、external output 和 resize 前后不丢失用户 draft、cursor 或 paste parser state。
- Terminal UI 所有 runtime 输出经过严格有序、支持 backpressure 和 flush/shutdown 的单一输出队列。
- Terminal UI 已 finalized 的 transcript/tool/subtask 状态和输入 history 有界，不因 native scrollback 增长而线性占用内存。
- Terminal UI 超长输入以 UTF-8 bytes 计量，软阈值引导 `/edit`，硬阈值安全拒绝新增内容且进程不退出。
- Terminal UI 和 TUI 都支持 `Ctrl+L` 无损重绘各自拥有的 prompt/live region，不清空或 replay native scrollback。
- 修复 legacy `*.runtime.json` 被 session meta scanner 误判的问题，并补 `/sessions`、`/resume`、session delete 回归测试。
- 使用 Terminal UI 完成自动 compact、进程重启、`/resume`、继续任务的真实主力路径验收。
- TUI 工具结果的 adaptive collapse，避免大段 JSON、日志和目录列表淹没 transcript。
- 完整输出仍可通过稳定的 tool reference、`/last-tool`、`/artifacts` 和 Inspector 访问。
- `Ctrl+O` Transcript Inspector：历史工具选择、展开/折叠、滚动、搜索和退出恢复。
- native scrollback 默认行为、终端选择复制、resize 和输入框稳定性不回归。
- tool output 事实和 typed summary 由 renderer-independent view model 生成；Terminal 完整展示，TUI 应用 collapse policy。
- live、commit、resume 和 Inspector 使用同一套 tool identity 和 detail source。
- 对 `batch_read`、subtask batch 等聚合结果提供结构化摘要，不把机器向 JSON envelope 直接当正文展示。
- Terminal/TUI committed transcript 从常驻 renderer state 中安全释放，长会话不因已经写入 native scrollback 的正文持续增长内存。
- `Ctrl+L` 提供不清空 native scrollback 的 renderer-owned region 强制重绘和终端状态恢复。
- Inspector、picker、permission 和 resize 等模式切换完整保留输入 draft、cursor 和 paste 状态。
- 极窄窗口和快速 resize 采用受限 live region，减少终端物理 reflow 造成的输入框残线和重复边框。
- CJK、emoji、ANSI、超长单行、二进制样式内容和错误输出安全退化。
- Terminal、Ink 和 print renderer 不因协议扩展而出现行为回归。

## v0.2.22 现状审计

Terminal UI 以下能力已经存在，v0.2.23 只作为回归门禁，不重复重写：

- stable default renderer、完整 append-only tool/assistant 输出和原生 scrollback。
- CJK/emoji grapheme 编辑、Backspace/Delete、`Home/End`、多行 `Up/Down`。
- Alt/Option+Enter、`Ctrl+J`、bracketed/unbracketed multiline paste、`/paste` 和 `/edit`。
- 输出期间恢复当前 prompt、resize 重绘、live revision、permission、`/resume` picker 和双 Ctrl+C 退出。
- prompt 已显示 context 百分比和 compact 提醒；cost 不做实时常驻显示。

TUI 以下能力已经存在，v0.2.23 只作为回归门禁，不重复重写：

- multiline prompt、视觉行内的 `Up/Down/Home/End`、paste 和动态输入高度已经实现。
- 主界面使用 primary-screen Inline TUI，提交历史保持 append-only native scrollback。
- `InlineTerminalSurface` 已做 changed-row diff；render scheduler 已做 30 FPS 上限和帧合并。
- transcript layout cache 已限制为 256 项；runtime tool events 和 subtask timeline 已限制为 100 项。
- tool lifecycle 已按 `(callId, type)` 去重；`/last-tool`、`/trace`、`/artifacts` 已可追溯完整结果。
- resize generation、pending write 和 PTY 回归路径已经建立。

Terminal UI 当前代码级缺口：

1. permission `ask()` 清空当前 value/cursor，未恢复流式输出期间的用户 draft。
2. writer 没有 backpressure、flush 和 shutdown contract；每次 external write 都单独 clear/render prompt。
3. transcript entries、printed content、subtask timeline 和 input history 无容量上限。
4. 1,000,000 character 上限不等于 UTF-8 byte 预算，超大输入仍会被多处复制。
5. 没有 `Ctrl+L` prompt-only recovery 和 `Ctrl+R` 增量 history search。
6. legacy `*.runtime.json` 被全局 session list 当成 meta 文件并产生错误 warning。

TUI 当前代码级缺口：

1. `TuiUiState.transcript` 在成功 commit 后只推进计数，不释放已提交正文；长会话仍会线性持有完整 transcript。
2. 聚合工具虽然已有 batch metadata，但最终 body 仍可能以完整 JSON envelope 展示，缺少面向人的 step view model。
3. input parser 尚无 `Ctrl+O`、`Ctrl+L` 和 `Ctrl+R`，也没有统一的 modal input ownership 协议。
4. 终端出现外部污染或异常 resize 后没有用户可触发的无损重绘动作。
5. 内置主题仍以 dark + RGB 为默认，只支持 `NO_COLOR` 抑制，没有 color-depth 降级和 light/high-contrast preset。
6. 突然缩至 `24x8` 等极端尺寸时，终端可能在收到 `SIGWINCH` 前把过高 live region reflow 到 native scrollback；
   应通过更小的 live-region 上限降低影响，并用真实终端验收残余限制。

| 快捷键可发现性 | `? shortcuts`、Inspector footer 和折叠提示统一展示 `Ctrl+O/Ctrl+L/Ctrl+R` | 每会话最多一次上下文提示，不重复污染 transcript |
| Inspector 内鼠标 | 只在 alternate-screen Inspector 中可选开启，退出必须关闭 mouse capture | 主界面文本选择和滚轮始终归终端 |

P1 的实现不得拖延 P0 稳定性修复。若 Terminal Markdown/`Ctrl+R`、TUI theme preset 或 Inspector mouse 未达到门禁，
应在 release note 明确延期，
不得以半成品默认开启。

### P2：明确延期

- 主界面旧 scrollback 行鼠标点击展开。
- 默认常驻 alternate screen、pane/window manager 或 dashboard 化布局。
- 自定义快捷键编辑器和完整 keybinding DSL。
- Terminal UI 历史工具原地折叠、alternate-screen Inspector 或主界面 mouse capture。
- Terminal UI 实时 cost 常驻显示；cost 继续通过命令/持久化 usage 查询。
- 修改 Ink 或 print 的工具输出展示策略。
- 试图用 `CSI 2J`、`CSI 3J` 或重启 shell 清理已经产生的 native scrollback。

## 非目标

- 不把默认 TUI 改回常驻 alternate screen。
- 不把 Terminal UI 改为 renderer-owned 全屏界面；它继续是 shell-native append-only 主力入口。
- 不在 Terminal UI 默认折叠工具结果；完整输出和命令必须保留。
- 不在 primary screen 接管鼠标滚轮或文本选择。
- 不尝试删除、覆盖或原地重写 shell scrollback 中已经提交的行。
- 不改变模型可见 tool result，不以 UI preview 替换模型上下文中的结果。
- 不让 renderer 直接读取任意 artifact 文件；读取必须经过统一 detail repository 和 redaction。
- 不重新设计 `/trace`、`/last-tool` 和 `/artifacts` 的底层存储格式。
- 不在本版本构建通用 pane/window manager。
- 不以 retained in-memory transcript 作为历史详情的唯一来源；历史恢复必须依赖 durable session/trace/artifact。
- 不要求 Terminal UI 提供 TUI Inspector；不要求 Ink 提供新增交互，但必须兼容新增 runtime contract。

## Terminal UI 产品交互规范

### 1. Scrollback Contract

- assistant、tool、status、resume 和 compact 事件按发生顺序写入 native scrollback，默认不折叠、不重写。
- runtime 输出只能通过 `TerminalOutputQueue -> RawTerminalEditor.writeExternal()`，禁止模块直接 `process.stdout.write()`
  绕过 prompt ownership；启动 banner 和最终 shutdown newline 是唯一受控例外。
- 工具 start/final、permission decision 和 assistant final 必须保持严格 timeline；backpressure 只能延迟，不能重排或丢弃。
- 写入完成后 renderer 可以释放 heavy body，但 session JSONL、trace、artifact 和模型上下文不能改变。

### 2. Modal Draft Preservation

permission prompt 开始前按下文 `TerminalEditorDraftSnapshot` contract 保存 value、cursor、parser state、history cursor/draft
和 input-limit notice state。snapshot 必须深拷贝，且只能存在于当前 modal transaction。

approve、deny、abort、signal 和 throw 均走同一 `finally restoreDraft()`。权限回答使用独立 question buffer，不能复用并清空
普通 prompt buffer。若用户在 question 模式输入了非 y/n 内容，应明确拒绝并继续询问，不得把它混入原 draft。

### 3. Output Queue And Backpressure

- queue 使用下文唯一的 `TerminalOutputBatch` / `TerminalOutputQueue` contract；`enqueue()` 返回的 Promise 是该 batch
  已完成 writer 写入的 acknowledgement。
- queue 保留 FIFO；相邻 assistant deltas 可在 8-16 ms 内合并，但 tool/status 边界不能跨越。
- `output.write()` 返回 false 后等待 `drain`，等待期间 editor 仍接收输入，只暂停外部输出 flush。
- 每个 flush batch 只 clear prompt 一次、写入一批外部内容、render prompt 一次。
- stop/shutdown 必须先停止新 enqueue，再 flush 或按超时安全终止，最后恢复 raw mode、cursor 和 bracketed paste。

### 4. Input Budget And Recovery

推荐默认值：soft `64 KiB`，hard `256 KiB`，均按 UTF-8 bytes 计算；配置必须设安全上下界。超过 soft threshold
只提示一次 `/edit`；超过 hard threshold 时拒绝新增 grapheme，保留既有内容并继续可编辑。history 不复制超过 soft threshold 的
完整内容，可保存 bounded preview 或不进入 local history；durable session 仍在提交成功后保存一次。

Terminal `Ctrl+L` 只执行：cancel pending render -> clear known editor rows -> invalidate layout snapshot -> render current prompt。
不得发送 `CSI 2J/3J`，不得 replay transcript，连续触发必须 coalesce。`/redraw` 只作为 TUI fallback，不在 Terminal 注册。

### 5. Context、Compact And Cost

- prompt 保留 `ctx=N%`、80% `/compact` 提醒和 95% `auto-compact` 状态。
- 自动 compact 属于 Agent Core；Terminal UI 只展示 Store snapshot 和 compact lifecycle event。
- cost 不实时常驻 prompt；累计成本通过 `/cost`、session metadata 或 status 命令查询。
- `/resume` 展示 summary、generated time/source、covered messages 和 model-context/transcript restored counts。

### 1. 默认 Adaptive 模式

```json
        "errorPreviewMaxBytes": 2048
      }

```

显示模式：

- `adaptive`：小输出完整显示，大输出折叠并展示有限预览；默认值。
- `collapsed`：所有非空工具输出只显示摘要和详情提示。
- `full`：保持 v0.2.22 的完整输出行为，作为调试和兼容模式。

判定优先级：

1. 无 body：只显示 header。
2. 工具失败：显示错误摘要和较大的 error preview，不能把关键报错完全折叠。
3. 明确结构化且高噪声的聚合工具，如 `batch_read`：默认折叠，即使结果字节数较小。
4. 同时不超过 `inlineMaxLines` 和 `inlineMaxBytes`：完整内联。
5. 其他情况：显示 preview、折叠提示和 detail reference。

## 核心架构

v0.2.23 保持一套 Runtime 事实源，建立两条明确不同的 renderer 路径：

```text
Tool execution / QueryEvent
  -> AgentRuntimeController
     -> StructuredToolActivity + full tool fact + stable references
        -> TerminalUiAdapter
           -> TerminalEventSink
           -> TerminalOutputQueue
           -> RawTerminalEditor.writeExternalBatch()
           -> shell native scrollback (full append-only output)
        -> TuiUiAdapter
           -> ToolOutputPresentationPolicy
           -> ToolOutputView { summary, preview, detailRef, metrics, collapsed }
           -> TuiUiReducer
              -> InlineTerminalSurface.commit(summary/preview only)
              -> shell native scrollback
           -> ToolDetailIndex
              -> TranscriptInspectorController
              -> ToolDetailRepository.lazyLoad(detailRef)
              -> TranscriptInspectorSurface (temporary alternate screen)

Durable sources
  Session JSONL + compact checkpoint + trace + tool artifacts
    -> ToolDetailRepository
       -> redacted detail stream
```

架构原则：

- Runtime 决定工具事实、compact 边界和可追溯引用；renderer 决定当前展示密度，不决定是否 compact。
- Terminal adapter 始终选择完整 output，TUI adapter 才应用 adaptive/collapsed/full policy。
- Terminal 的输出所有权集中在 `TerminalOutputQueue`，任何 runtime sink 不得绕过 queue 直接写 stdout。
- Terminal 在 queue 确认写入后释放 finalized heavy state；native scrollback 和 durable session 是已提交事实源。
- Policy 只生成 presentation，不修改原始 tool result。
- Native scrollback commit 继续 append-only 和 exactly-once。
- Inspector 是一个显式、可恢复、临时的 renderer mode，不是默认 TUI surface。
- Detail lazy load 必须有字节上限、分页或流式读取，不能把超大输出一次复制进内存。

### 扩展架构边界

v0.2.23 增加 Terminal 主力链路和 TUI 增强链路的独立边界：

```text
Terminal modal interaction
  -> RawTerminalEditor.captureDraft()
  -> permission / picker / external editor
  -> restoreDraft() in finally

Terminal runtime output
  -> TerminalOutputQueue.enqueue(batch)
  -> ordered write
  -> wait for drain when write() returns false
  -> acknowledge batch
  -> evict finalized heavy entry

Known aggregate tool result
  -> AggregateToolPresenter (schema-guarded, renderer-neutral)
  -> ToolOutputView.aggregate
  -> TUI compact rows / Inspector step rows

InlineTerminalSurface.commit(batch)
  -> write succeeds
  -> acknowledgeCommittedBatch(batchId, generation, recordIds)
  -> evict exact committed prefix from renderer hot state
  -> retain only bounded recent metadata

TUI mode transition
  -> InputOwnershipController.capture()
  -> Inspector / picker / permission interaction
  -> InputOwnershipController.restore()

Ctrl+L / surface recovery
  -> wait for queued commit
  -> invalidate only live-region snapshot
  -> erase owned rows
  -> repaint latest frame and restore cursor
```

边界约束：

- Terminal queue acknowledgement 必须发生在实际写入完成之后；blocked write、shutdown 或 writer error 时禁止提前释放正文。
- permission/picker 等 modal interaction 只能通过 editor snapshot transaction 切换输入所有权；`finally` 是唯一恢复出口。
- Terminal bounded state 只保留最近轻量 metadata；完整正文不得同时长期驻留在 sink、printed cache 和 editor history。
- `AggregateToolPresenter` 只解析 OpenHorse 自己定义、带 schema/version 的聚合结果；未知 JSON 仍按普通 text/json policy 处理。
- commit acknowledgement 必须带 `batchId + transcriptGeneration + recordIds`，不能只按数量删除，避免 resize、resume 或异步回调
  误删新 generation 的记录。
- 已写入 shell 的正文不再是 renderer state 的事实来源。Inspector 和 resume 通过 session/trace/artifact repository 分页加载。
- modal 输入所有权只能由 runner 切换；surface、layout 和命令 handler 不能分别保存一份 prompt draft。
- force redraw 不能清理 shell history，不能重新 commit transcript，只能重画当前 TUI-owned live region。
- compact frame 是小尺寸下的正常布局状态，不允许依赖 catch 后清屏恢复。

## 数据契约设计

### Terminal UI Contracts

建议新增 Terminal 专属、不可持久化的 renderer contracts：

```typescript
export interface TerminalEditorDraftSnapshot {
  value: string;
  cursor: number;
  parserState: TerminalInputParserState;
  historyCursor?: number;
  historyDraft?: string;
  inputLimitNoticeShown?: boolean;
}

export interface TerminalOutputBatch {
  id: string;
  chunks: readonly string[];
  releaseEntryIds: readonly string[];
}

export interface TerminalOutputQueue {
  enqueue(batch: TerminalOutputBatch): Promise<void>;
  flush(): Promise<void>;
  close(): Promise<void>;
}

export interface TerminalRetentionPolicy {
  maxInputHistory: number;       // default 500
  maxFinalizedMetadata: number;  // default 512
  maxSubtaskTimeline: number;    // default 100
  inputSoftBytes: number;        // default 64 KiB
  inputHardBytes: number;        // default 256 KiB
}
```

约束：

- snapshot 仅存在于当前 modal transaction，不写 session、trace 或日志，避免把尚未提交的用户输入持久化。
- queue 必须 FIFO；同一 batch 内只清理/重画一次 prompt，避免每个 chunk 反复擦除输入区。
- `enqueue()` resolve 表示所有 chunk 已写入 writer；只有此时 sink 才能按 `releaseEntryIds` 释放 heavy state。
- 输入上限按 UTF-8 bytes 计算；软阈值只提示，硬阈值拒绝新增 bytes，但保留已有 draft 并允许删除、提交或 `/edit`。
- retention policy 必须有默认值和配置校验；非法值回退默认值，不能形成无界数组。

### 5. Committed Transcript Eviction

当前 `markTranscriptCommitted()` 只累加 `committedTranscriptCount`。v0.2.23 应以精确 acknowledgement 替代“计数即成功”：

```typescript
export interface TranscriptCommitAcknowledgement {
  batchId: string;
  generation: number;
  recordIds: string[];
}

export interface RendererTranscriptWindow {
  records: TuiTranscriptRecord[];
  baseSequence: number;
  queuedCount: number;
  committableCount: number;
  committedCount: number;
}
```

提交成功后的 reducer 事务：

1. 校验 generation、batch id 和 record id 前缀与当前窗口完全一致。
2. 把需要 Inspector 最近访问的轻量 metadata 写入 `recentToolDetails`，上限默认 512。
3. 删除已经确认写入的 finalized prefix，不保留 `content`、styled rows 或 full output。
4. 同步减少 queued/committable/committed 边界并推进 `baseSequence`。
5. acknowledgement 不匹配时拒绝 eviction，记录可诊断 warning，并安排一次 live-region redraw；不能猜测删除。

约束：

- surface write reject、partial write、generation 变化或 runner shutdown 时不得 eviction。
- durable session/trace 写入是 Runtime 的责任；renderer eviction 不删除任何可审计历史。
- Inspector 首屏可使用 bounded recent index，向前翻页必须调用 repository，不能要求 state 中保留全部历史。
- resume 加载 transcript 时仅把当前可见/live 窗口放入 hot state；其余历史通过 repository cursor 访问。

### 6. Input Ownership

所有 modal interaction 共用一个 controller：

```typescript
export interface TuiInputDraftSnapshot {
  value: string;
  cursor: number;
  parserState: TuiInputParserState;
  historySearch?: {
    query: string;
    selectedIndex: number;
    originalDraft: string;
  };
}

export type TuiInputOwner =
  | 'prompt'
  | 'inspector'
  | 'session-picker'
  | 'file-picker'
  | 'permission'
  | 'history-search';
```

- owner 切换是单向状态机：capture current -> activate target -> close target -> restore prior。
- snapshot 必须深拷贝 paste buffer 和 incomplete UTF-8 buffer，不能共享可变 `Buffer`。
- modal 关闭、异常、signal 和 resize 都走同一 restore path。
- `Ctrl+O`、`Ctrl+L`、`Ctrl+R` 只由当前 owner 解释；普通文本和 bracketed paste 不经过快捷键猜测。

### 7. Surface Recovery And Compact Layout

`InlineTerminalSurface` 新增受队列串行化保护的 `forceRedraw()`：

```typescript
forceRedraw(getLatestLiveFrame: LiveFrameProvider): Promise<TuiTerminalRenderResult>;
```

实现要求：

- 等待已排队 commit 完成，失效 changed-row snapshot，然后只 erase `ownedLiveRows`。
- 重新测量 columns/rows，布局最新 state，一次写入并恢复 cursor visibility、DECAWM 和 bracketed paste。
- 禁止发送 `CSI 2J`、`CSI 3J`，禁止重新提交静态 transcript。
- `Ctrl+L` 连续触发应 coalesce，surface 已关闭时为安全 no-op。

小窗口布局建议：

- `rows >= 12`：沿用动态预算，但 live transcript tail 默认最多 `min(8, floor(rows * 0.25))` 行。
- `8 <= rows < 12`：status 压缩为一行，live transcript 最多一行，composer 保留 3-5 行。
- `rows < 8` 或 `columns < 32`：进入 compact frame，隐藏非关键 model/cost metadata，composer 使用无边框或单边框模式。
- prompt 的可编辑行和 cursor 永远优先于装饰、shortcut hint 和 running timeline。
- 任何尺寸都不得构造负高度、超宽 border 或写到终端最后一列触发 pending wrap。

### 8. Theme And Color Profile

主题选择属于 TUI 配置：

```typescript
type TuiThemePreset = 'dark' | 'light' | 'high-contrast' | 'auto';
type TuiColorProfile = 'truecolor' | 'ansi256' | 'ansi16' | 'none';
```

- `auto` 只根据显式环境能力选择 color profile，不猜测终端背景；背景 preset 仍使用稳定默认或用户配置。
- `COLORTERM=truecolor|24bit` 才使用 RGB；否则按 TERM 能力降级到 256/16 色。
- `NO_COLOR` 或非 TTY 使用 `none`，但 success/error/running/collapsed 必须保留文字 marker。
- 用户输入灰白底必须与 user text 达到可读对比；light preset 不得继续使用浅底浅字。
- theme id 继续进入 transcript layout cache key，切换主题必须 invalidation，不得复用旧 styled rows。

### 9. Inspector Surface

新增：

```text
src/tui-ui/transcript-inspector.ts
src/tui-ui/transcript-inspector-layout.ts
src/tui-ui/transcript-inspector-surface.ts
```

职责分离：

- controller：状态转换、详情 lazy load、搜索和 key actions。
- layout：把 Inspector state 变为 viewport rows，不写 stdout。
- surface：只管理 alternate screen、cursor、mouse optional、resize 和终端恢复。
- runner：在 Inline mode 和 Inspector mode 之间切换 input owner。

禁止把 Inspector 逻辑塞进 `InlineTerminalSurface`。两个 surface 的 ownership 不同，混在一起会重新引入 v0.2.21 的
scrollback 和退出恢复问题。

## 关键流程

### 工具完成并折叠

```text
tool_result
  -> persist full output / artifact
  -> createToolOutputView()
  -> emit StructuredToolActivity(outputView, detailRef)
  -> finalize transcript entry
  -> TUI layout adaptive summary/preview
  -> commit once to native scrollback
```

事务顺序必须保证 detail source 先于 summary commit 可用。若 artifact 持久化失败：

- 小输出可以退化为 inline full。
- 大输出必须显示 `detail unavailable` 警告，不能错误声称 full output retained。
- 工具本身的成功状态不因展示 artifact 写入失败而改成执行失败，但要记录 renderer/runtime diagnostic。

### 打开 Inspector

```text
Ctrl+O
  -> save prompt/input state
  -> InlineTerminalSurface.suspend()
  -> enter alternate screen
  -> load detail metadata only
  -> render virtualized inspector viewport
  -> user expands one entry
  -> lazy read detail page
```

### 退出 Inspector

```text
q / Esc / Ctrl+O / signal / error
  -> cancel pending detail reads
  -> disable mouse if enabled
  -> leave alternate screen
  -> restore cursor + bracketed paste
  -> InlineTerminalSurface.restore()
  -> rebuild current live frame
  -> restore prompt/input/cursor
```

恢复流程必须幂等；重复调用 `close()` 不得再次输出破坏性 terminal sequence。

### Resume

```text
/resume
  -> restore transcript and session id
  -> rebuild ToolDetailIndex from trace metadata
  -> do not load artifact bodies
  -> main transcript remains summary/preview
  -> Ctrl+O can lazy-load historical detail
```

如果旧 session 没有新 `detailRef`，使用 `sequence + callId + artifactId` 兼容推导；无法推导时显示旧内容或
`detail unavailable for legacy session`。

- incomplete UTF-8、bracketed paste 中途和 multiline draft 在 modal 进入/退出后完整恢复。
- 选择、展开、折叠、toggle all、search、next/previous。
- `Ctrl+R` 搜索、继续搜索、Esc 回退、Enter 采用和原 draft 恢复。

- Inspector 展开状态不写入 durable session。
- Resume 后 tool sequence、call id 和 detail ref 稳定。

- 256 KiB 附近的大段 paste 不导致异常退出；超限后给出稳定提示并保留可编辑 draft。

- `/sessions`、`/resume`、delete 在存在全部 sidecar 时无伪 warning，compact 后重启继续任务不重复旧上下文。

普通 TUI：

### 性能门禁

- Terminal 连续 10 MB 输出不做正文全量二次拼接，queue backlog 可观测且受 writer backpressure 约束。
- Terminal 10,000 条 finalized event 后 retained heavy content 为 0，轻量 metadata/history 不超过配置上限。
- blocked writer 不 busy-loop；事件循环可继续处理 resize、abort 和 shutdown signal。
- 10,000 条 tool metadata 列表只 layout 当前 viewport。
- 10,000 条 finalized transcript commit 后，renderer heavy records 保持在配置的 hot-window 上限内。
- 10,000 条 metadata 的 Inspector 搜索不读取 full artifact body，搜索延迟目标小于 100 ms。
- Inspector 初次打开不读取任何 full artifact body。
- 单个 10 MB artifact 使用分页读取，峰值额外内存目标小于 10 MB。
- 快速上下移动和连续 resize 不产生 stale async detail 覆盖。
- 主 TUI stream scheduler 和 30 FPS 上限不回归。
- 连续 1,000 次 `Ctrl+L` 由 scheduler/surface coalesce，不产生无界写队列。

## 验收标准

### Terminal UI 主力场景

- 默认 `openhorse` 和显式 `--ui terminal` 都进入稳定 Terminal UI，不改变用户既有启动方式。
- 用户在 assistant streaming 或工具运行时输入 multiline/CJK draft，permission/picker 插入后内容和 cursor 不丢失。
- 工具输出保持完整 append-only；10 MB 分块输出不乱序、不重复、不破坏 prompt，结束和退出前 queue 均完成 flush。
- 10,000 条 finalized tool/subtask event 后 renderer state 保持在 retention 上限，native scrollback 内容仍完整。
- 64 KiB 后提示 `/edit`，256 KiB 后拒绝新增 bytes 但不退出；用户仍可编辑、删除或提交已有内容。
- `/sessions` 不把合法 sidecar 报成损坏 meta；`/resume` 和 delete 对 `.runtime.json`/`.compact.json` 行为一致。
- 自动 compact 后重启并 `/resume`，恢复 checkpoint 模型历史而不是完整旧上下文，摘要时间、来源和覆盖数准确。
- `Ctrl+L` 能修复 prompt 残影，同时不清空 shell scrollback、不创建 session message、不改变 context/cost。

### TUI 截图场景

对用户截图中的 `batch_read -> 4 steps -> 3.9 KB`：

- 主 TUI 最终只占最多 5 个 visual rows。
- 必须显示成功状态、工具名、4 steps、耗时、3.9 KB 和 collapsed 提示。
- 不直接展示顶层 JSON envelope。
- `Ctrl+O` 后能选择该工具并查看完整 4 个 step。
- 每个 step 的 args、summary 和 output 可辨识，不重复渲染相同 envelope。
- 退出 Inspector 后输入框、scrollback 位置和用户未提交输入保持不变。

### 数据完整性

- UI 折叠前后，模型收到的 tool result 字节内容一致。
- trace 和 artifact 中的完整输出一致。
- `/last-tool #N --full`、Inspector 和 `/artifacts show` 使用同一 detail source。
- Secret redaction 规则在三个入口一致。
- Resume 后仍可读取 compact 前后持久化的工具详情。

### Native Scrollback

- Terminal UI 和默认 TUI 主界面都不进入 alternate screen。
- 已提交历史不被重绘、删除或原地修改。
- 终端原生搜索、选择、复制和鼠标滚动继续可用。
- Inspector 只在显式打开期间接管 viewport，退出后完整恢复。

### 长会话与恢复

- Terminal queue acknowledgement 和 TUI commit acknowledgement 后，heavy transcript record 从 renderer hot state 释放，
  但 session JSONL、compact checkpoint、trace 和 artifact 不变。
- 10,000 条 transcript / tool metadata 场景下，主界面 render 成本不随完整历史线性增长。
- resume 不把全部历史正文重新常驻 Terminal/TUI state；TUI Inspector 可按 cursor 分页访问旧记录。
- timeout、cancel、provider error、tool error 和进程恢复后均不存在永远 `running` 的 tool/subtask 行。

### 输入与尺寸

- Terminal permission/session picker/external editor，以及 TUI `Ctrl+O`、picker、permission 和 `Ctrl+R` 前后都保留 multiline
  draft、cursor 和 paste/parser state。
- `Ctrl+L` 后 session、token/cost/context 状态、输入 draft 和 native history 不变。
- Terminal 输入预算按 UTF-8 bytes 执行，软/硬阈值不会截断 grapheme、制造 lone surrogate 或终止进程。
- 快速 resize 与窗口切换后不出现永久重复边框、超宽行、负高度或 cursor 跑出 composer。
- 极端终端尺寸无法避免的 shell reflow 必须记录为平台限制，但 OpenHorse 不得崩溃或继续累积残行。

## 风险与控制

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| Terminal modal snapshot 恢复遗漏 | 用户未提交输入丢失或重复 | capture/restore transaction + `finally`；approve/deny/abort/throw PTY 矩阵 |
| Terminal queue blocked 或 drain 永不到达 | 输出停滞、无法退出 | writer error/abort/close 状态机、flush timeout 诊断、禁止 busy-loop |
| queue acknowledgement 前提前 eviction | 完整输出永久不可见 | acknowledgement 是唯一 release 条件；write failure 保留 entry 并记录 diagnostic |
| 超长输入按字符而非 bytes 计量 | CJK/emoji 超预算或被截断 | 所有入口统一 `Buffer.byteLength`，split paste 和 external editor 边界测试 |
| bounded state 删除了 durable history | resume/审计缺数据 | 只清 renderer cache；先持久化 Session/trace/checkpoint，再允许 renderer release |
| sidecar 过滤过宽 | 真正损坏 session 被静默忽略 | 仅排除明确 suffix；损坏 `<sessionId>.json` 继续 warning，delete 使用同一分类表 |
| Terminal Markdown parser 阻塞流式输出 | 主力路径延迟或输出重排 | P1 line-oriented renderer、无完整文档回溯、可按 capability 回退 plain text |
| 把折叠误用到模型上下文 | Agent 得不到完整结果 | presentation policy 只存在 UI event 路径；增加字节一致性测试 |
| Artifact 不存在却显示可展开 | 用户进入详情后失败 | commit 前验证 detail source；缺失时明确降级 |
| Inspector 异常退出泄漏 alt screen | 终端不可用 | 独立 idempotent surface、finally restore、signal PTY tests |
| Ctrl+O 与终端/输入冲突 | 无法进入或误提交 | input parser 独立 key token，允许 `/tools` fallback |
| 超大详情导致内存上涨 | 长会话卡顿或 OOM | metadata-first、分页读取、LRU、取消旧请求 |
| commit 后过早 eviction | 未写入内容从界面丢失 | generation + batchId + exact record IDs acknowledgement；write 成功前禁止释放 |
| recent detail index 自身无限增长 | 修复正文后仍有 metadata 泄漏 | bounded hot index + repository cursor paging，不在 state 保留全量历史 |
| 聚合 schema 漂移 | step 摘要错误或详情不可查 | schema/version guard，失败时降级普通 output view，禁止 renderer 猜字段 |
| `Ctrl+L` 误清历史或重复提交 | native scrollback 数据损坏 | 只 erase owned rows，禁止 `CSI 2J/3J`，commit/redraw 共用串行 surface queue |
| modal 切换丢 draft | 用户输入丢失 | 单一 Input Ownership Controller、deep snapshot、异常路径统一 restore |
| 极窄窗口仍发生 shell reflow | 少量历史行被终端重排 | compact frame + live-row hard cap；记录平台限制并做真实 Terminal 验收 |
| RGB 主题在低色深终端不可读 | 用户输入和状态不可辨识 | color profile 检测、256/16 色映射和非颜色 marker |
| Mouse capture 破坏原生选择 | 用户体验倒退 | P0 不在主界面启用 mouse；Inspector mouse 仅 P1 |
| Resume 后引用失效 | 历史详情不可查 | stable callId/sequence/artifactId，legacy fallback 测试 |
| Preview 泄漏 secret | 安全问题 | redaction 在 repository/runtime 边界完成，renderer 不绕过 |

## 已冻结产品决策

以下作为 v0.2.23 默认实现约束；后续调整必须先更新本文档和对应测试：

1. Terminal UI 是稳定默认和发布主力；P0-A Slice 1-3 先于 TUI 新交互完成。
2. Terminal 工具输出保持完整 append-only，不做历史原地折叠，不进入 alternate screen，不接管 mouse。
3. Terminal 输入默认 soft limit 64 KiB、hard limit 256 KiB；history 500、finalized metadata 512、subtask timeline 100。
4. Terminal/TUI `Ctrl+L` 都只重绘 renderer-owned live region，不提供清屏语义；TUI 保留 `/redraw` fallback。
5. cost 不在 Terminal/TUI 实时常驻展示；context 使用 Store snapshot，95% compact 仍由 Agent Core 触发。
6. TUI 工具输出默认 `adaptive`；大输出 preview 4 行 / 1 KB，错误 preview 8 行 / 2 KB，`full` 保留作调试模式。
7. TUI `Ctrl+O` 打开临时 alternate-screen Inspector；默认主界面仍保持 native scrollback。
8. 可见 collapse、`Ctrl+O` 和 Inspector 只在 `--ui tui` 生效；Terminal 只接收共享事实字段并完整展示。
9. TUI renderer hot metadata 默认保留最近 512 条；更早历史由 repository 分页读取。
10. Terminal append-only Markdown、Terminal/TUI `Ctrl+R`、theme preset 和 Inspector mouse 属于 P1；P0 未完成前不得优先开发。
