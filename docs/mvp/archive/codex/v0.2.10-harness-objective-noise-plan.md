# v0.2.10 Harness 目标连续性与降噪方案

## 目标

让 OpenHorse 在长会话里能持续沿着**用户核心目标**推进，同时把 prompt 中的“噪音”压到最低：

- 关键意图稳定：短反馈、补充、质疑不会覆盖根任务。
- 只保留有价值上下文：工具结果优先摘要化，重复/低价值事实降权。
- compact 与 resume 可复用：重载后仍能继续“下一步该做什么”。
- /harness explain 能说明**为什么入模**和**为什么被剔除**。

## OpenHorse 现状与差距

**已具备**（可复用）

- `src/harness/context-harness.ts`：`rootObjective`、`activeInstruction`、`taskEpoch`、`intentHistory`。
- `src/harness/intent.ts`：区分新任务/补充/修正/验证/配置/反馈。
- `src/harness/evidence.ts` + `src/harness/assembler.ts`：有 evidence 排序与预算装配能力。
- `src/services/compact/compact.ts`：compact 时保留结构化 context state。
- `src/commands/index.ts` `/harness explain`：已输出 include/omit 证据清单。

**关键差距**

1. `contract`/`objective` 仍有被单条输入重写的风险，需强化“新任务才更新根目标”。
2. 当前证据源偏“宽”：`tool_result`、`decision`、长输出容易把短期噪音拖入长期上下文。
3. compact/reconcile 的来源是单点状态+历史，缺少“版本一致性诊断”（transcript 与 sidecar 冲突时要明确降级策略）。
4. 大量短目标更新场景下，上下文仍可能被重复“重复历史化”占用预算，导致关键限制、待办、验证信息被挤出。

## 方案设计

### 1）把目标控制作为稳定层

- 在 `ContextHarness` 引入明确的 `GoalState`，并定义三层目标：
  - `goalRoot`（根目标）
  - `activeInstruction`（当前轮次目标）
  - `openObjectiveSignals`（待消化的补充信号）
- 意图规则改为：
  - 仅 `new_task` 和显式“替换/中断”类意图才更新 `goalRoot` 与 `taskEpoch`。
  - `refine_current_task / continue_current_task / casual_or_feedback / verify_or_test` 不改根目标。
- 现有 `createTaskContract/updateTaskContract` 继续保留，但新增 `rootObjective` 与 `activeInstruction` 的一致性校验器。

### 2）降噪：证据按“任务价值”进入上下文

- 对 `ContextLedger` 做“可持久化噪音闸道”：
  - 低价值 `user_requirement`/`verification` 重复项降级为 `session` TTL。
  - 高频失败日志不直接进 evidence，先入 `turnSummary.unresolved`。
  - 工具输出默认只吃摘要（`summary`/短摘要）及关键元数据（工具名、路径、退出码）。
- 在 `evidence.ts` 中加 `signal` 评分维度：
  - 与当前输入/活动文件/工具高度匹配加分。
  - 与当前 `taskEpoch` 一致加分。
  - unresolved/失败项保底保留，但设上限。
- 保留 `maxEvidencePerTurn`，超出部分转为 `omittedEvidence` 并记录原因。

### 3）Prompt 装配：从“单段大文本”转为“可解释片段”

- `assembleMessages` 继续注入动态 harness context，但结构按片段输出：
  1. Core Goal（根目标/当前指令/约束）
  2. Active todos + verification（未完成高优先）
  3. Evidence（按分值）
  4. Recent turn summaries（最近 4~6）
- 新增 `PromptAssemblyPlan`（固定配额）：
  - Core: 不得低于 6%
  - Open todos / verification: 不得低于 10%
  - Evidence: 不得低于 18%
  - Recent turns: 不得低于 12%
  - 剩余给模型上下文缓冲
- `PromptAssemblyStats` 增加 `rejectionsByReason`（e.g. budget/duplication/low-score）。

### 4）compact / resume 的一致性

- `/compact` 输出必须保留：
  - 根目标快照
  - 当前验证状态（passed/failed/warn）
  - open todos + next action
- `resume` 时做三路重建：
  - sidecar（优先）
  - session meta `harnessState`（补齐）
  - transcript 重演摘要（兜底）
- 加 `reconciledAt` 与 `diagnostics`：若 transcript 与 state 冲突，标记可读告警而不是静默覆盖。

### 5）/harness explain 与可观测性

- `showHarness(explain)` 增强：
  - 输出 “为何本轮保持/更换 objective”
  - 输出 top-k 入模证据、被剔除证据（按原因分组）
  - 输出 `turnSummaryDigest`（最近 unresolved、风险、待验证命令）
- `collectDoctor` 新增一项：`harness.noise_ratio = omitted / total`。

## 验证策略

### 自动化

- Unit：
  - `harness-intent`、`harness-assembler`、`harness`、`compact`。
- 集成：
  - 长会话 30+ turns：先定义目标 -> 频繁短反馈 -> 插入验证命令 -> 触发 compact -> `/resume --last` -> `继续`
  - 同时包含“目标替换”与“局部补充”两类短句。

### 手工

- `npm run build`
- `npm test -- --runInBand`（先保证红绿）
- 真实场景：`继续`、`不对吧`、`灰色填充`、`先验证后继续` 与工具密集输出。
- 用 `/harness explain` 核对：
  - 根目标没漂移
  - 高价值证据入模
  - 低价值日志进入 omitted

### 自动 compact 续作（v0.2.10+）

当前基础能力已具备（`getModelContextWindow` + `AUTO_COMPACT_THRESHOLD=0.95`），但为减少误触发和漏触发，建议补充“模型上下文自适应”的闭环优化：

- **模型窗口感知增强**
  - `/model` 统一走一套 `ModelContextInfo` 映射，当前别名（如 `qwen3.5-plus`、`qwen3.6-plus`、`qwen3-max-2026-01-23`）需要补齐 `contextWindow/maxOutputTokens`。
  - `discoverModelContexts()` 的 `/models` 发现结果要定期刷新，并按会话模型 `setModel()` 更新 auto-compact 配置。
- **“提前 compact”策略**
  - 新增 `predictiveCompactThreshold`（例如 88%）用于 pre-warm：接近上限前先持久化 `contextCapsule`、`harnessState`，避免到达 95% 前的重排抖动。
  - `query` 提前估算当前 `requestMessages` 的 prompt token（`estimateMessagesTokens`），若预估占比超过 `predictiveCompactThreshold`，在下一次 LLM 调用前触发轻量 `/compact`。
- **单模型与总长度双保险**
  - `checkAndCompact` 同时保留“会话 token 百分比 + recent assistant 压缩风险指数”（连续 tool-heavy turn、长输出历史）作为触发因子，降低工具密集场景的上下文溢出风险。
- **自动化可观测**
  - `/harness explain` 增加 `contextWindowUsed / modelContextWindow / compactMode / preCompactArmed`。
  - `collectDoctor` 增加“auto compact 最近行为”（触发次数、间隔、最后触发比例）。
- **手工与回归**
  - 增加 `/model` 命令输出字段：`contextWindow`、`maxOutputTokens`、`autoCompactThreshold`、`predictiveThreshold`。
  - 新增回归测试：未知模型回退时 `getCtxPercent` 的默认窗口与真实窗口差异告警场景。

## 成功标准（v0.2.10）

1. 用户连续“短反馈 + 继续 + 验证指令”后，`/harness explain` 中 `rootObjective` 不变化。
2. 20+ 轮后，`/resume` + “继续”能回到正确任务上下文，未出现“重做开场”现象。
3. compact 后首次对话输出，能看到本任务核心目标和下步动作，而非大量早期噪音。
4. `promptAssemblyStats` 的 `omittedEvidence` 占比显著下降或有明确解释。
5. 自动 compact 在 1) 连续 tool call、2) 长 token 会话中不会频繁重试同一轮消息，并且能在阈值区间提前准备上下文。
