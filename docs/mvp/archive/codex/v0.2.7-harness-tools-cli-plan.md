## 上下文

v0.2.6 完成了 runtime boundary、prompt cache、tool scheduler、structured artifacts、edit preview picker、session search、API contract tests、warning dedup。当前代码库已有：

- **Runtime**: `AgentRuntimeController` 统一 turn 生命周期，4 个 renderer（terminal/ink/tui/print）共用同一协议
- **Harness**: intent 分类、contract 维护、evidence ranking、prompt assembly、completion gate
- **Tools**: 调度器抽离、并行执行、artifact 存储、permission 策略
- **Session**: 索引、搜索、abort 截断、resume
- **UI**: Ink SelectList overlay、TUI edit overlay、terminal formatted output

对照 vision 文档，v0.2.7 聚焦三个方向：
1. **Harness v3** — evidence ranking 引入学习信号、intent 分类从正则升级为结构化、compact 从启发式升级为 LLM-driven
2. **工具专业化** — checkpoint/撤销、LLM-driven compact summary、工具结果结构化序列化
3. **CLI 体验** — 改进对话 compact 质量、enhanced doctor 诊断

## 优化轮次

### Round 1: LLM-Driven Compact Summary
**依据**: vision §6 "compact: 自动/手动 compact 输出结构化 state，再输出自然语言 summary"
**文件**: `src/services/compact/summary-generator.ts` (新), `src/services/compact/auto-compact.ts`
**内容**:
- 新增 `generateLLMSummary(messages: Message[], llm: LLMService): Promise<string>`
- 调用 LLM 生成结构化摘要：用户目标、已完成步骤、关键文件变更、未解决问题、下一步
- `compactMessages()` 优先使用 LLM summary，fallback 到现有启发式
- 30s 超时，失败时降级到现有逻辑
- 不影响 auto-compact 的 token-based 触发逻辑
**验证**: 创建长对话后 `/compact` 输出可读摘要，agent 能续接

### Round 2: Harness Evidence Ranking 改进
**依据**: vision §3 "证据索引：工具结果、文件路径、验证输出、用户要求、决策记录都应转为可评分 evidence"
**文件**: `src/harness/evidence.ts`
**内容**:
- 引入简单学习信号：被 harness 选入 prompt 的 evidence 记录 `includedCount`
- 未被选中但用户再次提及的 evidence 提升 `recency` 权重
- evidence 类型扩展：新增 `decision_record`（用户决策）、`verification`（验证输出）
- 评分公式保持简单：`score = importance * recency * (1 + includedCount * 0.1)`
- `/harness explain` 显示 evidence 被选入次数
**验证**: 同一 evidence 在多轮后被重复提及会自动提升 ranking

### Round 3: Intent 分类增强
**依据**: vision §2 "区分新任务、补充、纠错、验证、配置、闲聊反馈"
**文件**: `src/harness/intent.ts`
**内容**:
- 当前 intent 分类基于正则，覆盖中文/英文新任务、继续、验证
- 新增识别：
  - `refinement`（补充/细化）: "再加一个要求"、"also need"、"actually"
  - `correction`（纠错）: "不对"、"not like that"、"wrong"、"应该是"
  - `configuration`（配置）: "切换到"、"use model"、"change mode"
  - `clarification`（澄清）: "什么意思"、"what does"、"explain"
- 每种 intent 设置不同的 contract 更新策略：
  - `new_task`: 创建新 contract epoch
  - `refinement`: 更新 activeInstruction，保留 rootObjective
  - `correction`: 标记前一步为 failed，更新 activeInstruction
  - `configuration`: 更新 harness config，不改 contract
  - `clarification`: 不改 contract，仅记录
**验证**: 20+ 种中英文输入样本的 intent 分类准确率

### Round 4: Checkpoint & 撤销能力
**依据**: vision §8 "关键文件编辑前创建可恢复快照；支持撤销到某个 turn"
**文件**: `src/core/checkpoint.ts` (新), `src/tools/index.ts` (edit_file/write_file hook)
**内容**:
- `createCheckpoint(projectPath, turnId, files: string[])` — 编辑前保存文件快照
- `restoreCheckpoint(projectPath, turnId)` — 恢复到指定 turn 的文件状态
- `listCheckpoints(projectPath)` — 列出可用 checkpoint
- edit_file/write_file 在首次修改文件时自动创建 checkpoint
- checkpoint 存储在 `~/.openhorse/projects/<hash>/_checkpoints/`
- 新增 `/checkpoint list` 和 `/checkpoint restore <turnId>` 命令
- TTL 7 天自动清理
**验证**: 编辑文件 → `/checkpoint list` → `/checkpoint restore` → 文件恢复

### Round 5: 工具结果结构化序列化
**依据**: quality review "引入统一的结构化序列化通道，减少不同工具边界的解析差异"
**文件**: `src/framework/tool-serializer.ts` (新), `src/tools/index.ts`, `src/framework/query.ts`
**内容**:
- 定义统一 `ToolResultEnvelope`: `{ success, output, summary, artifactRef, metadata, schemaVersion }`
- 工具输出统一走 `JSON.stringify(envelope)` 再传给 LLM
- 非 JSON 输出自动包装为 `{ success: true, output, schemaVersion: 1 }`
- query loop 解析 tool result 时优先尝试 envelope 格式，fallback 到 raw string
- 向后兼容：现有工具不改动也可正常工作
**验证**: 所有现有工具测试结果不变，envelope 格式工具可被正确解析

### Round 6: Enhanced Doctor 诊断
**依据**: vision §5 "CLI 长时间使用仍保持可读、可输入、可恢复、可审计"
**文件**: `src/services/doctor.ts`
**内容**:
- 现有 doctor 检查：API key、config、tools、MCP、skills、session、harness
- 新增检查：
  - artifact 目录大小和文件数
  - checkpoint 目录状态
  - session JSONL 完整性（每行可解析、无截断）
  - prompt cache 配置状态（stable prefix 是否标记）
  - warn-dedup 统计（如果有 suppressed warnings）
- 输出格式改进：分组更清晰，失败项置顶
**验证**: `/doctor` 输出包含所有新增检查项
