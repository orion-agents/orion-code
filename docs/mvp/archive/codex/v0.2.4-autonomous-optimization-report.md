## 详细变更

### Round 1: 死代码清理 + 类型修复

**删除**: `src/harness/harness.ts` (348 行)
- `HarnessEngine` 从未接入 query loop, 是多 agent 执行器的遗留代码
- 安全检查已在 `bash_security.ts` 和 tool `checkPermissions` 中实现

**修改**:
- `src/index.ts`: 移除 HarnessEngine 导出
- `src/tools/index.ts`: executeTool 使用 `OPENHORSE_MODE` env var 替代硬编码 `'development'`

### Round 2: CJK 准确的 Token 估算

**新增**: `src/utils/token-estimate.ts` (152 行)
- `estimateTokens()`: 按字符类型区分 token 比率
  - CJK (中文/日文/韩文): ~1.5 tokens/char
  - ASCII 字母/数字: ~0.25 tokens/char (4 chars per token)
  - 标点: ~1 token/char
  - 换行: ~1 token
- 覆盖 Unicode 范围: CJK Unified Ideographs, Hiragana, Katakana, Hangul, Fullwidth Forms, CJK Extensions

**修改**:
- `src/harness/evidence.ts`: 替换 `text.length / 4` 为准确估算
- `src/services/compact/auto-compact.ts`: 替换 `messages.length * 200` 为 `estimateMessagesTokens()`

### Round 3: 工具 getSummary 实现

**为所有 11 个内置工具实现 getSummary**:

| 工具 | 摘要格式 |
|------|---------|
| read_file | 📄 read {path} ({lines}L, {bytes}B) |
| write_file | 💾 write {path} ({bytes}B) |
| edit_file | ✏️ edit {path} (all) |
| exec_command | 🔧 exec: {cmd} ({bytes}B output) |
| list_files | 📁 list {path} ({count} entries) |
| glob | 🔍 glob {pattern} → {count} matches |
| grep | 🔎 grep /{pattern}/ → {count} matches |
| memory_save | 🧠 save {name} ({type}) |
| memory_recall | 🧠 recall "{query}" → {count} memories |
| memory_forget | 🧠 forget {name} |
| history_search | 📜 history "{query}" → {count} found |

### Round 4: Harness /harness explain 增强

**新增 ContextHarness 方法**:
- `getContract()`: 获取当前任务契约
- `getIntentHistory()`: 获取意图历史
- `explain()`: 生成结构化诊断摘要

**/harness explain 现在显示**:
- Contract (objective, requirements, prohibitions, success criteria)
- Recent Intents (最近 5 轮, 带 confidence)
- Capsule (completed steps, open todos, changed files, verification)
- Prompt Assembly (budget, included/omitted evidence)

### Round 5: LLM-driven Compact Summary

**新增**: `generateLLMSummary()` in `summary-generator.ts`
- 调用 LLM 生成高质量结构化摘要
- 摘要内容: goal, actions, state, decisions
- 30s 超时, 失败时降级到启发式摘要

**修改**:
- `compactMessages()` 接受可选 `llm` 参数
- 当 LLM 可用时使用 LLM 摘要, 否则使用启发式

### Round 6: Session 索引 + 搜索

**新增**: `src/services/session-index.ts`
- `SessionIndex`: 追踪每 session 的 files, tools, topics
- `updateSessionIndex()`: 每次消息追加时自动更新
- `searchSessions()`: 按文件路径/工具名/关键词快速搜索
- 索引文件: `.index.json` 存储在 session 消息同级目录

**修改**:
- `appendSessionMessage()`: 自动更新 session 索引

### Round 9: 工具结果大小限制

| 工具 | 限制 |
|------|------|
| read_file | 500 行 + 50KB 字节限制 |
| exec_command | 50KB (已有) |
| list_files | 500 entries |
| glob | 200 matches |
| grep | 100 results (已有) |

### Round 12: Edit File Fuzzy Match

**新增**: `fuzzyMatch()` 函数, 两种模糊匹配策略:
1. **Whitespace normalization**: 匹配不同缩进/空白的相同文本
2. **Line-by-line matching**: 匹配缩进不同的多行代码

**效果**: 当精确匹配失败时自动尝试模糊匹配, 提高 edit_file 成功率
