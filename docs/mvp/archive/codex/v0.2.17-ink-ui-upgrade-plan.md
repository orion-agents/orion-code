# v0.2.17 Ink UI 升级计划

## 背景

当前 `terminal` 仍是 OpenHorse 的稳定默认 UI。`ink` 是 beta 级 React/Ink 渲染器，已经具备基础组件树、`PromptInput`、`Transcript`、`SelectList`、`StatusLine`、`NativeCursor`、工具活动展示和 PTY smoke。

本版本目标不是替换 `terminal`，也不是重写 agent runtime，而是在 `ui-runtime-boundary.md` 与 `ui-ultimate-experience.md` 的约束下，把 Ink UI 从“可用实验”推进到“可持续验证的 beta 工作台”。

## 核心目标

- Ink UI 继续通过 `AgentRuntimeController`、`AgentRuntimeInput`、`AgentRuntimeEvent` 接入 agent 行为。
- Ink UI 不拥有独立的 tool、session、harness、permission、MCP、skills 逻辑。
- 优先升级输入、布局、overlay、工具时间线、session restore、错误展示和 PTY 覆盖。
- 将窗口大小变化后的重绘稳定性作为 P0：拖动终端宽窄、高度变化、连续 resize 后不能出现重复 status、残缺边框、错位 prompt、历史内容串行或展示混乱。
- 保持 `terminal` 为默认稳定 UI；Ink 通过 `openhorse --ui ink` 显式启用。

## 当前状态评估

已有基础：

- `src/ink-ui/launch.tsx` 负责 Ink renderer 启动、raw stdin、resize 和 native cursor controller。
- `src/ink-ui/screens/ReplScreen.tsx` 负责组件编排、overlay、history、permission、session picker 和 runtime controller。
- `src/ink-ui/components/PromptInput.tsx` 已支持多行视口、CJK 宽度、半透明背景和运行态边框。
- `src/ink-ui/components/Transcript.tsx` 已区分 user/command/tool/error/assistant，并接入 Markdown 与 ToolActivity。
- `tests/ink-ui.test.ts` 和 `tests/ink-ui-pty.test.ts` 已覆盖基础 helper、cursor、prompt layout、tool activity 和 PTY smoke。

主要风险：

- Ink 的 viewport clear / resize 仍可能破坏用户对 scrollback 的预期。
- 窗口变化后的全量重绘可能造成 Ink 屏幕混乱：重复 status line、残留旧 frame、prompt 与 transcript 交叠、cursor 锚点落到错误位置。
- Native cursor 依赖 Ink DOM/yoga 节点推断，IME 候选词和光标位置需要继续实测。
- overlay、shortcuts、picker 必须避免进入 durable transcript。
- session restore 后的可见 transcript 与 runtime session 语义必须保持一致。
- 工具事件顺序、长命令摘要、artifact/full-view 入口需要在 Ink 展示中和 terminal 保持一致。

## 非目标

- 不把 Ink 设为默认 UI。
- 不迁移或复制 runtime 行为到 Ink 组件。
- 不为了修复 Ink 展示问题修改 prompt、tool schema、harness 或 session 语义。
- 不在 v0.2.17 引入新的远程 UI、print mode 能力或 native/Rust TUI 重构。

## 设计方向

### 1. Runtime 边界保持单一

Ink 只消费共享 runtime 协议：

- 提交输入：`AgentRuntimeInput.type = submit`
- live revision：复用 controller 的 active-turn interrupt/restart 语义
- permission：`permission_requested` -> `permission_decision`
- session picker：`SessionPickerRequest` -> `select_session`
- transcript：只渲染 runtime `append/update/finalize/replace/clear` 事件

验收点：同一条用户输入在 `terminal` 和 `ink` 下产生相同 runtime event 序列，差异只允许存在于视觉层。

### 2. Ink View Model 收敛

将 Ink 内部展示状态逐步对齐 `src/runtime/ui-view-model.ts`：

- `Transcript` 只接收结构化 transcript entry，不从原始字符串反推 agent 行为。
- `ToolActivity` 展示统一使用 runtime tool activity 格式化结果。
- `StatusLine` 展示 `StatusSnapshot` 等价信息：model、session、tokens、cost、ctx、running/error layer。
- `PromptInput` 只管理输入视觉和 cursor，不决定 turn 语义。

### 3. 输入与光标稳定性

重点提升：

- CJK、emoji、组合字符、Backspace、Delete、Ctrl+U、Ctrl+W、Home/End 等输入一致性。
- 多行输入和 bracketed paste 只提交一次。
- 运行中输入修正时，prompt 不被 assistant/tool 输出挤乱。
- resize 后重算 layout，不重复打印 status，不留下残缺边框。

实现建议：

- 保持 `input-buffer.ts` 和 `prompt-layout.ts` 作为纯函数核心。
- 增加 viewport/cursor golden tests。
- PTY 中增加 resize 后继续输入、中文输入后删除、多行 paste 后提交的断言。

### 4. Overlay 与 Picker 统一

Ink overlay 覆盖：

- slash command palette
- `@file` picker
- session picker
- edit preview picker
- permission picker
- `?` shortcuts

要求：

- overlay 是 UI 状态，不写入 transcript。
- Esc 只取消当前 overlay；permission overlay 的 Esc 明确转换为 deny。
- session picker 支持完整列表滚动、PageUp/PageDown、size、project、model、title。
- permission picker 展示 tool name、cwd/路径范围、风险信息和 allow/deny。

### 5. Transcript 与工具时间线升级

Ink transcript 应达到：

- user/command 输入用整行浅灰背景，不加多余标题。
- assistant Markdown 支持 heading、list、table、code block、diff、error block。
- tool activity 按 call order 展示 queued/running/success/error/skipped。
- 长命令和长参数被截断时显示 artifact 或 `/last-tool` 提示。
- resume 标记和 restored messages 清晰展示，但不伪装成 assistant 回复。

### 6. 状态与错误层级

StatusLine 保持克制：

- 默认一行展示：running/completed/error、model、session、tokens、ctx、cost。
- error 需展示 layer：renderer/runtime/provider/tool/session/memory/MCP/skills。
- provider/API limit、context overflow、permission denied、tool timeout 要给出不同可行动提示。

### 7. 窗口变化重绘与布局预算

升级 `layout-budget.ts`：

- 宽终端显示更多 transcript/tool detail。
- 窄终端优先隐藏低优先级 status 字段。
- overlay 打开时收缩 live transcript，不覆盖 prompt。
- prompt rows、overlay rows、live transcript rows 由统一预算计算，避免魔法数字分散。
- resize 必须走“清理旧 frame -> 重算 layout -> 重绘单一当前 frame -> 恢复 cursor anchor”的确定流程。
- 连续 resize 需要 debounce/coalesce，避免中间帧刷进可见区域造成状态行重复或边框残留。
- PTY screen model 必须断言最终屏幕没有重复 prompt/status、没有残缺边框、没有 transcript/prompt 交叠。

## 验收标准

v0.2.17 Ink UI 升级完成时，应满足：

- `terminal` 默认行为不回退。
- `openhorse --ui ink` 可稳定完成普通 chat、slash command、tool call、permission、resume、live revision。
- Ink overlay/helper 不污染 durable transcript。
- Ink 工具时间线顺序与 runtime event 顺序一致。
- Ink PTY 覆盖 CJK、resize、paste、permission、session picker、tool ordering。
- Ink resize/redraw 必须通过自动化或手工验收：窗口变化后最终屏幕稳定、无重复 status、无残缺 border、无 prompt/transcript 交叠、cursor 仍回到输入区域。
- 任何 agent 行为差异都能在 runtime parity 测试中被发现。

## 风险与处理

- 如果 Ink native cursor 继续影响中文输入法，优先降级为更保守的 prompt 光标展示，并记录 beta gap，不改 runtime。
- 如果 resize 清屏影响体验，先限制 Ink 的 viewport reset 范围，再用 PTY screen model 验证；不能把“偶发混乱”作为 beta 可接受行为。
- 如果 overlay 逻辑开始复制 command/session/permission 语义，立即回退到 runtime request/decision 协议。
- 如果 Ink 需要新事件，先扩展 `AgentRuntimeEvent`，再由 renderer 消费。
