# OpenHorse v0.1.4-plus Roadmap — 收尾与优化

## Context

v0.1.1 ~ v0.1.4 roadmap 已基本完成（CLI、Retry/Memory、Session/项目记忆、Web/MCP/Todo/Plan/Bash 安全）。经过对 src 目录的全面审计，发现三类问题：

1. **集成断层**：`embeddings` / `vector-store` / `semantic-search` / `agents/router` / `skills/loader` 等模块已经写完并通过测试，但**未在 CLI 主流程中接入**，属于"提前落地的 v0.1.5 特性"。
2. **状态易失**：`todo_write`、`enter_plan_mode` 工具的状态保存在模块级全局变量，未进入 Store/AppState，也未持久化，重启即丢。
3. **健壮性缺口**：MCP 客户端无重连/心跳；session 元数据 / MEMORY.md 索引写入无事务；fallback model 链路缺端到端验证；`memory_forget` 软删除对用户不可见。

**v0.1.4-plus 不引入新特性**，专注收尾：把已写好的代码接入主链路，补齐持久化与健壮性。

---

## Part 1: 状态管理统一 (P0)

**问题**：[src/tools/todo.ts:20](../../src/tools/todo.ts#L20)、[src/tools/plan.ts:11-12](../../src/tools/plan.ts#L11-L12) 使用模块级全局 `currentTodos` / `isPlanMode` / `currentPlan`，绕过了 [src/framework/store.ts:18-29](../../src/framework/store.ts#L18-L29) 的 AppState。

**改造**：
- 扩展 AppState：新增 `todos: TodoItem[]`、`planMode: boolean`、`currentPlan: string | null`
- `todo_write` / `enter_plan_mode` / `exit_plan_mode` 通过 `ctx.store.setState({...})` 更新
- CLI 渲染层从 store 订阅状态显示
- 会话切换时 Store 重置

**持久化**（可选 P1）：
- todos 写入 `~/.openhorse/projects/<hash>/state.json`
- `/resume` 时一并恢复

---

## Part 2: MCP 启动与健壮性 (P0)

**问题**：[src/tools/mcp.ts:212-221](../../src/tools/mcp.ts#L212-L221) 支持 `~/.openhorse/mcp.json` 但 CLI 启动时不会自动加载；server 进程崩溃后无重连。

**改造**：
- `src/cli.ts:main()` 启动阶段读取 `~/.openhorse/mcp.json`，自动 spawn 所有声明的 server
- `SimpleMCPClient` 增加：
  - 心跳（每 30s ping）
  - 断线后 3 次指数退避重连
  - 多次失败后从 registry 移除并提示用户
- 新增 `/mcp` 命令查看当前连接状态

---

## Part 3: Strategy Tracker 完整接线 (P0)

**问题**：[src/core/strategy-tracker.ts](../../src/core/strategy-tracker.ts) 已实现，[src/framework/query.ts:89](../../src/framework/query.ts#L89) 也已创建实例，但 `tool_call` / `tool_result` 事件未明确写入 tracker，`isExhausted` 触发的 alternative 提示路径未验证。

**改造**：
- query.ts 在 `tool_call` 事件触发 `startApproach` + `addTool`
- `tool_result` 事件触发 `recordResult`
- `isExhausted()` 时往 messages 注入"考虑替代方案"的 user message
- 增加 `tests/strategy-tracker.test.ts` 端到端覆盖

---

## Part 4: Fallback Model 链路验证 (P0)

**问题**：[src/services/llm.ts](../../src/services/llm.ts) 的 `withRetry` + `FallbackTriggeredError` + `triggerFallback` 已实现，但缺乏端到端测试，不确定连续 529 是否能正确降级到 fallback model 并继续对话。

**改造**：
- 增加 `tests/llm-fallback.test.ts`：mock 主模型连续 3 次 529，验证：
  - 切换到 fallback model
  - 用户层面有可见提示
  - cost tracker 记录两段模型的 token
- 修复任何暴露出的 bug

---

## Part 5: 语义搜索接入 (P1)

**问题**：`src/memory/embeddings.ts`、`src/memory/vector-store.ts`、`src/memory/semantic-search.ts` 已完整实现（Ollama + OpenAI + sqlite-vec），但 [src/tools/index.ts](../../src/tools/index.ts) 的 `memory_recall` 仍是基于关键字的 `searchMemories`，零调用点。

**改造**：
- `memory_save` 时同步生成 embedding 并写入 vector-store
- `memory_recall` 默认走 semantic-search，关键字搜索作为 fallback
- 增加 `OPENHORSE_EMBEDDING_PROVIDER` 配置（默认 `none`，保持向后兼容）
- 提供 `/memory reindex` 命令对已有记忆做批量 embedding

## Part 6: Skills 系统接入 (P1)

**问题**：`src/skills/` 实现了 loader 和 registry，`tests/skills.test.ts` 通过，但 CLI 未调用，系统提示中也不引用任何 skill。

**改造**：
- CLI 启动时 `loadSkills(projectPath)` 扫描 `.openhorse/skills/`
- 在系统提示中加入 "Available skills" 段
- 增加 `/skills` 命令列出/启用
- 模型可通过 `skill_invoke` 工具触发

## Part 7: Router/Agents 接入或下线 (P1)

**问题**：[src/agents/router.ts](../../src/agents/router.ts)（246 行）+ `src/core/agent.ts` 实现完整但 REPL 不调用。

**改造**（二选一）：
- **接入**：在 handleChat 前用 router 选择 agent 角色，注入对应系统提示
- **下线**：明确标注为 v0.1.6 预留，移出主源码目录或在 README 中标注实验性

## Part 8: Memory & Session 健壮性 (P1)

**问题**：
- [src/memory/storage.ts:237](../../src/memory/storage.ts#L237) `updateMemoryIndex` 与 file 写入无事务，崩溃可能导致 MEMORY.md 与实际文件不一致
- `memory_forget` 软删除（`status: deleted`）对用户不可见，`memory_recall` 仍能搜索到

**改造**：
- `updateMemoryIndex` 改为：先写临时索引文件，rename 原子替换
- `memory_recall` 默认过滤 `status: deleted`，新增 `includeDeleted` 参数
- session-storage 的 metadata 写入同样改为原子 rename

## Part 9: Web Tools 增强 (P2)

**问题**：[src/tools/web.ts](../../src/tools/web.ts) `applyPrompt` 是简单 title/summary 提取，并未真的让 LLM 处理 prompt；HTML→markdown 也是 basic 实现。

**改造**：
- `applyPrompt` 调用一次 LLM（cheap model）做内容提取
- HTML→markdown 改用成熟库（如 turndown）
- 增加并发限速与 cache（同一 URL 15 分钟内复用）

- AppState 包含 `todos` / `planMode` / `currentPlan`，重启后 `/resume` 可恢复

- 触发 fallback model 的 e2e 测试通过
- `memory_recall` 默认使用 embedding，速度可接受
- `git diff --stat` 主链路代码变动 < 800 行（重在接线，不写新功能）
