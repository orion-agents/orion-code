**Ink** 是一个 React-based 的终端 UI 框架，被以下项目使用：

- Gemini CLI

**核心优势**：
- React 组件化开发体验
- Flexbox 布局（使用 Yoga）
- Hooks 支持 (useInput, useStdin, useApp)
- TypeScript + TSX 支持

#### CommandPanel.tsx - 命令面板

```tsx
import React, { useState } from 'react';
import { Box, Text } from 'ink';
import { useInput } from 'ink';

interface Command {
  name: string;
  description: string;
  type: 'chat' | 'cmd';
}

export function CommandPanel({ commands: initialCommands }: { commands: Command[] }) {
  const [selectedIndex, setSelectedIndex] = useState(0);
  const [filter, setFilter] = useState('');
  const commands = initialCommands.filter(c => 
    c.name.includes(filter) || c.description.includes(filter)
  );

  useInput((input, key) => {
    if (key.upArrow) {
      setSelectedIndex(Math.max(0, selectedIndex - 1));
    }
    if (key.downArrow) {
      setSelectedIndex(Math.min(commands.length - 1, selectedIndex + 1));
    }
    if (key.return) {
      // 选择命令
      const selected = commands[selectedIndex];
      // ...触发命令执行
    }
  });

  return (
    <Box flexDirection="column" borderStyle="single">
      <Text bold>Commands</Text>
      {commands.map((cmd, i) => (
        <Box key={cmd.name}>
          <Text 
            color={i === selectedIndex ? 'green' : 'white'}
            bold={i === selectedIndex}
          >
            {i === selectedIndex ? '❯ ' : '  '}
            /{cmd.name} - {cmd.description}
          </Text>
        </Box>
      ))}
    </Box>
  );
}
```

## OpenClaude 深度模块分析

### 一、自愈系统架构

#### 1. Hook Chains (Self-Healing Agent Mesh)

**文件**: `docs/hook-chains.md`

Hook Chains 是 OpenClaude 的事件驱动恢复层。当关键工作流失败时，自动评估声明式规则并分发修复动作：

| 能力 | 描述 | 借鉴价值 |
|------|------|---------|
| **触发事件** | PostToolUseFailure, TaskCompleted | 高 - 错误驱动修复 |
| **修复动作** | spawn_fallback_agent, notify_team, warm_remote_capacity | 高 - 自动恢复 |
| **安全防护** | 深度限制、冷却窗口、去重、中止安全 | 高 - 防无限循环 |
| **配置** | `.openclaude/hook-chains.json` | 中 - 声明式配置 |
| **Feature Gate** | `feature('HOOK_CHAINS')` | 中 - 可选启用 |

**安全设计亮点**:
- **Depth Guard**: `chainDepth >= maxChainDepth` 阻止链式爆炸
- **Rule Cooldown**: 每条规则 30s 冷却 (可配置)
- **Dedup Window**: 相同事件/动作组合 30s 抑制
- **Abort-Safe**: 中止信号传播时安全跳过
- **Default Disabled**: 默认关闭，需显式启用

#### 2. Auto-Fix 系统

**文件**: `src/services/autoFix/`

Auto-Fix 是工具执行失败后的自动重试/修复机制：

| 文件 | 功能 | 借鉴价值 |
|------|------|---------|
| `autoFixHook.ts` | Auto-Fix 钩子构建 | 高 - 钩子集成 |
| `autoFixRunner.ts` | Auto-Fix 执行器 | 高 - 重试引擎 |
| `autoFixConfig.ts` | Auto-Fix 配置 | 高 - 配置系统 |

**设计模式**: 工具失败 → 检查 Auto-Fix 规则 → 执行修复 → 重试 (最多 N 次)

#### 3. Compact / Auto-Compaction 系统

**文件**: `src/services/compact/` (14 文件)

OpenClaude 的会话自动压缩系统非常成熟：

| 文件 | 功能 | 借鉴价值 |
|------|------|---------|
| `autoCompact.ts` | 自动触发压缩 (基于 token 计数) | 高 - 自动压缩 |
| `compact.ts` | 核心压缩逻辑 | 高 - 摘要算法 |
| `microCompact.ts` | 微压缩 (仅压缩当前 turn) | 高 - 增量压缩 |
| `sessionMemoryCompact.ts` | 会话记忆压缩 | 高 - 记忆集成 |
| `snipCompact.ts` | 裁剪压缩 (移除中间消息) | 中 - 裁剪策略 |
| `apiMicrocompact.ts` | API 级微压缩 | 中 - API 优化 |
| `cachedMicrocompact.ts` | 缓存微压缩 | 低 - 性能优化 |
| `postCompactCleanup.ts` | 压缩后清理 | 中 - 资源管理 |
| `compactWarningHook.ts` | 压缩警告 | 中 - 用户体验 |
| `timeBasedMCConfig.ts` | 基于时间的 MC 配置 | 中 - 时间策略 |

- **Full Compact**: 完整会话压缩，保留关键上下文

- **Session Memory Compact**: 压缩后将摘要保存到记忆系统

### 2. Auto-Fix 自动修复系统

**目标**: 工具执行失败后的自动重试和修复

**技术方案**:
```typescript
// src/services/auto-fix.ts
interface AutoFixConfig {
  enabled: boolean;
  maxRetries: number;        // 最大重试次数
  cooldownMs: number;        // 重试间隔
  rules: AutoFixRule[];
}

interface AutoFixRule {
  id: string;
  trigger: { toolName: string; errorPattern: string };
  action: 'retry' | 'alternate' | 'fallback';
  maxRetries: number;
}

interface AutoFixService {
  shouldAutoFix(toolName: string, error: Error): AutoFixRule | null;
  executeFix(rule: AutoFixRule, context: ToolUseContext): Promise<FixResult>;
  trackRetry(queryChainId: string): boolean;  // 防止无限重试
}
```

## OpenClaude vs OpenHorse 对比分析

### 可引入的关键设计

| OpenClaude 设计 | OpenHorse 引入方式 | 优先级 |
|----------------|-------------------|--------|
| **Auto-Compact** | 引入 token 计数 + 自动压缩 | P0 |
| **Hook Chains** | 简化为 3 种修复动作 | P0 |
| **Auto-Fix** | 工具失败重试框架 | P0 |
| **Plugin Lifecycle** | 完整插件生命周期 | P1 |
| **Plugin Policy** | 插件权限隔离 | P1 |
| **Permission Classifier** | Bash 命令智能分类 | P1 |
| **Session Storage** | 持久化 + 历史浏览 | P2 |
| **Task System** | 多类型任务管理 | P2 |
| **Bridge** | 远期远程桥接 | 远期 |

### OpenHorse 差异化竞争优势

| 方向 | OpenClaude | OpenHorse v0.1.13 优势 |
|------|-----------|----------------------|
| **自愈系统** | 完整但复杂 | 简化版，3 种核心动作 |
| **插件系统** | 官方市场 + 社区 | 轻量插件，易扩展 |
| **权限系统** | 多层分类器 | 规则优先，学习辅助 |
| **压缩策略** | 5 种策略 | 核心 2 种 (full + micro) |
| **部署复杂度** | 高 (React + Ink + Bun) | 低 (Node.js + 轻量) |

**核心竞争力**:
1. **自愈优先** — 自动压缩 + Auto-Fix + Hook Chains 三位一体
2. **轻量插件** — 无官方市场依赖，用户自建插件生态
3. **渐进复杂度** — P0 核心功能立即可用，P1/P2 按需扩展
4. **学习增强** — 从用户决策中学习权限偏好
