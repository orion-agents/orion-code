# 05 · 开发路线图（Orion Code Desktop v1.0）

> 基于 `01` 现状、`02` 竞品、`03` 功能规划、`04` 技术选型。
> 估算前提：单团队 **3–5 人**（2 前端 / 2 引擎+架构 / 1 QA+DevOps），按"人周"粗估；阶段可独立交付、可并行。

---

## 一、阶段总览与优先级

| 阶段 | 名称 | 主要交付 | 优先级 | 估时 |
|---|---|---|---|---|
| **M0** | 准备与治理 | 版本统一、UI 收敛、monorepo、原生模块预构建 PoC | P0 | 2 周 |
| **M1** | 桌面外壳 | Electron 外壳 + 引擎复用 + 设置中心 + 自动更新 | P0 | 4–6 周 |
| **M2** | 核心交互 | 富文本对话、三模式、会话/文件管理 UI | P0 | 4–6 周 |
| **M3** | 协作与生态 | 产品化多 Agent、技能市场、自动化调度 | P1 | 5–7 周 |
| **M4** | 多模态与连接器 | 图像/音视频生成+输入、连接器市场 | P1 | 4–6 周 |
| **M5** | 打磨与发布 | 安全沙箱、长对话治理、签名发布 | P0/P1 | 3–4 周 |
| **合计** | — | v1.0 客户端首发 | — | **约 22–35 周** |

> 总估时区间大，取决于并行度（M3/M4 可在 M2 之后并行）与团队规模。

---

## 二、逐阶段明细

### M0 · 准备与治理（P0，2 周）
**目标**：消除桌面化前的结构性障碍。
- [ ] 统一版本号（package.json 0.2.19 ↔ git v0.2.22 不一致，先对齐）。
- [ ] 收敛 UI 层：标记并废弃 `ink-ui`/冗余 `ui`/`ui-v2`，仅留 `terminal-ui`/`tui-ui` 作为 CLI 通道。
- [ ] 抽取 `packages/engine`（将 `src/` 重构为内部 npm 包，CLI 与桌面共享）。
- [ ] **原生模块预构建 PoC**：`@electron/rebuild` 对 `better-sqlite3`+`sqlite-vec` 在 Electron ABI 下编译验证；CI 多平台（mac x64/arm64, win, linux）预构建 + `NODE_MODULE_VERSION` 校验。
- [ ] 删除/隔离 `src/agents/*` 桩（leader/brain），规划 M3 真实编排。
- **里程碑 M0✅**：引擎包可独立被 Electron 主进程 `import` 且向量库加载成功；CLI 行为不变。

### M1 · 桌面外壳（P0，4–6 周）
- [ ] Electron 主进程 + 渲染进程骨架；菜单/托盘/快捷键。
- [ ] 首次引导：登录/BYOK、工作目录选择+**授权沙箱根**。
- [ ] **设置中心（M-6）**：模型/提供商、API Key、外观主题、权限默认姿态（改默认 `allow`→`ask`）、记忆开关 —— GUI 编辑 `~/.orion-code/orion.json`。
- [ ] 引擎接入：主进程 `bootstrapRuntime()`，事件经 IPC → React 状态。
- [ ] 自动更新（electron-updater）+ 签名 + 崩溃上报（脱敏）。
- **里程碑 M1✅**：双击打开客户端，配好 Key 与目录，能跑通一次 CLI 等价的查询（无图形对话 UI 也可，先通链路）。

### M2 · 核心交互（P0，4–6 周）
- [ ] **富文本对话 UI（M-2）**：Markdown+代码高亮+内联 diff+图片预览+`@` 引用选择器+草稿历史。
- [ ] **三模式（M-3）**：Ask / Plan / Craft，切换零成本；高风险统一走审批门。
- [ ] **会话管理（M-4）**：列表/搜索/标签/恢复（resume picker）；项目级目录管理。
- [ ] **文件浏览器（M-5）**：授权目录树、文件预览、`edit_file` GUI 版（diff+行级编辑）、Git 状态。
- [ ] 工具过程可视化（tool_call 卡片时间线）。
- **里程碑 M2✅**：达到 WorkBuddy 级核心对话体验 —— 可对话、可看 diff、可切模式、可恢复会话、可浏览文件。

### M3 · 协作与生态（P1，5–7 周）
- [ ] **真·多 Agent 协作（M-7）**：Team Mode，创建/分配角色/权限，并行执行，状态监控；Supervisor 复用 `runtime/subagents` 约束（预算/权限/轨迹）+ 扩展为可写。
- [ ] **技能市场（M-8）**：远程浏览/搜索/安装/更新，兼容 `SKILL.md` 与 OpenClaw 生态；版本管理。
- [ ] **自动化调度（M-9）**：定时（RRULE）/一次性 GUI 编排 + 任务模板 + 结果投递。
- [ ] **记忆可视化（M-11）**：三层记忆浏览/编辑/健康度。
- **里程碑 M3✅**：多 Agent 可在 UI 内可视化协作；技能一键安装；定时任务可设。

### M4 · 多模态与连接器（P1，4–6 周）
- [ ] **多模态输入（M-13）**：截图/设计稿拖入对话。
- [ ] **多模态生成（M-13）**：新增 `image_gen` / `tts` / `video_gen` 工具，对接 OpenAI Images/Speech 或自托管；客户端内预览/导出。
- [ ] **连接器生态（M-10）**：IM/办公连接器市场（微信/企微/飞书/钉钉/QQ、腾讯系），MCP+OAuth 底层；远程指令（手机→桌面）。
- **里程碑 M4✅**：可生成图片/语音并预览；可连一个 IM 远程触发任务。

### M5 · 打磨与发布（P0/P1，3–4 周）
- [ ] **安全沙箱（M-12）**：Docker/E2B 或等效隔离，高危/Full-Auto 默认进沙箱；工作目录授权可视化、命令分级策略编辑、SSRF 规则查看。
- [ ] **长对话治理**：auto-compact + 消息压缩调优，目标 >50 轮不衰减（修正 WorkBuddy 痛点）。
- [ ] **复杂任务稳定性**：重规划/异常重试/工具超时强化（修正 WorkBuddy 卡死痛点）。
- [ ] 签名公证（macOS notarize / Windows 签名）、安装包、更新通道、崩溃看板。
- [ ] 用户文档 + 上手引导。
- **里程碑 M5✅**：v1.0 客户端首发，达到 Codex/WorkBuddy 同等效果水平。

## 三、优先级排序（P0 必做 / P1 达同等 / P2 后续）

- **P0（无则不成客户端）**：M0 治理、M1 外壳+设置、M2 对话+三模式+会话/文件、M5 沙箱+发布。
- **P1（达竞品同等）**：M3 多 Agent+技能市场+自动化+记忆可视化、M4 多模态+连接器。
- **P2（生态/差异化，可 v1.x）**：云端同步/账户/计费、统一 App Server 多端（对标 Codex）、更多连接器、Tauri+WASM 体积优化。

## 四、风险与缓解

| 风险 | 等级 | 缓解（对应阶段） |
|---|---|---|
| 原生模块 ABi 不匹配致启动崩溃 | 🔴 高 | M0 预构建 PoC + CI 多平台 + LIKE 降级（现状已有） |
| 长对话质量衰减（WorkBuddy 痛点） | 🟠 中 | M5 auto-compact/压缩调优 |
| 复杂任务卡死（WorkBuddy 痛点） | 🟠 中 | M5 重规划/重试/超时（exec_command 已有） |
| 多 Agent 信息孤岛（WorkBuddy 痛点） | 🟠 中 | M3 Supervisor 统一 ledger/轨迹 |
| 体积/启动慢影响转化 | 🟡 低 | Vite 拆包/懒加载；v2 评估 Tauri+WASM |
| 多端协议不一致 | 🟡 低 | 统一 `UiEventSink` 事件序列化（M1 定协议） |

## 五、验收标准（v1.0 发布门槛）

1. **启动**：冷启动 < 5s（含原生模块加载）；mac/win/linux 一键安装包可装可更新。
2. **核心对话**：富文本 + diff + 三模式可用；会话恢复率 100%。
3. **安全**：高危操作 100% 进入审批/沙箱；无未授权文件访问；轨迹脱敏生效。
4. **复用无损**：既有 `SKILL.md` / `mcp.json` / CLI 入口全部兼容可用。
5. **多 Agent**：UI 内可创建并行 Agent 并监控（非桩）。
6. **技能市场**：可浏览/安装/更新至少 1 个远程技能。
7. **多模态**：至少图像生成+输入预览可用。
8. **稳定性**：连续 50+ 轮对话不显著衰减；复杂任务有重规划兜底。
