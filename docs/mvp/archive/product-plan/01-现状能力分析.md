# 01 · Orion Code 现状能力分析（v0.2.19）

> 数据来源：对 `src/` 全量静态探索（`Explore` 子代理）+ 关键文件逐行核实（`src/agents/leader.ts`、`src/core/brain.ts`、`package.json` 依赖树）。
> 结论已在 `00-索引与执行摘要.md` 汇总。本文给出完整证据。

---

## 1. 项目定位

Orion Code 定位为 **"Universal Agent Harness Framework"（通用智能体编排框架）**，以 TypeScript 编写的 **CLI / Agent Harness**，唯一入口 `bin/orion`，对外同时以 **npm library** 形态发布（`main: dist/index.js` + `types: dist/index.d.ts`）。

- 版本：`v0.2.19`（`package.json`）。git 历史已演进至 `v0.2.22` 标签，版本号未同步（非缺陷，但应在客户端化前统一）。
- 目标运行时：**Node >= 18**（`engines`）。
- 本质：**服务端/终端型 agent 引擎**，非面向终端用户的「产品」。

---

## 2. 全量功能模块清单（用户可见能力）

### 2.1 CLI 命令入口（`src/cli.ts`）
- `orion`（无参）：启动稳定原生终端 UI（默认 renderer = `terminal`）。
- `orion doctor`：本地诊断报告（`services/doctor.ts`），`--output-format text|json`。
- `orion diff`：汇总当前 git workspace 改动（`services/workspace-diff.ts`）。
- `orion commit`：生成只读 commit plan（`services/commit-plan.ts`）。
- `orion -p "task"` / `--print`：实验性非交互 print 模式（`print-ui/launch.ts`），读 stdin。
- `--ui <mode>`：`terminal`（稳定）/ `tui`（beta）/ `ink`（已弃用）/ `print`。
- `--output-format text|json`、`--help`、`--version`。

### 2.2 工具系统（`src/tools/index.ts` + `framework/tool.ts`）
统一 `buildTool()` 工厂封装，导出 `OpenHorseTool` 并转换为 OpenAI function-call 格式。运行期工具池 = 静态工具 + MCP 工具（`getRuntimeTools()`）。

| 类别 | 工具 | 说明 / 关键文件 |
|---|---|---|
| 文件/IO | `read_file` `write_file` `list_files` `edit_file` `glob` `grep` `batch_read` | `edit_file` 支持精确/模糊/批量替换 + preview（`src/tools/index.ts:294`） |
| Shell | `exec_command` | `sh -c` spawn，流式截断 50KB，timeout/abortSignal/进程组 kill；`bash_security.ts` 做 `blocked/safe/caution` 分级 |
| 记忆 | `memory_save` / `memory_recall` / `memory_forget` | user/feedback/project/reference 四类，带 frontmatter 的 `.md`（`src/tools/index.ts:501-710`） |
| 历史 | `history_search` | 跨会话检索历史工具调用（`src/tools/index.ts:713`） |
| Web | `web_fetch` `web_search` | fetch 含 **SSRF 拦截**（私有网段/IP/`.internal`/`.local` 黑名单）+ 10MB 上限；search 委托 provider MCP / 适配器链（Tavily/Brave/DuckDuckGo/Custom） |
| Git/LSP/Todo/Plan | `GIT_TOOLS` `lspTools` `TODO_TOOLS` `PLAN_TOOLS` | `src/tools/git.ts` `lsp.ts` `todo.ts` `plan.ts` |
| MCP | 自动发现 `~/.orion-code/mcp.json` | `mcp__<server>__<tool>` 命名暴露为一等工具；stdio/sse/http/streamable-http，含心跳与重连 |

### 2.3 Agent Loop（核心能力，强）
- 生成器式 agentic 循环 `query()`（`src/framework/query.ts:692`），事件流：`request_start → assistant_tool_calls → tool_call → tool_result → message → complete`。
- **LoopBudget 护栏**：默认 24 次 LLM 请求 / 120 次工具调用 / 用户轮次，可自适应升级为 `complex` profile。
- **并发工具调度**（`src/framework/tool-scheduler.ts`）：并发安全工具并行（默认 6），危险工具串行；权限决策来源可追溯（tool_policy/config/user/drift_guard）。
- **自动压缩**（auto-compact）：95% 上下文阈值触发（`services/compact/*`）。
- **Context Harness**（`src/harness/context-harness.ts`）：意图分类、任务契约、证据索引（evidence）、ledger、完成门（completion gate）、漂移守卫（drift guard）。

### 2.4 记忆系统（多层，强）
- **文件层**（`src/memory/storage.ts`）：`~/.orion-code/projects/<hash>/memory/`，`MEMORY.md` 索引 + 各 `.md` 条目（frontmatter），项目级作用域。
- **向量层**（`src/memory/vector-store.ts`）：`better-sqlite3` + `sqlite-vec` 虚拟表，余弦相似度语义检索；embedding 失败或 sqlite-vec 不可用时**自动降级**为文本 LIKE 检索。
- **Harness 上下文层**（`src/harness/*`）：`ContextLedger` / evidence / turn-summary，单次会话内结构化上下文（非跨会话持久化）。
- **会话层**（`src/services/session-storage.ts` + `session-memory/*`）：JSONL 会话历史 + 会话级记忆。

### 2.5 Skills 系统（`src/skills/*`）
- 基于 `SKILL.md` + YAML frontmatter 的可扩展技能；扫描优先级 builtin < user < configured < project（`loader.ts`）。
- 内置：`code-review` / `security-check` / `test-gen`（`src/skills/builtin/`）。
- `generateSystemPromptInjection()` 注入 system prompt，支持 auto-trigger。

### 2.6 多 Agent（⚠️ 名不副实，已核实）
- `src/runtime/subagents/*`：**真正的**只读调查子代理（v0.2.20 引入），root Agent 可请求 1–3 个**只读调查**子代理（Supervisor 统一管预算/权限/轨迹），角色限定 `research | review | test-investigate`，有严格上限钳制。
- `src/agents/*`（leader/coder/coordinator/router/fork/worker-pool）：**遗留/桩实现**。逐行核实：
  - `src/agents/leader.ts:45` `coordinateTask()` 仅返回占位对象 `{ message: 'Task ... coordinated by Leader', timestamp }`。
  - `src/core/brain.ts:103` `findBestAgent()` 的能力匹配失败时直接 `return agents[0]`。
  → **当前不存在产品化的多 Agent 编排能力**，仅 subagents 的只读调查可用。

### 2.7 安全与可靠性（强，优于多数 CLI agent）
- 命令分级（`bash_security.ts`）、SSRF 拦截（`web.ts`）、轨迹脱敏（`redaction.ts`）、完成门/漂移守卫（harness）、验证 profile（`verification-profile.ts`）、自动修复（`auto-fix/*`）、checkpoint、cost/strategy tracker。

### 2.8 多 UI 渲染器（均为终端型，维护面大）
- `terminal-ui`（稳定）、`tui-ui`（beta）、`ink-ui`（**已弃用** Ink/React）、`print-ui`（非交互）、`ui-v2`（实验壳）。
- 共存 7 套 UI 相关目录：`terminal-ui` / `tui-ui` / `tui-core` / `ink-ui` / `ink` / `ui` / `ui-v2`，收敛未完成。

## 3. 架构设计

### 3.1 分层
```
CLI 入口        src/cli.ts  → bootstrapRuntime() 组装 Store/LLM/MCP/Session
   │
UI 层           terminal-ui / tui-ui / ink-ui / print-ui / ui-v2   (均 TUI, 消费统一 UiEventSink)
   │
Runtime 层      src/runtime/* (agent-runtime-controller, ui-view-model, subagents, chat-controller)
   │
Agent Loop      src/framework/query.ts (generator) + tool-scheduler.ts
   │
Framework 抽象  buildTool / toOpenAITool / Store(pub-sub) / prompt / harness
   │
Services 层     llm / config / global-config / mcp / session-storage / compact / web-search / skills / doctor
   │
Tools 层        src/tools/*  (bash/file/web/git/lsp/todo/plan/memory/mcp)
   │
存储/记忆       memory/* (file + better-sqlite3/sqlite-vec) , session-storage (JSONL)
```

### 3.2 Agent Loop 工作机制（`src/framework/query.ts`）
1. 每轮：`autoCompact` 预测性压缩 → `harness.assembleMessages()` 注入动态上下文（保持首个 system 消息稳定以利 prompt cache）→ `llm.chatStream()` 流式调用。
2. 若返回 `tool_calls`：`prepareToolCalls()`（解析参数 + 漂移检查 + 权限检查）→ `executeToolCalls()`（并发/串行，按原函数顺序产出）。
3. 工具结果经**模型可见预算**压缩（`summarizeModelVisibleToolResult` / `omitModelVisibleToolResult`），写入消息并推入下一轮。
4. 无工具调用且通过 completion gate → `complete`。
5. 全链路贯穿 `AbortSignal` / `CostTracker` / `StrategyTracker` / `Harness` 记录。

### 3.3 记忆持久化
- 向量库 `VectorStore`（`vector-store.ts`）用 `better-sqlite3` 打开 `~/.orion-code/vector.db`，建 `memories` 表 + `vec0` 虚拟表（sqlite-vec）；`upsert` 用事务保证 embed 失败不写脏数据。
- 语义开关 `isSemanticEnabled()` 门控——需配置 embedding provider（OpenAI `text-embedding-3-small` 或 Ollama `nomic-embed-text`，见 `embeddings.ts`）；否则回退关键词检索。
- 会话 JSONL 文件（`session-storage.ts`），含 harness sidecar、trace（脱敏）。

## 5. 优势（Strengths）

1. **成熟的 agentic loop**：生成器式 `query()` 带事件流、预算护栏（可自适应升级）、并发工具调度、自动压缩、abort/重试/provider 诊断 —— 工程扎实。
2. **多层记忆 + 语义检索**：文件 `MEMORY.md` 索引 + sqlite-vec 向量库 + harness 上下文（ledger/evidence）+ 会话记忆，且有优雅降级。
3. **MCP 一等公民集成**：`mcp__server__tool` 命名对齐 Claude Code / Codex，支持多传输与重连。
4. **强安全设计**：命令分级、SSRF 拦截、轨迹脱敏、完成门/漂移守卫、验证 profile、自动修复 —— 高于一般 CLI agent。
5. **可扩展 Skills + 受约束子代理**：SKILL.md 优先级插件化 + 受预算/权限约束的只读子代理。
6. **OpenAI 兼容 + fallback**：流式、指数退避、529 触发 fallback、provider 错误分类。
7. **多渲染器容错**：terminal/tui/ink/print 多级 UI，ink 已标记弃用以收敛。

---

## 6. 不足 / 差距（Weaknesses，已逐项核实）

1. **原生模块 ABI 风险（最大部署隐患）**：`better-sqlite3@12.10` 与 `sqlite-vec@0.1.9` 为 **C++ 原生模块**，强绑定 Node ABI。Node 版本切换、或后续打包为桌面客户端（Electron/Tauri 有独立 ABI）时极易出现 `NODE_MODULE_VERSION` 不匹配。**当前测试环境已暴露此问题**（better-sqlite3 ABI 失败导致 vector / storage-maintenance 测试套件失败）。与"桌面客户端"诉求直接冲突。
2. **语义记忆强依赖外部服务**：`VectorStore` 初始化失败/禁用时退化为文本 LIKE；默认可能不可用，需额外配置 OpenAI/Ollama embedding（`isSemanticEnabled()` 门控）。
3. **"多 Agent" 名不副实（已逐行核实）**：`src/agents/leader.ts:45` 仅返回占位对象，`src/core/brain.ts:103` 的 agent 选择是 `return agents[0]`。真正的多 Agent 仅 `runtime/subagents` 的**只读调查**子代理，能力有限、无产品化协作 UI。
4. **"多模态生成" 是误称（已核实）**：全代码库**没有任何图像/音频生成工具**。`src/tools/` 中不存在 `image_gen` / `tts` / `generateImage` / `text-to-speech` 工具（grep `image_gen|tts|generateImage|speech|image-to-image` 在 `src/` 下零命中，命中项均来自 `node_modules` 或 Markdown 渲染）。所谓多模态仅停留在"终端渲染 Markdown 里的图片链接"。
5. **多套 UI 并存，维护面大**：7 套 UI 相关目录，Ink 已弃用但仍保留，收敛未完成。
6. **默认权限偏宽松**：`toolConfirmation` 默认 `allow`（`config.ts` + `INTERNAL_DEFAULTS`），破坏性写操作默认无需确认，仅靠 `write_file`/`edit_file` 的 `checkPermissions` 返回 `ask`。对产品化客户端而言默认安全姿态偏弱。
7. **无 Settings / 会话管理 / 文件浏览器 UI**：配置仅靠 `~/.orion-code/orion.json` + 环境变量；会话 picker 仅在终端内，没有图形化设置面板、文件树、会话列表视图。

## 7. 与「桌面客户端应用（类 Codex / WorkBuddy）」的结构性缺口

| 桌面客户端要素 | Orion Code 现状 | 证据 |
|---|---|---|
| 真实前端框架（React DOM / Webview） | **无**。React 17 仅服务已弃用 Ink TUI；无 `react-dom`、无 Electron/Tauri/`BrowserWindow`/`webview` | grep 全仓（root package.json 无命中；仅 node_modules 命中） |
| 桌面/Web 外壳 | **无**。纯 CLI，`bin/orion` 是 Node 脚本 | `bin/orion`、`src/cli.ts` |
| 设置 UI | 无图形设置面板；仅 JSON 配置 + env | `services/global-config.ts`、`docs/orion.example.json` |
| 会话管理 UI | 终端内 session picker，无可视化会话列表/搜索/标签 | `terminal-ui/launch.ts`、`ui-v2/components/session-picker.ts` |
| 文件浏览器 / 编辑器集成 | 仅终端读写工具（`edit_file` + preview）；无 IDE 式文件树、diff 视图 | `src/tools/index.ts:294`、`ui/tool-preview.ts` |
| 多模态 UI（图片/富文本/渲染） | 仅 `marked-terminal` 文本渲染；无图片预览、无画布、无富文本输入 | `runtime/rich-text/*`、`ink-ui/components/Markdown.tsx` |
| 插件市场（Marketplace） | 无。Skills 仅本地目录扫描，无远程市场/安装/更新 | `src/skills/loader.ts`、`discovery.ts` |
| 作为产品的封装 | 以 **npm library** 形态发布；虽有 `sdk/*` 暴露 SDK 表面，但无安装器/自动更新/账户/计费 | `package.json`、`src/sdk/*` |
| 原生模块在桌面端的预构建 | `better-sqlite3`/`sqlite-vec` 需为桌面运行时单独 prebuild，当前未处理 | `package.json` deps、`memory/vector-store.ts` |
| 跨平台安装/更新 | 仅 `npm install orion` + Node>=18；无独立分发通道 | `package.json` scripts、`README.md` |

**结论性判断**：Orion Code 目前是**架构扎实、能力完整的 CLI Agent Harness**（agent loop、MCP、多层记忆、安全、Skills、子代理均为亮点），但距离「桌面客户端产品」仍有**结构性代差**。关键缺口：① 没有 Web/桌面 UI 框架与外壳；② 没有图形化设置/会话/文件管理界面；③ 没有插件市场；④ 原生模块（ABI）会成为桌面化的最大技术障碍；⑤ 对外宣称的"多 Agent 协作"与"多模态生成"在当前代码中未真正实现。
