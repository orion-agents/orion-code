# Orion Code v0.1.2 Pre-release Draft — Pre-commit Candidate

> RC2–RC17 are historical, superseded, or deliberately invalidated candidates. RC16 was invalidated by exact-target
> parser gaps and a Print shutdown rejection path; RC17 was invalidated by legacy multi-target npm/PR/release
> fail-open behavior and an Oxford-comma bypass. RC18 was later superseded when storage, controller fail-closed,
> deletion-fence, and subagent-scope fixes changed the source and package input. The current worktree is a
> pre-commit candidate with partial local evidence, not the final merge artifact. External release gates remain
> pending and the release is NO-GO.

v0.1.2 closes the single-session, single-active-Goal continuity loop introduced as a skeleton in v0.1.1.

## Highlights

- Typed Goal continuation carries goalId, revision, generation, sessionId, and continuation index without creating
  fake user messages.
- Goal tools are scoped to the current async runtime turn and session.
- `update_goal complete|blocked` is a turn-bound request; only the coordinator audit changes terminal state.
- The additive Goal contract, plan snapshot, evidence ledger, and criterion-by-criterion completion audit survive
  compact, process restart, and `/resume`.
- Failed, missing, unmapped, wrong-kind, expired, wrong-Goal, stale-workspace, or truncated evidence fails closed.
- Publish, PR, merge, and registry criteria require fresh external or trusted-user evidence; local version output
  cannot prove external state.
- Trusted external assertions are bound to the exact tool invocation and cannot be replayed for a different call.
- Persisted terminal sidecars replay the same semantic, action-aware, freshness audit before terminal state is
  restored.
- Restart and `/resume` restore an active Goal as paused; explicit `/target resume` is required to continue.
- Shared Goal events project into the public TUI, technical terminal renderer, and experimental Print mode.
- Per-turn accounting, budget preflight, CAS sidecar writes, and 20+ turn regression coverage are enforced.
- Failed, retried, fallback, and missing subagent usage is retained so incomplete accounting fails closed.
- `/doctor` reports valid or malformed Goal deletion fences and live/fence collisions without rewriting either file.
- Print mode stops active Goal continuation before runtime shutdown, includes terminal Goal events in JSON, and
  waits for both stdout and stderr flush callbacks before the CLI exits.
- Build and prepack clean `dist` before compilation so stale generated renderers cannot enter the package.
- Storage cleanup only atomically quarantines paths; writable metadata repair remains fail-closed disabled where
  race-safe directory-relative writes cannot be guaranteed.
- `SafetyChecker` isolates all policy arrays at constructor/update/read boundaries and recompiles blocked/dangerous
  matchers atomically before publishing a new policy, preventing external alias mutation from bypassing safety.
- Runtime, CLI, MCP, and Web User-Agent versions come from the installed Orion package rather than caller-provided
  npm environment variables.
- Git commits accept only exact file allowlists, reject directory/pathspec expansion, reject unrelated pre-staged
  files, and restore the index if staging verification fails.

## Compatibility and rollback

v0.1.2 reads v0.1.1 Goal sidecars and normalizes missing additive fields in memory. A real state update performs
the first write. A legacy `complete` marker without a v0.1.2 evidence contract is restored as paused and must be
re-verified; contract-bearing terminal data that fails audit replay is quarantined.

Prefer publishing a fixed v0.1.3 rather than overwriting v0.1.2. If the default registry version must be rolled
back, obtain explicit registry-write approval and run:

```bash
npm deprecate @orion-agents/orion-code@0.1.2 "Release blocked; use 0.1.1 or the next fixed release"
npm dist-tag add @orion-agents/orion-code@0.1.1 latest
npm view @orion-agents/orion-code dist-tags --json
npm view @orion-agents/orion-code@latest version
npm install -g @orion-agents/orion-code@0.1.1
orion --version
```

v0.1.1 ignores additive v0.1.2 fields but does not intentionally delete them. Rollback is complete only after the
registry reports `latest=0.1.1` and both a clean default install and an explicit `@0.1.1` install report
`orion v0.1.1`. The loopback-registry drill completed during RC7 proved this procedure without modifying
production npm state; a real rollback still requires separate registry-write approval.

## Scope limits

This release does not add multi-Goal scheduling, cross-session orchestration, unattended background execution, or
a stable Print/JSON API. TUI remains the public product; terminal-ui remains a technical diagnostics renderer; Ink
remains deprecated.

## Known limitations

- The richer TUI Goal inspector is deferred; v0.1.2 exposes compact Goal status, `/target status`, audit notices,
  and evidence IDs.
- `/doctor` and metadata preview are read-only. Writable Goal/project metadata repair remains disabled.
- The resilience V2 coordinator reports fallback disposition and pauses with incomplete accounting; it does not
  yet perform a real fallback-model switch.
- Automatic rescheduling after a standalone, non-query permission request remains deferred.
- Retained Ink/React/Yoga compatibility dependencies may emit deprecation warnings. Ink receives no new product
  features and is scheduled for physical removal in v0.2.
- RC18 full-source coverage exceeded 70% on all four metrics, but that run is historical because later source
  changes invalidated its denominator. The final merge candidate must rerun full-source coverage before the Gate
  or any waiver decision can be closed.
- RC12 and RC13 were not promoted after shared fixtures were observed. The repaired fixture set passed 20 rounds
  with three concurrent Jest processes (60/60 logs, 4 suites / 103 tests per process). This does not replace real
  Terminal acceptance.

## Pre-commit release status

multi-target external criterion; successful Goal commits could be reported as failed after lock cleanup and split
memory from disk; parallel children shared a mutable scope holder; `/doctor` accepted unsafe-integer fence revisions;
and Print did not wait for stderr flush. RC16 included those fixes but was invalidated when later audit found that
unversioned npm package conjunctions, package-specific versions, shared-repository PR shorthand, and GitHub URL

an Oxford-comma form were shown to fail open. RC18 addressed those parser gaps, but later Goal storage consistency,
controller mutation fail-closed, deletion-fence, and subagent-scope fixes changed the source/package input. RC16
