# v0.3.4 stabilization contract

The complete HTTP schema remains [the v0.3.3 OpenAPI document](v0.3.3-web-api.yaml), updated in the v0.3.4 branch to match the compatible wire additions below.

## Context-bound Settings mutation

```text
bootstrap(workspaceId, contextRevision)
  + settings(revision)
  -> PATCH settings(requestId, workspaceId, expectedContextRevision, expectedRevision, operations)
  -> admission guard
  -> idempotency digest
  -> atomic settings coordinator update
```

The Context guard is checked before any durable operation. A mismatch is `409 context_revision_conflict` with zero writes, Runtime applies, Session changes or provider requests.

## File identity

`kind` describes the lexical entry (`file|directory|symlink`). For a readable contained symlink, optional `targetKind` describes the effective target (`file|directory`). Authorization evaluates both the lexical alias and canonical Workspace-relative path at list and content-read time.

## Terminal ordering

```text
ready -> optional gap -> retained replay -> buffered live tail -> optional exit -> close
```

PTY output stays paused while replay drains. A high surrogate at the end of a non-final chunk remains buffered; final exit replaces any unpaired surrogate with U+FFFD. Browser xterm submission waits for acknowledgement when the remaining capacity cannot hold a complete pair.

## Durable tool truth

Legacy records are accepted only when both terminal receipt and durable receipt fact are absent. Modern records require both; canonical receipt digest, execution policy digest and durable fact fields must match before a successful `tool_finished` projection is emitted.
