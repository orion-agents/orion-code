## 2. Confirmed bugs (by severity)

### P1 — must fix before merge

**P1-1 · [SECURITY] SSRF protection bypassed by HTTP redirect**
- `src/tools/web.ts:311, 323, 328`
- `isUrlSafeForSSRF(url)` runs **only on the initial URL**. `fetch` is called with `redirect: 'follow'`, and `response.url` (the final URL) is recorded but **never re-validated**.
- Trigger: any fetched page returns `302/307` to an internal address (`http://169.254.169.254/`, `http://127.0.0.1:…`, `http://10.x`, `http://[fd00::]`).
- Impact: cloud metadata service / intranet admin ports reachable → information disclosure.
- Fix: use `redirect: 'manual'`, follow one hop at a time, re-run `isUrlSafeForSSRF` on **every** hop target.

**P1-2 · [DATA LOSS] `create`/`replace` can silently overwrite an active on-disk Goal**
- `src/runtime/goals/coordinator.ts:671, 698` + `src/services/goal-storage.ts:1166, 1200`
- `create()` guards against an active in-memory goal, but passes `this.state.goal?.revision` as `expectedRevision`. On the `load()` failure path the code sets `this.state.goal = null` (coordinator.ts:662) **while the disk sidecar is still present**. Then `expectedRevision === undefined` → `saveGoalInternal` skips the CAS/revision branch and the deletion-fence branch (both require `expectedRevision !== undefined`), and `!existsSync(path)` is false → it **overwrites the existing active goal**.
- Trigger: a failed goal reload (disk goal survives) followed by `/target create` or `/target replace`.
- Impact: in-progress Goal + its evidence/audit lost; state machine bypassed.
- Fix: when `expectedRevision === undefined`, require the sidecar to be `not_found` **or** already in a terminal state before allowing a fresh write; otherwise reject.

**P1-3 · [SAFETY] `plan` mode (and `acceptEdits`/`auto`) silently executes tools flagged `ask`**
- `src/framework/tool-scheduler.ts:292, 339`
- The **entire** ask/deny/confirm branch is gated on `permissionMode === 'default'`. In any other mode a tool whose policy returns `behavior === 'ask'` falls through to `return exec()` — executed **with no confirmation and no `confirmToolUse` callback**.
- Trigger: running in `plan` mode (whose contract is *do not execute changes*) when a mutating tool's `checkPermissions` returns `'ask'`.
- Impact: plan-mode's non-execution guarantee is broken; confirmations are silently skipped.
- Fix: branch by mode — `default` → interactive confirm/allow/deny; `plan` → deny `'ask'`/mutating tools; `auto`/`acceptEdits` → allow.

### P2 — should fix this cycle

- **P2-1 · [SECURITY] API key prefix leaked.** `src/services/config.ts:487` emits `${config.apiKey.slice(0,7)}***` — exposes the first 7 chars (recognizable prefixes like `sk-`, `AIza`, `AKIA`). Mask fully or hash.
- **P2-2 · [SECURITY/DoS] Unbounded response read.** `src/tools/web.ts:331-340, 362` only blocks when a `Content-Length` header exceeds the cap; a chunked/headerless huge body is read fully into memory. Stream with a hard byte ceiling and abort on overflow.
- **P2-3 · [CORRECTNESS] Wrong usage field.** `src/runtime/agent-runtime-controller.ts:1654` reads `goal.lastTurn?.totalTokens`; the real field is `goal.lastTurn?.usage.totalTokens` (types.ts:385). Provider budget pre-check silently degrades to estimated prompt tokens.
- **P2-4 · [CORRECTNESS] Web-search result mismatch.** `src/services/web-search-mcp.ts:275` falls back to `messages[0]` when no matching `id` is found → in multiplexed/out-of-order responses it returns **another request's** result. Use a per-id pending-request map.
- **P2-5 · [CORRECTNESS] `deletedPaths` always empty.** `src/services/storage-maintenance.ts:333, 398` — `deletedPaths` is declared/returned but never pushed; callers reading it get a misleading empty list. Push actually-deleted paths (or fold into `quarantinedPaths` and document).
- **P2-6 · [CORRECTNESS] `pending` task can't `complete`/`fail`.** `src/services/task-manager.ts:106-112, 220, 235` — `VALID_TRANSITIONS.pending` omits `completed`/`failed`, so calling `complete()`/`fail()` on a still-`pending` task silently no-ops and drops the result. Allow `pending → completed/failed` or warn.
- **P2-7 · [CORRECTNESS] `search()` corrupts memory LRU.** `src/memory/store.ts:196-204` — `search()` goes through `readWorking()`/`readShortTerm()`, which call `touchAll()`, flattening `lastAccessedAt` for all entries and defeating real LRU eviction. Search directly without touching.
- **P2-8 · [CORRECTNESS] Negative elapsed not clamped; fail-closed not persisted.** `src/runtime/goals/accounting.ts:23` + `coordinator.ts` `failClosedAfterPersistenceError` — clock rollback yields negative `timeUsedMs`; the thrown `RangeError` path only flips in-memory state to `paused` and never persists, so fail-closed is lost on restart. Clamp `Math.max(0, …)` and persist on the error path.
- **P2-9 · [DEAD CODE] `fallback_once` never switches models.** `src/services/provider-resilience/coordinator.ts:133-135` + `error-classifier.ts` — only increments a counter; no model switch ever occurs and the classifier never returns it. Either implement the fallback or remove the enum/branch.
- **P2-10 · [DEAD CODE] `sharedGate` always `undefined`.** `src/runtime/subagents/runtime-integration.ts:151` — `SubagentTurnInputs` has no `sharedGate` field, so the provider gate is rebuilt every root turn. Wire it through or delete the branch.
- **P2-11 · [DEAD CODE] Duplicate `instanceof`.** `src/services/llm.ts:556` — redundant `ProviderRetryExhaustedError` check after an earlier branch already handled/threw it.
- **P2-12 · [CONTRACT] `GoalBlocker.retryable` is literal `false`** (`types.ts:49`) while `AgentTurnOutcome.blocker.retryable` is `boolean` (`:394`); `isGoalBlocker`/`auditBlocked` require `=== false`. Persisting `outcome.blocker` directly (without coordinator rebuild) fails validation and quarantines the sidecar as corrupt. Narrow the type or document the rebuild requirement.
- **P2-13 · [DEAD CODE / DRIFT] `blockerFingerprint` unused.** `src/runtime/goals/completion-audit.ts:857` is never called; the fingerprint format is duplicated inline in `tools.ts` (~331) and `coordinator.ts:1341`. A format change in one place silently breaks `blockersMatch`. Centralize on `blockerFingerprint`.
- **P2-14 · [DIAGNOSTIC] Inverted label.** `src/runtime/goals/coordinator.ts:157` — `planUpdateProposed ? 'no-change' : 'none'` is backwards. Cosmetic/log-only.
- **P2-15 · [SUBTLE] `totalTokens` excludes subagent share.** `src/runtime/agent-runtime-controller.ts:746-749` — `totalTokens` is computed from root-only tokens; consumers treating it as "total cost" undercount subtasks. Either add `subagentTokens` or document it as root-only.
- **P2-16 · [TEST/REAL] print-mode flush never resolves.** `tests/print-mode.test.ts` "does not resolve until redirected stderr reports its queued diagnostics flushed" **reproducibly times out (5003 ms)** in isolation. The promise that should resolve when redirected stderr flushes its queued diagnostics is never fulfilled — points at event-sink flush wiring in `src/print-ui/launch.ts` (changed this PR). Verify the flush-completion signal.

## 3. Jest failure root-cause (mostly environment, NOT code regressions)

The 27 failures are **environment/parallelism blocked**, confirmed by isolating suites:

| Suite | Verdict | Root cause |
|-------|---------|-----------|
| `vector.test.ts` | **ENV** | `better-sqlite3` built against `NODE_MODULE_VERSION 137`; running Node needs `127`. Rebuild native module. |
| `storage-maintenance.test.ts` | **ENV** | Sandbox `EACCES` on the safe-delete trash dir (`/var/folders/…/codebuddy-safe-delete-bulk/…`) + vector DB unavailable. |
| `tui-ui-pty.test.ts`, `terminal-ui-pty.test.ts` | **ENV** | Headless sandbox has no real PTY (64 s timeouts). |
| `goal-lifecycle-pty.test.ts` | **ENV (parallelism)** | **PASSES in isolation** (44 s). Full-run failure = PTY/resource exhaustion under `--runInBand`/parallel load. |
| `goal-long-session-combined.test.ts` | **ENV (parallelism)** | Same as above. |
| `print-mode.test.ts` | **1 real + env** | 10/11 pass in isolation; the diagnostic-flush timeout (P2-16) is a reproducible real failure; the other full-run failure was the 28 s test SIGTERM'd by parallelism. |

**Action:** re-run the suite in proper CI (matching Node for `better-sqlite3`, a real PTY, and without the sandbox `EACCES`) before treating these as green. The code's own acceptance tests (goal lifecycle, storage-maintenance symlink safety) are exactly what must pass pre-merge.

## 4. Corrected false positive

- **Subagent `grep` directory-symlink escape (flagged by CR agent) is NOT real.** In `src/runtime/subagents/child-executor-guard.ts:312-317`, `checkGrepDescendantSymlinks` uses `entry.isDirectory()` / `entry.isSymbolicLink()`. Node `Dirent.isDirectory()` returns **false for symlinks** (reflects the entry's own type), so a directory symlink is **not** pushed/traversed — it's skipped at `statSync(...).isFile()` (line 324). File symlinks ARE correctly validated (line 339). So `grep` does **not** escape via directory symlinks.
- **Real residual gap:** `glob` is in `BASE_PATH_TOOLS` (line 29), which gets **only** `checkContainment` (base-path) and **no descendant symlink check** (the descendant check runs only for `grep`/`SEARCH_PATH_TOOLS`). Whether this is exploitable depends on whether the glob executor follows directory symlinks — verify, but rate **lower confidence / not a confirmed escape**.
