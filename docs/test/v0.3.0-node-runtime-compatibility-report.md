## 1. 结论

Orion Code v0.3.0 的当前安装与运行合同为：

- Node `22.12.0+`；
- Node `24.0.0+`；
- Node `26.0.0+`。

同一个 `@orion-agents/orion-code@0.3.0` npm tarball 在上述三个最低版本上完成独立 clean
install、原生 SQLite、CLI/TUI/Web/Goal/subagent/Skill/MCP/compact-resume runtime 探针，并由真实
Google Chrome 完成三次完整 Primary 旅程和三版本 critical 旅程。没有用一个 Node 版本编译的
`node_modules` 代替另一个 ABI，也没有把 skip、retry 或预期失败记为 pass。

这是开发候选的兼容性 `GO`，不是发布授权。artifact receipt 明确记录 `dirty=true`；可发布版本仍须由
clean commit 重新生成新 tarball，并让远端 CI 对该新 SHA 重跑相同门禁。

## 6. 本轮加固

- `package.json` 与 shrinkwrap root 的 Node engine 统一为
  `^22.12.0 || ^24.0.0 || ^26.0.0`，dependency policy 对两者做 fail-closed 一致性校验。
- CLI 在进入产品代码前拒绝不支持或低于 floor 的 Node 版本；Node 20 不再属于 v0.3 合同。
- CI source、exact-tgz runtime 与 real-Chrome critical matrices 显式覆盖 Node
  22.12.0/24.0.0/26.0.0；缺失或 skip 不能生成 `GO` receipt。
- Runtime/Web/final receipt 校验 Node major、完整 semver floor、时间戳、digest、状态、场景覆盖和
  tarball/runner/target binding。
- Settings Host-restart 场景在停止旧 Host 前等待 startup catalog response 完成；没有全局放宽
  console error 门槛，额外错误仍会使场景失败。

## 7. 边界与后续发布条件

1. 本地证据是 macOS arm64 + Chrome 152；CI 的 pinned-floor Linux lanes 必须在 clean commit 上继续
   产出远端证据，不能用本报告替代跨 OS 证明。
2. `better-sqlite3` 声明范围为 `^12.10.0`，本次 consumer install 实际解析为 `12.11.1` 并在三个
   macOS ABI 上通过；这仍允许未来 registry 解析漂移，也存在 prebuild 下载失败后回退本地
   toolchain 的供应链/网络风险。后续应固定 consumer resolution 或评估 N-API 版本。
3. 未接入产品 first-party MCP path 的 legacy HTTP/SSE transport 仍依赖环境 EventSource；本次承诺的
   first-party stdio MCP 已通过，不把未接入分支扩大为产品支持声明。
4. source 为 dirty，live-provider canary 为 `NOT_RUN`，且未执行 commit/tag/push/npm publish。发布前必须
   从获批的 clean commit 重建；新 artifact SHA 会使本报告中的 candidate receipt 自动失效，必须重跑。
