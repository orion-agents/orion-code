# Orion Code v0.3.3 Web Workbench 真实 E2E 计划

- 版本：v0.3.3
- 状态：实施中；任何 required scenario 缺失、skip、expected-fail 或证据不完整均为 `NO_GO`
- 产品计划：[`../plan/v0.3.3-plan.md`](../plan/v0.3.3-plan.md)
- API 合同：[`../architecture/v0.3.3-web-api.yaml`](../architecture/v0.3.3-web-api.yaml)

## 1. 测试目标

v0.3.3 必须同时证明两条产品能力：

1. `appearance.style=classic|orion-blocksmith` 是 Host 持久化的封闭内置设置，默认方块工坊；它与
   `system|light|dark` 原子保存、即时生效、重启恢复，且不放宽 CSP 或引入远程资产；
2. Web Host 使用显式 Session actor 路由，至少三个 Session turn 可并行；切换只加载目标最新页与增量，
   后台任务、审批和草稿保持；第 4 个任务进入可见、可取消的 FIFO 队列；工作树写入由共享仲裁器保护。

Shell 同时保持右栏折叠为右侧全高 48px rail，Settings 常驻入口仅在项目栏底部。

## 2. 运行边界

每次发布验证只接受以下链路：

1. 从待发布源码构建一次 exact npm tarball 和 artifact receipt；
2. 安装到全新、run-owned prefix，不导入用户 HOME、`.env` 或全局配置；
3. 从安装包的 `bin/orion web --no-open --port 0 --cwd <fixture>` 启动真实 Host；
4. 使用真实 Google Chrome、真实 HTTP/SSE/Terminal WebSocket、确定性 loopback OpenAI provider；
5. raw PNG、脱敏网络/console facts 留在 `tests/tmp/web-e2e/<run-id>`，最终 receipt 绑定 tarball SHA、
   installed target digest、runner digest、browser version 和 scenario manifest digest；
6. Node 22.12.0、24.0.0、26.0.0 使用同一 tarball 跑 critical matrix；primary Node 22.12.0 fresh run 三次。

禁止以 Vite dev server、源码 import Host、fake Runtime、DOM 状态注入、`force` click、固定 sleep 或手工截图
代替发布证据。

## 3. required scenario

### Track A：内置方块工坊

`WEB33-P0-01..12` 依次覆盖默认 appearance、原子切换、刷新/重启、独立 reset、多窗口/外部编辑、
last-good、Tool/approval/Plan/Goal、真实 PTY、Files/Git/Review/大输出、响应式、axe/zoom/forced colors、
CSP/资产/隐私。

### Track B：多 Session 与 Shell

`WEB33-P0-16..24` 依次覆盖运行中切换、双 turn 并行、后台审批、同 workspace 写仲裁、双标签页显式路由、
warm/cold/10k 切换预算、pool/LRU/restart、右栏 rail、Settings 单入口。

完整语义和阈值以产品计划第 12、22 节及
`src/runtime/release-receipts.ts::WEB_E2E_WEB33_SCENARIOS_V1` 为唯一编号源。测试标题必须只含一个
`WEB33-P0-XX`；每个场景至少提供一张受控 PNG 和 `tests/e2e/scenarios.ts` 要求的结构化 facts。

## 4. 关键硬断言

- 并行：两个 provider request 同时处于未完成状态，`peakRunning >= 2`；Session A/B 的 prompt、turn、
  transcript、approval、journal 和最终 marker 不交叉；
- 排队：前三个 Session running 时第 4 个返回 `session_turn_queued`，携带 UUID `queueId`、位置与
  `runtimeRevision`；取消后 provider request 和 durable turn side effect 都为 0；
- 切换：warm p95 ≤150ms、cold p95 ≤800ms；单次最多一页 snapshot + cursor delta；全局 SSE 不重连，
  Settings/Skills/MCP/Tool catalog 请求数为 0；
- 写入：同 workspace 变更工具串行，stale target revision 在副作用前 409；不同 workspace 可并行；
- 主题：Settings 草稿只改变 CSS 预览；Host CAS 成功后根 `data-ui-style`、`data-theme` 和 theme-color
  同一视觉提交生效；Terminal ID/buffer/focus 不变；
- Shell：320、390、760、1024、1180、1181、1440、1920 无水平溢出；桌面折叠 rail=48px 且始终右侧
  全高；正常态“打开设置”持久按钮恰好 1 个；
- 安全：console error/warning、page error、HTTP 5xx、secret finding、dropped event、CSP violation 均为 0。

## 5. 分层门禁

1. 单元/合同：Settings schema 1→2 兼容、Session registry、actor CAS、queue cancel、arbiter、event/reducer；
2. 集成：真实 `OrionRuntimeV1`、ToolGateway、Thread journal、loopback provider，禁止 fake executor 证明
   并行或写入正确性；
3. 浏览器：全量 WEB33 exact-tarball Chrome；
4. 矩阵：Node 22.12/24/26 critical WEB33；
5. 回归：全部旧 E2E、SET、WEB31、WEB32 required scenarios；
6. 发布：final receipt 只有在 source clean、同 tarball、所有 manifest GO 后才可 GO。

## 6. 当前完成定义

代码、单元测试或单次本机截图不等于完成。只有以上分层门禁均通过并生成新的 v0.3.3 digest-bound
receipt，才可将计划状态改为完成；在此之前不得合并、打 tag 或发布 npm。
