## 真实性能

真实本地 catalog：453 个 Session、99 个项目；目标长 Session 为 90 条 transcript、1,011 个
Thread events。

| 路径                        |                   修复前 |                                     最终候选 |
| --------------------------- | -----------------------: | -------------------------------------------: |
| `GET /api/v1/workspaces`    |                19,590 ms |                   20.9–29.8 ms（常驻热路径） |
| `GET /api/v1/sessions`      |                 3,895 ms |                   1.37–1.66 ms（常驻热路径） |
| Web 切换 2 条 Session       | 约 2,637 ms 的旧基线样本 |                                   415–444 ms |

| CLI `/resume` 90 条 Session |        613,458-byte JSON | 1,741-byte JSON；1.017–1.044 s fresh process |

CLI 时间包含约 0.85 s 的 Node/CLI 进程启动。Store 中完整模型上下文没有裁剪；只有 renderer
历史窗口被限制为最近 50 条、总计最多 256 KiB，print 模式不回显旧 transcript。

90 条 Session 的首次冷开仍比 `< 1 s` 目标高 157 ms，因此本报告只判定热路径达标。若后续真实
Thread 冷开超过 1 s 的比例上升，应按方案落盘 `ThreadHeadV1` 和不可变 transcript page index，不能
通过延长 timeout 掩盖。
