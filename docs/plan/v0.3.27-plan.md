## 1. 版本决策与用户价值

v0.3.27 建议聚焦一个完整切片：**专业代码审查闭环**。

CLI 从“输入 `/review` 后进入普通 Agent 对话”，升级为“明确审查范围、只读执行、输出可定位的
问题和覆盖说明、保留可恢复收据”；Web 复用相同运行时结果，在现有审阅面板中完成问题查看、
diff 定位和向修复任务反馈。不是新增另一套 Agent 引擎，也不是只改一个审查提示词。

交付后，用户应能：

1. 在 CLI 审查当前工作区，或审查相对指定基线的已提交改动，看到实际比较对象。
2. 获得按严重程度组织、包含触发条件、影响和准确位置的问题，而不是泛泛建议或原始 JSON。
3. 在 Web 发起同类审查，在审阅面板中定位问题，并把选中问题加入当前修复草稿。
4. 在审查期间切换会话、继续其他任务；刷新或重启后查看已经提交的审查结果。
5. 明确区分“未发现问题”“覆盖不完整”“执行失败”“结果已过期”，不把工具成功当成审查通过。

### 1.1 为什么选这一切片

项目级目标要求 CLI 首先具备专业编码能力，Web 为同一条工程主路径提供可视化承载。
当前 `/review`、只读子任务、结构化 diff、TurnCommit、Context 和 Web 审阅面板都已有接入点，
但没有形成共享的代码审查产品契约。补齐这条链路比继续堆叠面板和 slash 命令更接近可验证的价值。

本次是基于源码缺口作出的版本建议，不代表人工缺陷集质量或线上故障频率已经测量。
若实施前现有会话、diff 或恢复回归仍为红，先修复这些 P0，再接入本切片；不以新功能掩盖可靠性问题。

**必须交付：** 两种审查范围、共享只读执行、结构化 findings、覆盖说明、CLI 展示、Web 问题定位、
显式修复反馈、持久化与兼容、真实 Host / PTY 验证、人工标注质量评测。

## 3. 用户流程与命令边界

### 3.1 CLI

建议语法在 PR0 冻结；不得静默改变已有合法用法：

```text
/review                         当前工作区：暂存 + 未暂存 + 可安全读取的未跟踪文件
/review all                     兼容别名，等同当前工作区
/review --base main             merge-base(main, HEAD) → HEAD 的已提交改动
/review --path src/runtime      当前工作区中的路径过滤
/review --base main --path src  基线比较中的路径过滤
```

现有 `/review <existing-path>` 映射为路径过滤并给出明确范围；无法识别的参数提供用法或澄清，
不能当成分支、路径或任意普通聊天悄悄继续。路径使用结构化参数，不拼接 shell 字符串。
`--base` 不夹带脏工作区改动；界面明确提示这一点。非 Git 项目、无效 ref、无共同祖先、
浅克隆造成的信息不足、歧义 merge-base 均返回可操作错误，不能改用另一个比较范围。

开始时显示仓库、范围、解析后的 commit / 快照、过滤路径、模型和预算；结束时显示 findings、
覆盖范围、跳过原因、耗时和结果状态。80 / 120 列、CJK、NO_COLOR 均有清晰降级。

### 3.2 Web

沿用现有右侧审阅工作区，提供“变更 / 审查结果”轻量视图切换：

1. 选择“工作区 / 相对基线”，可选路径过滤，确认实际比较说明后开始审查。
2. 列表显示严重程度、问题标题、文件和行号；正文显示触发条件、影响、证据和覆盖说明。
3. 点问题优先打开对应快照 diff，准确区分 old / new side；只有安全映射到当前文件时才提供文件行跳转。
4. “交给 Agent 修复”将问题引用合并进草稿，由用户正常发送；保留既有草稿，不自动启动修复。
5. 已运行的审查有独立状态，可取消；切到其他会话不取消、不重连审查，也不全局置灰导航。

审查执行占用所属会话的正常回合资源。已有回合运行时沿用队列语义，不绕过 actor 上限另起引擎。
队列保存仓库、会话和 selector，在**实际获准开始审查时**冻结输入，界面注明“以开始时快照为准”。
启动后不因用户切项目、切分支或切会话而重新定向到当前前台选择。

## 4. 共享审查契约

### 4.1 身份、状态与结论

建议新增 `CodeReviewRequestV1`、`CodeReviewResultV1`，放在共享 Runtime / domain 层。
以下是需实现和测试的设计字段，不是当前已有 API：

```typescript
type ReviewSelectorV1 =
  | { kind: 'worktree'; paths?: string[] }
  | { kind: 'base'; ref: string; paths?: string[] };

type ReviewRunStateV1 =
  | 'queued'
  | 'running'
  | 'completed'
  | 'partial'
  | 'failed'
  | 'cancelled';

type ReviewConclusionV1 = 'findings' | 'no_findings' | 'inconclusive';

interface ReviewFindingV1 {
  findingId: string;
  priority: 'P0' | 'P1' | 'P2' | 'P3';
  title: string;
  trigger: string;
  impact: string;
  fileKey: string; // Host validates against the frozen manifest.
  side: 'old' | 'new';
  startLine: number;
  endLine: number;
  evidence: string;
}
```

结果至少包含：schemaVersion、reviewId、workspaceIdentity、sessionId、threadId、turnId、
requestedSelector、实际 resolved target、输入 snapshotDigest、rulesDigest、状态和结论、
findings、coverage、限制与风险、模型标识、usage、开始／结束时间、receiptDigest。
coverage 必须有实际已检查文件和区间、跳过对象及原因、截断和预算耗尽情况，不能只记总文件数。
P0 仅用于有充分证据、无需特殊前提即可阻断使用的严重问题；等级定义、去重和有效位置规则在 PR0 冻结。
队列尚未获准执行时不伪造 turnId / snapshotDigest；它们在 admission 后绑定，最终收据必须完整。

不把状态压成一个布尔值：

| 情况 | 允许显示的结论 |
| --- | --- |
| 完整完成、覆盖声明通过校验、零有效问题 | “本次审查范围未发现问题”，不是“代码没有缺陷” |
| 发现有效问题，即使部分范围未覆盖 | 展示问题，同时突出 partial / 未覆盖清单 |
| 失败、取消、格式无效、空响应或覆盖无法确认 | inconclusive，不允许绿色“审查通过” |
| Git 无变更且范围解析成功 | “所选范围无变更”，无需调用模型；与“审查完成无问题”区分 |
| 代码或规则随后改变 | 保留历史结论，额外标记 applicability=stale；不篡改原收据 |

模型自报 coverage 不是独立证明。Host 记录实际提供的快照内容和读取活动，校验模型声明是否超出
可见范围；无 skipped 也不等于模型必然识别所有缺陷，质量仍依赖人工标注评测。

### 4.2 快照与比较来源

1. 默认 worktree 的 staged、unstaged 和 untracked 分开记录，不把同一路径的两段比较混成一个来源。
2. base 范围在开始时解析 ref、HEAD、merge-base 为不可变 OID；ref 后续移动不改变该次输入。
3. Git 对象按 OID 读取；工作区内容有前后校验、内容 digest 和有界重试。持续变化则失败或 partial，
   不用仅凭时间戳或一个仓库 revision 代表所有正文已冻结。
4. rename / delete 使用 old / new path 和 side；删除行不能跳到不存在的新文件行。
5. 文件读取复用敏感文件、二进制、越界和符号链接安全策略；这些限制同时作用于模型输入和落盘快照。
6. 适用 AGENTS.md 按目标文件的祖先作用域解析，记录规则 digest；不只假定当前 cwd 的规则覆盖所有路径。
   审查后规则变化影响再次运行及修复适用性，不静默重写历史结果。
7. Git 使用参数数组及受控只读子进程，禁用 external diff / textconv，避免可选锁和任意仓库命令执行。
   共享读取服务不开放任意 Git 子命令给模型。

模型看到的目标正文和 diff 必须来自冻结快照，普通 `read_file` 也不能绕回可变工作区正文。
补充读取依赖文件时经审查专用读取适配层有界捕获并记录 digest / provenance；如果不能证明它与
该次输入一致，停止或标记不完整，不能一边声称冻结、一边用当前内容拼接旧问题。
只报告本次改动引入或加剧的可证明缺陷；现存无关问题不混入本次 findings。

建议把最小公共实现归入 `src/services/code-review/` 或已有合适的共享服务目录；具体归属在 PR0 确定。
保留现有 Web Git reader 的公开行为与测试，不为复用而重写全部 Git 功能。

### 4.3 有界资源

PR0 固定默认预算并写入测试：每次最多 50 个文件、2 MiB 可发送正文、1 MiB diff、50 次读取工具调用、
5 分钟执行时间；最多 100 条 findings，最终结构化结果最多 256 KiB。
这些是本版初始产品限制，不是已测性能；Provider token 窗口更小时取更严格值，不能在运行中偷偷放大。
超限列入 skipped / partial，允许用户缩小路径重新运行，不静默截断后宣布全部完成。

## 5. 只读执行：不能停留在提示词

### 5.1 共享执行路径

审查沿用 AgentLoop、ToolGateway、取消、预算、队列与 usage 链路。以不可变 workflow constraints
约束该回合；不是创建另一种聊天 Runtime，也不是临时修改用户全局权限或强制改成 PLAN 模式。

- 模型只暴露有界 read / list / glob / grep 及安全批量读取能力；Host 提供冻结的 Git 输入。
- 默认不向审查模型开放 shell、写文件、编辑、Git mutation、MCP、外网工具、动态高权限技能、
  递归派生任务或修改运行设置；测试命令也可能写缓存，因此不在只读审查内自动执行。
- constraints 同时进入 capability compilation 与最终 tool dispatch；直接调用、批量调用、别名、
  steering、压缩和恢复都不能绕过。AUTO / ALLOW 只能收紧或维持，不能提升该回合权限。
- Provider 的必要模型连接由既有受控调用负责，与“向 Agent 开放任意网络工具”分开。
- 允许 Orion 数据目录中的必要日志、快照和收据写入；禁止修改被审查仓库、index、refs 和用户配置。
- 仓库规则、代码注释和工具输出都是不可信内容；不能要求“先运行修复脚本”而突破只读边界。

模型指令应显式加载审查策略：只报有证据、可操作的问题，解释触发与影响；排除纯风格意见、
无依据猜测和重复问题。输出经过 schema、路径成员、行范围、side、大小与文本安全校验。
无效 finding 单独计数和展示限制；不能因清理掉全部无效条目而转成 no_findings。

### 5.2 审查与修复分离

修复是用户之后发起的普通编码回合，使用其明确选择的模式和权限，重新校验输入是否适用于当前代码。
审查回合结束不遗留只读锁；普通 BUILD 不被意外降权。反过来，后续 BUILD 也不能追溯提升审查回合权限。

修复反馈只提供可信来源和建议，不把 finding 的 evidence 当自动执行指令。暂存、提交、推送、发布
仍遵守已有授权边界；“完成审查”不授权这些动作。

## 6. 持久化、恢复与兼容

### 6.1 单一事实链

共享 Runtime 持久化 versioned review receipt，并由同一回合提交关联摘要和 digest；CLI / Web
读取相同投影。可复用 TurnCommit 的收据模式，但新字段、序列化和摘要算法必须有明确兼容方案，
不得改变旧 TurnCommit 的可验证性，也不得仅往未知事件中塞字段就假定旧客户端能读取。

- 结果 schema 校验和持久化完成后才发布终态事件；崩溃于半写入时不能出现 completed。
- 既有终态结果不可被重试覆盖；重跑使用新 reviewId，保留来源关系。
- 重启恢复显示已提交结果；中断中的审查显示 interrupted / inconclusive 的恢复说明，
  不自动重启 Provider 请求。执行态到展示态的映射要写入协议测试。
- 取消后的晚到结果不覆盖取消状态、不更新别的会话；使用现有 turn / actor 归属防护。
- 审查产物纳入既有 Session / Thread 删除与孤儿清理生命周期；不增加无法回收的旁路目录。

审查输入快照作为内容寻址 artifact 保存。每个 Session 默认保留最近 5 份输入，且原始输入总量
不超过 10 MiB；超限先回收旧输入，保留有界结果和 manifest，并标记 snapshot_unavailable。
快照被回收后，历史问题不能偷偷打开当前同路径正文冒充原证据；结果也需遵守既有会话存储上限。
不记录凭据、环境变量明文或被过滤的敏感文件内容。

### 6.2 Host / Web 增量契约

建议复用现有 command 通道添加 `start_code_review`，参数为类型化 selector；取消复用对应回合控制。
保留现有 Git `/review` 事实读取接口，不改变含义。新增有界分页的审查列表和单条收据读取接口，
建议为 `GET /sessions/:sessionId/code-reviews` 与 detail；最终路径、类型名在 PR0 与实际 router 对齐。

要求：

1. bootstrap 显式声明 `codeReviewV1` 能力，command / event / snapshot / receipt 的版本与验证器同步。
2. Host 继续落实 loopback、会话归属、workspace 身份和 Context 校验；不能由浏览器路径绕过安全 token。
3. 老 Host / 新 Web 隐藏不支持的启动动作并解释；新 Host / 旧客户端能读取旧会话，未知内容正确降级。
4. 旧会话没有审查收据时显示“尚无审查结果”，不能扫描普通聊天猜测 findings 充当已提交结果。
5. 审查结果读取不创建 actor、不连接 Provider，不触发执行式 Session 激活。

## 7. Web 定位与反馈细节

新增 `review_finding` Context 引用，至少含 reviewId、findingId、receiptDigest 和 workspace 身份。
Host 解析权威收据及快照，验证权限、当前适用性和大小，再组装 Context；不接受客户端传来的
任意正文、行号或仓库 revision 作为权威事实。

| 交互 | 必须行为 |
| --- | --- |
| 点击当前问题 | 打开精确 source / side / 行范围；复用现有安全文件映射，必要时扩展 line reveal |
| 点击已提交基线问题 | 打开冻结比较，不拿当前工作区文件替代历史内容 |
| 同文件 staged 与 unstaged 各有问题 | 保持各自来源和锚点；避免文件名相同就复用错误 diff |
| 文件删除、改名、被过滤、快照回收 | 给出准确不可定位原因，问题仍可查看；禁止错误回退 |
| 将问题加入草稿 | 不覆盖草稿，不自动发送；引用有可移除标签和简短摘要 |
| 发送时代码或规则已变化 | stale conflict（建议 409）在 Provider 前返回，保留草稿；用户重新审查后再修复 |
| 切到会话 B | B 的草稿、模型、滚动与状态独立；A 的进度只更新 A，不抢回前台 |
| 审查 partial / failed / cancelled | 不用“0 问题”遮盖状态，保留可重试入口和限制说明 |

本版不迁移所有旧 hunk 反馈为新格式；旧文本反馈继续可用，但不冒充具有完整来源校验的 finding Context。
视觉沿用当前活动栏、面板、内部分割和主题，不另造全屏审查 IDE；侧栏宽度、对话固底、窄屏抽屉均回归。

## 9. 真实测试方案

### 9.1 分层与证据真实性

- **单元／契约：** selector 解析、范围、版本、摘要、finding 校验、预算、权限、stale、事件幂等。
- **真实 Git 集成：** 临时真实仓库和真实 Git 对象；包含 tracked / untracked、暂存与未暂存同文件、
  rename / delete、CRLF / Unicode、二进制／敏感／越界、浅克隆与 ref 错误、审查期间外部改动。
- **真实 PTY：** 运行打包 CLI，验证启动、排队、CJK、输出、取消、恢复和正常编码回合的权限恢复。
- **真实 Host + Chrome：** 使用安装后启动的 Host 和打包 Web，UI 不 mock API、不把组件测试叫 E2E。
  可控 Provider 只控制模型响应与攻击性工具调用，用来验证协议／拒绝路径，不证明模型真实审查能力。
- **真实模型质量：** 固定模型、预算、提示、仓库提交和人工标注答案，单独运行与报告；不得拿可控 Provider
  的预设正确 finding 计算召回率。执行付费模型测试前确认适用授权和预算，本轮计划不执行。

只读断言必须比较仓库文件内容、Git index、refs、tracked / untracked 清单与用户配置；仅断言
`git status` 干净不足以证明没有发生“写入后撤销”。记录工具 gateway 拒绝记录及子进程列表，
区分合法 Orion 数据目录写入与目标仓库写入。测试复用既有 fixture、artifact 和 evidence 管道。

### 9.2 本版关键 E2E 场景

新增独立 `WEB327-P0-*` 场景并登记到维护中的场景注册表；下列均为待实现，不是现有已通过用例。

| 场景 | 操作 | 达成目标与证据 |
| --- | --- | --- |
| WEB327-P0-01 范围 | worktree 与 base、同文件 staged / unstaged、路径过滤 | UI / CLI 显示实际快照；预期输入 hash 对应真实 Git 内容，无混源 |
| WEB327-P0-02 只读 | ALLOW / AUTO 下模型尝试 shell、编辑、MCP、间接批量写入 | 在 dispatch 被拒；仓库／index／refs／配置前后不变；无实际写入调用 |
| WEB327-P0-03 定位 | 新增、删除、改名、历史比较、重复行 | findings → 正确 side / 行 → 有效 Context；历史内容不串当前文件 |
| WEB327-P0-04 并发 | A 审查中切 B、B 发消息、新建 C、再回 A | 无全局灰态、无 A 结果串 B、无导航触发 Provider / Runtime 重建 |
| WEB327-P0-05 陈旧 | 审查后改代码／index／分支／规则，再发送反馈 | 历史结果仍可读，反馈明确 stale 且 Provider 前阻止，草稿保留 |
| WEB327-P0-06 恢复 | 刷新、Host 重启、结果提交前崩溃、取消后晚到 | 已提交结果一致；半提交不完成；不自动重放 Provider，不覆盖终态 |
| WEB327-P0-07 不完整 | 超预算、截断、无效 JSON、越界 finding、空输出、Provider 失败 | partial / inconclusive 如实显示，不能得到绿色 no_findings |
| WEB327-P0-08 生命周期／兼容 | 旧会话、旧 Host、输入回收、Session 删除 | 正确降级，无旧数据损坏、无孤儿 artifact、无把当前内容冒充旧证据 |
| WEB327-P0-09 反馈边界 | 有草稿时加多个问题、手动发送、修复后重审 | 草稿保留且无自动副作用；修复为新回合；重审产生新收据 |
| WEB327-P0-10 布局 | 宽／窄屏、主题、面板拖宽、内部拖动、长问题和长代码 | 输入框固底、面板不落下方、无横向撑破、键盘焦点可达 |

每项保存机器断言、Host／Provider 事件摘要、输入／收据 digest 和必要截图；失败同样保留 artifact。
负向场景不能仅靠截图通过。注册表、critical gate、证据索引同步维护，原有 critical 场景不降级、不删除。

### 9.3 审查质量基准

本版建立至少 20 个独立样本：12 个明确缺陷样本 + 8 个干净／合理改动对照，覆盖至少 TypeScript / JS
和 Python，包含边界判断、异步／取消、资源生命周期、权限／路径与回归。每个样本固定 repo commit、
scope、可见材料、预期触发条件与允许定位范围，并在运行前人工复核，不允许看过结果再改答案。

固定一个用户实际支持的模型与配置，独立运行 3 轮，逐轮报告而非只报最好一轮。初始门槛：

- 每轮召回至少 9 / 12 个标注缺陷；重复问题不增加 TP，错误位置不算命中。
- 每轮有效 finding precision ≥ 80%；分母含误报，不能把误报先过滤掉再计算。
- 每轮最多 1 / 8 个干净样本出现缺陷误报；风格建议不得伪装成问题凑数量。
- 每轮至少 18 / 20 个样本在预算内产出有效终态；partial / failed / cancelled 单独计数，
  不剔除失败样本后再提高召回或精度。
- 报告每样本耗时、token / 成本、人工接管和无效输出；语义匹配由人工判定并记录理由。

门槛在 PR0 冻结；这些是本版有限基准，不是对任意代码库的质量保证。没有实际模型预算时必须记
`not_run`，不能用 fixture 替代；未达标则不宣布专业审查稳定交付，先修正实现或显式重新评审范围。
长期目标中的多语言 50+ 真实编码任务评测继续保留，不能被这 20 个审查样本替换。

### 9.4 性能与原有能力回归

沿用项目级指标：缓存会话暖切换 p95 ≤ 100ms；10 / 100 / 1000 会话与 10k 历史分组、每组
24 次切换、3 轮记录；没有有效缓存时的读取与首屏单独统计，不能把网络等待混入或从报告删除。
元数据冷首屏目标 ≤ 500ms，CLI 输入反馈目标 ≤ 50ms；固定机器、数据、构建、采样方式。

审查列表读取不拉全量 diff / 正文、不启动模型；切会话不为了看结果重新激活执行 Runtime。
评测新增模块前后事件循环延迟、切换、发送与新建；超门槛先定位投影、I/O 或主线程开销，不靠固定延时掩盖。
完整复跑既有 v0.3.24 会话响应、v0.3.25 回归、v0.3.26 diff / Session 生命周期关键场景。

## 11. 风险与控制

| 风险 | 控制与退出条件 |
| --- | --- |
| 新 UI 有入口但 Runtime 仍普通聊天 | 明确 workflow discriminator；测试真实 compiler / gateway 的约束，禁止静默 fallback |
| 只冻结 revision、不冻结内容 | OID / digest / 内容 artifact 绑定；可变读取重新校验，不一致则 partial 或失败 |
| 模型误报、幻觉位置、空响应被当通过 | schema 与 manifest 校验 + 人工缺陷集；输出不可判定时 inconclusive |
| 规则或正文包含提权提示 | 不可信输入不得改变 workflow constraints；真实负向测试，而非只检查 prompt |
| 持久化扩展破坏旧摘要与恢复 | versioned receipt、旧样本兼容、半提交注入与升级／回滚测试 |
| 读取审查结果又造成会话卡顿 | 元数据／正文分离、有界投影、无执行式激活、持续保留导航性能门槛 |
| 为做审查扩大成全仓架构重写 | 仅提取所需 Git reader 和审查域；通用 Repo Intelligence、repair loop 与自动化延期 |
