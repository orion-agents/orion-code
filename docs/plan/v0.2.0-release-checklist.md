# Orion Code v0.2.0 release checklist

Status: `candidate`; this checklist distinguishes implementation evidence from commit, CI, tag,
GitHub Release, npm publication, and dist-tag promotion. Pending delivery receipts are not passes.

## Identity and package

- [x] Branch is `v0.2.0`; `package.json` and root `npm-shrinkwrap.json` identity are `0.2.0`.
- [x] README, migration guide, CHANGELOG, main plan, and package manifest describe the same breaking
      runtime and command surface.
- [ ] Release artifact is built from a clean immutable source SHA.
- [ ] Exact tarball contains only the allowlisted package manifest and is within entry/size budgets.
- [ ] `release:check --expected-version 0.2.0` passes against that exact source.

## Core goal gates (G1–G6)

- [x] **G1 Lean by default:** frozen v0.1.9 baseline is 33 schemas / 20,596 bytes; the ordinary
      v0.2.0 coding step exposes 7 schemas / 3,947 bytes. Unselected Skill definition/resource and
      MCP connection/process/socket counts are zero.
- [x] **G2 Higher task efficiency:** the deterministic successful-task corpus records no success
      or false-completion regression, no model-request growth, and a successful-task input-token
      median reduction above 30%.
- [x] **G3 One trustworthy execution path:** root, nested batch, long-tail, MCP, Skill, and subagent
      calls use Capability → Policy → Approval → Sandbox → Execute with durable lineage.
- [x] **G4 Crash-safe recovery:** event projection, TurnCommit, Compact, Goal, importer, and
      parent/child fork boundaries have deterministic crash/replay tests.
- [x] **G5 Predictable interaction:** TUI, terminal, print, Goal, Plan, Compact, and subagent share
      versioned runtime events and bounded replay/backpressure.
- [x] **G6 Maintainable foundation:** public/tarball legacy owners are absent; composition has one
      runtime, one Agent Loop implementation, and one TaskContext completion owner; 1,000 scope
      churn leaves no fake resources.

The checked implementation items above still require the source and artifact gates below before
release. Machine receipts, not this prose, are authoritative.

## Exact artifact and runtime matrix

One tarball SHA must be built once and installed unchanged in every runtime job. Rebuilding per Node
version is not equivalent evidence.

- [ ] Node 20 exact-tarball matrix passes all required probes.
- [ ] Node 22 exact-tarball matrix passes all required probes.
- [ ] Node 24 exact-tarball matrix passes all required probes.
- [ ] Each matrix verifies install/package/bin identity, version/help, public exports, built-in Skill
      assets, and native SQLite.
- [ ] Installed-tarball TUI, terminal, print, Goal, subagent, Skill, MCP, and compact/resume journeys
      pass with runner and target digests bound to the tarball.
- [ ] `ReleaseReceiptV1` verifies artifact, all runtime matrices, benchmark comparison, task eval,
      confluence, and full-test receipt; missing, skipped, dirty, mismatched, or failed evidence is
      No-Go.

## Acceptance contract

- [x] AC1–AC22 have executable contract, integration, chaos, architecture, or product E2E coverage.
- [x] PLAN writes a PlanReceipt in the same TurnCommit and implementation starts only on the next
      logical turn.
- [x] A productive Goal can continue beyond 20 turns, completes through evidence audit, and exits
      automatically; no fixed continuation-count stop or ghost shutdown continuation remains.
- [x] Nested `batch_read` children re-enter ToolGateway under the same frozen snapshot and retain
      parent/child invocation lineage.
- [x] Legacy session cutover is side-by-side, atomic at the index, replay-verified, and fail closed.
- [x] Public exports/config/help do not expose a plugin SDK, marketplace, service locator, dynamic
      third-party JavaScript loader, or legacy Harness owner.
