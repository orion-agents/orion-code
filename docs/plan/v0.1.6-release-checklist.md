## Change and compatibility boundary

- Goal creation requires explicit user authorization; model-created implicit Goals are rejected.
- Non-user continuation is bounded and returns control to the user.
- `/goal exit` aborts active Goal execution, rejects pending permission, and removes persisted
  Goal state.
- `/goal clear --yes` and `/target clear --yes` are intentionally unsupported. Because Orion is
  pre-1.0, this breaking command change is permitted only with explicit CHANGELOG/README migration
  text; storage compatibility remains unchanged.
- Native migration failures preserve `vector.db` and surface rebuild guidance.
- Terminal output strips model-controlled ANSI/OSC/C0/C1 sequences.
- macOS seatbelt and `exec_command` use stable project/cwd boundaries consistently.
- Dependency-health is offline by default; registry reporting is opt-in with `--full-network`.
- `/memory validate` performs a bounded source-symbol scan and reports incomplete validation as a
  failure rather than claiming stale references are absent.

## Required source gates

All checks must be rerun after the final release-preparation commit:

```bash
git diff --check
npm run deps:check -- --policy-only
npm run lint
npm run build
npx tsc --noEmit
npm audit --audit-level=high
npm test -- --runInBand
npm test -- --coverage --runInBand
npm run release:check -- --skip-tests
```

GitHub exact-head CI must pass Node 20/22/24 verification, TypeScript type-check,
dependency security audit, release gate, and dependency-health reporting. A rerun is evidence
only for the same SHA and may not hide a deterministic failure.

## Tarball and clean-install gates

Create the tarball from a clean checkout of the final candidate SHA. Record outside the tarball:

- filename, byte size, file count, unpacked size;
- SHA-256 of the `.tgz`;
- npm `dist.integrity`-compatible SHA-512 and SHA-1 shasum;
- complete `npm pack --json` file manifest;
- exact Git SHA and `package.json` version.

Install that exact tarball into separate clean prefixes under Node 20, 22, and 24. For each
runtime verify:

- `orion --version` prints `0.1.6` and `orion --help` starts;
- default TUI and non-semantic import/startup do not eagerly load native SQLite;
- `better-sqlite3` opens `:memory:` and `sqlite-vec` loads/query succeeds;
- the installed package contains no source-only or local-secret artifacts.

## User-path acceptance

- Goal lifecycle PTY: active Goal exits through `/goal exit`, pending permission is denied,
  persisted state is removed, and no automatic continuation remains.
- Compatibility negative test: both old clear forms reject without storage or permission side effects.
- Terminal security: assistant/system/tool content containing clear-screen, cursor, OSC title,
  hidden-cursor, C0, or C1 controls reaches the writer as safe text only.
- Sandbox: with `args.cwd != projectRoot`, permission precheck and execution plan the same cwd;
  seatbelt secret-file denies stay anchored to project root.
- Huoshan: using the existing local Orion configuration, run one redacted real-provider smoke;
  record provider/model/protocol and success/failure metadata without printing credentials,
  request headers, or response content that may contain secrets.

## Security and scope audit

- No `.env`, local Orion/OpenClaw config, credential, session database, generated `dist/`, tarball,
  temporary prefix, or `events.append` file enters the commit.
- Review all tracked files in the PR and run a secret-pattern scan before push.
- Open P0/P1 issues and unresolved actionable reviews block `READY_TO_PUBLISH`.
- Dependabot upgrade PRs are evaluated separately unless they fix a release-blocking advisory.

## Go / No-Go

`READY_TO_PUBLISH = GO` only when the final pushed PR SHA has all source/CI gates, tarball matrix,
user-path acceptance, provider smoke, clean worktree, issue/review audit, and an immutable PR
evidence receipt. It does not mean merged, tagged, released, or published.

After GO, stop and request authorization in this order:

1. merge PR #152;
2. create and push `v0.1.6`, then create the GitHub Release;
3. publish `@orion-agents/orion-code@0.1.6 --tag next`;
4. read back registry metadata and install the public exact version;
5. separately decide whether to move `latest` from `0.1.4` to `0.1.6`.

## Rollback

Before npm publish, rollback means stop, fix or revert through a reviewed PR, and create no tag.
After npm publish, never reuse `0.1.6`; deprecate it only with explicit authorization and publish
a forward patch. The current stable fallback remains:

```bash
rollback_prefix="$(mktemp -d /tmp/orion-rollback.XXXXXX)"
npm install --prefix "$rollback_prefix" '@orion-agents/orion-code@0.1.4'
"$rollback_prefix/node_modules/.bin/orion" --version
```
