### Published artifact versus maintenance branch

- `refs/tags/v0.1.4` is the immutable published source tree. Always dereference it
  explicitly; the repository also has `refs/heads/v0.1.4`, so the bare name is ambiguous.
- The `v0.1.4` branch has continued receiving maintenance commits after publication.
  Those commits are not retroactively included in npm `0.1.4` or the GitHub Release.
- `release:check` validates the tag's package version and current CHANGELOG contract,
  then reports an ahead/diverged maintenance checkout as a warning. It does not
  incorrectly require a moving maintenance branch HEAD to equal the release tag.

## Go / No-Go

### Go conditions

- R1–R6 all have focused test evidence (above).
- No-write / no-generic-MCP / SSRF / body-limit negative tests all pass.
- ResearchPacket, Goal evidence, and renderer schema have compatible/rollback notes (this file + plan §11).
- Docs do not present experimental/partial sources as verified or complete.

### No-Go conditions (any triggers a block)

- Web content can change system prompt, tool permission, or Goal state.
- Child gains write / exec / generic MCP / recursive subtask.
- A claim without a source binding can reach `verified`/`complete`.
- Source failure / provider fallback / timeout / cancellation is silently dropped.
- Packet crosses project / session / Goal scope, or resume overwrites an active Goal.
- Only local dirty worktree or stale test results, no final source/CI/package evidence.
