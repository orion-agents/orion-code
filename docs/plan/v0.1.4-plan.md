> 状态：DRAFT / PLAN MODE，等待用户确认后进入 POC。
>
> 计划日期：2026-08-05
>
> 权威顺序：用户当前目标与授权边界 > `docs/goals/orion-code-项目级目标.md` > 当前 source/test/runtime 证据 > v0.1.3-2 收口计划 > 历史市场/竞品笔记。

## 1. 版本定位

### 1.1 一句话目标

将现有只读 `research` subagent 从“能读仓库并返回 JSON”升级为安全、可追溯、可恢复的 Research-to-Evidence 闭环：研究问题有范围，结论绑定来源，来源可复核，结果可被 Goal、TUI、terminal-ui 和 Print/JSON 继续消费。

### 1.2 为什么现在优先做 Research

项目级 Goal 的北极星闭环是：

```text
项目目标 → 成功条件 → 研究/规划 → 执行 → 验证 → 证据审计 → 继续或完成
```

当前代码已经具备若干基础，但中间的“研究”仍是断开的：

| 能力            | 当前状态                                                      | v0.1.4 要解决的缺口                                                                     |
| --------------- | ------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `research` role | 已存在，只能使用 `read_file/list_files/glob/grep/batch_read`  | 无法在统一权限门下访问受控 WebSearch/WebFetch；无法明确 local/web/mixed 范围            |
| WebSearch       | 已有 MCP/provider adapter/fallback 链路                       | 主要返回格式化文本，不是可复核的 typed source 集合                                      |
| WebFetch        | 已有逐跳 SSRF、DNS、响应体上限和安全错误处理                  | 研究结果尚未保存 URL、标题、摘要、抓取时间、内容 hash 和来源关系                        |
| 子任务结果      | 有 `summary/findings/files/commands/verification/risks/usage` | 没有 `sources`、`claims`、`citation`、冲突和新鲜度字段                                  |
| 子任务持久化    | 有 `onSubtaskResult` 扩展点                                   | 没有稳定的 ResearchPacket schema 和 session/Goal artifact 语义                          |
| Runtime/UI      | 有 subtask 生命周期事件                                       | 没有研究阶段、来源、引用和失败原因的统一事件投影                                        |
| Goal 证据       | 已有 evidence ledger/completion audit                         | 研究结论不能直接、可验证地进入 requirement evidence；也没有防止模型自述冒充外部证据的门 |

因此，v0.1.4 不应继续堆叠“更多工具”或“更多 Agent”，而应先把已有 research、Web、Goal evidence 和 shared runtime 接成一个可信闭环。

### 1.3 目标映射

- **G1 目标忠实度**：研究问题、成功条件、结论和证据保持同一 objective/revision 语义。
- **G2 安全可控自主执行**：研究默认只读；外部网络、凭据、来源域名和抓取预算都经过风险门。
- **G3 单一运行时与 TUI 主产品**：研究事件由 shared runtime 产生，TUI 优先展示，其他 renderer 只消费同一事件。
- **G5 Provider/扩展可替换**：provider/MCP/adapter 只提供来源数据，不能绕过权限、审计和输出协议。
- **G6 本地优先、可恢复**：ResearchPacket、来源 hash 和失败状态可持久化、恢复和清理，不覆盖原始 session/Goal 数据。

## 3. v0.1.4 的目标与验收合同

### 3.1 产品目标

用户可以提出一个明确的研究问题，例如“确认这个仓库的 provider fallback 是否真实切换模型，并给出代码和测试证据”，Orion Code 能够：

1. 解析研究问题、范围、时效和输出要求；
2. 在 local-only、web-only 或 mixed 策略下获取受控来源；
3. 并行执行互相独立的只读研究包；
4. 将来源、事实、结论和不确定性结构化；
5. 将每个关键结论绑定到一个或多个可复核来源；
6. 以统一 runtime event 和 ResearchPacket 返回给 root Agent、TUI、terminal-ui、Print/JSON；
7. 在 provider、网络、超时、来源冲突或引用缺失时保持 partial/failed，而不是伪装成完成。

### 3.2 验收目标

| ID  | 验收标准                                                                                                                                                    | 必须证据                                                                    |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |

| R2  | mixed research 的 WebSearch/WebFetch 仅在显式外部授权和安全策略通过后执行；子 Agent 不能获得写工具、通用 MCP、递归 subtask                                  | permission matrix、forbidden-tool negative test、SSRF/body-limit regression |

## 4. 非目标

本版明确不做：

- 可写、后台、unattended 或跨 Session 的研究 Agent；
- 多 Goal/DAG/团队调度；这些仍属于 v0.2 Goal runtime 路线；
- 通用远程 MCP、OAuth、Tool Search、远程工具市场或任意 MCP 动态暴露；
- 浏览器自动化、JavaScript 执行、登录态抓取、Cookie/本地浏览器 session 复用；
- 无边界的网页爬虫、递归链接抓取、自动下载文件或二进制执行；
- 以搜索结果数量、模型置信度或“看起来合理”替代来源绑定和独立验证；
- 让研究来源直接成为 Goal complete 的充分条件；
- 删除 Ink、建设第二套 Agent runtime 或把 terminal-ui 建设成公众产品线；
- 自动 tag、push、PR、merge、npm publish 或外部消息发送。

## 5. 研究能力的最小闭环

```text
ResearchRequest
  → scope/policy/budget validation
  → local sources + approved web sources
  → normalize/dedupe/redact/hash
  → claims + source bindings + conflicts
  → ResearchPacket
  → runtime events / artifact / Goal evidence candidate
  → root verification and completion audit
```

### 5.1 ResearchRequest

建议字段：

```ts
interface ResearchRequest {
  schemaVersion: 1;
  objective: string;
  scope: {
    projectRoot: string;
    paths?: string[];
    domains?: string[];
    freshness?: 'any' | 'recent' | 'as_of';
    asOf?: string;
  };
  mode: 'local' | 'web' | 'mixed';
  maxSources: number;
  maxFetchBytes: number;
  maxDurationMs: number;
  expectedOutput?: string;
  goalBinding?: { goalId: string; objectiveRevision: number };
}
```

约束：路径必须通过现有 child scope guard；外部域名只能使用明确的 domain policy；`mode=web|mixed` 必须经过外部网络权限；时效字段不能被模型静默删除。

### 5.2 ResearchSource

建议字段：

```ts
interface ResearchSource {
  id: string;
  kind: 'file' | 'search_result' | 'web_page' | 'provider_document';
  canonicalUrl?: string;
  displayUrl?: string;
  projectPath?: string;
  title?: string;
  excerpt?: string;
  provider: string;
  retrievedAt: string;
  contentHash?: string;
  status: 'retrieved' | 'partial' | 'failed' | 'blocked' | 'stale';
  failureReason?: string;
  redactions?: string[];
}
```

规则：

- 文件来源使用项目相对路径、byte range 或 line range；不得保存绝对用户路径到外部可见结果。
- Web 来源 canonicalize scheme/host/path，去除或脱敏 secret-bearing query 参数。
- `contentHash` 对 canonical content 计算；hash 不是内容真实性证明，只用于复核漂移。
- `displayUrl` 与实际请求地址分开，避免把 Authorization、API key 或追踪参数显示给用户。
- 来源抓取失败仍保留 `status=failed|blocked`，不得删除失败事实。

### 5.3 ResearchClaim 与 ResearchPacket

```ts
interface ResearchClaim {
  id: string;
  text: string;
  sourceIds: string[];
  evidenceKind: 'file' | 'external' | 'inference';
  verification: 'observed' | 'partially_observed' | 'unverified' | 'contradicted';
  confidence?: 'high' | 'medium' | 'low';
  conflicts?: string[];
}

interface ResearchPacket {
  schemaVersion: 1;
  packetId: string;
  projectPath: string;
  sessionId: string;
  goalId?: string;
  objectiveRevision?: number;
  request: ResearchRequest;
  summary: string;
  claims: ResearchClaim[];
  sources: ResearchSource[];
  gaps: string[];
  risks: string[];
  usage: SubtaskUsage;
  createdAt: string;
}
```

`ResearchPacket` 是事实与推理的边界：`observed` 必须能追溯到 source；`inference` 必须显式标记；`contradicted` 和 `unverified` 不得进入完成证据的正向通过集合。

## 6. 选型与决策

### 6.1 方案比较

| 方案                               | 结论     | 原因                                                                         |
| ---------------------------------- | -------- | ---------------------------------------------------------------------------- |
| A. 扩展现有 `subtask`/Supervisor   | **采用** | 保留预算、scope、provider gate、abort、usage 和 renderer event；改动边界最小 |
| B. 新建独立 `/research` Agent 引擎 | 暂不采用 | 会复制 query、权限、artifact、Goal 和 renderer 语义，违反单一运行时原则      |
| C. 直接给 child 通用 MCP           | 拒绝     | `readOnlyHint` 不能证明参数、网络、远端写入和来源范围安全                    |
| D. 只靠 prompt 要求“列出链接”      | 拒绝     | 无法保证 claim/source 绑定、来源状态、hash、失败和恢复语义                   |
| E. 先做向量知识库/长期记忆         | 延后     | 先把来源可信度、引用和生命周期稳定下来，再决定索引/检索存储                  |

### 6.2 选定架构

1. **Research coordinator**：复用现有 Supervisor/Budget/ProviderGate，负责 request policy、source budget、并行包和 packet aggregation。
2. **Source adapters**：本地文件 adapter、WebSearch adapter、WebFetch adapter；WebSearch MCP 仍作为专用 provider adapter，不变成通用 MCP。
3. **Source normalizer**：canonical URL、redaction、dedupe、hash、limit 和 provider metadata。
4. **Citation validator**：验证 claim 引用的 source 存在、状态允许、范围匹配和格式完整。
5. **Research artifact store**：以 session/project 作用域保存 packet 和索引；写入使用现有 atomic/CAS/lock 约束。
6. **Runtime event projection**：新增 `research_started`、`research_source`、`research_claim`、`research_completed`、`research_failed` 等结构化事件；UI 不复制业务逻辑。
7. **Goal evidence bridge**：只生成 evidence candidate；由 root verification/completion audit 决定是否纳入正式完成证据。

## 7. 安全与兼容设计

### 7.1 外部内容是不可信数据

- Web page、search snippet、MCP text 一律包裹为 untrusted source content，不能改变 system prompt、权限、目标或工具集合。
- 页面中的“执行命令”“上传密钥”“忽略之前指令”等内容只能作为研究对象，不能变成 Agent 指令。
- source excerpt 长度、总字节、来源数和单域名来源数均有限制。

### 7.2 权限边界

- local-only 不发起网络请求。
- web/mixed 在 root permission gate 下确认；child 只继承已批准的 research capability，不重新解释全局 `toolConfirmation`。
- child 永远不得接收 `exec_command`、写工具、memory mutation、通用 MCP 或 `subtask`。
- 外部来源失败、DNS/SSRF/size/timeout/credential error 均为可见失败或 partial，不静默 fallback 成“已研究”。

### 7.3 数据与兼容

- ResearchPacket schema 必须带版本；未知字段忽略但未知 schema fail closed。
- 旧 `SubtaskResult` 可以兼容读取为没有 sources/claims 的 legacy packet，但不能被宣称为 citation-complete。
- 不改变既有 `SubtaskResult` 必填字段和 renderer event 顺序；先添加可选字段和新事件。
- packet、source excerpt、trace 和错误统一执行 secret redaction；不把 API key、Authorization、Cookie 或完整 query secret 持久化。

## 8. 分阶段工作包

### P0-R1：Research contract 与 local-only 可靠闭环

涉及：`src/runtime/subagents/types.ts`、`result-parser.ts`、`tool.ts`、`supervisor.ts`、新的 `research` contract/normalizer。

任务：

- 定义 `ResearchRequest/Source/Claim/Packet` schema、版本和状态机；
- 将现有 `SubtaskResult` 兼容映射为 legacy/local packet；
- 要求每个 observed claim 具备 file/source evidence；
- 对 invalid JSON、缺 summary、无证据、超限、取消和 partial 结果 fail closed；
- 建立 deterministic local fixture 和 packet hash/serialization contract。

退出条件：local-only research 在一个项目范围内可返回可恢复 packet，且不接触网络和写工具。

### P0-R2：受控 Web research adapter

涉及：`src/services/web-search-adapters.ts`、`src/services/web-search-mcp.ts`、`src/tools/web.ts`、research policy。

任务：

- 将现有 WebSearch adapter 输出归一为 `ResearchSource`，保留 provider/status/duration；
- 将 WebFetch 结果归一为 source，并复用现有 SSRF/DNS/redirect/body/abort 防护；
- 增加 domain policy、source count、bytes、timeout、provider request 和 per-turn cost budget；
- 仅允许专用 WebSearch/WebFetch capability，不暴露通用 MCP；
- provider fallback 只能改变 provider，不得丢失 source status 或把失败写成 success。

退出条件：一条 mixed request 能完成“search → 选择来源 → fetch → source hash → citation”，任一安全门失败都有结构化原因。

### P0-R3：Citation、冲突与证据候选

涉及：`src/harness/evidence.ts`、`src/runtime/goals/evidence.ts`、completion audit、ResearchPacket。

任务：

- claim/source 多对多绑定和引用完整性验证；
- 同 URL 多版本 dedupe，内容 hash 漂移标记 stale；
- 互相矛盾的来源生成 `conflicts`，不自动选择更符合模型回答的一方；
- 输出 `verified/partially_observed/unverified/contradicted`，只允许符合规则的 claim 生成 evidence candidate；
- 将研究证据和执行验证证据区分，避免 Web 摘要替代测试、构建或文件事实。

退出条件：completion audit 对“有来源但无独立验证”的 claim 明确保持 partial/unmet。

### P1-R4：Shared runtime 与 TUI/Print parity

涉及：runtime event、view-model、TUI、terminal-ui、Print/JSON、命令帮助。

任务：

- 研究生命周期进入统一 `AgentRuntimeEvent`；
- TUI 优先展示阶段、来源数量、来源失败、引用和风险；
- terminal-ui 保持技术诊断/回退能力；
- Print/JSON 输出稳定 schema，不能只打印拼接文本；
- `/research` 若需要用户入口，只注册为只读内建命令并复用同一 coordinator；不另建执行引擎。

退出条件：同一 fixture 在 TUI、terminal-ui、Print/JSON 中事件顺序、状态和结论一致，并通过一个真实 PTY。

### P1-R5：Research artifact、resume 与 Goal integration

涉及：session storage、artifact registry、GoalCoordinator、session resume/restart。

任务：

- packet 与 source metadata 原子保存、CAS/lock、project/session/Goal scope 隔离；
- restart/resume 恢复研究状态为 completed/partial/failed，不重放外部副作用；
- 外部 source 只作为 evidence candidate，不能绕过 Goal recovery gate、completion audit 或权限门；
- clear/repair/cleanup 保留原 packet/hash 的可追溯记录。

退出条件：中断、恢复、损坏 packet、旧 schema、不同 project/session 和 active Goal 覆盖尝试均有 negative test。

### P1-R6：质量、文档与成本硬化

任务：

- source ranking 只做可解释排序（新鲜度、provider、scope match、重复度），不把排序当真实性；
- 增加研究成本诊断、provider/网络失败恢复建议和 `/cost` reconciliation；
- 更新 README/中文 README/帮助/配置示例，明确 experimental/conditional/stable 状态；
- 建立 release checklist、coverage scope、clean install、Node matrix、真实 terminal 和外部状态 evidence ledger。

## 9. POC 阶段

在 P0-R1/P0-R2 正式实现前，先完成三个小型 POC：

### POC-1：Local packet

- 输入：固定 project fixture + 研究问题；
- 动作：只读 `read_file/grep/batch_read`；
- 输出：至少 2 个 file claims、每条有 path/line evidence、可序列化 packet；
- 通过条件：不调用网络、不写源文件、invalid/partial 可重放。

### POC-2：One provider + one page

- 输入：一个显式批准的安全 provider 和一个 allowlisted URL；
- 动作：WebSearch 返回 source candidate，WebFetch 获取一个页面，运行 SSRF/DNS/body/abort 门；
- 输出：canonical URL、title、provider、retrievedAt、content hash、excerpt、claim binding；
- 通过条件：mock provider、private DNS、redirect、超大 chunk、超时和缺 key 均有可预测结果。

### POC-3：Goal evidence boundary

- 输入：一个“来源支持但尚未本地验证”的 Goal criterion；
- 动作：ResearchPacket 生成 evidence candidate；
- 输出：completion audit 仍返回 partial/unmet，要求测试/文件/运行时验证；
- 通过条件：不能通过改写 summary、增加来源数量或提高 confidence 绕过 audit。

## 11. Rollout、回滚与 Go/No-Go

### Rollout

1. local-only ResearchPacket，默认隐藏外部 network；
2. 单 provider WebSearch/WebFetch POC，显式标记 experimental；
3. mixed mode、citation validator、artifact 和 renderer parity；
4. 扩展 provider adapter 和文档；
5. 生成最终 source/package/clean install/CI evidence，再决定是否稳定开放。

### 回滚

- Research capability feature/config flag 回退到 local-only 或 `subtask` legacy result；
- 保留已写入 packet 的 source status/hash，不删除原始 session/Goal evidence；
- provider failure 只禁用该 adapter，不改变其他 provider、root runtime 或 Goal state；
- schema 迁移失败进入只读恢复态，禁止覆盖旧 packet。

### Go 条件

- R1-R9 必须有 focused test evidence；R7 必须有 PTY/parity evidence；
- 外部 research 默认仍受权限确认、预算和来源 policy 约束；
- no-write/no-generic-MCP/SSRF/body-limit negative tests 全部通过；
- ResearchPacket、Goal evidence 和 renderer schema 有兼容/回滚说明；
- 文档没有把 experimental/partial source 当成 verified 或 complete。

### No-Go 条件

- Web 内容能改变 system prompt、工具权限或 Goal state；
- child 获得 write/exec/generic MCP/recursive subtask；
- claim 没有 source binding 却可进入 verified/complete；
- source failure、provider fallback、timeout 或 cancellation 被静默丢弃；
- packet 越 project/session/Goal scope，或恢复时覆盖 active Goal；
- 只有本地 dirty worktree 或旧版本测试结果，没有最终 source/CI/package evidence。

## 12. 风险与开放问题

| 风险/问题                         | 当前决策或后续动作                                                                                    |
| --------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Web prompt injection              | P0 安全要求；所有外部内容作为 untrusted data，加入 adversarial fixtures                               |
| DNS TOCTOU/代理重解析             | v0.1.4 先完成 preflight DNS 与 redirect gate；若要强保证，另做 connector/dispatcher POC，不伪称已解决 |
| Source authenticity               | 来源和 hash 只证明“读取了什么”，不证明内容真实；需要 provider/domain policy 和用户可见 caveat         |
| Provider 输出格式差异             | 统一 normalizer；无法解析的响应保留 failed/partial，不强行制造 citations                              |
| 研究成本失控                      | 多维预算、usage reconciliation、并发/超时/bytes/source 上限                                           |
| 研究结果污染 Goal                 | 只生成 evidence candidate；completion audit 仍需独立执行验证                                          |
| 现有 subtask legacy compatibility | 可选字段向后兼容；legacy packet 明确标记 citation-incomplete                                          |
| 研究入口                          | 优先复用 `subtask`/shared runtime；是否新增 `/research` 在 POC 后确认，不先复制引擎                   |
