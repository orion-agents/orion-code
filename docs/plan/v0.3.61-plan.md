## 1. 背景与定性

- 本轮为**纯文档/簿记周期**（无 `src/`、`web/` 产品代码变更；对
  `tests/coding-task-eval.test.ts` 的 `packageVersion` pin 是每轮 bump 的
  机械性配套，历轮一致，不视为产品 delta）。质量条款 C 一般要求 docs-only
  周期不占版本号，但主指令「每轮仅推进一个版本号 → v0.3.99」为更高优先级的
  用户显式要求，且版本工作树的开版提交必然携带六处 bump（release gate 把
  `package.json` 版本钉到 `codex/vX.Y.Z` 分支名）。沿 v0.3.38–v0.3.60 历轮
  先例走完整发布链路，并在 Release notes 标注该张力。

## 4. 验收标准

1. `npm run build` 通过（tsc + vite）。
2. `npm run release:check` PASS（含全量 Jest、tarball 一致性、六处 bump 一致性、
   CHANGELOG 状态检查）；`tests/coding-task-eval.test.ts` 5/5 绿。
3. release gate 对 `codex/v0.3.61` 分支名与 `package.json` 版本一致性 PASS。
4. CI（PR run）全绿后才允许 squash 合并；单一 flake 按「单次复跑绿=瞬时可合并；
   仍红=停止报告」处置。
5. squash 合并后 tag `v0.3.61` 打在 main 合并提交并推送；干净 worktree 构建
   tarball；sha 核验与 CI 收据逐字节一致；npm publish 后 registry 防缓存确认；
   GitHub Release `--latest` 建立并含逐作业门禁表。
6. 全程不触碰主工作区未跟踪文件；按文件精确 `git add`。
