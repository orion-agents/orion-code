## 1. 执行摘要

v0.1.1 是 Orion Code 首个公开补丁版本。它不以增加更多命令、Provider 或实验 UI 为目标，
而是把 v0.1.0 已公开的能力收敛成一个可信赖的产品基线。

本版本有四个核心结果：

1. **TUI 成为明确的公众产品界面**：默认启动、公开文档、帮助、交互优化和发布验收都以
   TUI 为主。
2. **terminal-ui 收敛为技术版本**：仅承担 runtime 协议验证、诊断、兼容性排查和必要回退，
   不再与 TUI 并行发展公众体验。
3. **Ink 完成废弃收口**：v0.1.1 不删除 CLI 入口以避免补丁版本产生破坏性兼容变化，但停止
   新功能和非关键体验维护，明确安排在 v0.2.0 删除。
4. **命令、目标和安全语义统一**：修复 `/target` renderer 分叉、破坏性存储命令、上下文清理
   误导、帮助信息漂移和直接操作 stdout/process 的业务处理器。

v0.1.1 的发布结论不能只依赖 build 或大批 Jest 通过。必须同时具有：

- 共享命令契约证据；
- Goal/TUI/terminal-ui parity 证据；
- 破坏性操作无确认不产生副作用的证据；
- TUI 真实 PTY 与真实终端证据；
- tarball 和 npm registry 干净安装证据；
- 中英文文档、CLI 帮助和实际行为一致性证据。

旧 `docs/mvp/v0.1.1-plan.md` 保留为命令审计与问题来源；本文件是 v0.1.1 的总体执行计划。

### 2.2 优先级定义

| 优先级 | 含义 | 发布规则 |
|---|---|---|

### 3.2 当前工作树候选改动

当前工作树已经出现以下未提交候选方向：

- completion gate 在缺少证据时持续阻止完成；
- compact 前后 Harness objective 变化时发出 warning；
- batch-read 允许工具集合收敛为共享常量；
- warning 事件进入共享 transcript/status。

这些改动与总体目标方向一致，但在 v0.1.1 中只能作为候选实现，不能视为已完成。合入前必须：

- 明确其所属分支、提交边界和与用户其他改动的归属；
- 补齐目标连续性、warning event parity 和 completion-gate regression test；
- 证明不会造成无进展死循环、重复 warning 或 renderer 私有行为；
- 通过完整 Gate 后再进入 v0.1.1 PR。

### 3.3 文档漂移

当前英文 README、中文 README、v0.1.0 文档、配置注释和 status 文案对 UI 稳定性与默认路径的
描述并不完全一致。v0.1.1 必须形成唯一公开口径：

```text
TUI          public product / default
terminal-ui  technical renderer / diagnostics and fallback
Ink          deprecated / removal scheduled for v0.2.0
Print/JSON   experimental non-interactive boundary
```

## 5. 范围

### 5.1 P0 必须完成

#### P0-A：UI 产品身份收敛

- 引入明确常量：

```ts
PRODUCT_UI_RENDERER = 'tui';
TECHNICAL_UI_RENDERERS = ['terminal'];
DEPRECATED_UI_RENDERERS = ['ink'];
DEFAULT_UI_RENDERER = PRODUCT_UI_RENDERER;
```

- `UiRendererStatus` 至少能表达 `product`、`technical`、`deprecated` 和
  `non-interactive`，不再把 TUI 显示为 beta；
- `orion`、`orion --help`、`/status`、`/doctor` 和启动 Banner 使用同一 UI 口径；
- terminal-ui 不显示为公众主产品，但继续使用共享 runtime、permission 和 goal events；
- Ink 启动时显示一次明确警告：已废弃、无新功能、计划 v0.2.0 删除、替代项为 TUI；
- 默认 command palette 和 README 不再推荐 Ink。

验收：

- 默认启动和所有公开说明均把 TUI 标为 product/default；
- terminal-ui 标为 technical，不标 beta 或公众 stable product；
- Ink 标为 deprecated，且不会因为废弃而改变共享 runtime 语义；
- UI 状态由同一 helper 生成，不散落硬编码字符串。

#### P0-B：共享命令契约

扩展命令定义：

```ts
interface SlashCommand {
  execution: 'builtin' | 'agent-workflow' | 'renderer-local';
  rendererScope?: Array<'tui' | 'terminal' | 'print'>;
  risk: 'read-only' | 'state-write' | 'destructive';
  availability?: (ctx: CommandContext) => Availability;
  deprecated?: {
    since: string;
    replacement?: string;
    removeIn?: string;
  };
}
```

要求：

- registry 是 help、palette、completion 和命令参考的事实源；
- alias 参与解析和补全，但不重复占用默认面板；
- TUI 本地 `/tool-output`、`/redraw` 进入同一 metadata registry；
- unavailable 命令解释条件，如 Git、MCP、embedding、session 或 artifact；
- command result 的 `success` 必须与真实结果一致；
- 业务命令不能直接调用 `process.exit`、裸写 stdout 或操作具体 TUI surface。

验收：

- 所有命令具有 execution、risk 和 scope；
- 名称与 alias 全局唯一；
- `/help`、palette 和 completion 的稳定命令集合一致；
- destructive 命令不能绕过统一确认协议。

#### P0-C：Goal 与完成语义统一

- `/target` 和 `/goal` 统一经过 `parseTargetCommand` 与
  `AgentRuntimeInput.type = 'goal_control'`；
- 删除 `src/terminal-ui/launch.ts` 的目标命令业务分支；
- TUI 和 terminal-ui 不直接创建、暂停、恢复或清理 Goal；
- Print/JSON 对交互性 Goal 操作给出确定性结果，不能无限 follow；
- `/goal` 保留为兼容 alias，不在默认 palette 单独展示；
- completion gate 在缺少证据时保持阻止，不允许“阻止一次后自动放行”；
- compact/resume 后 objective、constraints、next action 和 verification state 不漂移；
- warning、goal event 和 completion audit 使用共享 runtime event。

验收：

- `/target budget 50000` 被解析为预算操作，不创建同名目标；
- v0.1.6 起统一使用 `/goal exit` 停止 Goal 执行并清理状态；旧 clear 语法不再支持；
- TUI 与 terminal-ui 创建目标后产生等价 Goal snapshot 和 event 顺序；
- 缺少验证时不能宣告完成；
- compact/resume 后输入“继续”仍使用同一根目标；
- renderer 不拥有 GoalCoordinator 或私有 continuation loop。

#### P0-D：存储与上下文安全

- `/storage repair` 默认只预览；修改要求精确摘要和 `--yes`；
- `/storage cleanup` 默认 dry-run；删除要求精确目标、数量、路径和 `--yes`；
- 所有路径在执行前解析，禁止宽泛目录、未解析变量和不安全递归目标；
- `/clear-history` 更名或重新定义为“只清当前 model context”；
- 旧 `/clear-history`、`/reset` 保留兼容警告，不能声称永久删除持久 session；
- 若提供持久 session 删除，必须是独立命令、独立确认和独立测试；
- `/clear` 发送 `clear_view` event，不由业务 handler 写 `\x1Bc`；
- `/exit` 发送 shutdown request，不由共享 command handler 直接 `process.exit`。

验收：

- 无 `--yes` 时 storage 命令的文件系统签名保持不变；
- preview 内容与实际执行目标完全一致；
- context clear 后 `/resume` 的行为与提示一致；
- TUI surface 不被共享命令的裸 ANSI 清屏破坏；
- shutdown 前 session、Goal 和 accounting 有持久化机会。

#### P0-E：发布可信度

- 版本、Banner、帮助、package metadata 和文档统一为 `0.1.1`；
- build、lint、全量测试、聚焦测试和真实 PTY 均有记录；
- npm tarball 内容经过清单审核；
- tarball 与 registry 安装分别验证；
- 在用户真实 zsh/PATH 中确认实际执行的是新安装的 `orion`；
- 所有 P0 关闭后才允许 npm publish。

### 5.2 P1 应完成

#### P1-A：TUI 公众体验

- 保持当前确认过的 Banner 几何，只修复错位、回退和宽度兼容；
- 用户输入前后留白成为 transcript layout contract；
- 连续 user/assistant、user/tool、resume、错误、中断和窄终端均有布局测试；
- CJK、emoji、bracketed paste、多行输入和 Ctrl+C 双击退出稳定；
- tool activity、warning、verification 和 Goal event 按真实顺序展示；
- 公开快捷键、palette、help 和 status 优先服务 TUI。

#### P1-B：命令信息架构

默认 TUI palette：

```text
Workflow  /target  /diff  /commit  /review  /security  /test-gen
Session   /resume  /sessions  /compact
Context   /skills  /skill  /todos
Runtime   /model  /mode  /tools
System    /status  /doctor  /help  /clear  /exit
```

Advanced 或 `/help --all`：

```text
/session-rename  /context-clear  /harness  /memory  /mcp  /safety
/storage  /usage  /loop-stats  /trace  /last-tool  /artifacts
/checkpoint  /migrate  /edit-preview  /tool-output  /redraw
```

兼容入口：

- `/goal` → `/target`；
- `/cost` → `/usage lifetime`；
- `/task`、`/run`、`/chat` 隐藏并显示替代方案；
- `/migrate` 移到 Advanced，并声明 OpenHorse 迁移生命周期；
- `/agents` 在能展示真实 task/subagent tree 前不作为公众主能力。

#### P1-C：条件能力与错误分层

- 非 Git、无 MCP、无 embedding、无 session、无 artifact 时解释不可用原因；
- 错误区分 renderer、runtime、provider、tool、session、memory、MCP 和 skills；
- 用户错误、条件不可用、权限拒绝、运行时错误和用户取消使用不同 error code；
- provider 配置问题提供 protocol、base URL、model 和诊断入口，不泛化成模型失败。

### 5.3 P2 可延期

- 从 registry 自动生成完整命令参考；
- 更丰富的 prompt assembly stats 与 replay UI；
- terminal-ui 的额外诊断视图；
- v0.2.0 Ink 物理删除准备；
- hooks、plugins、remote UI 和团队策略设计。

## 6. 明确非目标

v0.1.1 不做：

- 物理删除 Ink、React 和 Yoga；这是 v0.2.0 的破坏性变更；
- 把 terminal-ui 继续建设为第二个公众产品；
- 重做已确认的 Banner 或引入新的图片协议；
- 新增一批 slash commands；
- 多目标 DAG、跨 Session 调度或完整 v0.2 Goal Runtime 重构；
- Desktop、Web、IDE 或远程客户端；
- 新 Provider 大扩展、模型托管或云同步；
- 为追求测试通过而缩小项目级目标或弱化安全门槛。

## 10. 发布流程

### 10.1 发布前

1. 从对应开发分支确认 current upstream；
2. 锁定 v0.1.1 文件范围，排除无关 dirty changes；
3. 完成 P0/P1 requirement matrix；
4. 运行全部自动化、聚焦 PTY 和手工验收；
5. `npm pack --dry-run` 审查 package 文件、大小、bin、license 和 assets；
6. 用生成 tarball 安装到干净 prefix；
7. 在用户实际 zsh/PATH 验证 `which orion`、`orion --version` 和默认 TUI；
8. 提交、推送并创建 draft PR；
9. 等待 CI、代码审查和 merge readiness。

### 10.2 发布

1. 合并经过验证的 PR；
2. 创建 `v0.1.1` tag 与 release note；
3. `npm publish --access public`；
4. 等待 registry packument 和 tarball 可公开读取；
5. 从 registry 全新安装 `@orion-agents/orion-code@0.1.1`；
6. 验证版本、默认 TUI、terminal-ui 技术回退和 Ink 废弃提示；
7. 更新发布证据和已知问题。

### 10.3 回滚

发布前：

- revert 或修正 PR，不移动 tag，不发布 npm；
- 保留 v0.1.0 为用户可安装基线。

发布后：

- npm 版本不可复用；发现阻断问题时 deprecate `0.1.1`；
- 立即发布修复版本 `0.1.2`，不覆盖既有 tarball；
- 文档给出 `npm install -g @orion-agents/orion-code@0.1.0` 回退命令；
- 若问题仅在 TUI，可临时建议 `--ui terminal` 技术回退，但不能把它重新定义为公众主产品。

## 11. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 在 patch 版本直接删除 Ink | 破坏 CLI 兼容 | v0.1.1 冻结并警告，v0.2.0 删除 |
| terminal-ui 技术化导致 runtime 测试减少 | 语义分叉未被发现 | 保留 parity 和最小 smoke，不投入平行产品 polish |
| GoalCoordinator 双重路由 | 重复 turn、状态污染 | shared controller 唯一 owner，renderer 只发 input |
| completion gate 永不放行 | 无进展循环 | no-progress/blocked test、budget 和 finish reason |
| compact warning 刷屏 | transcript 噪声 | 只在真实 objective mismatch 时发出并去重 |
| storage preview 与执行不一致 | 误删数据 | 相同 resolved target snapshot 驱动 preview 和 execute |
| 工作树混入无关改动 | 发布污染 | 范围清单、干净 worktree candidate、tarball 审查 |
| README/帮助再次漂移 | 用户误解产品状态 | shared descriptor、文档审计、snapshot test |
| PTY 总量通过掩盖真实终端问题 | npm 包不可日用 | macOS Terminal 手工 smoke 作为独立 Gate |

## 12. Go / No-Go

### Go

- TUI 在代码、帮助、status、doctor 和文档中一致标为公众默认产品；
- terminal-ui 一致标为技术版本，且共享 runtime parity 通过；
- Ink 一致标为废弃，替代项和 v0.2.0 删除计划明确；
- `/target` 无 renderer 私有业务分支；
- completion gate 缺少证据时不会宣告完成；
- storage destructive operation 无确认零副作用；
- context clear、session delete、clear view 和 shutdown 语义准确；
- command contract、全量 Jest、聚焦 PTY、真实终端、tarball 和 registry install 全部通过；
- PR、版本、包、文档和发布证据一致。

### No-Go

- TUI 仍被公开描述为 beta；
- terminal-ui 仍被描述为与 TUI 并行的公众主产品；
- v0.1.1 直接删除 Ink 或 React/Yoga，造成 patch 版本破坏性变化；
- `/target` 在任一 renderer 中绕开 shared controller；
- `/storage cleanup` 或 repair 可无确认修改数据；
- `/clear-history` 仍声称永久删除但 `/resume` 可以恢复；
- shared command handler 仍直接清屏或退出进程；
- Kitty/iTerm 图像数据在不支持的终端输出为长字符串；
- 只报告 build/lint 或总测试数量，没有目标、安全、PTY 和安装证据；
- npm tarball 混入当前工作树的无关文件。
