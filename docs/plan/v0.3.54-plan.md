## 1. 背景与定性

- v0.3.53 的发布扣留决策（条款 B：`WEB32-P0-08` 根因未定）由发布日按任务规则解除：
  main run `41930947053` 的 `Web E2E full suite three consecutive runs` 红经
  **单次** `gh run rerun --failed` 后 attempt 2 = success 18/18 → 定性为瞬时
  flake，允许合并；合并后 push CI `42438966303` 的 `Exact tgz on Node 24.0.0
floor` PTY 探针红同样经单次复跑转绿。**该定性不等于根因修复**：
  `WEB32-P0-08` 根因仍开放（证据与静态排查见
  `docs/plan/evidence/v0.3.53/investigation-and-audit.md`），本轮不宣称其已修复。
- 本轮为**纯文档/簿记周期**（无 `src/`、`web/`、`tests/` 产品代码变更）。质量条款
  C 一般要求 docs-only 周期不占版本号，但主指令「每轮仅推进一个版本号 → v0.3.99」
  为更高优先级的用户显式要求，且版本工作树的开版提交必然携带六处 bump（release
  gate 把 `package.json` 版本钉到 `codex/vX.Y.Z` 分支名）。沿 v0.3.38–v0.3.53
  历轮先例走完整发布链路，并在 Release notes 标注该张力。

## 4. 验收标准

1. `npx jest tests/coding-task-eval.test.ts` 5/5 绿。
2. `npm run build` 绿。
3. 提交后 `npm run release:check`：`Version consistency (package 0.3.54)`、
   `CHANGELOG.md entry`、`README release state`、`Release ref` 等项通过；
   `Jest suite` 项如因本机 better-sqlite3 ABI / PTY 环境家族失败，以 CI 同名
   job 结论为准，不得改断言掩盖。
4. CI（PR run）：`Web E2E critical journey ×3`、`Web E2E full suite three
consecutive runs`、Node 矩阵、`Dependency security audit`、release gate
   逐作业核对；单一作业 flake 允许一次 `gh run rerun --failed`，仍红即停止报告。
5. squash 合并 → tag `v0.3.54` 打在 main 合并提交并 push → 清洁 worktree 构建
   tarball → sha 核验（CI `release-receipt` / `web-e2e-receipt` 小 artifact 的
   `tarballSha256`，必要时 `release-package` tarball 逐字节比对）→ 剥离代理 env
   后 `npm publish --ignore-scripts` → 防缓存直连确认 `latest=0.3.54` 并记录精确
   入库时间 → `gh release create v0.3.54 --latest`（notes 含逐作业门禁表、
   tarball sha256、安装命令，并标注 docs-only 周期占用版本号的张力）。
6. 汇报：版本号、plan 路径、PR 链接、tag、npm 精确时间戳、Release 链接、
   tarball sha256；dependabot open PR 数量。
