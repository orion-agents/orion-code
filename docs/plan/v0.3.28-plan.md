## 1. 版本决策与用户价值

v0.3.27 交付了审查契约（`src/services/code-review/contract.ts`）、共享 Git 快照读取器
（`snapshot.ts`）与只读 workflow 约束（`constraints.ts`），但 `/review` 仍是一条普通
slash 聊天：无类型化范围、无冻结快照输入、无结构化 findings、无收据。

v0.3.28 把 `/review` 从"普通对话"升级为"类型化审查工作流"的 CLI 主链：

1. `/review` 参数被解析为类型化 `ReviewSelectorV1`（worktree / base、路径过滤）；
   无法识别的参数给出用法说明，**不再静默落入普通聊天**。
2. 审查输入来自 admission 时冻结的 Git 快照（staged / unstaged / untracked 分源，
   base 范围以 merge-base OID 冻结），receipt 记录 `inputSnapshotDigest`。
3. 模型输出经契约校验：finding 形状、快照成员、finding 预算；无效条目计数并如实展示，
   不会把不完整运行伪装成绿色"未发现问题"。
4. 产出完整 `CodeReviewResultV1` 收据（digest 重算可验证），TUI 按 priority 分组展示
   问题、覆盖、跳过与限制；"所选范围无变更"与"审查完成未发现问题"严格区分。
5. 只读边界由 `REVIEW_WORKFLOW_CONSTRAINTS` 绑定进 rulesDigest；本切片的执行模型是
   单轮有界补全（快照直接进入 prompt），不存在向模型开放的任意工具面，审查回合不产生
   对被审查仓库的任何写入。

## 2. 任务分解

### S1 类型化 selector 解析 — `src/services/code-review/selector.ts`

- `parseReviewSelector(args: string)`：
  - 空 / `all` → `{ kind: 'worktree' }`；
  - `--base <ref>` → `{ kind: 'base', ref }`；
  - `--path <path>`（可重复）→ paths；
  - 单个存在的相对路径参数 → worktree 路径过滤（兼容既有用法）；
  - 未知参数、缺值、重复 `--base` → 类型化错误（`usage` 文案），不猜测分支或路径。
- 验收：单测覆盖全部分支与拒绝路径；解析结果为冻结对象。

### S2 有界单轮审查运行器 — `src/services/code-review/runner.ts`

- `ReviewModelAdapter` 注入接口（CLI 接线用 `LLMService.chat` 适配）；测试注入 fake。
- 流程：`resolveReviewBudgets` → `captureReviewSnapshot`（含 `readWorktreeFile`）→
  admission 窗口内捕获冻结 unified diff（同一 runGit 参数）并按 `maxBodyBytes` 截断 →
  组装审查指令 prompt（含约束 digest 与规则 digest）→ 单轮补全 → JSON 输出解析 →
  `validateReviewFinding` + 快照成员校验 + `maxFindings` 预算 →
  `resolveReviewConclusion` → 构建 `CodeReviewResultV1` 并 `verifyReceiptDigest`。
- 状态映射：取消（AbortSignal）→ `cancelled`；模型/解析失败 → `failed`；
  覆盖截断或快照跳过 → `partial`；空范围 → `completed` + `no_findings` +
  `empty_scope_no_changes` 限制（不调用模型）。
- 规则摘要：cwd 至仓库根祖先的 `AGENTS.md` 内容 + 只读约束 digest 合成 `rulesDigest`。
- 验收：真实临时 Git 仓库集成测试（分源、base 冻结、路径过滤、空范围、成员越界
  finding 拒绝、超预算截断、取消、无效 JSON、digest 可验证）。

### S3 TUI 输出格式化 — `src/services/code-review/format.ts`

- 头部：范围、resolved target、模型、预算；主体：按 P0→P3 分组的 finding（文件:行、
  触发、影响、证据）；尾部：覆盖、跳过、限制、状态横幅。
- 无效 finding 计数必须可见；`partial` / `failed` / `cancelled` 不显示为绿色通过。

### S4 CLI 接线 — `src/commands/*`

- `workflow-commands.ts`：`review` 命令改为 `execution: 'builtin'`，路由 `handleReview`。
- `workflow-command-handlers.ts`：`handleReview` 解析 selector（失败返回用法，
  不继续为聊天）；`ctx.llm` 缺失返回明确错误；有 Runtime hook 时走 hook，直接路径
  使用 `ctx.cwd` + `ctx.llm` 构造 adapter 运行 S2 并渲染 S3。
- 验收：命令层单测；既有 `/review <path>` 用法兼容。

### S5 版本发布

- 六处版本 bump：`package.json`、`npm-shrinkwrap.json`（顶层 + `packages[""]`）、
  `CHANGELOG.md`、`README.md`（install pin + 首部摘要）、`README.zh-CN.md`（同前）。
- 顺带把 v0.3.27 条目状态由 `candidate` 更新为 `published`（tag 已存在）。
- `npm test`（精确路径）、`npm run build`、`npm run release:check` 通过后走
  push → gh PR → squash 合并 → tag → npm publish → registry 直连确认。

## 4. 验收标准

1. S1–S4 单测与集成测试全绿；`npm run build`、`npm run release:check` 通过。
2. `/review` 全部参数路径有单测；未知参数不再静默进入普通聊天。
3. 收据 digest 重算验证通过；无效 finding 不产生绿色结论。
4. E2E：本切片不新增 Web 场景（无 Web 改动），不触碰
   `WEB_E2E_FULL_SCENARIOS_V1`；PTY / 真实模型质量评测记 `not_run` 并在 CHANGELOG
   中如实声明。
5. 发布链路完整：PR 合并、tag `v0.3.28`、npm registry 可见。

## 5. 风险

| 风险 | 控制 |
| --- | --- |
| 单轮补全审查质量有限 | 本版定位为接线切片；质量评测属 PR4，未运行即 `not_run` |

| 破坏既有 `/review` 用法 | 保留 `<path>` 过滤兼容；无 Runtime 时维持旧行为 |
