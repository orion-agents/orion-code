## 1. 版本决策与用户价值

v0.3.27–v0.3.32 建立了专业审查回路的契约、CLI 运行时、Web 共享闭环、文档对齐与连续
两轮交付状态审计，但发布收据链路仍按周期出现两处事实缺口：

1. **CHANGELOG 交付状态漂移。** main 上 CHANGELOG 的 0.3.32 条目仍为
   `Status: candidate`，而 tag `v0.3.32` 与 npm `latest=0.3.32` 均已存在（2026-10-23
   发布），需按事实更新为 `published`。
2. **v0.3.32 发布事实未形成仓库内证据。** v0.3.32 的发布链路事实（PR #288、squash
   合并提交 `d24f531`、tag `v0.3.32`、registry shasum `e0542251…0c5`、tarball 入库
   时间 2026-10-23T03:39:28.945Z）尚未有任何证据文件记录。

v0.3.33 交付上述两项回填，并顺带完成一次 **近三版（0.3.30–0.3.32）交付状态审计**：
以 registry 直连查询与 git tag 交叉核对每版的「tag 存在 + npm 版本存在 + dist-tag
latest 指向」三项，审计结果写入本轮证据文件，作为 G1 证据纪律的周期性检查样例
（滚动窗口相对 v0.3.32 轮前移一版）。

**本版明确不做（仍属 PR4 剩余项，待有凭据环境）：** 人工标注付费质量评测（12 缺陷 +
8 干净样本、3 轮运行）、真实模型全链路验收、TurnCommit 收据投影与跨重启恢复、
`start_code_review` 协议命令化、finding Context 结构化注入。
