## 1. 版本决策与用户价值

v0.3.27–v0.3.35 建立了专业审查回路的契约、CLI 运行时、Web 共享闭环、文档对齐与连续
多轮交付状态审计，但发布收据链路仍按周期出现两处事实缺口：

1. **CHANGELOG 交付状态漂移。** main 上 CHANGELOG 的 0.3.35 条目仍为
   `Status: candidate`，而 tag `v0.3.35` 与 npm `latest=0.3.35` 均已存在（2026-10-25
   确认，tarball 入库 2026-10-24T20:06:04.738Z），需按事实更新为 `published`。
2. **v0.3.35 发布事实未形成仓库内证据。** v0.3.35 的发布链路事实（PR #291、squash
   合并提交 `cfbb4e2`、tag `v0.3.35`、registry shasum `b54d87b2…433b`、tarball 入库
   时间 2026-10-24T20:06:04.738Z）尚未有任何证据文件记录。

v0.3.36 交付上述两项回填，并顺带完成一次 **近三版（0.3.33–0.3.35）交付状态审计**：
以 registry 直连查询与 git tag 交叉核对每版的「tag 存在 + npm 版本存在 + dist-tag
latest 指向」三项，审计结果写入本轮证据文件，作为 G1 证据纪律的周期性检查样例
（滚动窗口相对 v0.3.35 轮前移一版）。

**本版明确不做（仍属 PR4 剩余项，待有凭据环境）：** 人工标注付费质量评测（12 缺陷 +
8 干净样本、3 轮运行）、真实模型全链路验收、TurnCommit 收据投影与跨重启恢复、
`start_code_review` 协议命令化、finding Context 结构化注入。

## 4. 验收标准

1. `npm run release:check` 通过（除已知的 4 个 better-sqlite3 环境性 Jest 失败，
   以 CI 同名 job 为准；worktree 未提交状态在 commit 后消除）。
2. `tests/coding-task-eval.test.ts` 5/5 绿；`npm run build` 绿。
3. CI（18 项检查）全绿：含 Release gate、build exact tgz、dep-health、harness、
   exact tgz ×3 平台、Web E2E critical journey ×3、Web E2E full suite 三连跑。
   已知常红基线（audit / type-check / Node 矩阵 / full suite）以历史轮次为准判断
   是否为环境性失败；时序 flake 用 `gh run rerun --failed` 处理。
4. PR squash 合并后 tag `v0.3.36` 指向 main 合并提交。
5. npm publish 后 registry 直连 curl（`Cache-Control: no-cache`）确认 0.3.36 存在
   且 `dist-tags.latest=0.3.36`。
6. 无 E2E 场景新增（docs-only 切片），不涉及场景 ID 登记。
