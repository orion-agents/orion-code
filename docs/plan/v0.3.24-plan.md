## 1. Executive Summary

本版解决两个用户可见问题：会话创建、切换和恢复时的等待，以及发送消息瞬间其他会话被置灰。源码已经证明，全局 `pendingAction` 把会话级请求误当作整个 Workbench 的锁；创建会话的前台生命周期还包含快照读取。现有缓存可以显示旧快照，但每次选择仍请求快照，后台消息并未持续写入完整的会话投影。同步 Git 探测与文件锁也存在阻塞 Node 事件循环的路径；它们是否占据主要耗时，必须通过 PR-0 测量。

目标是将 Workspace Context、浏览器会话导航和 Session 执行的状态所有权分开。浏览 A、切到 B、在 B 编辑草稿不应等待 A 的命令响应或 Agent 回合。写操作仍必须经过真实 Session ID、Context Revision、Runtime Revision、权限及共享工作区写入仲裁。实施按 PR-0 至 PR-4 推进，先建立主线性能基线，再逐层修复，最后用打包 Host 和真实浏览器验收。

## 3. 用户问题与复现路径

| 编号 | 现象与最短复现 | 预计观测 | 当前证据级别 |
| --- | --- | --- | --- |
| U1 | 在 A 发送请求期间点击其他项目中的 B，或点击新建 | B 行变灰；新建按钮禁用；A 请求结束后恢复 | 禁用条件已由源码确认；真实时长待测 |
| U2 | A/B 快速来回切换，尤其 A 已有新流式内容或长历史 | 先看到旧缓存/加载态，再由快照重建内容；可能有滚动跳动 | 代码路径与风险已确认；出现频率待测 |
| U3 | 连续点击新建，或创建后马上选择旧会话 | 创建和快照共用等待态，异步结果可能与后续选择交错 | 等待链已确认；竞态需构造验证 |
| U4 | 让 Catalog 锁竞争或 Git 探测变慢，同时访问 Web Host | 创建、其他 HTTP 或 SSE 可能一起延迟 | 同步阻塞路径已确认；影响量待测 |

PR-0 复现矩阵：S1 10 会话；S2 100 会话；S3 1000 会话侧栏；S4 长历史；S5 A 运行时切 B；S6 A 运行时跨 Workspace；S7 发送瞬间切换；S8 连续创建 10 次；S9 A→B→A；S10 HTTP 快照乱序；S11 SSE 断线；S12 慢磁盘与 Catalog 锁；S13 创建成功而快照失败；S14 双浏览器标签。优先使用可控 Runtime fixture，不调用付费模型；对 S5/S6/S11/S14 增加真实打包 Host 浏览器复核。

问题闭环判定（所有性能归因须由 PR-0 数据补足）：

- U1 发送导致置灰：现象是 B 行/新建禁用；路径为 `sendCommand → runOperation → pendingAction → ProjectNavigator.workspaceTransitionLocked`；机制是会话请求占用全局 UI 锁。S7 在延迟 A 的 `POST /commands` 时点 B，记录 DOM disabled、click→高亮及 B 的请求。若禁用持续时间与 A pending 对齐，且去除该依赖后 B 可操作，即判为主因。PR-1 改用 A 专属 token 和 Context 级真实锁；回归测 A/B 命令归属、审批及草稿；验收是 A 请求未完成也能进入 B，且不能向未同步 B 发命令。
- U2 切换/还原：现象是旧内容闪回、Skeleton 或滚动跳；路径为 `selectSession → reset_session_view → applySessionSnapshot → loadSessionSnapshot`，后台事件经 `reduceEnvelope`。S4/S9/S10 注入网络乱序和长历史，量测点击、首帧、缓存显示、GET 完成、React commit 与滚动锚点。若旧投影先于权威内容可见且响应或构造耗时覆盖卡顿区间，确认其贡献。PR-2/3 引入可信缓存与每 Session 新鲜度；PR-4 只优化实测渲染瓶颈。回归测 HTTP/SSE 顺序、无串话和草稿/滚动；验收见第 16/19 节。
- U3 新建等待：现象是 POST 已成功后按钮仍忙，或后续选择被新建响应抢回；路径为 `createSession → POST → reset_session_view → GET snapshot → runOperation.finally`。S8/S13 延迟 GET、让 POST 失败或使 GET 失败，分别记录按钮禁用时长、POST 次数、列表 ID、当前选择。若按钮释放时间随 GET 延迟而变，即确认等待耦合。PR-2 将正式 ID 入列与快照同步分开，创建局部单飞；回归测 10 连点、后选优先及失败恢复；验收是只有一次正式创建、B 可继续浏览，失败不丢已创建 Session。
- U4 Host 停顿：现象是创建时其他 HTTP/SSE 同步变慢；路径为 `WebWorkbenchController.createSession → session-storage.createSession → execFileSync/withFileLockSync/atomicWriteFileSync`。S12 用隔离数据目录制造慢 Git 与 Catalog 锁竞争，记录各阶段和 Event Loop Delay、同进程无关请求与 SSE P95。只有阻塞区间与同进程延迟重合，且改造后两者下降，才能把它列为主要性能根因。PR-2 根据 PR-0 数据采用有界异步探测或保持原子性的锁改造；回归测双进程一致性、崩溃恢复和路径身份；验收是阻塞预算改善且无元数据丢失。

## 4. 前端状态所有权分析

`web/src/types.ts:WorkbenchState` 同时持有全局 `pendingAction`、浏览器前台 `activeSessionId`、`sessionProjectionById`、`sessionRuntimeById`、`sessionSync`、当前 `sessionSnapshot`、Composer 和 `processing`。`web/src/reducer.ts:pending_action` 仅保存一个标签；`web/src/useWorkbench.ts:runOperation` 对不同操作共用一个序号。这解释了为什么会话 A 的请求能影响 B 的 UI。

| 所有者 | 应持有的状态 | 允许等待的操作 | 不得被其锁住的操作 |
| --- | --- | --- | --- |
| Workbench / Context | 当前 Workspace、Context Revision、连接及迁移状态 | 真正的 Context 激活和破坏性 Workspace 操作 | 同一 Context 内浏览会话、修改独立草稿 |
| Session Navigation | 每个浏览器标签的选中项、列表、摘要、缓存投影、快照同步、草稿、滚动锚点 | 目标会话缺少可信快照时的该会话写入 | 其他会话的选择、读取、编辑草稿 |
| Session Execution | Actor、Turn、工具、权限、队列、Durable Receipt | 对应 Session 的写入与审批 | 无关 Session 的导航 |

`pendingAction` 消费者盘点：`ProjectNavigator` 的项目添加、跨项目会话行、会话菜单、新建和分页；`App` 的若干全局控件；`Conversation` 的历史/队列/审批控件；`ComposerControlCenter` 的输入控制与发送；`useWorkbench` 的 Workspace 基线和 Session 快照 Effect。PR-1 要将每个消费者映射到其真实作用域，再替换锁条件。现有全局锁原先可能保护 Context 与结果顺序，但源码注释并未证明所有使用者都需要它；通过 Context Guard、请求身份和定向错误状态维持该不变量。

## 5. Session Create 调用链

`ProjectNavigator` 新建按钮 → `useWorkbench.createSession` → `runOperation('创建会话')` → `api.createSession` (`POST /sessions`) → `WebWorkbenchController.createSession` → `session-storage.createSession` → `saveSessionMeta` / Catalog 更新 → 返回 Session summary → `sessions_loaded`、`reset_session_view` → `loadSessionSnapshot` (`GET /sessions/:id/snapshot`) → `runOperation` 清除 `pendingAction`。

已确认：按钮禁用覆盖 HTTP POST 与后续 GET 的总时长；Host 创建本身不会激活或关闭 Session Actor (`WebWorkbenchController.createSession`)。设计为“创建中”局部反馈，正式 ID 返回后写入列表；快照在后台单独同步。临时 UI 身份只能用于显示，不能用于命令、权限或工具执行。创建成功而快照失败时保留正式会话并给该会话重试入口；POST 失败只清除其对应占位。重复点击必须单飞或由稳定幂等请求 ID 去重，不能产生多个隐形会话。若用户在等待期间选了 B，创建结果不得把前台抢回。

## 6. Session Switch 调用链

同 Workspace：`ProjectNavigator` → `selectSession` → `rememberForegroundSession` → `reset_session_view` → 总是 `loadSessionSnapshot`。缓存命中时 `reset_session_view` 立即套用旧快照，但状态仍为 `refreshing`；缓存未命中则清空当前投影并显示加载态。`selectSession` 返回的 Promise 等待 GET。`useWorkbench` 的快照 Effect 遇到任何 `pendingAction` 直接返回。

跨 Workspace：`ProjectNavigator` 以 `operationLocked || state.processing` 禁用非活动项目会话；未禁用时 `activateContext` 仍经 `runOperation`、`POST /context/activate`、`loadBaseline`。Host 的 `activateContext` 会迁移控制平面，并在换 Workspace 时等待旧控制平面空闲；Session Actor 注册表保留运行中的 Actor。这条链需要单独的响应性预算，不能把它等同于同 Workspace 的本地切换。

同 Workspace 纯浏览理论上无须重新连接 Runtime：`activateSession` 只读取 Registry summary；`sessionSnapshot` 读取 Session、索引与投影，不调用 `ensureResident`。SSE 是 Host 级连接，不应因本地选中项变化而重建。上述是源码机制判断，不代表冷快照读取或 React 绘制无耗时。

## 7. Send Command 调用链

`ComposerControlCenter.deliver` → `actions.submit/queue` → `useWorkbench.sendCommand` → 全局 `runOperation` 写 `pendingAction` → 校验 live 连接、活动快照及 Runtime Revision → `api.command` (`POST /commands`) → `WebWorkbenchController.dispatch` 通过 Session Registry admission 路由对应 Actor → 返回后清理全局 `pendingAction`。

`ProjectNavigator` 使用 `operationLocked = Boolean(state.pendingAction)`，跨项目又使用 `workspaceTransitionLocked = operationLocked || state.processing`。因此发送瞬间其他项目会话被禁用是确定的前端因果链。`ComposerControlCenter` 也把这个全局值用于 `composerReady`，会话 A 请求可错误影响切换到 B 后的写入。PR-1 保留发起时的 Workspace、Context、Session、Runtime Revision 及唯一操作 token；响应只更新所属会话，只有真实共享变更使用 Context 级锁。

## 8. Host 同步阻塞分析

`session-storage.createSession` 依次进行 `resolveProjectPath`、`getGitBranch`、`saveSessionMeta`。前两处使用 `execFileSync`；`normalizeSessionMeta` 在缺分支信息时还可能补查 Git。`src/product/paths.ts:resolveProjectStoragePath` 有另一条同步 Git 根解析路径。`saveSessionMeta` 在 Session 文件锁内原子写元数据，然后 `updateSessionCatalog` 在 Catalog 锁内读、更新、原子写；冷 Catalog 可能扫描目录。`src/services/file-lock.ts:withFileLockSync` 的重试使用 `Atomics.wait`，Catalog 代码允许最多等待 10 秒。

这些路径在 Node 主线程运行时会阻止同进程 HTTP/SSE 继续执行，这是机制上已确认的阻塞风险；实际用户卡顿中各阶段占比尚未测量。PR-0 要在隔离数据目录中记录 create total、Git 根/分支探测、metadata 锁等待与写入、Catalog 锁等待/扫描/写入、Snapshot/索引读、Event Loop Delay、SSE 交付延迟；区分冷/暖缓存及 10/100/1000 会话。若 Git 是主因，先尝试有界异步探测和安全缓存；若锁是主因，再设计保持跨进程锁、原子写、Catalog 一致性与崩溃恢复的异步 admission/写入。禁止仅把 `*Sync` 批量替换为 Promise。

## 9. Snapshot / SSE 恢复分析

`loadSessionSnapshot` 以 Workspace、Context Revision、Session ID 去重，并给请求分配 requestId；Reducer 校验 Context 和最近 requestId，晚到的其他会话快照只进入后台缓存。这些保护应保留。`reset_session_view` 即使缓存命中也执行 `applySessionSnapshot`，从 snapshot 再构造 transcript、工具等前台数组；`cacheSessionProjection` 最多 8 个或 8 MiB，并在更新时估算序列化大小。

`reduceEnvelope` 按 Host 全局 Cursor 去重；后台 `session_runtime_changed` 更新 Runtime summary，但其他 Session 的 `thread_event`/`runtime_event` 不写入其完整前台投影。因此切回可能先看旧快照，再收到 HTTP 更新。另一个待验证竞态是：同 Session 的新 SSE 已应用，但较早发起的 HTTP 快照稍后到达；当前请求 ID 只比较 HTTP 请求间的新旧，没有明确比较该 Session 的事件新鲜度。仅比较全局 Cursor 会把其他 Session 的事件混入判断，方案应记录每 Session 最新事件 Cursor 或可证明等价的 revision。

SSE `WebEventHub` 保留有界事件并在 Cursor 超出窗口时发 `replay_reset`；任何缓存复用都必须服从该协议。网络重连后先恢复可信的 Durable 状态，再开放目标会话写入。后台事件可更新对应缓存或标记 dirty，不能把 A 消息投影到当前 B。缓存空间和预取并发必须有界；失败后只能对目标会话显示同步错误与重试，不回退到旧会话。

## 11. 根因优先级排序

1. P0：会话级请求误用全局 `pendingAction`，直接解释“发送时其他会话置灰”。
2. P0：创建与目标快照共用同一前台操作生命周期，直接解释“新建后仍等待”。
3. P0：缓存恢复强制刷快照、后台完整投影不更新，解释“切回还原”机制；可见耗时待测。
4. P0 风险：同步 Git/锁阻塞 Host 事件循环；用户卡顿中的贡献待测。
5. P1 风险：React 历史构造、Layout 与滚动重置；只有 Profile 证明时才优化。

## 12. 架构改造建议

使用现有 reducer 与 `sessionProjectionById`、`sessionRuntimeById`、`sessionSync`，增加最小的作用域信息，不引入第二套 Store。Context 迁移拥有单独 busy 状态；创建有单飞状态；命令、Composer、历史分页、对话框各自按 Session/资源记录 pending。导航选择立即更新浏览器本地身份；冷会话只让其正文显示 Skeleton、写入等待可信快照。缓存命中只有在 Context、连接与事件新鲜度均可信时才能直接开放操作。

发送与创建的 Promise 捕获发起时身份，完成时使用 request token + Context Revision + Session ID 校验归属。HTTP 快照携带请求 ID；SSE 更新按 Session 记录最新 Cursor，旧 HTTP 不得覆盖更新投影。背景状态可标记 dirty 或合并可验证事件；选择时视情况局部同步。草稿及滚动锚点按 Session 保存。Host 的 Session Actor 仍懒分配且有容量限制，共享工作区写入仍交 Workspace Mutation Arbiter。

## 16. 性能指标与预算

下表全是设计目标；主线 baseline 尚未采集。PR-0 与候选版本均须记录环境、至少 20 次常规导航样本、P50、P95、原始样本及失败数；长历史、锁竞争要单独分组。用 `performance.mark`/Chrome trace 对齐浏览器与 Host requestId，不把网络、React 和 Host 时间混成一个数。

| 指标 | 目标 | 必留证据 |
| --- | --- | --- |
| 点击 → 选中高亮 | 下一可用渲染周期；代表性开发机器 P95 < 100ms | click/commit/paint 时间戳、20+ 样本 |
| 点击 → Warm 内容可见 | P95 < 150ms | 缓存命中、是否额外 GET、首帧截图/trace |
| Cold 切换 | 侧栏立即可继续操作；目标正文 Skeleton，不等待 Actor | 点击时间、Snapshot ready、Actor 分配数 |
| A 执行期间进入 B | B 可选、可读、可编辑；可写仅在 B 快照可信且权限允许 | 控件状态、请求轨迹、两 Session ID |
| 新建与 Host | 不造成明显主线程长任务；量化 Git/锁/索引及 Event Loop Delay | create 分段、锁竞争、SSE 延迟 |
| 纯浏览副作用 | Actor 新建、Turn、模型/工具调用均为 0 | Registry、网络和 Durable Receipt 计数 |

前端额外量测 click→first frame、Snapshot ready、React render/commit、Long Task、Layout/Paint；后端量测 Snapshot/indexed transcript、Catalog lock、Runtime admission、SSE delivery。达标判定同时要求正确性，不接受仅动画变快或错误地开放未同步会话写入。

## 17. 并发与安全不变量

1. Session ID、Workspace ID、Context Revision、Runtime Revision 和 requestId 必须与请求发起时身份一致；过期响应不能修改当前会话。
2. 浏览器当前选中项是本标签状态；双标签不共享前台选择。Context 激活仍需服务端 Revision Guard。
3. A 的 Actor 在用户浏览 B 时继续运行；Actor 容量、队列及关闭语义由 Session Registry 决定。
4. Workspace Mutation Arbiter、ToolGateway、ExecutionPolicy、Permission Approval 仍保护真实文件写入；UI 导航不绕开它们。
5. 临时创建占位不能执行命令；目标会话 Snapshot/Composer 控制版本不可信时只禁其写入。
6. SSE replay、Durable Thread 恢复、Snapshot Identity 和 Cursor 顺序保留；任何浏览操作不得重复执行工具。
7. Catalog 跨进程锁、原子写、Session Identity 与 crash recovery 不因性能改造失效。
8. 缓存/预取有容量与并发上限，故障后可通过权威 Snapshot 恢复。

## 18. 风险和回滚方案

| 风险 | 预防与回滚 |
| --- | --- |
| 状态拆分遗漏消费者，出现串 Session 命令 | PR-1 先列全部 pending 消费者及类型化作用域；保留旧 Guard 的测试；异常时回退到该 PR 前提交 |
| 旧 HTTP 覆盖新 SSE 或缓存错认 ready | PR-3 用同 Session Cursor/Revision 和乱序测试；只回退缓存复用优化，保留权威 GET |
| 异步 Catalog 改造损坏持久性 | PR-0 证据决定是否改；双进程、进程中断、损坏恢复测试；失败时保留现有同步写路径 |
| 跨 Workspace 乐观导航与实际 Context 不一致 | 显示 pending Context、禁止目标写入直至确认；失败回滚 Context 身份并保留目标可重试 |
| 缓存/预取放大内存和网络 | 延续 8 项/8 MiB 投影上限与有界预取；超限标脏并冷读 |
| 长历史优化引入滚动错位 | 保存 Session 锚点与阅读位置，Chrome 截图/交互测试；按 PR 隔离回滚 |

每个 PR 独立提交并可单独回退。PR-0 的样本与原始日志保留，回滚后复测同一场景；不得用改变权限或降低测试断言代替回滚。

## 19. 验收标准

- S1–S14 均有四态结果，P0 场景 S5/S6/S7/S8/S9/S10/S11/S13/S14 必须 `pass` 才能宣称修复完成。
- A 发送与运行期间，B 及其他项目的会话行不因 A 的 pending/processing 置灰；B 可浏览与编辑，写入服从 B 的真实权限和同步状态。
- 新建期间可导航；失败只影响该创建；成功但快照失败保留正式 Session；重复触发不创建意外的多个会话。
- Warm 切换达到第 16 节目标；Cold 切换先反馈、后同步；A→B→A 无错误回退、消息串话、草稿丢失或滚动意外跳动。
- 纯浏览不连接新的 Runtime Actor、不重新启动 Turn、不调用模型/工具；SSE 重连和 Durable 恢复维持一致。
- 所有性能结论引用 baseline 与候选的同环境原始样本；未测量项目仍标 `not_run`，不能称为已解决。

## 20. Release Gates
