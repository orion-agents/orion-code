## 1. 背景与定性：本轮含产品修复（非 docs-only）

- **用户报告的产品缺陷**：Web 端通过对话框添加后的工作空间在项目导航中**没有
  任何删除或归档入口**，列表只增不减。
- **根因定位（evidence：代码走查 + 服务端契约核对）**：服务端早已具备完整闭环
  ——`DELETE /api/v1/workspaces/:id`（server.ts）→
  `WorkbenchController.removeWorkspace`（durable registry `WorkspaceRegistryV1`
  持久化移除，激活项 409 `workspace_active` 拒绝）→ `api.removeWorkspace` →
  `useWorkbench.removeWorkspace`。缺口**纯在 UI**：
  `ProjectNavigator.tsx` 的移除按钮仅在 `!project.available && !project.active`
  （不可用项目）时渲染，正常可用的项目行只有「新建会话」一个动作。
- **修复设计**：每个非激活项目行渲染独立的移除入口（与既有 `.project-remove`
  样式/悬停显隐规则一致）；不可用项目保留原有的立即移除语义；可用项目新增
  destructive 确认弹窗（复用 `ConfirmDialog`，说明磁盘会话保留、仅关闭终端）；
  激活中的项目按钮禁用并以 title 说明「先切换到其他项目」（与服务端
  `workspace_active` 409 语义一致，避免必然失败的点击）。
- 关于「归档」：工作区（workspace）实体无服务端归档概念；会话（session）已有
  归档/还原（v0.3.7）。移除工作区条目不删除磁盘会话（重新添加即可恢复），
  与「从列表消失但数据保留」的归档语义等效。本轮如实以「移除 + 数据保留」
  交付，不引入新的 workspace 归档状态机。
- 其余簿记切片沿 v0.3.38–v0.3.65 历轮先例（欠账清偿 + 三版滚动审计 + 六处
  bump）；本轮**含 `web/` 与 `tests/` 产品代码变更**，属正常版本推进轮。
- 无新增已知风险面：`WEB32-P0-08` / `terminal_journey` PTY 探针 flake 家族根因
  仍开放（连续两轮 CI 未复现），如实延续记录。

## 2. 任务分解

  以 patch 迁入 worktree 并还原主工作区（`git status` 0 条）。

  绑定）不得靠改断言或跳过用例「转绿」。

  （WEB32-P0-08 / PTY 探针签名），真回归必须修复后重走 CI，不得绕过。
