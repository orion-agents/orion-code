# Orion Code v0.3.4 稳定化开发计划

- 版本：v0.3.4
- 状态：Implementation / qualification pending
- 日期：2026-09-01
- 基线：v0.3.3 Draft PR #243（不得借本计划自动合并或发布）
- 目标：关闭 Web Workbench 的跨 Context 写入、敏感内容、终端顺序和发布证据缺口

## 1. 决策摘要

v0.3.4 是向后兼容的补丁版，不扩张 v0.3.3 的产品功能边界。它把已有的多 Session、Files、Git、Review、Terminal、Settings 与 release receipt 变成可安全发布的实现：

1. 所有 Settings 写入绑定 `workspaceId + expectedContextRevision + expectedRevision`，陈旧页面稳定返回 409 且零副作用；
2. Web 文件、Git diff、tool artifact、命令输出和持久 trace 使用同一 fail-closed 脱敏边界；
3. durable tool receipt 与 journal fact 必须成对并通过 canonical digest 校验，单边证据不得显示成功；
4. Terminal 的 PTY 分片、浏览器写队列、replay/live/exit 顺序和关闭语义保持 Unicode 完整且确定；
5. Review 明确区分真实总数与当前可见页，符号链接保留 lexical 类型并投影有效目标类型；
6. 发布 receipt 拒绝失败 canary、重复运行证据和脚本执行边界不明的安装证明。

## 3. 实施切片

### P0-A：Context 与命令隔离

- `UpdateSettingsRequest` 强制携带 Workspace Context guard；幂等 digest 包含 guard。
- Controller 在读取当前 Settings coordinator 前校验 guard，避免 A 页面写入 B Workspace。
- cold/resident actor 的 Composer action 必须从 actor Runtime 的 canonical Session 投影最终
  model/effort/permission，不能回写创建 actor 前的陈旧 Session 副本。
- 命令输出使用 async-local collector；并发命令不得替换/串扰进程级 `console.*`。
- `reject-busy` slash command 在调度前执行策略，命令失败不得清除仍在运行的 turn。

### P0-B：敏感资源边界

- 文本 redactor 先处理 URL userinfo，再处理结构化敏感键，覆盖 X 前缀及嵌套字段。
- 文件授权同时检查用户别名和 canonical Workspace-relative 路径。
- Git diff 在启动任何 Git 内容进程前检查 current path 与 rename source。
- tool artifact derivative、命令 transcript、SSE/snapshot 和磁盘 trace 不得出现 synthetic marker。

### P1-A：Terminal 与 durable receipt

- TerminalManager 缓冲跨 PTY 回调的代理对；最终孤儿代理字符只在 exit 时替换为 U+FFFD。
- 浏览器 write queue 在剩余容量不足以容纳代理对时等待 ACK，不重复调度空 animation frame。
- WebSocket 在 replay 期间缓存 live frame 与 exit，严格按 ready/gap → replay → live tail → exit → close 排空。
- Thread UI 只接受“receipt 与 durable fact 都无”的 legacy，或“两者都有且校验通过”的现代记录。

### P1-B：Read model 诚实性

- 每一内容页都再次检测 binary marker，不能只检查首 8 KiB。
- symlink 节点保留 `kind=symlink`，对可读目标增加 `targetKind=file|directory`。
- Review 返回 `totalChangedFiles`；`changedFiles.length` 只代表当前可见页。
- Session rename 对缺失、非字符串、空白和超长值 fail closed，合法值持久化前 trim。

### P1-C：Release receipt

- `liveCanary=FAIL` 必须产生 `NO_GO`。
- runtime matrix 的 runId 与 manifestDigest 必须跨三条 Node 运行唯一。
- exact-tgz 安装分“禁止 scripts 的安全提取证明”和“隔离的真实 native consumer probe”，不得混为同一结论。
- 浏览器 E2E 的前景 Session 取自对应 Page 的 foreground state 或显式 Session ID，不能把 Host
  bootstrap 的 actor 状态误当成标签页选择。

## 4. 非目标

- 不增加新 Agent 模式、模型供应商、远程服务、插件系统或云端账户；
- 不改变 v0.3.3 的多 Session actor pool、Composer 或主题产品语义；
- 不自动合并 Draft PR，不创建 tag，不复用已发布版本号；
- 不以 source build、旧 dist、HTTP health 或单一 Node 版本代替 exact-tgz 浏览器证明。

## 5. 发布判定

本计划中的“实现完成”只允许创建 Draft/Ready-for-review PR。只有用户明确允许合并，且合并后的 main 重新生成同一版本的 clean exact artifact 与全矩阵 `GO` receipt，才可进入 npm publish。任何旧 receipt、dirty source、skip、expected-fail 或缺失 Node lane 都是 `NO_GO`。
