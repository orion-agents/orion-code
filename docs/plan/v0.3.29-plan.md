## 1. 版本决策与用户价值

v0.3.28 把 CLI `/review` 升级为类型化审查工作流（frozen snapshot → 单轮有界补全 →
契约校验 → digest 可验证收据），但 Web 审阅面板仍只展示 Git 变更事实：无法在浏览器里
发起同类审查、查看结构化 findings、把问题定位回 diff 或送回修复草稿。

v0.3.29 把共享审查运行时接入 Web Host（PR3 核心子切片）：

1. Host 提供 `POST /review/run`（异步启动）与 `GET /review/runs`、
   `GET /review/runs/:runId`，复用 v0.3.28 的 `runCodeReview` 运行器与冻结契约，
   不新增第二套审查引擎（G3）。
2. 模型 adapter 从控制面 Runtime 的 `llm`（`OrionCodeUiRuntime.llm`）派生；
   Host 未配置模型时返回类型化错误 `review_no_model`（422），不伪装运行。
3. 运行结果为完整 `CodeReviewResultV1` 收据；读回时重算 digest 验证，并用
   admission 时的 `repositoryRevision` 与当前值对比给出 `stale` 标记（结果过期可见，
   不把过期结果显示为当前结论）。
4. Review 面板新增"审查结果"区：按 P0→P3 分组的 findings（文件:行、触发、影响、
   证据）、状态横幅如实区分 completed / partial / failed / running / stale；
   每个 finding 可定位到既有 diff 视图，并可把 finding 作为类型化文本送回对话草稿
   （提交仍由用户确认，不自动修复）。
5. 同一 Workspace 同时只允许一个运行中的审查（`review_run_in_progress` 409）；
   收据历史有界（最近 20 条），Host 重启后清空并在 UI 如实显示"Host 重启后历史不保留"。

**本版明确延期（与 v0.3.27 plan §1.2 一致）：** TurnCommit 收据投影与跨重启恢复、
`start_code_review` 协议命令化、finding Context 结构化注入、人工标注付费质量评测
（PR4，记 `not_run`）、真实 Host + Chrome 全链路 E2E（本机沙箱无模型凭据；记 `not_run`）。

## 2. 任务分解

### S1 Host 审查运行服务 — `src/web/code-review-run-service.ts`（新增）

- `WebCodeReviewRunServiceV1`：
  - `start(selector, context)`：单飞 guard（运行中 → `review_run_in_progress`）；
    adapter 缺失 → `review_no_model`；后台执行 `runCodeReview`（cwd 取当前
    Workspace），结束前再次校验 context guard；
  - `list()` / `get(runId)`：读回时重算 `verifyReceiptDigest`，并对比当前
    `repositoryRevision`（admission 时记录）标记 `stale`；
  - 历史上限 20 条，超出淘汰最旧的非 running 记录。
- 依赖全部注入：`ReviewModelAdapterV1 | null` 工厂、`runCodeReview`（测试可换 fake）、
  `repositoryRevisionProvider`、`now`。
- 验收：单测覆盖并发 guard、无模型错误、成功/失败/取消状态映射、stale 标记、
  digest 复核、历史上限淘汰。

### S2 Host 接线与协议 — `src/web/workbench-controller.ts`、`src/web/server.ts`

- Controller：构造 run service；adapter 工厂从 `this.runtimeValue.llm` 派生
  （null → `review_no_model`）；暴露 `reviewRunStart` / `reviewRunList` /
  `reviewRunGet`，全部走 context guard。
- Server 路由：
  - `POST /review/run`：`assertMutation` + `executeMutation`（fast start，立即返回
    `{ runId, status: 'running' }`）；
  - `GET /review/runs`、`GET /review/runs/:runId`：只读，context guard query。
- 验收：端点测试（真实 server harness + fake runtime 注入 fake `llm`）覆盖
  启动→轮询完成、409、404、422、`assertMutation` 缺 nonce/Origin 拒绝（403）。

### S3 Web 客户端结果视图 — `web/src/`

- `api.ts` + `types.ts`：`reviewRunStart` / `reviewRuns` / `reviewRun` 客户端方法与
  镜像类型。
- `ReviewPanel.tsx`：新增审查结果区（运行按钮、收据列表、findings 分组、状态横幅、
  stale 提示）；finding 点击 → 按 path 匹配变更文件并打开既有 diff；finding
  "送回对话" → `onSendToComposer`（含 file:line 与触发条件的类型化文本）。
- 纯函数拆分（分组、finding→composer 文本、状态横幅文案）便于 renderToStaticMarkup
  断言；复用 `ResourceSplitLayout` 既有骨架，不新增全局样式依赖。
- 验收：纯逻辑单测 + `renderToStaticMarkup` 视图测试；不修改 Files/Git 面板行为。

### S4 版本发布

- 六处版本 bump：`package.json`、`npm-shrinkwrap.json`（顶层 + `packages[""]`）、
  `CHANGELOG.md`、`README.md`（install pin + 首部摘要）、`README.zh-CN.md`（同前）。
- 顺带把 v0.3.28 条目状态由 `candidate` 更新为 `published`（tag 已存在、npm 已可见）。
- `npm test`（精确路径）、`npm run build`、`npm run release:check` 通过后走
  push → gh PR → squash 合并 → tag `v0.3.29` → npm publish → registry 直连确认。

## 4. 验收标准

1. S1–S3 单测全绿；`npm run build`、`npm run release:check` 通过。
2. Web 发起审查→轮询→查看 findings→定位 diff→送回草稿的链路在单测/端点测试层闭合；
   真实 Host + Chrome 全链路记 `not_run`（沙箱无模型凭据），CHANGELOG 如实声明。
3. 收据读回必须通过 digest 复核；失败/部分/取消/stale 不渲染为绿色通过。
4. 不新增 E2E 场景，不触碰 `WEB_E2E_FULL_SCENARIOS_V1`。
5. 发布链路完整：PR 合并、tag `v0.3.29`、npm registry 可见。

## 5. 风险

| 风险 | 控制 |
| --- | --- |
| Host 长任务占用 mutation 通道 | start 立即返回，模型调用在后台执行，客户端轮询 |
| Host 重启丢收据 | UI 明示"Host 重启后审查历史不保留"；持久化属延期项 |
| 模型未配置时按钮无响应 | `review_no_model` 类型化错误直接展示给用户 |
| 破坏既有 Review 面板 | 结果区为增量区块；既有快照/diff 行为与测试保持不变 |
