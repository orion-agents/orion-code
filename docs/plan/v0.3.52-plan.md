## 1. 版本决策与用户价值

1. **修掉 main 的 critical journey 红灯（条款 B）**：WEB32-P0-09 的中间态断言修正
   后，`Web E2E critical journey ×3` 与三连跑作业具备稳定转绿条件；main CI 转绿是
   本版发布的前置条件。
2. **给 WEB32-P0-08 的可复现失败装上诊断**：当前超时信息只有「没等到请求」，无法
   区分「host 从未发出」与「发出但内容不含 `context-manifest`」。补充到达请求摘要
   后，下一轮可据此定位真因。
3. **清偿 0.3.51 开版欠账 + 三版滚动审计（0.3.49–0.3.51）**，维持发布证据链纪律。

**本版明确不做：** 放大 45s fixture 超时以规避 P0-08；人工标注付费质量评测；真实
模型全链路验收；TurnCommit 收据投影；`start_code_review` 协议命令化。

## 2. 任务分解

### S1 E2E 时序红灯修复 — `tests/e2e/web-v032-context-plan-queue-recovery.spec.ts`

- WEB32-P0-09：把提交「继续规划」反馈后对 `planReview.status` 的单次读取改为
  `expect.poll(...).toBe('awaiting_review')`（沿用 60s 预算），并把已有的 revision
  变化轮询与 status 轮询合并为对同一快照的轮询，避免重复读取。
- 验收：`Web E2E critical journey on Node 22.12.0 floor` 转绿；断言语义不变（仍是
  「继续规划后回到 awaiting_review 且未触发执行」）。

- 六处 bump 至 `0.3.52`：`package.json`、`npm-shrinkwrap.json`（顶层 +
  `packages[""]` 手改）、`CHANGELOG.md`、`README.md`（首部摘要 + install pin）、
  `README.zh-CN.md`（同前）。
- 同步 `tests/coding-task-eval.test.ts` 的 `packageVersion` pin（0.3.51 → 0.3.52）。
- CHANGELOG：0.3.51 `candidate` → `published`（PR #310、merge `0702878`、tag
  `v0.3.51`、npm `2026-11-04T18:11:26.062Z`、GitHub Release 链接），并新增 0.3.52
  `candidate` 条目。
