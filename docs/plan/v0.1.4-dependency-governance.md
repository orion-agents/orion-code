# v0.1.4 dependency governance evidence

Date: 2026-08-09

## Runtime contract

Orion Code v0.1.4 supports Node `20.x`, `22.x`, and `24.x` and emits CommonJS.
Dependency upgrades must preserve all three Node majors, the CommonJS load path,
and the existing OpenAI-compatible Chat Completions integration.

| Dependency | Candidate checked | Compatibility result | Decision |
| --- | --- | --- | --- |
| `openai` | `7.4.0` | `engines.node >=22`; excludes Node 20 | Do not install while v0.1.4 supports Node 20 |
| `openai` | `6.49.0` | CommonJS `require` export; Chat Completions retained; Node 20/22/24 probes pass | Upgrade from `4.104.0` |
| `ink` | `7.1.1` | Node `>=22`, ESM-only, React and React types `>=19.2` | Do not upgrade the deprecated renderer in place |
| `react` | `19.2.8` | Runtime itself remains CommonJS-compatible, but Ink 7 couples it to the incompatible migration above | Keep React 17 until Ink removal |
| `lodash-es` / `type-fest` | current direct dependencies | No source or test references outside manifests | Remove |
| `@types/better-sqlite3` | `7.6.13` | Type-only package | Move to `devDependencies` |

The Ink compatibility renderer is already scheduled for physical removal in
`src/tui-ui/INK-REMOVAL-MIGRATION.md`. Its temporary Ink 3 / React 17 pair is an
explicit, executable exception in `scripts/dep-health-check.sh`, not an implied
claim that the old framework is current.

## Automated controls

- `npm run deps:check` validates manifest/lock scopes, CommonJS loading, Chat
  Completions availability, dependency-tree consistency, and `npm audit`.
- `npm run deps:check -- --policy-only` runs the deterministic offline contract
  checks used by Jest.
- `.github/dependabot.yml` groups weekly npm minor/patch updates and checks GitHub
  Actions monthly. Node-22/ESM-only majors are ignored until their runtime
  contracts change.

## Issue #71 disposition

Close #71 after the focused LLM tests, PTY smokes, Node 20/22/24 probes, build,
lint, `npm audit`, and dependency-health gate pass. The issue asked for an
Ink/React upgrade plan rather than an unsafe in-place major upgrade; the checked
removal roadmap plus enforced exception satisfies that boundary. Any decision to
drop Node 20 or retain and modernize Ink should be a new release-scoped issue.
