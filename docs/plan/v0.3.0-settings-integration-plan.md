## 1. 结论与交付目标

v0.3.0 要把当前“能改三个值的弹窗”升级为真正的 Settings 子系统：Host 是唯一真源，
设置具备明确作用域、来源、生效时机、磁盘持久化、原子批量保存、跨标签/跨进程冲突检测、
外部文件编辑收敛、错误恢复和秘密隔离；Web、TUI、命令与 Runtime 不能再绕过同一套设置协调器。

完成后，用户可以可靠地完成以下操作：

- 设置主题与动效，并在刷新、端口变化和 Host 重启后保留；
- 设置全局默认模型，且不会把“当前会话临时切换”误认为默认值；
- 设置当前工作区的 Effort 默认值，重启后仍按 `project > global > model default` 生效；
- 设置全局工具确认策略，明确知道它的作用域和开始生效的时间；
- 看见每个字段的有效值、显式覆盖值、来源、作用域和生效时机，并可“重置为继承值”；
- 在两个标签页或外部编辑 `orion.json` 时得到可解释冲突，不丢草稿、不静默覆盖；
- 查看 Provider 凭证的 `ready / missing / unavailable` 状态，但浏览器永远拿不到密钥值；
- 通过“打开配置文件”进入高级编辑；请求不接收、响应不返回任意本地路径。

v0.3.0 的发布结论只有两种：上述 P0 合同和真实 E2E 全部通过则 `GO`；任一持久化、
CAS、秘密泄漏或恢复用例失败则 `NO_GO`。不能以当前单字段 CAS 测试代替完整 Settings 证明。

### 2.3 当前 P0 缺口

1. `src/web/workbench-controller.ts:73,453-515` 的 revision 是从 `1` 开始的内存整数；Host
   重启、其他进程、slash command 或外部文件编辑都可绕过 CAS。两个不同 requestId 的并发异步
   mutation 也可能同时通过同一 revision。
2. `web/src/useWorkbench.ts:426-448` 把一次保存拆成最多三次 PATCH；第二步失败时第一步已经提交，
   但 UI 仍把它表现为一个事务。
3. Web 模型设置仅执行 `/model` 并改 LLM/Store，未写 `defaultModel` 或 Session metadata：
   `src/web/workbench-controller.ts:482-497`、`src/commands/model-command-handlers.ts:417-470`。
4. Effort 虽写到 `projects[cwd].defaultEffort`，启动只读取全局 `defaultEffort`：
   `src/commands/model-command-handlers.ts:650-671`、`src/services/config.ts:367-373`。
5. Theme/Motion 只在当前浏览器 localStorage：`web/src/App.tsx:17,27-53,249-271`。
6. 当前 reducer 只有 baseline/本地 PATCH 回写，没有 `settings_changed` 事件：
   `web/src/reducer.ts:78-93,133-134`。
7. 任意 HTTP 409 都被显示成“其他客户端更新”，无法区分 revision conflict、runtime busy 与
   requestId/body conflict：`web/src/useWorkbench.ts:449-455`。
8. 当前测试只证明顺序单字段 stale CAS；未证明并发、Host 重启、项目 Effort 恢复、UI 草稿冲突、
   部分失败、外部文件热加载或 Settings 专项 secret-negative。

## 3. 范围与非目标

### 3.1 v0.3.0 必须交付

- `SettingsCoordinatorV1`：所有持久设置写入口的唯一协调器；
- `orion.json` 严格读取、持久 revision、进程内队列、文件锁内 CAS、原子批量 mutation；
- General、Models & Reasoning、Permissions、Advanced 四个静态页面；
- Host-backed Theme/Motion、全局默认模型、项目 Effort、全局工具确认；
- 每字段的 scope/source/applies/override/writable 元数据及 reset-to-inherited；
- Provider/credential 的脱敏就绪状态与 pathless “打开配置文件”；
- secret-free `settings_invalidated` SSE 与浏览器 SettingsMirror；
- inline dirty/saving/conflict/invalid/read-only/restart-required 状态；
- 单元、合同、集成、真实浏览器 E2E、重启与安全门禁。

### 3.2 明确不做

- 不引入 DSH/Cordis 式插件注册、动态 Settings section、Plugin SDK、插件市场或外部 JavaScript；
- 不把 Skills、MCP、Model 合并成“插件”。它们继续保留现有独立领域边界；
- 不提供任意 JSON Pointer、任意文件路径或任意环境变量编辑能力；
- 不在浏览器返回已有 API key、Authorization/Header、cookie、credential value 或环境变量名；
- 不在 v0.3.0 提供 MCP `env/headers` 的 Web CRUD；Inspector 继续只读展示；
- 不伪造 locale 切换。Orion 当前没有完整 i18n 资源，语言设置等 i18n 完成后再加入；
- 不宣称 DSH 使用 SSE，也不复制其 UI、品牌或源码。

### 3.3 后续扩展，不阻塞 v0.3.0

- Provider/model 可视化 CRUD 与 model discovery；
- 独立 `CredentialStore` 的 write-only set/delete API；
- project-scoped tool policy、sandbox 和 agent-loop 高级项；
- locale、键位、状态栏等跨 TUI/Web 偏好；
- 经真实认证后的非 loopback Settings。未实现认证前始终仅绑定 loopback。

## 4. 产品信息架构

Settings 使用静态导航；字段少时移动端退化为单列，不做动态 slot。

| 页面               | v0.3.0 字段/能力                                                                     | 作用域                              | 生效时机                               |
| ------------------ | ------------------------------------------------------------------------------------ | ----------------------------------- | -------------------------------------- |
| General            | Theme：`system/light/dark`；Motion：`system/reduced`                                 | global user                         | `live`                                 |
| Models & Reasoning | 全局默认模型；当前工作区 Effort；当前 Session 模型/effort 只读摘要与“转到会话控制”   | global / project / session-readonly | `new-session` / `next-logical-request` |
| Permissions        | 全局 `toolConfirmation=ask/allow/deny`；硬拒绝与 allowlist 边界说明                  | global                              | Runtime idle 后的下一逻辑请求          |
| Advanced           | 配置状态、last-good/错误、打开配置文件、Provider 凭证 readiness、Skills/MCP 只读入口 | read-only/action                    | n/a                                    |

必须避免两个现有语义错误：

- “当前会话模型”不是“默认模型”。Settings 写 `GlobalConfig.defaultModel`；当前会话仍通过 `/model`
  或会话控制切换，保存默认值不偷偷改正在进行的会话。
- Effort 的 Settings 字段是 active workspace 的 project default。若 Session 已有显式 effort，页面显示
  “被会话覆盖”，并提供转到会话控制，不覆盖该 Session 值。

工具确认保持 Orion 既有的 global + live Runtime 语义，但 Settings mutation 只允许在 Runtime idle 时提交；
选择 `allow` 需要二次确认，并明确“不会越过硬拒绝、sandbox、workspace boundary 或风险上限”。审批
`once/project/global` allowlist 是另一个授权领域，不混入默认策略单选项。

### 4.1 页面状态机

```text
closed
  -> loading
  -> ready(clean)
       -> ready(dirty)
            -> saving
                 -> ready(clean)
                 -> conflict(draft preserved)
                 -> rejected(draft preserved)
       -> stale(auto refresh when clean)
  -> invalid(last-good visible, writes disabled)
  -> unavailable/read-only
```

交互要求：

- 只有 Host-backed 字段进入 dirty；外观也改为 Host-backed 后统一进入原子保存；
- 未修改时禁用按钮；按钮文案为“应用 N 项”；
- 关闭/Escape/遮罩遇到 dirty 时确认丢弃，clean 时直接关闭并恢复触发器焦点；
- conflict 内联展示“服务器最新值 / 我的草稿”，提供“采用服务器值”和“基于最新值重试”；
- `runtime_busy` 预先禁用相关字段并解释，不得误报为 revision conflict；
- invalid external edit 时展示 last-good，只允许刷新/打开文档，不允许覆盖坏文件；
- 成功、冲突和错误都在 dialog 内用 `role=status/alert` 宣告，不依赖 dialog 外 toast。

## 5. 目标领域模型

### 5.1 单一配置真源与覆盖链

继续使用 `$ORION_CODE_CONFIG_DIR/orion.json`：

```text
internal/model default
  -> GlobalConfig (orion.json root)
  -> ProjectConfig (orion.json.projects[canonical active workspace])
  -> Session override / current Runtime state
```

v0.3.0 新增：

```ts
interface WebAppearanceConfigV1 {
  theme?: 'system' | 'light' | 'dark';
  motion?: 'system' | 'reduced';
}

interface GlobalConfig {
  web?: { appearance?: WebAppearanceConfigV1 };
}
```

字段到现有存储的映射：

| Settings key                   | 持久化位置                              | effective 解析                                        |
| ------------------------------ | --------------------------------------- | ----------------------------------------------------- |
| `appearance.theme`             | `web.appearance.theme`                  | explicit global → `system`                            |
| `appearance.motion`            | `web.appearance.motion`                 | explicit global → `system`                            |
| `defaults.model`               | `defaultModel`                          | explicit global → internal default                    |
| `defaults.effort`              | `projects[activeProject].defaultEffort` | session → project → global → model capability default |
| `permissions.toolConfirmation` | `toolConfirmation`                      | explicit global → internal default                    |

Settings API 不暴露 `projects[/absolute/path]`。Host 根据已激活且 canonicalized 的 workspace 解析 project key，
避免客户端构造跨 workspace 写入。

### 5.2 字段描述

```ts
type SettingsSourceV1 = 'internal' | 'model' | 'global' | 'project' | 'session';
type SettingsScopeV1 = 'global' | 'project' | 'session';
type SettingsAppliesV1 = 'live' | 'next-logical-request' | 'new-session' | 'restart';

interface SettingsFieldViewV1<T> {
  effectiveValue: T;
  explicitValue?: T;
  inheritedValue?: T;
  source: SettingsSourceV1;
  scope: SettingsScopeV1;
  applies: SettingsAppliesV1;
  overridden: boolean;
  writable: boolean;
  blockedReason?: 'runtime_busy' | 'read_only' | 'invalid_document';
}
```

`explicitValue` 只适用于非秘密字段。Provider credential 仅返回：

```ts
interface CredentialSlotViewV1 {
  providerId: string;
  state: 'ready' | 'missing' | 'unavailable';
  source: 'environment' | 'legacy' | 'none';
  writable: false; // v0.3.0 Web 不写 secret
}
```

不得返回具体环境变量名、密钥长度、前后缀或可用于枚举凭证的信息。

### 5.3 持久 revision

现有内存整数替换为不透明、带本机密钥的字符串：

```text
revision = "hmac-sha256:" + HMAC-SHA256(local revision key, exact current orion.json bytes)
```

- revision key 是独立的 32-byte 随机值，保存为配置目录内 0600 文件；它不是设置真源，也不得进入
  API、日志、trace 或错误消息；
- 文件不存在时，对明确的 `missing-document-v1` sentinel 计算 revision；
- revision 在 Host 重启后稳定，并可发现任何外部字节变化；
- 客户端只做相等比较，不解析或递增；
- mutation 在持有文件锁后重新读取并计算 revision，再比较 `expectedRevision`；
- 不把 revision 写进 `orion.json`，避免手工编辑忘记递增；
- 不直接把含凭证文档的裸 SHA-256 暴露给浏览器，避免形成低熵秘密的离线猜测 oracle；
- watcher 只用于快速失效，正确性来自每次锁内重读和 CAS。

## 6. 写入与运行时一致性

### 6.1 `SettingsCoordinatorV1`

新增唯一协调链：

```text
Web/TUI/command
  -> SettingsCoordinatorV1.prepare()
  -> in-process serialized queue
  -> withFileLockSync(orion.json)
       -> strict reread + exact-byte revision
       -> expectedRevision CAS
       -> apply bounded typed operations to raw clone
       -> validate full candidate + model registry
       -> atomicWriteFileSync(mode=0600, fsync=true)
  -> apply prepared Runtime transition
  -> emit settings_invalidated
```

关键不变量：

1. 所有持久设置写入口都调用 Coordinator。`/settings`、`/model --default`、
   `/effort --project|--global`、`permission_mode_change` 不再各自直接写文件；
2. 普通 `/model <id>` 仍是 Session 控制，不改 default settings，但必须更新 Session metadata；
3. 一个 PATCH 的全部 operations 在同一次锁与一次 atomic rename 中提交；
4. 候选文档严格校验失败时零写入；未知设置 key、越界值、重复 key、超限 operation 均 400；
5. 初次读取就是非法 JSON 时 fail closed，不能沿用 `loadGlobalConfig()` 的“静默回默认值”路径覆盖原文件；
6. watcher 遇到非法外部编辑时保留 last-good Runtime，发布诊断并禁用 Web 写入；
7. write queue 的一次失败不能 poison 后续请求；
8. requestId 幂等缓存仍校验 body digest；同 requestId 不同 body 返回 409。

### 6.2 prepare → persist → apply

- `prepare` 验证 model 是否存在、Effort 是否受当前 model 支持、Runtime 是否 idle，并构造新配置和
  Runtime transition，不产生副作用；
- `persist` 在锁内 CAS 后一次写盘；
- `apply` 更新共享 runtime config/store，并在需要时 rebind Session Runtime；
- apply 失败时，仅在磁盘 revision 仍等于刚提交 revision 时用 CAS 恢复旧字节；若期间出现外部写入，
  进入 `settings_recovery_required`，暂停新的 agent turn 并要求 reload，不覆盖第三方更改；
- tool policy 变更必须同步重建/刷新 ExecutionPolicy 投影，保证实际行为与 durable receipt 的 policy
  digest 一致；
- project Effort 必须接入 `product-bootstrap.ts`，启动解析与 `/effort status` 使用同一 resolver。

### 7.2 原子 mutation

`PATCH /api/v1/settings`

```ts
interface UpdateSettingsRequestV1 {
  requestId: string; // UUID
  expectedRevision: string;
  operations: readonly SettingsOperationV1[]; // 1..20, total body <= 64 KiB
}

type SettingsOperationV1 =
  | { op: 'set'; key: 'appearance.theme'; value: 'system' | 'light' | 'dark' }
  | { op: 'unset'; key: 'appearance.theme' }
  | { op: 'set'; key: 'appearance.motion'; value: 'system' | 'reduced' }
  | { op: 'unset'; key: 'appearance.motion' }
  | { op: 'set'; key: 'defaults.model'; value: string }
  | { op: 'unset'; key: 'defaults.model' }
  | { op: 'set'; key: 'defaults.effort'; value: EffortPreference }
  | { op: 'unset'; key: 'defaults.effort' }
  | { op: 'set'; key: 'permissions.toolConfirmation'; value: 'ask' | 'allow' | 'deny' }
  | { op: 'unset'; key: 'permissions.toolConfirmation' };
```

同一 key 在一个请求中只能出现一次。`unset` 恢复继承，不把当前 effective value 写成新的 override。
成功返回 `{requestId, revision, appliedKeys, settings}`，exact retry 返回第一次的相同结果。

### 7.3 Problem codes

| HTTP | code                         | 语义                                   |
| ---- | ---------------------------- | -------------------------------------- |
| 400  | `settings_invalid_operation` | key/value/数量/组合非法                |
| 403  | `settings_write_forbidden`   | nonce/origin/loopback/read-only 失败   |
| 409  | `settings_revision_conflict` | 文件 revision 已变化，零字段提交       |
| 409  | `request_id_conflict`        | 同 requestId、不同 body                |
| 409  | `runtime_busy`               | 当前 turn/transition 不允许应用        |
| 422  | `settings_rejected`          | 候选文档或 model/effort 语义校验失败   |
| 503  | `settings_document_invalid`  | 外部文件非法；last-good 可读、写入禁用 |
| 503  | `settings_recovery_required` | persist 后 Runtime apply 无法安全收敛  |

客户端必须按 `code` 分支，不再把所有 409 解释成并发冲突。

### 7.4 Pathless advanced action

`POST /api/v1/settings/open-document`

- body 只有 `requestId`；
- 只在 loopback Host 开启；
- Server 自己解析 `getGlobalConfigPath()` 并调用受控 native opener；
- 不接受 path，不在响应或日志返回 path；
- 无文档时可创建权限 0600 的最小合法模板，创建同样走 Coordinator/CAS。

### 7.5 SSE invalidation

扩展 `WebEventEnvelope` 的判别联合：

```ts
interface SettingsInvalidatedEventV1 {
  type: 'settings_invalidated';
  eventId: string;
  cursor: number;
  durable: false;
  payload: {
    revision: string;
    reason: 'local-write' | 'external-edit' | 'workspace-change';
    state: 'ready' | 'invalid';
  };
}
```

事件不携带值、operation、绝对路径或秘密。SSE cursor 只负责连接内去重；断线/丢事件/Host 重启后的
最终真相始终由 `GET /bootstrap` + `GET /settings` 恢复。

## 8. Browser SettingsMirror 与草稿

新增 `web/src/settings/`，不要继续把 Settings 生命周期散落在 `App.tsx`、Dialog local state 和
`useWorkbench.ts`：

```text
SettingsMirror
  - one shared Host snapshot
  - one in-flight read + rerun flag + generation guard
  - last-good preservation
  - settings_invalidated / connection reset refresh

SettingsDraft
  - openedAtRevision
  - base values
  - typed operations
  - dirty keys
  - server-latest snapshot on conflict
```

规则：

- 打开 dialog 时从 Mirror hydrate 草稿；切 workspace 清空旧草稿；
- clean 状态收到 invalidation：合并重复刷新并自动采用新快照；
- dirty 状态收到 invalidation：抓取最新快照，保留草稿并进入 conflict-pending；
- 保存只发送一次 batch PATCH；成功后把服务端响应直接 fold 到 Mirror，防止旧 GET 覆盖新值；
- 409 revision conflict 不丢草稿；rebase 后仅重试用户仍确认的 key；
- Host 重启后的 Recover 必须重新 bootstrap 取得新 nonce，再取 settings，不能只刷新 session snapshot；
- localStorage migration：若 Host appearance 没有显式值而 legacy localStorage 有值，以一次 CAS batch
  导入；确认落盘后删除 legacy key。Host 已有值时 Host 获胜并清理 legacy key。

| 风险                           | 缓解                                                     | 回滚策略                                               |
