## 结论

1. **service 层一致性成立**：同一 repository revision 下，Git status 与 Review snapshot 的 total/staged/unstaged/untracked 计数完全一致（Review 分页修复后按页聚合正确）。
2. **计划 §2.1 记录的「页面 Git=7 而 Review=0」未在 service 层复现** → 根因指向 **浏览器 UI 层数据源分叉**，候选：
   - ReviewPanel 渲染以「验证收据/verification」为先决条件（v0.3.8 时收据扫描曾阻塞首屏约 7s；收据空/失败时 UI 落入「没有待审阅变更」分支，而 GitPanel 独立拉取正常）；
   - 或两面板在非同一 repository revision 时刻分别请求（请求间发生文件变更），UI 无 stale 合并防护。
3. **后续动作**：S1 引入 `WorkspaceRepositorySnapshotStore` 后，ReviewPanel 必须消费与 GitPanel 相同的 snapshot（同一 revision 主键）；Review 摘要与验证收据解耦渐进加载；并在真实 Host + Playwright 用「空收据仓库」复现该 UI 分支，加截图/断言回归。
