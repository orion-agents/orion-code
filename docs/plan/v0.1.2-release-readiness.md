## 1. 结论

RC2～RC18 均为已被后续修复取代、独立审查否决或主动失效的历史候选。RC18 关闭了
external assertion、Print shutdown 与多目标解析等缺口，但后续对 Goal 存储一致性、
controller mutation fail-closed、deletion fence 和 subagent scope 的审查又改变了
source/package input。因此 RC18 的临时 source 路径、测试计数、coverage 和 package hash 仅作历史
diagnostic evidence，不能关闭当前候选或最终发布 Gate。

当前工作树是 **pre-commit candidate**，不是 immutable merge artifact。当前候选已有以下阶段证据：

- build 和 lint 通过，lint 为 0 errors / 136 warnings；
- 38 suites / 869 tests 聚焦回归通过；Node 22 全量为 175 passed / 1 skipped suites、
  2943 passed / 2 skipped tests；
- 两次 byte-identical pack、clean-prefix install 与安装 runner identity 校验；
- identity-bound 默认 TUI、technical terminal-ui 和完整 Goal lifecycle PTY；
- 当前安装包 PTY；
- 复验 RC7 Verdaccio 回环 registry 的 v0.1.2→v0.1.1 rollback 流程证据；
- installed runner、package 与显式 staging boundary 的本地证据。

当前 Node 20/24 clean matrix、full-source coverage、有效并发 fixture stress、Node 20 `prepublishOnly`
与 publish dry-run 仍待从最终候选重放。真实 macOS Terminal 人工验收、用户登录 zsh PATH、
最终 merge artifact、远端
push/PR/CI/review/merge/tag/GitHub Release、npm actual publish 与发布后 registry install 仍无最终证据。
因此当前仍是可复验的本地候选，不是发布完成声明。

## 5. 回滚

发布前只允许在隔离 registry 演练，不能修改生产 npm 的 `latest` 或 deprecate 正常版本。真实回滚
必须具备独立写授权，并执行：

```bash
npm deprecate @orion-agents/orion-code@0.1.2 "Release blocked; use 0.1.1 or the next fixed release"
npm dist-tag add @orion-agents/orion-code@0.1.1 latest
npm view @orion-agents/orion-code dist-tags --json
npm view @orion-agents/orion-code@latest version
npm install -g @orion-agents/orion-code@0.1.1
```

回滚前必须先用 fence-aware 的 v0.1.2 `/doctor` 检查并备份 Goal sidecar、quarantine 文件及
`*.goal.json.deleted`。v0.1.1 reader/writer compatibility 只验证了**没有删除栅栏的 additive live
sidecar**；v0.1.1 不理解 deletion fence，可能把已删除 Goal 当作 revision-zero 新建。因此只要任一 fence
存在，在原配置目录执行 v0.1.1 Goal 写入就是 **NO-GO**，必须先由 fence-aware 版本只读检查并人工协调，
或让旧版使用不接触原 Goal 存储的隔离配置目录。malformed fence 或 live/fence collision 不得自动删除、
覆盖或二选一。v0.1.2 新增的 criteria/evidence UI 在旧版不可见，但原始数据不得删除。

registry state 和 fresh install 都证明 0.1.1，只能证明 registry/package rollback；它不能证明已有本地 Goal
数据可安全降级。数据回滚还必须证明目标配置目录不存在未协调的 deletion fence。
