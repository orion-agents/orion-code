## 1. 版本决策与用户价值

v0.3.27–v0.3.30 建立了专业审查回路的契约、CLI 运行时、Web 共享闭环与文档对齐，
但发布收据链路存在两处事实缺口：

1. **v0.3.30 证据的发布链路段是占位符。** `docs/plan/evidence/v0.3.30/qualification.md`
   的「发布链路（合并后回填）」段落仍为「待填」（PR / squash 合并提交 / 精确 tgz /
   registry 确认），而事实均已发生：PR #286、merge commit `15887f5`、tag `v0.3.30`、
   npm registry `latest=0.3.30`。证据文件停留在未回填状态会削弱「完成结论绑定当前
   证据」的项目纪律。
2. **CHANGELOG 交付状态漂移。** main 上 CHANGELOG 的 0.3.30 条目仍为
   `Status: candidate`，而 tag `v0.3.30` 与 npm `latest=0.3.30` 均已存在（2026-10-22
   发布），需按事实更新为 `published`。

v0.3.31 交付上述两项回填，并顺带完成一次 **近三版（0.3.28–0.3.30）交付状态审计**：
以 registry 直连查询与 git tag 交叉核对每版的「tag 存在 + npm 版本存在 + dist-tag
latest 指向」三项，审计结果写入本轮证据文件，作为 G1 证据纪律的周期性检查样例。

**本版明确不做（仍属 PR4 剩余项，待有凭据环境）：** 人工标注付费质量评测（12 缺陷

- 8 干净样本、3 轮运行）、真实模型全链路验收、TurnCommit 收据投影与跨重启恢复、
  `start_code_review` 协议命令化、finding Context 结构化注入。
