## 1. 版本决策与用户价值

v0.3.27–v0.3.29 交付了专业审查回路的契约、CLI 运行时与 Web 共享闭环，但存在三类
资格缺口：

1. **公开文档落后于实现。** 项目级目标 §8 已指出：README 中「Files／Git／Review
   只读」与「多项目不创建多个 Runtime」的概括已落后于当前实现（Files 支持带 CAS
   的文本编辑、Git 支持暂存/hunk/本地提交/历史、Review 支持发起共享审查运行；
   Host 使用有界 Session actor 池而非单 Runtime）。
2. **审查回路缺少一份使用与语义文档。** CLI `/review` 与 Web 审查运行的选择器、
   预算（tighten-only）、receipt digest、stale 语义、状态横幅与已知边界分散在
   plan 与 CHANGELOG 中，用户没有单一入口。
3. **发布状态漂移。** main 上 CHANGELOG 的 0.3.29 条目仍为 `candidate`，而 tag
   `v0.3.29` 与 npm `latest` 均已存在，需按事实更新为 `published`。

v0.3.30 交付上述三项；资格验证中的 exact-tarball 与全量回归由既有 CI gate
（exact tgz ×3 平台、full suite 三连绿）承载，本地记录构建证据。

**本版明确不做（仍属 PR4 剩余项，待有凭据环境）：** 人工标注付费质量评测
（12+8 样本、3 轮运行）、真实模型全链路验收、TurnCommit 收据投影与跨重启恢复、
`start_code_review` 协议命令化、finding Context 结构化注入。

## 2. 任务分解

### S1 README 对齐 — `README.md`、`README.zh-CN.md`

- 「Files, Git and Review are read-only」→ 如实描述：Files 提供带 CAS 冲突检测的
  文本编辑（512KiB 上限）；Git 提供暂存、hunk/行反馈、本地提交与历史读取；Review
  支持发起共享审查运行并查看 digest 可验证的 findings。push/reset/discard 等远端
  与破坏性操作仍未开放，属独立能力设计。
- 「The project navigator does not create multiple runtimes」→ 更新为 Host 级
  有界 Session actor 池（默认 3 个运行 / 4 个常驻）表述；跨项目 Session 选择仍是
  一次带 revision guard 的原子 Context 切换，UI 不拥有执行事实。
- 中英文同步；不改版本号以外的首部摘要（由 S4 统一 bump）。
- 验收：两文件表述与当前实现一致；不引入未交付能力的承诺。

### S2 审查回路文档 — `docs/architecture/code-review-loop.md`（新增）

- 覆盖：范围选择器（worktree / base）、只读 workflow 约束、tighten-only 预算、
  单轮有界补全、契约校验与 receipt digest 复核、stale 判定（repositoryRevision）、
  状态语义（completed / partial / failed / cancelled / stale 永不渲染为绿色通过）、
  Web 单飞与 409/422、Host 重启后审查历史不保留、finding → diff 定位 → Composer
  草稿（用户确认提交）。

## 5. 风险

| 风险                               | 控制                                                                                         |
| ---------------------------------- | -------------------------------------------------------------------------------------------- |
| README 新表述过度承诺未交付能力    | 只描述已实现行为；远端/破坏性 Git 操作与 IDE 能力保持「未开放」声明                          |
