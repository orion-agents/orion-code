## 1. 版本结论

### 1.1 一句话目标

将当前“功能已多、控制面分散”的 46 条 slash command 收敛为 TUI 优先、运行时共享、可发现、
可迁移的命令系统，并实现 provider-aware 的 `/effort`：用户能看到当前模型支持什么、设置什么、
请求实际发送什么，以及不支持或 fallback 时发生了什么。

### 1.2 为什么 v0.1.5 优先做这两项

项目 Goal 的当前阶段要求“公开能力与真实行为一致”。现状中两条关键链路仍未闭合：

1. **命令是主要控制面，但还不是单一协议。** Help、palette 和 completion 已读取同一注册表的
   一部分信息，业务 handler 仍大量直接写 `console.*`，runtime 再通过全局 monkey-patch 捕获 stdout；
   TUI 还有 `/permissions`、`/tool-output`、`/redraw` 私有执行分支。
2. **模型已有 `reasoning?: boolean`，但没有 effort 行为。** 当前请求统一走 OpenAI SDK 的
   `chat.completions.create()`，没有 reasoning/effort 参数、能力级别、作用域、session 恢复、fallback
   解析、reasoning token 记账或 renderer event。

因此，本版不以“再增加若干命令”为成功标准，而以以下闭环为成功标准：

```text
统一 CommandDescriptor
  → TUI palette / help / completion / docs
  → shared runtime invocation
  → structured CommandResult / AgentRuntimeEvent
  → renderer projection

Effort preference
  → model capability resolution
  → immutable logical-request snapshot
  → provider adapter payload
  → usage / fallback / error evidence
  → session resume 与 TUI/Print 可见状态
```

### 1.3 目标映射

| 项目目标                  | v0.1.5 对应结果                                                                                       |
| ------------------------- | ----------------------------------------------------------------------------------------------------- |
| G1 目标忠实度             | `/target`、计划、研究、验证等工作流入口不再被旧 `/task`、`/run` 语义稀释；effort 不改变 Goal 完成标准 |
| G2 安全自主               | 命令参数、风险、side effect、确认和可用性进入同一 descriptor；`/permissions` 不再由 TUI 私有执行      |
| G3 TUI 主产品、单一运行时 | TUI 是完整交互入口，terminal-ui 只做技术 parity，Print/JSON 消费同一结构化结果                        |
| G4 终端原生体验           | `/` palette 支持 CJK、窄屏、resize、参数补全和稳定键盘语义，并经真实 PTY 验证                         |
| G5 Provider 可替换        | effort 由 model capability + provider adapter 解析，不能把某厂商参数硬编码到公共 runtime              |
| G6 本地优先、可恢复       | effort scope、session 元数据和 usage ledger 采用可选字段/追加迁移，旧数据不被重写                     |

- [Codex config reference](https://developers.openai.com/codex/config-reference) 将
  `model_reasoning_effort` 建模为模型相关能力；当前文档明确其对支持的 Responses API 模型生效。

## 4. 当前命令审计与收敛决定

### 4.1 审计规则

每个当前 command 进入以下一种状态：

- **keep**：名称、语义和风险都清晰，继续作为产品入口；
- **merge**：能力保留，但并入一个 domain command/subcommand；
- **advanced**：仍可执行，但退出默认 palette，只在搜索或 `/help --all` 中出现；
- **compat**：从 canonical registry 移除，只保留带期限的解析 shim；
- **add**：存在真实 runtime 能力或本版会闭合完整链路后再新增。

兼容 shim 不计入公开命令数量，也不进入 help、palette、completion 或生成文档；精确调用时必须发出
结构化 deprecation warning。既有 `removeIn: v0.3.0` 不在 v0.1.5 偷跑删除。

### 4.3 本版明确不新增的市场常见命令

以下能力有价值，但本版不应为追赶命令数量而加入：

- `/plan`：必须先有共享、可持久化、可更新的 typed plan artifact；不能把当前 read-only permission
  mode 包装成“计划能力”。
- `/init`：生成项目指令会写仓库，需单独设计 merge/preview/ownership 合同。
- `/copy`、`/theme`、`/vim`、`/terminal-setup`：属于体验增强，排在命令语义与 effort 可靠性之后。
- `/plugins`、`/hooks`：需稳定的扩展生命周期、信任和审计协议，不在 v0.1.5 扩大安全面。
- `/background`、`/batch`、`/worktree`、定时任务：属于 v0.2 多目标/跨 Session runtime。
- `!` shell mode：直接执行 shell 会扩大绕过 tool permission/sandbox 的风险；本版拒绝。

## 5. 目标命令平台设计

### 5.1 单一 CommandDescriptor

注册表从“带 execute 函数的展示数组”升级为可生成 UI、协议、测试和文档的合同：

```ts
type CommandAudience = 'primary' | 'advanced' | 'compatibility' | 'internal';
type CommandExecution = 'runtime' | 'agent-workflow' | 'renderer-view';

interface CommandAlias {
  name: string;
  since?: string;
  deprecatedSince?: string;
  removeIn?: string;
  replacement?: string;
}

interface CommandDescriptor {
  id: string;
  name: string;
  aliases: CommandAlias[];
  title: string;
  description: string;
  category: CommandCategory;
  audience: CommandAudience;
  execution: CommandExecution;
  risk: CommandRisk;
  arguments: CommandArgumentSpec[];
  subcommands?: CommandSubcommandSpec[];
  rendererCapabilities?: string[];
  requiredCapabilities?: string[];
  sideEffects: CommandSideEffect[];
  lifecycle: { since: string; deprecatedSince?: string; removeIn?: string };
  handlerId: string;
}
```

约束：

1. built-in descriptor 不允许缺失 execution、risk、audience、sideEffects 或 lifecycle。
2. alias 与 subcommand 也有独立 deprecation/usage，不再只能给整个 command 标 deprecated。
3. availability 由可序列化 capability key + runtime resolver 共同决定，不能只存在无法生成文档的闭包。
4. workflow、skill、MCP prompt 可以扩展 registry，但必须声明 source、risk、作用域和命名冲突策略。
5. destructive command 不得作为空 `/` 的默认首屏项；搜索到时显示风险和确认要求。

### 5.2 Typed 参数与 palette

TUI `/` palette 在 v0.1.5 必须支持：

- 空 `/`：按 category 展示 primary command，最多 10 行，支持 PageUp/PageDown；
- 输入命令：name、alias、description、category 的 token/fuzzy 匹配，不只做 prefix；
- 输入空格后：切换到 subcommand/argument suggestion，不再继续展示整条 command 列表；
- enum、model、effort、session、path 等参数使用 typed candidate provider；
- unavailable item 保留可发现性但 disabled，并显示原因；internal/compat 不进入普通 palette；
- destructive、deprecated、scope、provider/extension source 使用简短 badge；
- Enter 只执行完整且可用的 invocation；缺参时补全或显示 usage，不靠 command-name 正则特判；
- Esc 关闭、Tab 补全、上下键导航、resize、CJK 光标与 paste 行为保持稳定。

TUI 可提供丰富 picker；terminal-ui 只实现同一 descriptor 的基础 completion/smoke；Print/Text 和
Print/JSON 对需要 picker 的 command 返回候选与 machine-readable next action，不等待交互输入。

### 5.3 Structured CommandResult

本版移除 `captureConsoleOutput()` 的产品依赖，不再在并发 runtime 中改写全局 `console`：

```ts
interface CommandResult {
  status: 'ok' | 'error' | 'cancelled';
  summary?: string;
  blocks: CommandResultBlock[];
  warnings?: CommandWarning[];
  picker?: CommandPickerRequest;
  effect?: CommandEffect;
  nextActions?: CommandNextAction[];
}
```

- handler 返回纯数据；format/color/layout 由 renderer 完成；
- runtime 发出 `command_started`、`command_completed`、`command_failed`、`command_deprecated` 等事件；
- command output 是否写 transcript 由 protocol policy 决定，不能由 `console.log` 的存在与否决定；
- error、cancel、unavailable 和 confirmation-required 是不同状态；
- 为外部客户端预留 command descriptor snapshot，但本版不承诺稳定 SDK。

允许按 slice 迁移 handler，但 **v0.1.5 GO 前所有 primary command 必须脱离全局 console capture**；
advanced/compat handler 若暂时保留 adapter，必须列入有 owner 和 v0.2 删除期限的例外清单。

## 6. Effort 能力设计

### 6.1 用户合同

```text
/effort
/effort status
/effort <auto|none|minimal|low|medium|high|xhigh|max>
/effort <level> --project
/effort <level> --global
```

- `/effort`：TUI 打开 active model 实际支持级别的 picker；非交互 renderer 输出状态和合法值。
- 默认作用域是当前 session；`--project` 和 `--global` 是显式持久化写入。
- `/reasoning` 是 active alias，不复制实现。
- `auto` 表示删除该作用域 override，回到下一级配置或 model/provider default。
- `max` 是行为信号，不是“无限 token”；Goal budget、loop budget、max output 和安全权限仍独立生效。
- active model 不支持 effort 时 command 为 unavailable，必须说明 provider/protocol/model 和恢复路径。

### 6.2 公共类型

```ts
type EffortLevel = 'none' | 'minimal' | 'low' | 'medium' | 'high' | 'xhigh' | 'max';
type EffortPreference = 'auto' | EffortLevel;

interface ReasoningCapability {
  kind: 'effort-level' | 'thinking-level' | 'thinking-budget';
  supportedLevels: EffortLevel[];
  defaultLevel?: EffortLevel;
  adapter: EffortAdapterId;
  source: 'config' | 'discovery' | 'builtin';
}

interface ResolvedEffort {
  requested: EffortPreference;
  effective?: EffortLevel;
  source: 'request' | 'session' | 'project' | 'global' | 'model-default' | 'provider-default';
  capabilitySource?: ReasoningCapability['source'];
  supported: boolean;
  warning?: string;
}
```

迁移 `ModelProfile.reasoning?: boolean` 时保持向后读取：

- `false/undefined` 不推断支持；
- legacy `true` 只表示“可能支持 reasoning”，不能自动选择 wire parameter；`/effort` 显示为
  `unavailable: capability levels/adapter not configured`；
- 新 `reasoningCapability` 优先级遵循 config > discovery > builtin；不能仅凭模型名称 fuzzy 猜测。

### 6.3 配置与作用域

建议优先级（高到低）：

1. 当前 logical request 的显式 override（Print/SDK 边界，交互 CLI 暂不暴露）；
2. session `/effort` 或启动参数 `--effort`；
3. `ProjectConfig.defaultEffort`；
4. `GlobalConfig.defaultEffort`；
5. model profile / provider default，即 `auto`。

持久化字段均为可选：

- `GlobalConfig.defaultEffort?: EffortPreference`；
- `ProjectConfig.defaultEffort?: EffortPreference`；
- `SessionMeta.effortPreference?: EffortPreference`；
- runtime/store 保存 `requested` 与 `effective`，但不持久化厂商 wire payload。

旧 config/session 无字段时行为与 v0.1.4 完全一致：不发送 effort 参数。sanitize、schema、示例和
doctor 必须同时更新；未知/非法值 fail closed，并给出精确路径。

### 6.4 Provider adapter

当前 `LLMService` 无论 provider protocol 都调用 `chat.completions.create()`，这是 effort 实现的前置
架构缺口。本版增加 immutable `ProviderRequestContext` 与协议 adapter：

| Adapter                   | v0.1.5 状态      | Wire contract                                                                                                                |
| ------------------------- | ---------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `openai-responses`        | P0 stable target | 按 active model capability 写 `reasoning.effort`；unsupported level 在发送前拒绝                                             |
| `anthropic-messages`      | P0 stable target | 写 `output_config.effort`；只暴露该模型支持的 low/medium/high/xhigh/max 子集                                                 |
| `openai-completions`      | 默认 unsupported | 官方 OpenAI reasoning effort 不应被盲目塞入 Chat Completions；第三方网关只有显式 profile adapter + characterization 后才发送 |
| `google-generate-content` | P1 conditional   | Gemini 3 映射 `thinkingLevel`；Gemini 2.5 的 `thinkingBudget` 只有 profile 明确 level→budget 表后才启用，不做拍脑袋数值映射  |

每次 logical request 创建后冻结 model/provider/effort/max-output/tool schema；retry 必须复用同一
snapshot，避免用户在重试间改变 payload。`/effort` 在 active turn 中可以被 shared controller 接受，
但只对**下一个 logical request**生效，不改变已发出的请求或其 retry。

### 6.5 Model switch、fallback 与错误

1. `/model` 切换后重新 resolve effort；若 session override 不被新模型支持，显示 structured warning，
   effective 回到 `auto`，requested 值保留供用户选择，不得静默声称仍为 high。
2. 自动 provider/model fallback 也必须用 fallback profile 重新解析；event 同时记录 requested/effective、
   source 和 downgrade reason。
3. 用户显式指定的 effort 被 provider 以 unsupported/invalid parameter 拒绝时，不自动删除参数重试；
   返回 `unsupported_effort`，提示 `/effort auto` 或支持级别。
4. `auto` 默认不发送 provider 参数；provider 自己的实际默认未知时显示 `provider default`，不能猜成
   medium/high。
5. effort 变更可能降低 prompt cache 命中；TUI 在持久 session 中首次切换时给一次非阻塞提示，usage
   记录 cache token 变化但不夸大因果。

### 6.6 用量、状态和事件

扩展 `LLMUsage` / usage ledger：

- `reasoningTokens?: number`（若 provider 单独报告；它是 completion/output 的子集时不得重复计费）；
- `effortRequested?: EffortPreference`；
- `effortEffective?: EffortLevel`；
- `effortSource?: ResolvedEffort['source']`；
- `providerProtocol?: ProviderProtocol`；
- `latencyMs?: number`。

OpenAI 读取 reasoning token detail，Gemini 读取 `thoughtsTokenCount`，Anthropic 未单独报告时保持
undefined。usage ledger 采用 additive schema migration，v1 记录继续可读，不批量重写历史文件。

新增 shared runtime event：

- `effort_changed`：requested、scope、previous、appliesFrom；
- `effort_resolved`：model/provider、effective、source、supported levels；
- `effort_unavailable`：精确原因和恢复路径；
- provider request/usage trace 增加 effective effort，但不写私有 reasoning 内容。

TUI footer 默认显示 `model=<id> effort=<effective|auto>`；`/status` 和 `/usage` 展示 requested/effective
差异。terminal-ui 与 Print/JSON 使用同一字段；Ink 不新增产品 UI。

## 10. 风险与控制

| 风险                                      | 控制                                                                            |
| ----------------------------------------- | ------------------------------------------------------------------------------- |
| 命令重构与 effort 同时改动面过大          | 按 C1/C2/E1/E2 独立 PR，先纵向样板再批量迁移；每个 slice 可单独回滚             |
| 全局 console capture 在并发时串流         | primary handler 全部改为 typed result；增加并发隔离测试，最终删除 capture       |
| `/permissions` 合并破坏安全语义           | 保留 mode 与 confirmation 两个轴；迁移测试覆盖每个组合和 negative side effect   |
| 用户以为 high/max 是硬预算                | UI/文档明确 behavioral signal；hard budgets 单独显示且不自动改写                |
| 静态 catalog 错报 effort 支持             | config/discovery 优先；legacy boolean 不启用 wire；unsupported 发送前拒绝       |
| provider fallback 静默降低 reasoning      | requested/effective 分离，event/trace/status 可见，显式 override 不自动无参重试 |

| dirty worktree 混入版本                   | 冻结范围、逐文件 stage audit、clean clone/package install 重新取证              |

## 11. Go / No-Go 与回滚

### 11.1 Go 条件

- C1～C8、E1～E9 全部有当前 source 对应证据；
- primary command 不再依赖 `captureConsoleOutput()`，TUI 不再私有执行业务 command；
- `/effort` 在 unsupported model 上诚实不可用，在 stable adapter 上有真实 payload 和 live 证据；
- build、lint、全量测试、coverage、Node 矩阵、真实 PTY 全部通过；任何 waiver 有 owner、范围、期限和审批；
- v0.1.4 predecessor、v0.1.5 package version、Banner、help、README、release note、npm metadata 一致；
- tarball clean install、真实 PATH、CI/review/merge/tag/release/publish/registry install 分开记录。

### 11.2 No-Go 条件

出现任一项即停止发布：

- 通过 prompt 文案或静态 boolean 冒充 effort API 已生效；
- unsupported effort 被静默删除、clamp、映射或计为成功；
- command handler 输出串到另一个 session/turn/subagent；
- destructive/配置写入命令绕过 shared preview/confirm；
- TUI、terminal-ui、Print 对 command 或 effort 产生不同业务结果；
- 旧 command 被提前删除且无 compat window；
- 只有 mock/dirty worktree/local partial tests，没有最终 source、PTY、package 或 live provider 证据。

### 11.3 回滚

1. effort provider 参数由单一 feature gate 控制；出现 provider 回归时可关闭参数注入，保留 config/session
   字段只读并显示 `temporarily unavailable`，不能假装仍生效。
2. command migration 每个 domain 保留旧名 compat map；回滚新 palette 时不回滚 shared runtime 的安全修复。
3. config/session/usage 都是 additive；旧二进制可忽略新字段，无需破坏性降级脚本。
4. npm 回滚发布前先停止 tag/publish；已发布时发布修复版本，不覆盖 registry 历史版本。

## 12. Definition of Done

v0.1.5 只有在以下结论都能被证据证明时才算完成：

1. 用户在 TUI 输入 `/` 能快速找到当前真正可用的控制入口，参数、风险、scope 和不可用原因清晰；
2. 过时、重复和误导命令已按迁移表收敛，旧调用有期限但不再污染产品 palette；
3. Help、palette、completion、文档和外部 command snapshot 来自同一 descriptor；
4. command 业务处理不直接控制 stdout，所有 renderer 消费同一 runtime result/event；
5. `/effort` 从用户选择贯通到 active provider request，并能用 payload/usage/trace 证明实际 effective 值；
6. model switch、fallback、unsupported、retry、abort、resume 和 config write failure 都有确定行为与测试；
7. effort 不绕过 Goal budget、loop budget、权限、安全确认或完成审计；
8. 最终 clean source 通过质量、PTY、provider、package、发布和回滚 gate，没有把计划、局部实现或本地测试
   误报为已发布能力。
