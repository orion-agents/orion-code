- 版本：v0.3.5
- 状态：Implementation in progress
- 日期：2026-09-02

- 目标：修复旧 Thread 快照误报损坏、会话切换假重连和跨项目 Runtime 中断，并交付可真实安装验证的 v0.3.5

## 1. 决策摘要

v0.3.5 是 Web Workbench 的会话连续性与运行时所有权修复版本。它不新增云端、多用户或
Agent 能力，而是让现有多 Session 架构达到以下产品语义：

1. v0.3.2 生成的 `threads-v2` cutover 可以在 v0.3.5 安全读取；旧摘要兼容不等于跳过
   event hash、projection hash 或 cutover identity 校验；
2. 浏览器到本地 Web Host 的 SSE 连接、当前 Session 快照同步、Session Runtime 生命周期是
   三个独立状态；任一 Session 快照失败不得伪造 Host 重连；
3. 同 Workspace 切换仅加载或刷新有界快照，不创建 Session actor、不连接 provider、不重载
   catalog、不重启 SSE；缓存命中先显示再校验；
4. 跨 Workspace 切换不得关闭其他 Workspace 中仍运行、排队或等待批准的 Session actor；
5. 页面只把 SSE 称为“本地 Host 连接”，不再把传输连接误称为模型 Runtime；
6. 安装、常驻启动、PR、合并、tag 与 npm publish 是彼此独立的交付门禁。

## 2. 已确认根因

### 2.1 旧 cutover 被误报损坏

`ThreadProjectionV1.version` 仍为 `1`，但 v0.3.3 新增的 `diagnosticEvents` 与
`compactEvents` 被无条件纳入 projection digest。v0.3.2 cutover 保存的是不含这两个字段的
旧摘要。因此：

- 同一事件前缀的 `eventDigest` 仍完全匹配；
- 用当前 projection 形状重算的 digest 与旧 `projectionDigest` 不同；
- `verifyDurablePrefix()` 将已验证历史误判为
  `ORION_THREAD_CUTOVER_INDEX_CORRUPT`；
- Web 500 边界再把原始错误隐藏为 `The local Web Workbench request failed.`。

真实数据只读复现中，`ba90c8e4…` 与 `56073576…` 都满足“event digest 匹配、仅 projection
shape digest 不匹配”；精确移除新增的两个字段后，摘要与旧 cutover 逐字节一致。

### 2.2 Session 快照错误污染 Host 连接状态

`snapshot_failed` 当前把全局 `connection` 设成 `replay-required`。随后正常 Session 快照把它
改为 `connecting`，但既有 SSE 并没有重建，也不会再次发出 `live`，从而出现：

- 底栏永久显示“正在连接”；
- Composer、Goal 和命令入口被错误禁用；
- 已恢复的会话仍保留上一会话的“刷新失败”通知；
- 用户看到的“Runtime 激活”其实是状态机串线。

### 2.3 切换路径仍有不必要等待

- 同 Workspace：前端先 `reset_session_view`，缓存未命中时清空内容，再等待 snapshot；实测正常
  snapshot 约 217–350 ms，返回 `phase=cold`、`runtime.active=false`。
- 跨 Workspace：Host 仍只有一个 active Workspace control Runtime。当前 Context 与目标项目不同时，
  `activateContext()` 会 shutdown registry/runtime 后重新安装 Runtime，造成真实等待，并中断跨项目并行。
- 当前进程虽以 `--cwd /Users/hope/ai-project/orion-code` 启动，但 Host Context 已被其他页面切到
  `/Users/hope`；点击 `orion-code` Session 因而属于跨 Workspace 切换。

## 4. 架构合同

### 4.1 Projection digest 独立版本化

新增显式 `projectionDigestVersion`：

- `1`：v0.3.2 core shape，不包含 `diagnosticEvents`、`compactEvents`；
- `2`：当前完整 shape，包含上述字段；
- 旧 entry 没有版本字段时，只允许从权威 event prefix 推导出的两个已知候选中精确匹配；
- 新 cutover 一律写 `projectionDigestVersion: 2`；
- `verifyThreadProjectionDigest()` 仍严格验证磁盘 projection 的实际完整结构；兼容逻辑仅用于验证
  历史 cutover/prefix receipt；
- 读取兼容不得改写 cutover index。派生 projection、head、transcript index 可以从权威 JSONL 重建；
- append 遇到缺少新字段的旧 projection 时，必须先以 `projection_schema_upgrade` 原因扫描完整事件日志，
  不能把“未知历史”升级成空集合。

### 4.2 三层状态机

```text
Web Host transport   connecting | live | reconnecting | offline | replay-required | closed
Session snapshot     idle | loading | refreshing | ready | failed
Session Runtime      cold | starting | idle | queued | running | waiting_approval | stopping | failed
```

约束：

- 只有 SSE gap/replay reset 能设置 transport `replay-required`；
- HTTP snapshot 失败只能设置对应前景 Session 的 `snapshot=failed`；
- 有缓存时 `refreshing` 继续展示缓存，但写操作等最新 CAS snapshot；
- snapshot 重试只请求当前 Session，不重载 Workspace、Settings、Skills、MCP 或 Tool catalog；
- Host 传输文案不得使用“Runtime 已连接”。

### 4.3 Session 切换与缓存

同 Workspace 选择流程：

```text
select Session
  -> browser-local foreground id
  -> cached projection immediately rendered (if present)
  -> bounded tail snapshot in background
  -> CAS identity check
  -> accept current response only when foreground/workspace/context still match
```

- 最近 8 个 Session 的投影缓存继续受 8 MiB 总预算约束；
- baseline 后在空闲阶段预取最近 Session 的有界 tail，最大并发 2；
- 预取错误静默记录为该 Session 的冷缓存缺失，不污染当前 Session 或 transport；
- 10k-message Session 仍只返回一个有界页面，禁止为切换读取完整 transcript/model catalog。

### 4.4 跨 Workspace Runtime 所有权

- `WebSessionRuntimeRegistryV1` 继续是 Host 级有界 actor pool，key 为
  `workspaceId + sessionId`；Workspace Context 切换不得 shutdown/recreate registry；
- 已运行 actor 保留其创建时的 Workspace kernel，直到正常结束或按 LRU 安全驱逐；
- active Workspace control plane 与 Session actor 分离；切换 control plane 不得释放仍被 actor 使用的
  Workspace kernel；
- warm Workspace control plane 可复用，冷 Workspace 首次安装可以异步显示明确的“正在同步项目”，但不能
  显示为 Session Runtime 激活；
- 同一 Workspace 的写工具仍通过 `WorkspaceMutationArbiterV1` 串行化，不同 Workspace 可并行。

### 4.5 错误边界

- 用户响应保持脱敏，但服务端必须记录稳定错误码与不含敏感内容的诊断；
- 已知兼容失败映射为可恢复的 Session snapshot problem，不得使用模糊 `web_internal_error`；
- 恢复按钮按错误域选择“重试 Session 快照”或“重建 SSE baseline”，不得一律执行全量 bootstrap。

## 5. 实施切片

### P0-A：Thread projection 兼容

- 在 `thread-projection.ts` 定义 digest scheme/version 和确定性候选计算；
- 在 `thread-event-store.ts` 的 prefix verify、prefix retain 与旧 projection append 路径接入；
- 在 `legacy-thread-materializer.ts` 写入新 version，并让重复 materialize 对已知旧摘要幂等；
- 增加 v0.3.2 固定 golden fixture，避免测试和实现互相自证；
- Controller snapshot 对已知 materialization 错误提供稳定 problem code。

### P0-B：浏览器状态解耦

- `WorkbenchState` 新增 `sessionSync`，`snapshot_failed` 不再修改 `connection`；
- snapshot 成功/重试清理 Session 域通知；
- `recoverSession()` 根据错误域选择局部 snapshot 或完整 SSE baseline；
- Composer/Conversation/Inspector 写操作同时要求 transport live 与 snapshot ready；
- 将连接文案统一改成“本地 Host”。

### P0-C：即时 Session 切换

- 缓存命中同步渲染，网络刷新不清空会话；
- baseline 后限流预取最近会话；
- 旧响应不得覆盖新的 browser-local foreground；
- 添加切换次数、缓存命中、snapshot latency 和 actor allocation 诊断计数。

### P1-A：跨 Workspace 连续运行

- Context switch 保留 Host 级 Session registry 和非目标 Workspace actors；
- control Runtime 切换与 actor Runtime shutdown 分离；
- shutdown Host 时才统一关闭全部 actors/control planes；
- 增加 A-running → B-select → A-complete 及 approval/queue 回归。

### P1-B：版本与发布卫生

- `package.json`、`npm-shrinkwrap.json` 升级到 `0.3.5`；
- 更新 CHANGELOG、README、docs 索引、E2E 版本断言；
- 修复 `release:check` 对 `codex/vX.Y.Z` / `GITHUB_HEAD_REF` 的版本识别；
- 增加 `format:check` 与 E2E TypeScript CI 门禁；
- 删除 Web 端硬编码 `v0.3.3` fallback，启动阶段显示中性占位。
