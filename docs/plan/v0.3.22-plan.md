## 1. 版本定位与总体目标

主题：**Agent Reliability & Efficiency — 高可信执行与可测量的 Coding Agent 效率提升。**

本版不追求功能数量，围绕四项目标：

1. **执行正确性**：解决潜在重复执行、身份冲突、失败恢复和持久化一致性问题。
2. **执行效率**：减少不必要的模型请求、重复文件读取、无效工具调用和 Token 消耗。
3. **任务完成质量**：用真实编码任务而非模拟工具 Schema 测试衡量 Agent 完成率。
4. **发布质量**：建立可靠 E2E、故障注入与真实安装产物验收机制。

投入比例（规划参考，非强制工时）：30% 执行正确性 / 30% Agent 效率优化 / 25% 测试与发布可靠性
/ 15% 诊断与交互透明度。

### 架构原则

保持现有主干与协议，不重建：

```
CLI / TUI / Web → Product Runtime → ThreadRuntime → AgentLoop → Query → ToolGateway → Tool Execution
```

保留：Thread → Turn → Step → Item 协议；StepSnapshot 的工具选择边界；ToolGateway 的权限与
执行收据机制；Thread Event Store 持久化；Goal/TaskContext 完成审计；Skills/MCP 集成。

明确不新增：第二套 Agent Loop、独立 Multi-Agent Orchestrator、整体 Harness 重写。

## 3. 任务详述

### T22-01：修复 ToolGateway 并发身份冲突（P0）

**涉及源码（已验证）：**

- `src/runtime/tool-gateway.ts:176`（inflight Map）、`:183-191`（invoke 去重）、
  `:188`（finally 清理）、`:193-223`（invokeOnce 与持久化守卫）、`:448-475`（createIntent /
  requestDigest）。
- `tests/tool-gateway.test.ts:211`（既有并发去重）、`:255`（既有完成后冲突）。

**问题（已验证成立）：**

执行未完成时，相同 `invocationId` 但不同 args / tool / snapshot / parent 的第二个请求会
直接复用第一个请求的 Promise：错误结果、错误成功判定，且第二个请求的外部副作用语义被破坏。
内存路径缺少持久化路径已有的 `requestDigest` 比对。

**方案：**

1. 将 inflight 值结构改为 `{ requestDigest, promise }`（或等价），键仍为 `invocationId`。
2. 复用 Promise 前比对完整请求摘要；摘要复用 `createIntent()` 的身份定义
   （含 `parentInvocationId`、`threadId/turnId/stepId`、`toolName`、`snapshotDigest`、`argsDigest`）。
3. 摘要不含 `startedAt` 等不稳定时间字段（`createIntent` 现状已满足，保持）。
4. 相同摘要：允许并发复用（幂等保护语义不变）。
5. 不同摘要：立即拒绝，抛 `ORION_TOOL_INVOCATION_CONFLICT`（复用既有错误码与
   `ToolGatewayError` 形状），必须发生在第二次外部副作用之前。
6. `finally` 清理只删除「与自己 requestDigest 一致」的占位项，避免误删并发新建的合法项
   （例如完成后立即以同 ID 合法重放被旧 finally 清掉的竞态）。
7. 保留既有持久化去重（journal）与 `ORION_TOOL_OUTCOME_INDETERMINATE` 语义，不改变
   Wire Protocol。

**必需测试（新增到 `tests/tool-gateway.test.ts`）：**

1. Same ID + Same Payload + Overlap：实际执行一次，两次调用拿到同一结果。
2. Same ID + Different Args + Overlap：第二个请求失败（CONFLICT），不产生第二次执行。
3. Same ID + Different Tool：身份冲突。
4. Same ID + Different Snapshot：身份冲突。
5. Same ID + Different Parent：身份冲突。
6. 已完成请求重复执行：保持既有去重语义（:255 用例不回归）。
7. 跨进程恢复后请求重放（journal 命中 + receipt）：不重复外部副作用。
8. Journal terminal 写入失败：不得伪造成功收据（与 :236 用例的语义衔接）。

**验收：** 同一执行身份只能对应唯一请求内容；不同请求不得共享执行结果、不得被误判为成功、
不得产生第二次外部写入。若实施时发现最新代码已修复，记录已有实现与测试证据而不是重复修改。

### T22-02：持久化执行与崩溃恢复可靠性（P0）

**涉及源码：** `src/runtime/thread-event-store.ts`（:830 `recoverIncomplete` 等）、
`src/runtime/thread-runtime.ts`（:122/:190 恢复选项）、Goal Runtime、对应 durability /
lifecycle tests。

**范围：** 不重建恢复架构（recoverIncomplete / TurnCommit / Tool Intent / Tool Receipt /
Goal terminal continuation / Thread Event Store 均已存在），只加强**边界一致性**与**故障注入
测试**。

**七个持久化边界：** Turn Start、StepSnapshot、Tool Intent、Tool Receipt、TurnCommit、
Turn Terminal、Compaction Pointer。

**故障注入矩阵（每边界 × 每故障至少一例）：** 进程异常退出（模拟 kill 后 journal 重放）、
Kill/Restart、Event Store 写入失败、Tool Receipt 写入失败、网络中断、用户取消、双 Session
重叠执行、Goal 中断后继续、Context Compaction 中断。

每个场景同时断言：文件系统实际副作用、Durable Event Stream、Tool Receipt 状态、最终 UI
Read Model、Goal/Turn 完成状态、用户可见恢复信息。

**验收：**

1. 崩溃后不自动重复外部写操作（重放优先询问/indeterminate，不静默重执）。
2. 无法确定执行结果时返回 `ORION_TOOL_OUTCOME_INDETERMINATE`（既有语义保持）。
3. Failed / Paused / Interrupted 的 Goal 不得投影为 Completed。
4. 同一 Goal 的恢复继续不产生重复副作用。
5. 损坏或冲突的 Receipt 不能投影为成功。
6. 不同 Session 之间不借用调用身份或权限。
7. 不改变既有 Wire Protocol。

### T22-05：Agent 执行效率优化（P1）

**涉及源码：** `src/framework/query.ts`、`src/runtime/agent-loop.ts`、
`src/runtime/product-orion-runtime.ts`、diagnostics / bench。

**已有基础（不得重复制造）：** Context Budget 分档、只读工具碎片化提示、Model Request
统计、StepSnapshot、TaskContext、Goal 完成审计、Context Compaction。

**三阶段：**

1. **观测**：为 Agent 生命周期增加阶段指标 —— Prompt Assembly / Provider Queue / Provider
   RTT / Tool Queue / Tool Execution / Context Compaction / Durable Commit；可关联 Turn、
   Step、工具类型与任务类别；不记录明文 Prompt、API Key 或敏感数据。
2. **识别**：用 T22-04 的 Eval 找出重复读文件、无效搜索、重复失败调用、不必要模型请求、
   只读工具串行化、无效 Compaction、Provider 排队等成本，按实际成本排序。
3. **单变量优化**：只做低风险项（批量只读建议触发时机、减少重复探索提示、工具选择提示优化、

## 6. 发布验收条件与阻断项

**正确性：** P0 回归通过；无重复外部副作用；无未解释的工具身份冲突；无跨 Session 状态串扰；
无错误的 Completed 状态。

**可靠性：** 崩溃恢复测试通过；必需 E2E 通过；真实发行产物通过安装验证；Source 与 Artifact
可追溯。

**效率：** 固定任务集完成率不下降；不增加错误完成率；有原始 A/B 数据；主要效率提升有统计
证据。

**可维护性：** 关键改动有自动化回归；新策略可回滚（Feature Flag）；不破坏既有 API / Wire
Protocol；确有兼容性变化时提供迁移说明。

**发布阻断（任一命中即不得发布）：** 未解释的 Durable Side Effect；False Completion；跨
Session 数据或身份串扰；P0 测试失败；必要 E2E 缺失；发布产物与测试版本不一致。
