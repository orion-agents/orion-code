# Orion Code v0.3.6 优化计划：Web Workbench 交互质量与 UI 测试基线

> 版本基线：`codex/v0.3.5` @ `2554e33`（v0.3.5 candidate 已本地安装验证）
> 评估日期：2026-09-02
> 评估视角：交互设计专家（UI 结构 / 交互模式 / 可访问性 / 反馈状态 / 测试能力）

---

## 1. 决策摘要

**评估对象**：Web Workbench（`web/src/`，19 个 tsx 组件 + `reducer.ts` + `useWorkbench.ts` + 5508 行 `styles.css`，无第三方 UI 库，纯手写 CSS/组件）。

**评估方法**：源码评审（组件树 + 交互模式 + aria/role/focus 扫描 + CSS 变量与响应式审计）+ **UI 测试能力审计** + 一个真实逃逸缺陷的复盘（Markdown 表格渲染失败，见 §2.1）。

**总体结论**：

| 维度 | 水位 | 判断 |
|---|---|---|
| 可访问性骨架 | **高于同类平均** | `role="tablist/tab/tabpanel"`、`aria-modal` 弹窗、`inert` 焦点隔离、`aria-live`、`prefers-reduced-motion`、`forced-colors` 高对比均已落地 |
| 状态管理 | **成熟** | `useReducer` + 约 30 个判别联合 action，纯函数 reducer，设置子系统独立切片 |
| 响应式布局 | **良好** | CSS 变量驱动三态（dock / rail / drawer）+ `ResizeObserver`，无容器级硬编码宽度 |
| 交互发现性 | **薄弱** | 快捷键仅靠原生 `title=` 暴露，无命令面板、无快捷键帮助面板 |
| 键盘可达性 | **有明确缺口** | 面板分割条纯 pointer 实现且 `aria-hidden`（键盘用户无法调宽） |
| 状态表达 | **存在 WCAG 风险** | 状态点仅用颜色 + `aria-hidden`（违反 WCAG 1.4.1 色彩非唯一手段） |
| **UI 测试能力** | **结构性缺陷** | **组件级渲染测试为 0**；逻辑层测得到、渲染层完全无覆盖 |

**v0.3.6 主题**：**交互质量与 UI 测试基线** —— 补上"组件渲染测试层"这块地基（这是本轮真实缺陷逃逸的根因），同时消灭 P0 级无障碍缺口，并提升交互发现性。

## 2. 已确认问题

### 2.1 组件级渲染测试为零（本轮 Markdown 表格缺陷逃逸的根因）— **最高优先级**

**现象**：2026-09-02 用户报告 Web Workbench 对话面板内 markdown 表格渲染失败（无边框、内嵌 `code` 挤成一团）。根因为 `web/src/components/Markdown.tsx`（189 行手写渲染器）**完全未实现 GFM 表格语法**，分隔行 `|---|` 被当作段落吞掉。

**为什么测试没抓到**——能力审计证据：

| 测试层 | 规模 | 覆盖范围 | 是否覆盖渲染 |
|---|---|---|---|
| `tests/web-*.test.ts` | **32 个** | reducer 状态机、`diff-hunks` 纯函数、terminal manager/协议契约、session collection、settings draft、SSR 安全 | **否** —— 全部为纯逻辑 / 契约层 |
| `tests/*.test.tsx` | **0 个** | — | — |
| `tests/e2e/*.spec.ts` | **18 个** | approval、goal/plan、packaged bootstrap、recovery、security-a11y、settings、v031/v032/v033 主题/布局/终端、session concurrency | 是（真实浏览器），其中 **12 个含截图断言**、**5 个接入 axe** |
| `@testing-library/react` | **未安装** | — | — |

**结构性判断**：质量网存在**中间层空洞** —— 单元层（jest）只测逻辑不测渲染，E2E 层（playwright）成本过高无法逐组件覆盖，导致 **189 行渲染逻辑零覆盖**。任何纯渲染缺陷（表格、列表、代码块、内联样式）都只能靠用户肉眼发现。

**本轮已建立的 PoC**：`tests/markdown-rendering.test.ts`（12 例，用 `react-dom/server.renderToStaticMarkup` 做 HTML 字符串断言，**12/12 绿**），证明无需引入 `@testing-library/react` 即可建立组件渲染测试层。同批配套改动：`jest.config.js` 的 ts-jest `jsx` 由 `'react'` 改为 `'react-jsx'`（对齐源码的新 JSX transform）。

### 2.2 面板分割条键盘不可达（WCAG 2.1.1 Keyboard）

- 证据：`web/src/components/layout/PanelResizeHandle.tsx:14`（注释明示仅指针）、`:102`（`aria-hidden`）。
- 仅有 `onPointerDown/Move/Up`，**无 `role="separator"`、无 `tabIndex`、无方向键 handler**。
- 影响：键盘与辅助技术用户只能展开/折叠，无法精确调整面板宽度。

### 2.3 状态指示仅依赖颜色（WCAG 1.4.1 Use of Color）

- 证据：`Conversation.tsx:313`、`:534`、`review/ReviewPanel.tsx:183`、`layout/WorkPanelDock.tsx:217` 的 `state-dot` / `rail-status-dot`。
- 圆点只用颜色表达状态，且 `aria-hidden` → 屏幕阅读器**无任何文本等价**。

### 2.4 快捷键发现性差（无命令面板 / 无帮助面板）

- 现有绑定：`Cmd/Ctrl+B` 切换项目导航（`App.tsx:178-217`）、`Cmd/Ctrl+Shift+B` 切换工作面板、`Cmd/Ctrl+Shift+1..5` 切 5 个面板（`WorkPanelDock.tsx:126-133`）、方向键 Tab 导航（`WorkPanelDock.tsx:258-272`）、`Esc` 关闭浮层。
- 暴露方式**仅原生 `title=`**（`ProjectNavigator.tsx:155`、`WorkPanelDock.tsx:212`）—— 触屏不可触发、键盘不可聚焦。
- **缺失**：命令面板（command palette）、快捷键帮助面板。

### 2.5 主题切换入口过深

- 主题状态由 `documentElement.dataset.theme` 驱动（`App.tsx:146`），切换入口**仅**在 `SettingsDialog` 外观分区（`App.tsx:59`）。
- 用户需打开设置弹窗才能切换 dark/light/system，无外壳快捷入口。

### 2.6 亮色 token 双源（维护风险）

- `themes/orion-blocksmith.tokens.css:58-108` 与 `styles.css:124`、`:210` **均定义亮色变量**，存在漂移风险，应收敛为单一源（tokens）。

### 2.7 通知系统单条非堆叠

- `App.tsx:429-482` 仅渲染单条 `notice`（`role=alert/status`），**无堆叠容器、无自动消失、无队列**。高频操作下后到的通知会静默覆盖前一条。

### 2.8 长消息流无窗口化

- `Conversation.tsx:233-239` 对 `timeline` **全量 `.map()`** 渲染 `<ol>`。虽有"加载更早内容"分页（`:192-203`）缓解，但单页仍全量渲染，长会话 DOM 量大。

### 2.9 中英文混排不一致

- 面板名用英文 `Agent/Review/Terminal/Files/Git`（`WorkPanelDock.tsx:30-34`）、眉标 `PROJECT WORKSPACE`（`:227`）、Inspector 段标题 `Context usage/Token usage/Loop statistics`（`Inspector.tsx:790-796`），而其余 UI 为中文。

### 2.10 已知遗留（本次评估附带发现，不属 v0.3.6 范围）

- `Markdown.tsx:40` 标题级别 off-by-one：`Math.min(6, heading[1].length + 1)` 应为 `heading[1].length`，导致 `##` 渲染为 `<h3>`。（`tests/markdown-rendering.test.ts` 已用注释标注实际行为，建议并入 v0.3.6 的 P0-A 一并修正。）

## 4. 架构合同

### 4.1 组件渲染测试层（新增能力）

- **技术选型**：`react-dom/server.renderToStaticMarkup`（已在 `markdown-rendering.test.ts` 验证）。**不引入** `@testing-library/react` / jsdom —— 目标组件为无副作用展示组件，字符串断言足够且零新依赖。
- **配置**：`jest.config.js` 的 `testMatch` 扩展为 `['**/*.test.ts', '**/*.test.tsx']`；ts-jest tsconfig 保持 `jsx: 'react-jsx'`（v0.3.6 已改）。
- **覆盖范围（P0-A 目标）**：
  - `Markdown`（已完成基线，含 GFM 表格 / 内联 code / 对齐 / 回退）
  - `Conversation`（消息流渲染、ApprovalCard / QueueDock 内联卡片、空态四态）
  - `ComposerControlCenter`（模型/模式选择、PlanReviewCard、禁用态）
  - `WorkPanelDock`（5 面板 Tab 切换、`role=tablist` 语义）
  - `ApprovalCard` / `DiffViewer`（权限审批语义、hunk 导航结构）
- **命名约定**：`tests/web-ui-<component>.test.tsx`。

### 4.2 键盘可调分割条

- `role="separator"` + `aria-orientation="vertical"` + `aria-valuenow/min/max`（百分比）。
- `tabIndex={0}` 纳入 Tab 序列；`←/→` ±2%，`Shift+←/→` ±10%，`Home` 最小宽，`End` 最大宽，`Enter`/双击 复位默认。
- 移除 `aria-hidden`；视觉焦点环复用现有 `:focus-visible` 样式。
- 指针交互行为**完全不变**（回归风险可控）。

### 4.3 状态指示去纯色

- 每个状态点在相邻位置提供 **`sr-only` 文本等价**（如"运行中 / 已完成 / 失败"），或附加形状/图标差异（●/○/▲）。
- 移除 `aria-hidden`（或改为 `aria-hidden` + 相邻 `sr-only` 文本二选一，不得两者皆无）。

### 4.4 快捷键帮助面板

- `Cmd/Ctrl+/` 唤起；`role="dialog"` + `aria-modal` + `aria-labelledby`；`Esc` 关闭并归还焦点（复用 `App.tsx:92-143` 既有焦点归还逻辑）。
- 内容为**单一数据源**：由快捷键绑定表生成，避免文档与实现漂移。
