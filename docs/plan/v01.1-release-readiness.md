## 1. 结论边界

当前代码、自动化、PTY 和生成 tarball 已达到“可以进入 PR/CI 和发布流程”的开发准出标准。
这不等于 npm 已发布：

- npm registry 当前 `latest` 仍为 `0.1.0`；
- v0.1.1 尚未创建 PR、通过远端 CI、合并、tag 或 publish；
- registry 全新安装只能在 publish 后验证；
- Computer Use 安全策略不允许自动操作 `com.apple.Terminal`，发布操作员仍应在 publish 前
  做一次最新候选的人工视觉确认。

因此本报告对开发候选给出 GO，对立即宣称“已发布完成”给出 NO-GO。

## 3. 修复的发布阻断问题

1. TUI 曾被配置注释和状态文案描述为 beta，terminal-ui 被描述为公众 stable fallback；
2. `/target` 在 terminal-ui 和默认 TUI 中使用不同的 GoalCoordinator 路由；
3. `/storage repair|cleanup` 可在没有明确确认时修改本地数据；
4. `/clear-history` 名称暗示持久删除，但实际只清内存上下文；
5. `/clear`、`/exit` 的旧 handler 直接操作 stdout/process；
6. completion gate 对 `markdown render test` 产生误判并造成额外模型循环；
7. completion gate 缺少证据时可能持续消耗模型预算；
8. 文档公开的 `orion migrate openhorse` 没有 CLI 路由；
9. `/migrate openhorse` 被标记为 destructive，却可无 `--yes` 写入；
10. terminal-ui PTY 仍断言旧的 “stable terminal UI” 文案。

- 对应 Jest/PTY 测试；
- package 0.1.1 元数据；
- README、目标、计划、release note 与本 readiness 报告。

## 8. 发布操作员剩余 Gate

以下项目不会阻止创建 PR，但在 npm publish 前必须关闭：

1. 显式排除用户图片与 `AGENTS.md` 后提交本分支；
2. 创建 PR，等待远端 CI 与代码审查通过；
3. 在 macOS Terminal 中启动最终候选，目视确认 Banner、输入间距与无 Base64 泄漏；
4. 合并并创建 `v0.1.1` tag；
5. 获得明确发布授权后执行 `npm publish --access public`；
6. 等待 registry packument 可见；
7. 从 registry 全新安装 `@orion-agents/orion-code@0.1.1`；
8. 复验 `orion --version`、默认 TUI、technical terminal 和 Ink 废弃提示。

任何一步失败，发布结论回到 NO-GO；npm 版本不可覆盖，应修复后发布 0.1.2。
