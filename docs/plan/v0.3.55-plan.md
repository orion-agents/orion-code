## 1. 背景与定性

- 本轮为**纯文档/簿记周期**（无 `src/`、`web/`、`tests/` 产品代码变更；对
  `tests/coding-task-eval.test.ts` 的 `packageVersion` pin 是每轮 bump 的
  机械性配套，历轮一致，不视为产品 delta）。质量条款 C 一般要求 docs-only
  周期不占版本号，但主指令「每轮仅推进一个版本号 → v0.3.99」为更高优先级的
  用户显式要求，且版本工作树的开版提交必然携带六处 bump（release gate 把

  先例走完整发布链路，并在 Release notes 标注该张力。

## 4. 验收标准

1. `npx jest tests/coding-task-eval.test.ts` 5/5 绿。
2. `npm run build` 绿。
3. 提交后 `npm run release:check`：`Version consistency (package 0.3.55)`、
   `CHANGELOG.md entry`、`README release state`、`Release ref` 等项通过；
   `Jest suite` 项如因本机 better-sqlite3 ABI / PTY 环境家族失败，以 CI 同名
   job 结论为准，不得改断言掩盖。
4. CI（PR run）：`Web E2E critical journey ×3`、`Web E2E full suite three
   consecutive runs`、Node 矩阵、`Dependency security audit`、release gate
   逐作业核对；单一作业 flake 允许一次 `gh run rerun --failed`，仍红即停止报告。
5. squash 合并 → tag `v0.3.55` 打在 main 合并提交并 push → 清洁 worktree 构建
   tarball → sha 核验（CI `release-receipt` / `web-e2e-receipt` 小 artifact 的
   `tarballSha256`，必要时 `release-package` tarball 逐字节比对）→ 剥离代理 env
   后 `npm publish --ignore-scripts` → 防缓存直连确认 `latest=0.3.55` 并记录
   精确入库时间 → `gh release create v0.3.55 --latest`（notes 含逐作业门禁表、
   tarball sha256、安装命令，并标注 docs-only 周期占用版本号的张力）。
6. 汇报：版本号、plan 路径、PR 链接、tag、npm 精确时间戳、Release 链接、
   tarball sha256；dependabot open PR 数量。
