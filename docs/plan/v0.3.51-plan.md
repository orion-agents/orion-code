### S4 质量条款 B 红灯修复 — `tests/e2e/fixtures/openai-provider.ts`

- **诊断**：WEB32-P0-08 在 `provider.waitForRequest(..., 45_000)`（spec:114）超时，
  而此前 `/api/v1/commands` 已成功返回并通过 contextReceipt 断言——UI 与命令链路
  正常，是 host 侧从未向 fixture provider 发出 LLM 请求。fixture 服务器
  `keepAliveTimeout = 1_000` 过短：host 的池化 HTTP agent 将 POST 派发到「刚被
  服务端按空闲超时关闭的 socket」时，请求被静默丢弃（Node 不自动重试非幂等
  POST），与「同 run 内先发请求成功、后发请求消失」「负载越高越易复现」的特征
  吻合（v0.3.50 轮 4 跑 3 红 1 绿、本轮 main rerun 仍红）。
- **修复**：`keepAliveTimeout` 由 `1_000` 改为 `0`（禁用空闲 keep-alive 连接的
  主动关闭，从根上消除陈旧 socket 复用竞态窗口），附 WHY 注释。
  `requestTimeout`/`headersTimeout` 维持不变。
- **验证**：`npm run build` 绿（该文件经 ts-node 在 E2E 运行时加载，tsc 检查
  其类型）；修复效果以本轮 PR CI 的 E2E 三连跑与后续 main 发布后 CI 为准——
  若修复后 E2E 三连跑仍复现 WEB32-P0-08 超时，则假设不成立，停止并如实报告，
  留待下一轮以其他假设处置。
