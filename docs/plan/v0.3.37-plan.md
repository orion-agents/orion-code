## 1. 版本决策与用户价值

v0.3.27–v0.3.36 建立了专业审查回路的契约、CLI 运行时、Web 共享闭环、文档对齐与连续
多轮交付状态审计，但发布收据链路本轮仍发现三处事实缺口：

1. **CHANGELOG 交付状态漂移。** main 上 CHANGELOG 的 0.3.36 条目仍为
   `Status: candidate`，而 tag `v0.3.36` 与 npm `latest=0.3.36` 均已存在（2026-10-25
   确认，tarball 入库 2026-10-25T01:59:21.552Z），需按事实更新为 `published`。
2. **v0.3.36 GitHub Release 缺失（发布证据链断点）。** 历轮（v0.3.28–v0.3.36）的
   GitHub Release 步骤被遗漏，`gh release list` 显示 Latest 仍停留在 v0.3.27。
   本轮已先于开版提交补发 **GitHub Release v0.3.36**
   （https://github.com/orion-agents/orion-code/releases/tag/v0.3.36），使 CHANGELOG
   published 条目能引用真实 Release 链接；本轮 v0.3.37 发布完成后同样必须创建
   GitHub Release（必做，不可留给下一轮），并自本轮起把「GitHub Release 创建」
   纳入每轮发布链路的固定第 8 步。
3. **v0.3.36 发布事实未形成仓库内证据。** v0.3.36 的发布链路事实（PR #292、squash
   合并提交 `6ea1d16`、tag `v0.3.36`、registry shasum `cce4f6cf…c51f`、tarball 入库
   时间 2026-10-25T01:59:21.552Z、补发 GitHub Release）尚未有任何证据文件记录。

v0.3.37 交付上述三项回填，并顺带完成一次 **近三版（0.3.34–0.3.36）交付状态审计**：
以 registry 直连查询与 git tag 交叉核对每版的「tag 存在 + npm 版本存在 + dist-tag
latest 指向」三项，审计结果写入本轮证据文件，作为 G1 证据纪律的周期性检查样例
（滚动窗口相对 v0.3.36 轮前移一版）。

**本版明确不做（仍属 PR4 剩余项，待有凭据环境）：** 人工标注付费质量评测（12 缺陷 +
8 干净样本、3 轮运行）、真实模型全链路验收、TurnCommit 收据投影与跨重启恢复、
`start_code_review` 协议命令化、finding Context 结构化注入。v0.3.28–v0.3.35 的
GitHub Release 历史欠账不在本版范围内逐版补发，仅以 v0.3.36 补发作为流程修复起点，
其余版本是否补发由维护者决策。

### S2 版本发布（六处 bump + 测试 pin）

- 六处 bump 至 `0.3.37`：`package.json`、`npm-shrinkwrap.json`（顶层 +
  `packages[""]` 手改，勿整体重生成）、`CHANGELOG.md`、`README.md`（install pin
  `0.3.37` + 首部摘要改为 0.3.37 candidate / 上一版 0.3.36 已发布）、
  `README.zh-CN.md`（同前）。
- 同步修正 `tests/coding-task-eval.test.ts` 的 `packageVersion` pin（0.3.36 →
  0.3.37）；**每轮 bump 都要改**，否则 release:check 的 Jest 新增第 5 个失败点。
- 本地验证：精确路径 Jest 套件（`tests/coding-task-eval.test.ts`）+ `npm run build`
  + `npm run release:check`；release:check 内含的 4 个 Jest 失败为本机
  better-sqlite3 `NODE_MODULE_VERSION` 环境问题，以 CI 同名 job 为准。
- 发布链路：push `codex/v0.3.37` → gh PR → CI 全绿（时序 flake 用
  `gh run rerun --failed` 一次）→ squash 合并 → tag `v0.3.37` → 干净 worktree
  build/pack（`mv dist/web-client` 后 `npm run build`）→ tarball sha256 与 CI
  web-e2e-primary artifact 的 `tarballSha256` 逐字节核验 → npm publish
  （`--ignore-scripts`）→ registry 直连 curl 确认并记录精确入库时间 →
  **GitHub Release v0.3.37（`gh release create --latest`，必做）**。

## 4. 验收标准

1. `npm run release:check` 通过（除已知的 4 个 better-sqlite3 环境性 Jest 失败，
   以 CI 同名 job 为准；worktree 未提交状态在 commit 后消除）。
2. `tests/coding-task-eval.test.ts` 5/5 绿；`npm run build` 绿。
3. CI（18 项检查）全绿：含 Release gate、build exact tgz、dep-health、harness、
   exact tgz ×3 平台、Web E2E critical journey ×3、Web E2E full suite 三连跑。
   已知常红基线（audit / type-check / Node 矩阵 / full suite）以历史轮次为准判断
   是否为环境性失败；时序 flake 用 `gh run rerun --failed` 处理。
4. 本地 tarball sha256 与 CI `web-e2e-primary` artifact 的 `tarballSha256` 一致。
5. PR squash 合并后 tag `v0.3.37` 指向 main 合并提交。
6. npm publish 后 registry 直连 curl（`Cache-Control: no-cache`）确认 0.3.37 存在
   且 `dist-tags.latest=0.3.37`，并记录精确入库时间。
7. **GitHub Release v0.3.37 已创建**（`gh release create v0.3.37 --latest`，notes
   含改动说明、质量门禁表、tarball sha256、安装命令）。
8. 无 E2E 场景新增（docs-only 切片），不涉及场景 ID 登记。
