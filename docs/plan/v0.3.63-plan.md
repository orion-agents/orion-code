## 4. 验收标准

1. `npm run build` 通过（tsc + vite）。
2. `npm run release:check` PASS（含全量 Jest、tarball 一致性、六处 bump 一致性、
   CHANGELOG 状态检查）；`tests/coding-task-eval.test.ts` 5/5 绿。
3. release gate 对 `codex/v0.3.63` 分支名与 `package.json` 版本一致性 PASS。
4. 全量 Jest 无新增失败；已知环境竞争家族（PTY ×2、跨进程锁、settings watcher、
   better-sqlite3 原生绑定）失败须隔离复跑定性，不得改断言掩盖。
5. PR CI：critical journey ×3、Node 矩阵（22/24/26）、release:check、audit
   全绿（单一 flake 允许 `gh run rerun --failed` 单次复跑；重跑仍红即停止）。
6. squash 合并 → tag `v0.3.63` → 干净 worktree 构建 → tarball sha256 与 CI
   收据逐字节一致 → npm publish → registry 防缓存确认 → GitHub Release
   （含逐作业门禁表 + sha256 + 安装命令）。

## 5. 风险与边界

- 主工作区未跟踪文件一律不动、不入提交；`git add` 按文件精确添加。
- worktree `node_modules` 为软链，悬空先修链再跑测试。
- 已知环境失败家族不得靠改断言或跳过用例「转绿」。
- 若 CI 重跑仍红：停止本轮，如实报告失败阶段，目标版本仍为 v0.3.63，留待
  下一轮重试（沿 v0.3.35 / v0.3.57 / v0.3.62 先例）。
