# Orion Code v0.3.4 Web 内置「雅致像素」主题开发计划

- 版本：v0.3.4
- 状态：Proposed / 待评审
- 日期：2026-09-01
- 范围：Web Workbench 内置视觉风格、外观设置、组件样式、真实浏览器视觉验收与发布证据
- 产品名称：`雅致像素 / Orion Refined Pixel`
- 内置风格 ID：`orion-refined-pixel`
- 视觉基线：[v0.3.4-orion-refined-pixel-reference.png](../assets/v0.3.4-orion-refined-pixel-reference.png)
- 视觉基线 SHA-256：`f4de59511ded2dba1b7b3da4941f223601e3540c521ba3bb9e123c45d2239329`

## 0. 决策摘要

v0.3.4 将效果图中的“高端、优雅、轻像素”方向实现为 Orion Code Web Workbench 的内置默认视觉风格：

1. 只开发随 Orion Code 编译和发布的内置主题，不建设插件 SDK、主题市场、主题包加载器或安装/卸载生命周期；
2. `orion-refined-pixel` 取代 [v0.3.3 计划](./v0.3.3-plan.md)中厚重木材、石材和游戏皮肤化的视觉方向，不同时实现两套新的像素主题；
3. 效果图是 v0.3.4 light 模式的强视觉基线，配色、材质轻重、组件几何、三栏比例、信息密度和层级必须与其一致；
4. 真实版本号、用户数据、交互状态、响应式布局、语义结构和无障碍要求以产品代码为准，不复制效果图中的示意数据或固定文字；
5. 保留 `appearance.theme=system|light|dark` 的明暗模式语义，新增独立的 `appearance.style=classic|orion-refined-pixel` 视觉风格轴；
6. 未显式配置 style 时，Web Workbench 默认使用 `orion-refined-pixel`；现有显式 theme 值不被覆盖，用户可以切回 `classic`；
7. 轻像素感由 1–2px 阶梯边线、小型方形状态灯、克制的切角、语义图标和低饱和宝石色构成；正文、代码、Diff、终端和 CJK 字形保持平滑渲染；
8. 完成定义是 exact tarball 中的真实 Chrome 页面通过视觉评审、功能回归、响应式、无障碍、CSP、性能和截图证据门禁，不是只完成静态 CSS 或生成一张相似概念图。

## 1. 基线、依赖与实施前置门

### 1.1 当前可验证检出

编写本计划时，本地仓库的实际状态为：

- 分支：`v0.3.1`，跟踪 `origin/v0.3.1`；
- HEAD：`2274639`；
- `package.json`：`0.3.1`；
- 当前代码只有 `system | light | dark` Web 明暗主题，没有独立 style 字段；
- `docs/plan/v0.3.3-plan.md` 是规划文档，不是当前检出已经实现或发布的主题；
- 工作树存在用户拥有的 `AGENTS.md`、质量计划、截图、脚本和 v0.3.3 计划改动，v0.3.4 实施不得接管、清理或覆盖这些内容。

因此，本计划不能被视为 v0.3.4 已经开发。开始编码前必须在目标开发分支重新记录 HEAD、版本、dirty state、现有 Settings schema、Workbench 布局和 v0.3.3 的实际交付状态。

### 1.2 与 v0.3.3 的关系

v0.3.4 只负责主题视觉和与之直接相关的设置、Token、组件及测试：

- v0.3.3 中的多 Session Runtime、切换性能、右栏布局修复和 Settings 单入口属于前置功能轨道；
- v0.3.4 不借主题重构修改 Session、Goal、Runtime、Composer 命令或 Work Panel 的业务状态机；
- 若目标分支尚未完成 v0.3.3 功能修复，先冻结可测试的布局合同，再并行开发 Token；不得用主题 CSS 掩盖布局缺陷；
- 当前可验证基线中 `orion-blocksmith` 尚未实现。若 Phase 0 发现它已在其他分支或发布包中对外发布，立即停止 style 枚举变更并补兼容 ADR，不得静默删除、重命名或复用已发布 ID。

### 1.3 当前主题调用链

当前 Web 外观是一条编译期内置配置链，不是插件：

```text
orion.json web.appearance.theme
  -> global config validation
  -> SettingsDocumentRepository atomic CAS
  -> SettingsCoordinator effective/explicit/last-good projection
  -> Web protocol and browser settings contract
  -> App writes <html data-theme="...">
  -> bundled CSS variables and component rules
  -> TerminalPanel synchronizes xterm colors
```

v0.3.4 在这条链上增加封闭 style 轴，不引入文件扫描、远程资源、动态 import、任意 CSS 或可执行主题代码。

## 2. 视觉基线合同

### 2.1 基线角色

参考图尺寸为 1536×1024，是 light 模式、桌面三栏布局和默认视觉密度的评审基线。它约束设计语言，不替代真实 DOM、文本、状态和响应式规范。

视觉评审分为三类：

| 类别     | 效果图约束                                                                         | 实现要求                               |
| -------- | ---------------------------------------------------------------------------------- | -------------------------------------- |
| 强一致   | 布局比例、明亮象牙色表面、深海军蓝品牌区、绿色主动作、薄边框、轻阴影、低饱和宝石色 | 在锚点视口逐项对照，未经评审不得偏离   |
| 语义一致 | 消息卡、Tool、Goal、Activity、文件、子代理、Composer 的层级和状态密度              | 使用真实组件和真实状态，不复制示意数据 |
| 产品优先 | 文案、版本、图标可访问名、焦点、响应式、错误和加载状态                             | 以运行时、WCAG 和当前产品合同为准      |

### 2.2 1536×1024 锚点布局

在固定 fixture、默认布局偏好和 100% 缩放下，目标几何为：

| 区域                    |              目标 | 允许偏差 | 说明                                      |
| ----------------------- | ----------------: | -------: | ----------------------------------------- |
| 左侧 Project/Session 栏 |             288px |     ±8px | 包含品牌牌、项目、Session 和 Runtime 状态 |
| 右侧 Work Panel         |             400px |    ±12px | Goal/Activity/Capabilities 与纵向状态卡   |
| 中央主工作区            |    自适应剩余空间 |        — | 不得低于当前核心内容最小宽度              |
| 顶部主栏                |              88px |     ±4px | 标题、breadcrumb、BUILD/ASK 与 Settings   |
| 底部 Composer           |             208px |    ±12px | 输入区、上下文 chips、模式按钮与发送      |
| 主区域间隔              | 8px / 12px / 16px |     ±2px | 使用统一间距 Token                        |

若 v0.3.3 已提供用户可调侧栏宽度，视觉测试必须先设置上述固定值再截图；日常使用继续尊重用户布局偏好，不能为了截图锁死宽度。

### 2.3 必须匹配的视觉特征

#### Shell 与表面

- 应用铺满视口，外壳以温暖象牙白和轻微冷灰分隔，不增加浏览器框、设备 mockup 或场景背景；
- 三栏之间使用 1px 中性边界和极轻的内高光，禁止厚木梁、粗石块、多层游戏边框；
- 卡片以白色或暖白色哑光表面为主，阴影只用于层级，不制造悬浮玩具感；
- 外壳四角可使用 2–4px 的轻微像素切角或角标，但不能影响 resize handle、focus ring 或命中区域；
- 背景纹理如确有必要，强度不得影响文字，且不能覆盖代码、Diff、Terminal 或表单控件。

#### 品牌与主导航

- 左上品牌牌使用深海军蓝哑光面，白色 `ORION CODE` 字标和克制的金色原创星形标记；
- 产品版本必须来自运行时，不写死效果图中的 `v0.3.0`；
- `GOAL` 选中态和“新建会话”使用同一语义绿系，但保持文字对比度和明确 focus 状态；
- 顶部未选中的 Activity/Capabilities 使用平面标签，不使用厚重凸起按钮。

#### 内容与状态

- Conversation 卡片、reasoning header、Tool details 和 Activity log 使用紧凑的白色内容层与 1px 边界；
- 用户、Orion、reasoning、Tool 等身份使用小型方形图标和文字双重编码；
- 成功、运行、等待、错误、选中不能只靠颜色；保留图标、标签、边线或状态文字；
- 进度使用细像素格，但每格是数据表达，不添加无意义装饰动画；
- 空状态使用小图标和一句短说明，禁止大型插画挤压真实工作内容。

#### Composer

- Composer 是中央区底部稳定控制台，不使用厚木质底座；
- 输入区为大面积暖白表面，边界清晰，focus 时显示 2px 可见外圈；
- BUILD、ASK、MODEL、CONTEXT 采用蓝、紫、金、青绿的低饱和宝石色，维持效果图的语义顺序；
- 发送按钮保持深蓝方形主动作，Stop/Steer/Queue 状态必须沿用真实运行逻辑；
- chips、选择器和按钮的文字继续使用平滑字体，不用像素字体。

### 2.4 允许差异

以下差异不算偏离效果图：

- 真实项目、Session、Goal、Tool、日志、文件和子代理数据；
- 真实版本号、国际化文案、时间、字节数和模型信息；
- 为 WCAG、键盘导航、触控目标和 forced-colors 增加的边框、说明和 focus ring；
- 760px 以下 drawer、单栏或 rail 模式的响应式重排；
- Terminal、代码、Diff 必须服从语法和 ANSI 可读性的颜色调整；
- 浏览器字体渲染造成的亚像素差异；
- system-dark/dark 的派生夜间色板，但组件几何和信息层级必须保持同一风格。

### 2.5 禁止偏离

出现以下任一情况，视觉评审直接判定为阻断：

- 回到 v0.3.3 参考图中的厚重木框、石材纹理或明显游戏皮肤；
- 大面积渐变、玻璃拟态、霓虹、强反射、3D 浮雕或高饱和糖果色；
- 为追求像素感而栅格化正文、代码、终端、CJK 或状态数字；
- 卡片边框套边框超过三层，或装饰元素抢占功能空间；
- 仅替换颜色，没有落实效果图的几何、层级、密度和轻像素细节；
- 以整张参考图作背景、切片或 CSS mask；
- 引入外部游戏的名称、商标、字体、纹理、图标、角色、音效或界面切片。

### 3.2 可量化指标

- 1536×1024 锚点布局的主要区域尺寸满足 2.2 节容差；
- 视觉评分至少 90/100，且任一维度不得低于该维度满分的 80%；
- 正文和控件文字对比度至少 4.5:1，大字号至少 3:1，非文本状态与控件边界至少 3:1；
- 320、390、760、1180、1440、1536 和 1920 CSS px 下无页面级横向滚动或核心控件遮挡；
- 200% 浏览器缩放下可完成打开项目、切换 Session、发送消息、审批、查看 Goal、打开 Work Panel 和设置；
- style/theme 切换在一个 animation frame 内更新根属性和 xterm 色板，不刷新页面、不重建 Runtime、不重连 Session；
- 主题相关新增首屏压缩资产不超过 96 KiB；优先 CSS 和现有 SVG，任何单一位图不得超过 32 KiB；
- 主题切换不产生 layout shift；切换后的 CLS 目标为 0；
- resize/scroll 压力旅程保持 55–60fps，主题相关 long task 为 0；
- axe blocking、console error、page error、HTTP 5xx、CSP violation 和 secret finding 均为 0。

v0.3.4 不包含：

- 主题插件 SDK、Marketplace、npm theme package、目录扫描或动态主题加载；
- 安装、卸载、启用、停用、热更新、签名或第三方主题权限模型；
- 用户输入的 URL、CSS、HTML、JavaScript、字体或图片；
- TUI 主题重做；
- Session Runtime、多会话并发、Goal 状态机、模型、权限或 Tool 行为重写；
- 全新导航、第二套 Composer 或第二套 Work Panel；
- 远程字体、远程图片、CDN 或放宽 CSP；
- 把参考图中的演示数据写成 fixture 之外的产品默认数据；
- 将 AI 效果图直接作为长期像素 diff golden。

## 4. 外观合同与兼容性

### 4.1 theme/style 双轴

`appearance.theme` 继续只表达明暗偏好，新的内置视觉风格使用独立 style：

```ts
type WebThemePreference = 'system' | 'light' | 'dark';
type WebUiStylePreference = 'classic' | 'orion-refined-pixel';

interface WebAppearanceConfig {
  theme?: WebThemePreference;
  style?: WebUiStylePreference;
  motion?: 'system' | 'reduced';
}
```

DOM 投影：

```html
<html data-theme="system" data-ui-style="orion-refined-pixel"></html>
```

服务端、协议和客户端只接受封闭枚举。任何其他 style 值必须进入现有 invalid/last-good 诊断链，不得被解释为路径、包名、URL、CSS 或脚本。

### 4.2 默认与重置

| 配置状态                     | effective style                          | effective theme                                    |
| ---------------------------- | ---------------------------------------- | -------------------------------------------------- |
| style/theme 均缺失           | `orion-refined-pixel`，source=`internal` | `system`，source=`internal`                        |
| style=`orion-refined-pixel`  | 雅致像素几何和表面                       | theme 选择 light/day 或 dark/night Token           |
| style=`classic`              | 当前经典几何                             | theme 保持现有语义                                 |
| theme=`system`               | style 不变                               | 跟随 OS，并同步 meta color 与 xterm                |
| Settings invalid/unavailable | 使用 last-good                           | 无 last-good 时回到 `orion-refined-pixel + system` |

“重置界面风格”只清除显式 style 并恢复内部默认；“重置明暗模式”只清除 theme 并恢复 system。启动时不得为了默认值写回配置，也不得覆盖用户已有显式 theme。

### 4.3 Schema 与滚动升级

- 使用目标分支的下一个可用 Settings schemaVersion，不在计划中盲写固定版本；
- 新客户端可以读取旧 schema，并把缺失 style 投影为内部默认；新 Host 只发送新 schema；
- 旧标签页遇到不认识的新 schema 时停止 mutation，提示 Workbench 已升级并要求刷新；
- Host 与 hashed Web client 作为同一 npm 包原子发布；
- 新 `web.appearance.style` 必须经过旧版宽容 loader 的真实回滚测试；回滚后应忽略未知 style 并保留原 theme，而不是让整个配置失效；
- legacy localStorage 继续只迁移旧 theme，不伪造 style；
- 若 Phase 0 发现已发布 `orion-blocksmith`，必须通过 ADR 决定保留、迁移或弃用策略，并为真实升级/回滚增加测试后才能继续。

## 5. 雅致像素设计 Token

### 5.1 网格、边界与圆角

- 布局网格：4px 基础单位，常用间距为 8/12/16/24px；
- 轻像素单位：2px，只用于切角、角标、状态格、图标和 focus 阶梯；
- 普通边界：1px；选中、focus 和危险确认可以使用 2px；
- 圆角：内容卡 4px，输入和主要容器 6px，小型按钮 2–4px；不用大量 pill；
- 阴影：`0 1px 2px` 或 `0 4px 12px` 的低透明阴影，模糊半径不得制造漂浮玩具感；
- 卡片最多三层表面，不用图片九宫格承担基础布局。

### 5.2 Light 主色板

以下值是从效果图整理的实现起点，最终值必须经过真实截图和对比度校准：

| `--rp-surface`       | `#ffffff` | 消息、Tool、Composer 内容面 |

### 5.3 Dark 派生色板

dark/system-dark 继续使用同一 `orion-refined-pixel` style，不新增第二个风格 ID。夜间色板应保持哑光、低饱和和薄边界：

- canvas 使用深石墨蓝，不使用纯黑；
- panel/surface 维持清楚的三层亮度关系；
- navy 品牌牌不得与 canvas 融合；
- 蓝、紫、金、青绿按钮降低亮度但保持文字对比；
- Terminal 与代码面独立校准 ANSI 16 色；
- 组件几何、间距和图标不因明暗模式变化。

dark 是功能完整的派生规格，但效果图对 light 的约束优先级最高。

### 5.4 字体与图标

- 正文和 CJK：沿用系统 sans 栈；
- 代码、Diff 和 Terminal：沿用系统 mono 栈；
- 品牌字标和短标签：使用现有字体、字重、字距和容器几何表达轻像素，不引入像素字体；
- 功能图标继续使用语义 SVG 和可访问名称，视觉上采用方形端点和 16px/20px 网格；
- 小型状态灯可用 CSS 2px 阶梯和 8px 方形轮廓；
- 不复制任何外部游戏或 IDE 的图标；新增图标必须是 Orion 第一方原创。

### 5.5 Terminal Token

除背景、前景、光标和选择色外，必须增加 ANSI black/red/green/yellow/blue/magenta/cyan/white 及 bright 变体的语义 Token。`TerminalPanel` 在 `data-theme` 或 `data-ui-style` 变化时更新 xterm options，但必须保持 PTY ID、WebSocket、buffer、selection、focus、IME 和 scrollback 不变。

## 7. CSS、组件与资产架构

### 7.1 建议文件组织

目标分支复核后按现有结构落位，建议拆分为：

```text
web/src/
├─ styles.css
├─ themes/
│  ├─ contract.ts
│  ├─ refined-pixel.tokens.css
│  ├─ refined-pixel.components.css
│  └─ refined-pixel.a11y.css
└─ assets/themes/orion-refined-pixel/
   └─ assets.json
```

原则：

1. `styles.css` 保留 reset、布局、不变量和 classic 入口；
2. tokens 文件只定义语义变量和 light/dark 映射；
3. components 文件只在 `:root[data-ui-style='orion-refined-pixel']` 下改变表面、边界、几何和图标呈现；
4. a11y 文件集中 forced-colors、reduced-motion、contrast 和 focus 的必要覆盖；
5. 不复制整套 React 组件，不在主题分支中复制业务 JSX；
6. 不常规使用 `!important`；必要的 forced-colors 规则必须注释原因；
7. 优先 CSS 和现有 SVG。若不需要位图，runtime 主题目录只保留资产审计文件或完全删除；
8. 本计划的参考 PNG 永不被 runtime import。

### 7.2 启动与实时切换

- 首帧 HTML 使用安全的默认 `data-ui-style` 与 `data-theme`，避免主题闪烁；
- Settings ready 后原子更新 style/theme，不新增 localStorage 外观副本；
- 同一 animation frame 更新 `data-ui-style`、`data-theme`、`color-scheme`、`theme-color` 和 Terminal 色板；
- 切换不得改变 focus、selection、scroll、draft、open dialog、active work panel 或 running command；
- system media query 变化只换 Token，不替换 DOM 或重建组件；
- 切换失败时保持 last-good 外观并显示现有诊断，不产生半应用状态。

### 7.3 资产规则

- 所有 runtime 素材必须本地打包、内容哈希、同源加载；
- `assets.json` 记录文件、用途、尺寸、license、来源和 SHA-256；
- 禁止远程字体、远程图片、data URL 大图、用户路径和动态网络请求；
- CSS 装饰不得包含秘密、用户名、绝对路径或真实项目数据；
- 发布检查必须遍历完整 `dist/web-client`，不能只检查 HTML 和 server bundle。

## 8. Settings 设计与交互

### 8.1 外观设置

Settings → 外观提供两个独立控件：

1. 界面风格：
   - `雅致像素（内置，默认）` → `orion-refined-pixel`；
   - `经典（内置）` → `classic`。
2. 明暗模式：
   - 跟随系统；
   - 浅色；
   - 深色。

每个风格使用纯 CSS 小预览卡，展示 panel、message、primary action 和状态色；预览不加载参考 PNG，不在 hover 时偷偷切换全局主题。

### 8.2 保存语义

- 用户可以分别修改 style/theme，也可以一次原子提交两个 dirty key；
- 保存成功后才更新 effective appearance；失败时两项都保持 last-good；
- reset 只 unset 对应 key；
- Settings read-only/invalid/unavailable 时禁用保存，并显示具体原因；
- 多窗口外部更新沿用 current mirror/rebase/conflict 语义；
- 主题切换不受 Runtime busy 限制，除非当前 Settings 合同明确阻断所有 mutation；若阻断规则变化必须在 Phase 0 记录。

## 9. 响应式、无障碍、动效与性能

### 9.1 响应式

| 视口        | 行为                                                  |
| ----------- | ----------------------------------------------------- |
| ≥1440px     | 三栏常驻，按参考图比例展示                            |
| 1180–1439px | 左右栏可收窄，中央保持可操作最小宽度                  |
| 760–1179px  | 一侧 rail/drawer，另一侧按用户上下文展开              |
| 390–759px   | 单主栏 + drawer；Composer 固定在安全区域内            |
| 320–389px   | 最小支持；标签可收缩但 icon、tooltip、aria-label 完整 |

像素切角、伪元素和阴影不得造成页面横向滚动。drag resize 的视觉 handle 可细，但实际命中区继续满足当前产品规范。

### 9.2 无障碍

- 所有交互保持原生 button/input/select 或等价语义；
- 键盘可到达项目、Session、顶部动作、Work Panel、Composer 和 Settings；
- focus ring 不得被切角、overflow 或伪元素遮挡；
- active、success、warning、danger 使用颜色、图标和文字多重编码；
- 触控/关键交互目标至少 44×44 CSS px，密集工具条可以保留较小可见图标但扩大命中区；
- 200% zoom、text spacing、forced-colors 和 screen reader journey 通过；
- pixel/dither 只允许在 `aria-hidden` 装饰层，不进入可访问名称；
- reference PNG 的任何文字都不能作为真实信息的唯一来源。

### 9.3 动效

- hover/focus/press 使用 80–160ms 的颜色、边界或 1–2px 位移；
- 不使用循环闪烁、视差、漂浮像素或装饰粒子；
- running 状态沿用现有语义动画；reduced motion 下改为静态图标和文字；
- 切换 theme/style 不做整页淡出，不影响输入和 Terminal 光标。

### 9.4 性能与安全

- CSS selector 保持 style 根作用域，不使用深层高代价全局选择器；
- 不为像素边框复制大量 DOM；优先伪元素和共享 primitive；
- 不用 JavaScript canvas 绘制主题 chrome；
- 不放宽 `style-src`、`img-src`、`font-src` 或 `connect-src`；
- 无远程主题请求、无动态执行、无用户 CSS 注入；
- 视觉截图和 manifest 在发布前执行隐私扫描，不包含真实 home path、账号、token 或私有仓库内容。

## 13. 验收标准

### AC-01 内置边界

Given v0.3.4 安装包，When 检查配置、产物、网络和 Settings，Then style 只有封闭内置值，不存在插件、市场、安装/卸载、目录扫描、远程资源、任意 CSS 或主题脚本。

### AC-02 效果图一致性

Given 1536×1024 reference fixture，When 执行视觉评审，Then 主区域尺寸满足容差、视觉评分 ≥90、任一维度 ≥80%，且无厚重木石、游戏皮肤或仅换色等阻断偏离。

### AC-03 默认与兼容

Given 没有显式 style/theme，When 打开 Workbench，Then 使用 `orion-refined-pixel + system`；Given 用户已有显式 theme，When 升级，Then 原值继续控制明暗，且可以切回 classic。

### AC-04 实时切换

Given 正在输入、滚动、查看 Tool 或运行 Terminal，When 切换 style/theme，Then 一个 frame 内完成视觉切换，页面、Runtime、Session、PTY、WebSocket、focus、selection 和 draft 不重建或丢失。

### AC-05 全状态覆盖

Given Session、Goal、Tool、Files、Git、Terminal 和 Composer 的真实状态矩阵，When 使用 refined style，Then loading/empty/running/success/warning/error/disabled/focus 全部清晰且行为不变。

### AC-06 响应式与无障碍

Given 320–1920px、200% zoom、keyboard、screen reader、forced-colors 和 reduced-motion，When 完成核心旅程，Then 无页面横滚、遮挡、不可见 focus、单色状态或阻断级 axe 问题。

### AC-07 安全、性能与资产

Given exact tarball，When 检查完整 `dist/web-client` 和运行时网络，Then 无远程主题请求、CSP 放宽、动态执行、敏感数据或未登记资产，且满足资产与性能预算。

### AC-08 发布证据

Given release candidate，When 核对 receipt，Then source SHA、tarball SHA/integrity、安装路径、浏览器版本、场景结果、截图 manifest 和 installed artifact 一致。

## 15. 发布门禁

### 15.1 本地门禁

- `npm run lint`；
- `npm run build`；
- 相关 Settings、protocol、config、Terminal 和 Web 单元测试；
- 完整 `npm test`；
- reference asset SHA 校验；
- Markdown 链接、代码块和格式检查；
- 320–1920px 浏览器矩阵；
- axe、keyboard、zoom、forced-colors、reduced-motion；
- visual scorecard、overlay 和实现 golden；
- CSP、network、asset、license 和 secret 检查；
- resize/scroll/streaming/Terminal 性能旅程。

### 15.2 Release 门禁

- package version、source SHA 和 release notes 指向 v0.3.4；
- clean source 构建，无未声明 dirty dependency；
- exact `npm pack` tarball 通过 clean-prefix 安装；
- installed Host 实际服务该 tarball 的 hashed `dist/web-client`；
- Chrome 执行 RP34-P0 全部场景，P1 不得有未解释失败；
- screenshot manifest、release receipt、tarball SHA/integrity 和 installed artifact 一致；
- 发布包没有 remote theme code、reference PNG runtime import 或未登记大资源；
- 最终 GO/NO-GO 由证据生成，不用计划勾选代替真实测试。

## 17. 建议交付顺序

严格按以下顺序推进：

```text
冻结真实基线与 reference fixture
  -> 决定已发布 style 兼容策略
  -> 打通 appearance.style 纵向切片
  -> 完成 Token/root/Terminal
  -> 按 reference 实现核心组件
  -> 状态矩阵与响应式
  -> a11y/CSP/性能/资产门禁
  -> 视觉评分与真实 DOM golden
  -> exact tarball 浏览器验收
  -> release receipt 与 GO/NO-GO
```

v0.3.4 的目标不是给现有界面加一层像素装饰，而是把效果图中“克制的像素细节、专业 IDE 密度和安静的高级感”完整落到真实 Workbench，同时保持 Orion Code 的功能、兼容性、安全边界和可验证发布流程。
